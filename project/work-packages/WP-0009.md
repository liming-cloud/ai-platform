## 问题

WP-0008 解决了第一阶段可量化违规，但上下文公开边界、经典领域驱动分层、统一异常、
真实分页、模块自动装配和启动模块所有权仍未达到可长期扩展的工程质量。继续新增业务
会扩大错误边界并使 bootstrap 成为集中装配瓶颈。

## 范围内

- 建立 `shared-kernel`、`shared-contract` 和 `platform-web`。
- 六个上下文迁移到 `interfaces/application/domain/infrastructure`。
- 为领域对象增加泛型标记，为每个主要包增加简体中文职责说明。
- 建立统一异常基类、错误编码、HTTP 安全映射和脱敏测试。
- 八类列表接口迁移到 MyBatis-Plus 页码分页和总数契约。
- 单表简单 SQL 迁移到 BaseMapper 与 Lambda Wrapper。
- 为上下文、平台和扩展建立按能力自动配置和上下文测试。
- 三个 bootstrap 成为可执行应用，删除整个 `backend/runtimes`。
- 更新前端分页契约、Docker、Compose、构建、部署和验收脚本。
- 完成全量验证、容器演练和正确性、复杂度、冗余、性能、架构、测试质量六维走查。

## 范围外

- 兼容旧游标分页、旧包名、旧模块路径、旧数据库或旧演示数据。
- 增加新业务功能、模型厂商、连接器、设备渠道或画像能力。
- 前端视觉重设计。
- 微服务拆分、Kubernetes 或生产数据迁移。
- 把事件序号、向量候选数量或任务批次改为页码分页。

## 公共接口与数据

- 列表 HTTP 参数统一为 `pageNumber=1&pageSize=20`。
- 列表响应统一为 items、pageNumber、pageSize、totalElements、totalPages、
  hasPrevious 和 hasNext。
- 删除 cursor、limit、nextCursor 以及相应编码解码。
- 公共错误统一为 code、message、traceId 和 details。
- 错误码统一为 `上下文.类别.四位序号`。
- 公共契约不得出现 Spring、MyBatis-Plus、Sa-Token 或数据库类型。
- 数据库继续按绿地环境重建，不提供兼容迁移。

## 约束

- 每次只迁移一个可独立验证的上下文，先完成 organization-access 试点。
- 领域层只依赖 JDK 和 shared-kernel。
- Controller 默认依赖具体应用服务；不创建一对一无价值接口。
- 跨上下文只通过已声明 facade、领域事件或扩展端口。
- Wrapper 只在 infrastructure 内创建，复杂 XML SQL 必须登记允许原因。
- Java 文件继续禁止 MyBatis SQL 注解，主代码继续禁止 UUID。
- 非启动模块通过 Spring Boot 自动配置注册能力，不使用宽泛组件扫描。
- bootstrap 主代码只保留启动类，不声明业务 Bean。
- 旧目录、旧分页和集中装配债务只能递减，不能新增。
- 新增文档、包说明和代码注释使用简体中文。

## 验收标准

- shared-kernel 的聚合根、实体和值对象泛型接口被全部领域类型正确实现。
- 六个上下文不存在 `api` 和 `adapter`，技术实现只位于 infrastructure。
- 领域层不依赖 Spring、MyBatis-Plus、Sa-Token、HTTP 或 shared-contract。
- 跨上下文依赖只指向已公开 facade 或扩展端口。
- 所有错误码格式正确且全仓唯一；未识别和基础设施异常不泄漏内部信息。
- 八类列表通过首页、中间页、末页、空页、越界页、总数、固定排序和租户隔离测试。
- SQL 观测证明 MyBatis-Plus 实际生成分页与总数 SQL。
- 简单单表 SQL 不再保留在 XML；所有复杂 SQL 进入允许清单。
- 每个自动配置通过存在、缺失、覆盖和关闭场景测试。
- 三个 bootstrap 独立启动且只装配自身角色入口或任务。
- `backend/runtimes` 删除，Docker 服务和进程隔离保持不变。
- Spring Modulith、ArchUnit、依赖环、包规模、错误码和架构债务门禁通过。
- 前端分页、空状态、错误状态和权限状态回归通过。
- 全量容器交付、恢复、容量、升级和双租户评测通过。
- 最终六维走查不存在未修复的高优先级问题。
