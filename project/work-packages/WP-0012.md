## 问题

M3 已提供受治理数据和可发布索引，既有助手与可信查询已能使用发布版本回答。但产品尚不能让助手负责人以草稿完成可复现测试，也没有受控反馈和受权诊断任务。普通查询仅接受已发布助手版本的既有不变量，与草稿测试目标存在明确冲突，不能由应用层或页面静默绕过。

## 范围内

- 固化 M4 的统一语言、上下文所有权、聚合边界、跨上下文契约、安全边界和验收反例。
- 按已接受 ADR-0036 实现草稿测试、查询反馈和诊断，并保持它们与普通查询边界隔离。
- 将 M5 至 M8 固化为依赖与范围地图，明确它们不在本工作包激活或实现。
- 在 ADR-0036 接受后，按领域设计卡实施草稿测试、可信问答恢复、反馈和受权诊断的最小纵向切片。

## 范围外

- M6 的评测数据集、评测运行、发布审批、版本比较、成本预算、审计导出和平台／租户治理。
- M5 的路由、回退、工具、MCP、多模态、音频及新增模型能力。
- M7 的设备问答、渠道 SDK、画像同意和开发者门户。
- M8 的生产发布、容量、灾备、漏洞和支持签署。

## 公共接口与数据

任何受认证接口均只从 `Authorization: Bearer` 恢复 `TrustedRequestContext`，不得提交租户、主体、成员、权限、渠道或令牌作为业务参数。

草稿测试不得放宽普通 `QueryRun` 的 `PUBLISHED` 版本限制。反馈和诊断的字段、权限、保留和脱敏规则必须以被接受的 ADR-0036 为准。

## 约束

- 保持 ADR-0016 的可信查询顺序、引用验证和终态事件语义；恢复只消费事件序号，不展示未验证正文。
- 只引用 M3 已发布索引和 M2 受控模型配置；不接收厂商、端点、密钥、任意模型参数或任意知识范围。
- 领域对象必须满足 ADR-0031；不新增非聚合根 `Entity`，不使用债务基线或 allowlist 豁免。
- 草稿测试与普通查询必须通过同一可信回答执行门面；在 ADR-0037 接受前不得复制或迁移可信执行路径。
- 诊断所需候选、授权与模型修订事实尚未持久化；在 ADR-0038 接受前不得用重检索、当前配置或用户事件伪造历史诊断。
- M5 至 M8 仅记录依赖边界；每个后续里程碑在激活前另建可独立验收的工作包并取得必要 ADR。

## 验收标准

- `docs/architecture/foundation-m4-m8-design-map.md` 清楚区分 M4 的实施前沿和 M5 至 M8 的未来边界。
- ADR-0036 明确草稿测试与普通查询的隔离、反馈最小事实和诊断投影边界，并已获人工接受。
- 每个实现切片都先具备领域设计卡与红灯反例，随后补齐应用、真实 PostgreSQL、HTTP／事件和浏览器证据。
- M4 自动验收和人工评审通过前，不得切换到 M5。

## 领域设计卡：AssistantTestRun

| 项目 | 设计 |
| --- | --- |
| 统一语言与所有权 | `AssistantTestRun` 表示助手负责人对一个 `DRAFT` `AssistantVersion` 发起的一次受控测试。它由 assistant-delivery 拥有；普通 `QueryRun`、公开事件、最终用户用量和运营汇总不属于它。 |
| 聚合与不变量 | 它是独立 `AggregateRoot`：开始时冻结助手版本、知识空间、索引修订和两项受控模型配置；只接受 SHA-256 题目摘要；只有占用独立测试配额的 `RUNNING` 运行可以进入终态；回答必须带连续的最小引用标识，且根不保存题目或回答正文。 |
| 协作与持久化 | PostgreSQL 仓储已在租户 advisory lock 短事务内原子占用独立日／并发配额并提交终态；应用层将在后续切片加载草稿读取快照、在事务外执行可信检索后提交该根。不得复用 `QueryRun` 表、事件或配额。 |
| 安全与保留 | 发起者和租户仅由 `TrustedRequestContext` 派生；领域只保存稳定请求成员标识。题目与回答仅在当前受权响应中出现；持久化运行仅保留摘要、冻结依赖、终态、用量和最小引用标识。 |
| 反例与证据 | 纯领域测试先拒绝无配额终态、错误题目摘要、非受控模型快照和不连续引用；随后补真实 PostgreSQL、应用、HTTP／事件及浏览器反例。 |

## 领域设计卡：QueryFeedback

- 统一语言与所有权：`QueryFeedback` 表示请求成员对一次已完成 `QueryRun` 作出的不可变最小判断。它由 trusted-query 拥有，以运行标识关联，不是 `QueryRun` 成员或事件。
- 聚合与不变量：它是独立 `AggregateRoot`，仅保存租户、反馈标识、运行标识、请求成员、正负结果、受控原因和时间。`HELPFUL` 对应正向；`INCORRECT`、`INSUFFICIENT`、`IRRELEVANT` 对应负向。没有正文、更新或撤回。
- 协作与持久化：应用层已加载同租户已完成 `QueryRun` 并验证请求成员；仓储用 `(tenant_id, query_run_id, requested_by)` 唯一约束原子拒绝重复，三列外键同时拒绝错配成员。删除查询运行时由同一保留边界级联删除反馈。
- 安全与保留：身份和成员只从 `TrustedRequestContext` 派生。反馈不能复制问题、回答、提示词、证据正文、令牌或内部诊断；不得在 M4 自动进入评测数据集。
- 反例与证据：已验证结果与原因不匹配、非法标识、完成态、跨成员、重复写入、级联删除、自动配置、HTTP 上下文传递和前端受控枚举交互；正文存储归零。最终真实角色浏览器验收与受权诊断仍待后续独立切片。

## 下一前沿

当前唯一前沿是 M4 的两项待决边界：`AssistantTestRun` 可信执行等待 ADR-0037，查询诊断最小事实投影等待 ADR-0038；反馈的完成态、唯一持久化、保留边界和受控 HTTP 入口已完成。M5 至 M8 不得提前激活。
