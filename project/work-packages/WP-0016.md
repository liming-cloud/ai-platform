## 问题

现有页面从功能堆叠出发，存在一次性问答、多个分页、助手选择与主任务混杂等产品断层。继续直接改生产前端会放大返工。

## 本工作包唯一结果

用锁定版本的 OpenDesign 交付全部关键流程的高保真原型、设计令牌、夹具和验收截图，并取得人工确认。

## 范围内

- 从官方仓库安装签名稳定版 OpenDesign 并锁定版本；macOS 使用绝对 MCP 路径。
- 以 `docs/prototypes/wp-0016/page-inventory.json` 为单一事实源，原型覆盖当前产品蓝图中的全部页面任务。
- M6 覆盖平台治理、租户治理、知识接入、索引、模型、助手、评测、普通用户登录、助手选择、聊天、历史和异常恢复。
- M7 设备问答与 M8 平台运维只做信息架构和视觉前置原型，不因此获得生产实现授权。
- 覆盖 loading、empty、error、denied、partial、disabled、success。
- 覆盖键盘、reduced-motion 和 390、1024、1440 宽度。
- 固定一个页面一个主要任务和一个普通目录分页的布局规则。

## 范围外

- 修改生产前端、后端 API 或数据库。
- 把原型代码直接当作生产实现。
- 在人工确认前推进 WP-0017。

## 公共接口与数据

使用脱敏 fixtures 表达拟议契约，不创建真实 API。普通用户目标路由为 /app/login、/app/assistants、/app/conversations/:conversationId。

## 约束

- 本轮人工业务复核仍不通过；按 `docs/prototypes/wp-0016/BUSINESS-CLOSURE.md` 及 `TENANT-SETUP.md` 修复交互。ADR-0075 已确认两级功能控制；ADR-0076 开放配额与三项登录策略编辑原型。新账户邀请、真实登录锁定和生产配额合同不得伪装为既有能力。

- 先形成 DESIGN.md、tokens、fixtures 和原型，再做视觉与任务评审。
- 助手使用可搜索选择器；完整目录进入独立页面。
- 聊天页只包含左侧会话历史、中央消息流和顶部助手信息；消息按事件序号加载更早内容。
- 人工拒绝时保持本工作包进行中，不修改生产前端。

## 验收标准

- 全页操作覆盖账本必须区分真实模拟、仅导航、待决策和未实现；有待决策或无结果操作时不得宣称整套原型可验收。
- 按 ADR-0075 先验证功能能用，再验收交互易用性；租户功能上限和普通成员对话权限必须有保存、取消、刷新及拒绝结果。

- 所有关键流程和状态有可操作高保真原型。
- 页面清单、审查器入口、实际渲染和成功态截图完全一致，不允许只写页面名称而没有实际原型。
- 三档宽度、键盘和 reduced-motion 截图及检查通过。
- 人工明确确认产品任务、信息架构和视觉基线。
