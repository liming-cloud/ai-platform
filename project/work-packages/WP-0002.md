## 问题

必须先建立固定版本、可独立启动的全新代码和 Docker 运行时，才能在不继承旧边界的前提下实施产品功能。

## 范围内

- 重建前后端工程骨架。
- 按 `docs/architecture/foundation-repository-layout.md` 的 M1 最小落地目录建立平台机制、六个上下文、首批扩展、三个运行入口、两个前端应用、公共契约和跨系统验证目录。
- 建立架构测试、统一错误、观测、全新 PostgreSQL、Redis、MinIO 和三个运行进程。
- 以本地确定性模型和 OpenAI 兼容探测证明第一条纵向契约。

## 范围外

- 旧系统兼容或数据迁移。
- 完整数据摄取和查询页面。
- 生产发布。

## 公共接口与数据

只实施 WP-0001 已批准、且供应商探测和健康检查必需的最小契约。

## 约束

- WP-0001 通过后才能激活。
- 公共类型不得暴露 Spring AI 或持久化类型。
- 只使用全新基础设施。
- 源码注释遵守根 `AGENTS.md` 的中文注释规范。

## 验收标准

- 全新检出能够使用固定基线构建。
- Maven 模块、上下文内部包、扩展和运行入口依赖门禁通过。
- 前端应用边界和共享包消费者门禁通过。
- 三个运行进程能够在 Docker 中启动。
- `console-web` 与 `query-web` 能够独立构建。
- 密钥只保存引用并完成脱敏。
- 供应商探测契约通过确定性测试。
