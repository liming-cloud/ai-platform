## 问题

工程骨架已经可运行，但用户尚不能在明确租户和权限边界内建立可供后续索引的知识空间。没有这条纵向闭环，模型、助手和查询都只能依赖伪造数据。

## 范围内

- 建立一个受限演示租户和租户管理员登录入口。
- 使用 Sa-Token 建立人员会话、租户上下文和 `knowledge:read`、`knowledge:write` 权限。
- 实现知识空间聚合及创建、列表公共契约。
- 实现受治理文本数据源的登记、UTF-8 内容上传和发布状态。
- 使用全新 PostgreSQL Schema、Flyway 和 MyBatis-Plus 实现真实持久化。
- 使用 MinIO 保存原始内容，数据库只保存对象引用和内容摘要。
- 对写操作实施幂等键、乐观锁、租户隔离、演示配额和审计记录。
- 在控制台完成“登录 -> 创建知识空间 -> 上传文本 -> 查看发布结果”单一任务流。
- 提供门店商品说明和校园信息两份合成文本。

## 范围外

- PDF、网页、数据库连接器和批量同步。
- 分块、向量化、检索和问答。
- 模型供应商连接持久化和助手发布。
- 企业单点登录、组织树和复杂角色管理。
- 旧系统数据迁移。

## 公共接口与数据

- `POST /api/v1/auth/sessions`
- `DELETE /api/v1/auth/sessions/current`
- `POST /api/v1/knowledge-spaces`
- `GET /api/v1/knowledge-spaces`
- `POST /api/v1/data-sources`
- `POST /api/v1/data-sources/{id}/content`
- `POST /api/v1/data-sources/{id}/publish`
- `GET /api/v1/data-sources`

公共错误遵循 `code`、`message`、`traceId`、`details`；写操作要求 `Idempotency-Key`，列表使用游标分页。数据库表、对象键和缓存键必须包含租户边界。

## 约束

- 领域层只依赖 JDK 和批准的平台值类型。
- Controller 不直接调用 Mapper、对象存储或 Sa-Token 静态接口。
- MyBatis-Plus 类型只存在于持久化适配器。
- 密码、会话令牌和原始内容不得进入日志或审计详情。
- 每个持久化测试使用真实 PostgreSQL 事务语义，不能用内存仓储冒充提交与回滚。
- 页面只围绕发布首份知识数据组织，不新增顶级导航。
- 演示默认限制为 3 个知识空间、20 个数据源和每个文件 20 MB。

## 验收标准

- 未登录、跨租户和缺少写权限的请求均被拒绝且不泄漏资源存在性。
- 重复幂等请求只产生一个知识空间或数据源。
- 并发更新只有一个版本成功，失败方不产生成功审计。
- 原始内容进入 MinIO，数据库记录对象引用、SHA-256 和发布版本。
- Docker 环境可从全新卷初始化数据库并完成任务流。
- 控制台覆盖加载、空、错误、拒绝、部分完成和陈旧状态。
- 门店和校园合成文本均能独立发布。
- 后端、前端、容器和治理门禁全部通过。
