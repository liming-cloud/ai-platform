## 问题

平台已有受控知识和授权候选检索，但还不能让租户管理员配置真实模型部署、
组装并发布助手，也不能让最终用户得到带引用或明确拒答的回答。
如果把 Spring AI、厂商参数、提示词和检索结果直接拼进 Controller，
模型差异、权限和引用规则会扩散到整个系统。

## 范围内

- 研究 Spring AI 2.0.0 正式能力并固定模型运行时、助手版本和查询流水线 ADR。
- 实现 `ProviderConnection`、`ModelDeployment`、`Assistant` 和
  `AssistantVersion` 的最小聚合、版本、发布状态与 PostgreSQL 持久化。
- 数据库只保存密钥引用；演示环境通过受限密钥存储适配器解析凭据。
- 通过 Spring AI 实现 OpenAI Compatible 与 Ollama 的 Chat 和 Embedding 工厂。
- 供应商连接和模型部署执行端点、凭据、认证、能力和最小调用探测。
- 模型部署显式记录能力，不根据厂商名称推断。
- 助手版本固定聊天部署、知识空间、活动索引、系统指令、引用和拒答策略。
- 查询流水线实现可信上下文、演示配额、策略、安全、检索、证据再鉴权、
  生成、引用校验和审计计量的固定顺序。
- 使用 Spring AI `ChatClient` 统一同步与流式调用，公共契约不泄漏框架类型。
- 查询事件使用带单调序号的服务端事件流，断线重连不得重复完成事实。
- 控制台在“治理”和“助手”既有导航内提供分步任务，不增加顶级导航。
- 查询站点围绕一次提问、答案、引用和拒答组织，不展示尚未发布助手。
- Docker 演示默认使用确定性替身；真实厂商冒烟由显式环境开关启用。

## 范围外

- Rerank、混合检索、结构化 Query DSL 和任意 SQL。
- 模型路由、静默降级、跨区域备用和成本最优化。
- Tool Calling、MCP、多模态、图像、音频和推理选项。
- 企业单点登录、设备凭据、硬件机器人和用户画像。
- 完整离线评测平台、审批流、成本看板、备份和灾备。

## 公共接口与数据

- `POST/GET /api/v1/model-providers`
- `POST /api/v1/model-providers/{id}/probe`
- `POST/GET /api/v1/model-deployments`
- `POST /api/v1/model-deployments/{id}/probe`
- `POST /api/v1/model-deployments/{id}/publish`
- `POST/GET /api/v1/assistants`
- `POST /api/v1/assistants/{id}/versions`
- `POST /api/v1/assistant-versions/{id}/publish`
- `POST /api/v1/query-runs`
- `GET /api/v1/query-runs/{id}`
- `GET /api/v1/query-runs/{id}/events`

写操作要求幂等键，更新和发布要求乐观版本。请求不得提交租户、明文密钥、
任意类名、原始 SQL 或可改变知识权限边界的模型覆盖参数。

## 约束

- 领域层只依赖 JDK 和已批准的平台值类型。
- Spring AI 类型只存在于模型扩展、查询适配器和组合根。
- `ChatModel`、`EmbeddingModel` 和 `ChatClient` 不在控制器或领域层创建。
- 供应商专属参数必须使用版本化命名空间、白名单和范围校验。
- 凭据、提示词全文、原始上下文和回答正文默认不进入普通日志。
- 助手发布必须固定不可变版本；查询任务只引用已发布助手版本。
- 检索后的证据必须按当前会话再次鉴权，生成前后都不能绕过。
- 无授权证据、证据不足或引用无法验证时必须拒答，不能伪造来源。
- 前端每页一个主要目标和一个主操作，高级参数默认折叠。

## 验收标准

- 租户管理员可按四步流程配置、探测并发布 OpenAI Compatible 或 Ollama 部署。
- 凭据保存后不可回显，接口、日志和错误均不包含密钥。
- 未授权端点、环回、链路本地、云元数据和私有地址按策略拒绝；
  Ollama 只允许运维显式批准的内部地址。
- 相同助手版本始终使用冻结的模型部署、索引和提示策略。
- 未发布、跨租户、缺少权限或超额请求不能执行模型调用。
- 门店和校园问题分别返回带可核验引用的回答，且不能交叉引用。
- 证据不足、引用不匹配和模型异常产生稳定拒答或失败事件。
- 流式事件序号单调，重连和幂等重试不重复计量。
- 前后端、架构、安全、容器、性能、治理和产品任务门禁全部通过。
