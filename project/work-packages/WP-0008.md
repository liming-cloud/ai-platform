## 问题

当前实现能够运行，但 SQL、标识、包结构、领域所有权、平台安全、平台持久化和运行装配
偏离已批准的企业级基座设计。继续在该结构上增加功能会放大错误边界。

## 范围内

- 删除 Java 源码中的全部 MyBatis SQL 注解，建立 Mapper XML 和 MyBatis-Plus 规范。
- 将 UUID 领域标识、数据库列和公共契约重建为雪花标识。
- 新增 `platform-persistence` 并实现统一 MyBatis-Plus 配置和标识生成。
- 将 `platform-security` 重构为安全核心与 Sa-Token 适配模块。
- 按聚合和用例拆分平铺包，增加包规模门禁。
- 增强组织权限与评测运营领域模型，并把业务不变量移回聚合或领域策略。
- 新增三个 bootstrap 模块，把控制器、调度和装配移出运行模块。
- 增加架构测试、真实 PostgreSQL 集成测试和从空卷重建验收。

## 范围外

- 兼容 UUID API、数据库或演示数据。
- 迁移旧数据或保留旧备份可恢复性。
- M2 新业务功能。
- 微服务拆分、Kubernetes 和生产多副本雪花节点分配。
- 新模型厂商、连接器、设备渠道或画像功能。

## 公共接口与数据

- 所有标识在 HTTP 和事件契约中改为十进制字符串。
- 所有数据库业务标识列改为 `BIGINT`。
- 当前数据库和演示数据从空卷重建。
- 公共错误、分页、幂等和业务语义保持不变，但不承诺旧标识格式兼容。
- Java Mapper 只保留方法签名；自定义 SQL 全部进入 XML。

## 约束

- 领域层只依赖 JDK、`platform-kernel` 和批准的安全核心值类型。
- 主代码不得引用 `java.util.UUID`。
- Java 文件不得出现 MyBatis SQL 注解。
- Sa-Token 类型只能存在于 `platform-security-satoken`。
- MyBatis-Plus 配置和通用拦截器只能存在于 `platform-persistence`。
- 运行模块主代码只能包含一个启动类。
- 不创建 `infrastructure`、`common`、`utils`、`manager` 或 `service.impl`。
- 每次只迁移一个可独立验证的纵向切片，不能一次性移动后再补测试。

## 验收标准

- SQL 注解扫描结果为零，8 个现有 Mapper 的定制 SQL 均有 XML 映射和数据库测试。
- 主代码 UUID 扫描结果为零，数据库业务标识均为 `BIGINT`，前端把标识作为字符串。
- `platform-persistence` 提供雪花标识、XML 扫描、租户、乐观锁、分页和危险操作阻断。
- Sa-Token 依赖和源码只存在于 `platform-security-satoken`，会话和可信上下文回归通过。
- 六个上下文符合聚合、用例、入站适配器、出站适配器目录预算。
- 组织权限和评测运营具有领域模型及纯领域测试。
- 三个 runtime 各只有一个主代码启动类，所有控制器和装配均有明确所有者。
- Spring Modulith、ArchUnit、Maven 依赖和包规模门禁全部通过。
- 210 项既有后端行为及新增回归全部保持，前端、容器、评测、恢复和容量重新验收。
- WP-0007 重新生成绑定整改提交和新镜像的 M1 技术验收清单。

## 证据

研究基线已经确认 8 个阻断问题及官方框架依据：
`docs/research/WP-0008-architecture-remediation-baseline.md`。

首个实现切片证据为 `project/evidence/WP-0008-persistence-foundation.md`。平台持久化、
雪花标识生成和债务递减门禁已经建立。第二个切片已经把 96 条注解 SQL 迁入 8 个
Mapper XML 并将该项债务归零。第三个切片已经迁移主体和成员标识，第四个切片已经
迁移全局租户标识，UUID 主代码文件从 122 降至 115。其他业务标识、安全边界、目录
和运行时迁移尚未完成，工作包不得标记完成。第五个切片已经迁移知识空间、数据源和
索引版本标识，第六个切片已经迁移供应商连接、模型部署及全部跨上下文模型引用，
UUID 主代码文件进一步从 83 降至 42。第七个切片已经贯通助手、助手版本、查询运行、
查询事件、运营审计与前端字符串契约，UUID 主代码文件从 25 降至 10。
