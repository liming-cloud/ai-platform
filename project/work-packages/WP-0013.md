## 问题

M4 已固定受控模型配置、冻结助手执行目标与可信回答执行门面，但尚未定义多类型模型能力、路由、回退、工具、MCP、多模态、音频、驻留、健康、延迟和成本策略的统一语言、所有权和安全边界。直接在既有查询或助手服务中叠加这些能力，会破坏冻结快照、可信引用和密钥最小披露语义。

## 本工作包唯一结果

形成 M5 的独立影响分析、领域设计卡和 ADR 提案，明确第一条可验收纵向切片及其反例、权限、冻结、保留、失败关闭与证据要求。ADR 获人工接受前，不创建 M5 的模型能力、路由、回退、工具、MCP、多模态或音频实现。

## 范围内

- 基于已接受的 M2 至 M4 决策，梳理 M5 受控模型扩展的上下文所有权、聚合／值对象／读取投影边界与跨上下文契约。
- 通过代码图谱确认受控模型配置、助手版本、可信回答执行和查询终态的现有依赖与变更影响。
- 提出需要产品负责人接受的 ADR，列出至少两种实质替代方案及拒绝原因。
- 为首条已接受切片登记测试先行、真实持久化、HTTP／事件、浏览器与全量验证的证据合同。

## 范围外

- 在 ADR 接受前实现任何 M5 生产代码、数据库迁移、公开接口或浏览器功能。
- 由用户输入厂商、端点、密钥、任意模型参数、任意工具地址或任意 MCP 服务器。
- M6 的企业治理、评测、发布审批、预算、审计导出和运营工作台。
- M7 的渠道 SDK、设备问答、画像同意和开发者门户。
- M8 的生产发布、容量、灾备、漏洞和支持签署。

## 公共接口与数据

本工作包不创建公共接口、数据库表、事件或浏览器路由。设计中出现的租户、主体、成员、权限、渠道和登录态均只能以 `TrustedRequestContext` 表达；任何未来运行契约均不得接收它们或令牌、厂商、端点、密钥、任意模型参数、工具地址或 MCP 地址作为业务输入。

## 继承约束

- 身份、租户、成员、权限、渠道和登录态仅从 `TrustedRequestContext` 恢复，不能作为业务参数。
- 所有运行必须冻结其受控模型事实；不得在读取、重放、诊断或回退时用当前配置伪造历史。
- 工具、MCP、外部网络、音频或多模态能力均须默认拒绝、最小披露与失败关闭，且不得绕过引用验证和资源再鉴权。
- 遵守 ADR-0031：跨根不变量由命名领域服务和不可变操作结果承载；禁止以债务基线或 allowlist 豁免违规。

## 约束

- 只能推进 `WP-0013`，不得以设计名义提前实现 M5 至 M8 的功能。
- 影响分析必须先使用代码图谱，覆盖模型配置、助手版本、可信回答执行、查询运行、权限、持久化和外部动作边界。
- ADR 提案未获人工接受前，只能形成设计和红灯测试计划，不能创建生产实现或修改既有查询语义。
- 后续切片必须先有领域设计卡与可证伪反例，并补齐应用、真实 PostgreSQL、自动配置、HTTP／事件、浏览器和全量验证证据。

## 验收标准

- 形成经代码图谱影响分析支撑的 M5 设计证据与至少一份 ADR 提案。
- ADR 清楚限定模型能力、路由与外部动作的所有权、权限、快照、失败、审计和保留边界，且不改变 M4 已冻结的普通查询语义。
- 首条实现切片在 ADR 接受前保持未实施；接受后先写可证伪的红灯测试再实现。
- M5 自动验收和人工评审通过前，不得激活 M6。
