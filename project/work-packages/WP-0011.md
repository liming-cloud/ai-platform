## 问题

当前数据入口只覆盖受限文本首发路径，无法让知识管理员以可追溯、可恢复且受权限约束的方式完成数据源、数据集、结构、质量、同步、退役、索引与重建的完整任务。M2 已提供受控 Embedding 配置，M3 必须把它作为索引冻结依赖，而不能恢复任意模型或端点输入。

## 范围内

- 先以产品和架构设计固定数据源、数据集、Schema、敏感级别、质量规则、同步报告、退役与索引重建的生命周期，并按 ADR-0031 收敛已确认的领域聚合边界。
- 实现文件、对象存储和结构化数据集的受控草稿、连接探测、同步、质量报告、重试与退役任务。
- 以不可变版本发布数据结构、来源产物和索引；索引只能绑定当前主体已授权、已启用的 M2 `EMBEDDING` 配置，并冻结配置、目录条目、维度与版本。
- 提供知识管理员的浏览器闭环，覆盖加载、空、失败、无权限、部分成功、过期和可恢复操作。
- 为权限、质量、幂等、重试、索引重建和模型配置同源绑定提供自动化、真实持久化和运行证据。

## 范围外

- 助手草稿、评测门禁、发布审批、模型多路路由、设备问答、SDK/API 渠道和生产运维工作台。
- 平台管理员的租户生命周期和平台/租户范围切换实现；该能力按 ADR-0027 在 M6 交付。
- 用户新增模型厂家、任意端点、任意嵌入维度或绕过 M2 模型配置授权。

## 公共接口与数据

数据领域的公共契约必须保持框架无关，并先完成必要 ADR。任何新的数据源类型、连接器协议、Schema 版本语义、质量门禁或索引重建规则均须有对应领域不变量和迁移说明。M3 不得破坏 ADR-0015 的索引状态机和 ADR-0023 的嵌入配置同源绑定。

受认证接口还必须遵守 ADR-0033：租户、主体、成员、凭据类型、渠道、权限版本和权限集合仅由令牌恢复的 `TrustedRequestContext` 提供，不得出现在路径、查询、请求体、表单、Header、事件或应用命令中。后续 M3 HTTP 与安全回归须覆盖伪造登录状态字段不参与授权或归属判定。

## ADR-0031 领域设计卡：同步完成与产物发布

| 项目 | 设计 |
| --- | --- |
| 语言与所有权 | “文件同步完成”是将已核验的 FILE 对象事实固定为一次 `SyncArtifact` 的操作；“产物发布”是将质量非阻断的产物显式固定为 `PublishedSyncArtifact` 的操作。两者均由 knowledge-data 上下文拥有；对象读取、鉴权、HTTP、事务与索引构建明确排除在领域服务外。 |
| 聚合 | `GovernedDataSource` 是来源状态机与并发版本根；`SyncArtifact` 是独立、不可变的产物根；`SourceRevision`、`QualityReport` 和 `PublishedSyncArtifact` 是不可变值事实。同步完成只允许 `SYNCING -> READY`，发布只允许 `READY -> READY`，两者均递增来源版本；产物必须属于来源当前修订，质量报告必须属于该产物。 |
| 协作 | `FileDataSourceSynchronization` 以已加载来源、来源修订和经事务外 I/O 核验的摘要事实创建产物、质量报告与 `FileSynchronizationCompletion`。`FileSyncArtifactPublishing` 以已加载来源、产物、质量报告和时间创建发布事实与 `FileSyncArtifactPublication`。两个结果是仓储原子提交的唯一写入输入；本切片不新增跨上下文事件或补偿。 |
| 安全 | 应用层先从 `TrustedRequestContext` 执行 `knowledge:write`、租户和知识空间范围加载；领域服务再次校验来源、修订、产物与质量报告的归属和 FILE 类型。操作结果不包含正文、对象键、连接信息、密钥或外部异常。 |
| 持久化 | `GovernedDataSourceRepository` 只接收不可变操作结果。PostgreSQL 实现只映射、以来源修订锁／乐观更新和同一事务提交来源、产物、质量或发布事实；不重新推导归属、质量或状态机。并发失配关闭失败且不留下半成品。 |
| 验证方式 | 纯领域反例覆盖类型、修订、归属、状态、质量阻断和过期版本；应用测试覆盖权限、对象 I/O 成功与失败编排；真实 PostgreSQL 覆盖原子提交与并发；自动配置与 HTTP 回归覆盖装配和对外失败语义。 |

## ADR-0030 领域设计卡：OBJECT_STORAGE 范围与对象集合修订

| 对象存储同步规约维度 | 设计 |
| --- | --- |
| 对象存储语言与所有权 | “平台托管范围”是部署侧预置、不可由知识管理员创建或枚举的授权边界；“范围选择修订”是知识管理员提交的、由平台已签发的范围标识与选择版本；“对象集合修订”是该选择在登记时冻结的实际对象元数据集合。三个术语均归 knowledge-data 上下文；M3 不提供平台范围管理 API、外部端点、桶名、对象键或凭据输入。 |
| 对象存储聚合 | `GovernedDataSource` 继续作为来源身份与状态机聚合根。`SourceRevision` 是不可变值事实：OBJECT_STORAGE 必须且只能携带一个 `ObjectStorageObjectCollection`；FILE 必须且只能携带一个 `FileSourceObjectReference`。集合由不透明平台对象标识、内容摘要、长度、媒体类型和新鲜度构成，按稳定顺序计算定义摘要；同一对象标识不得重复。 |
| 对象存储协作 | 本切片只建立领域事实及其仓储映射。后续登记服务只能接受受部署控制的范围解析器返回的已核验集合，并以 `SourceRevision.objectStorage` 创建修订；同步、探测、发布和索引不会读取可变前缀，也不会因本切片自动触发。 |
| 对象存储安全 | 对外契约仅允许不透明范围标识和选择修订；持久化对象标识同样不含端点、桶名、原始对象键或凭据。范围与对象集合均按租户、知识空间、数据源和修订绑定；跨范围、空集合、重复对象、摘要不合法或将 FILE 与 OBJECT_STORAGE 事实混用时关闭失败。 |
| 对象存储持久化 | `source_revision` 保存范围标识、选择修订和集合摘要；子表保存按序冻结的对象元数据，并以来源修订复合外键约束。仓储在单一注册事务中写入来源、修订和集合；读取时重建领域值对象，不推导或修改集合。 |
| 对象存储验证方式 | 先以纯领域反例验证类型专属事实、非空集合、重复对象和摘要一致性；再以真实 PostgreSQL 验证范围、选择修订和对象集合写后读一致、租户隔离和事务原子性；自动配置回归确保新增映射器可装配。 |

## ADR-0030 领域设计卡：STRUCTURED_DATASET 私有 CSV 与字段映射修订

| 结构化数据集设计维度 | 设计 |
| --- | --- |
| 结构化数据集语言与所有权 | “私有 CSV”是平台上传适配器生成且仅归属租户、知识空间和来源修订的 UTF-8 CSV 对象；“字段映射”是 CSV 标题字段到逻辑类型和敏感级别的有序声明；“行过滤”是没有原始字段值、SQL 或任意表达式的受控枚举。三者均归 knowledge-data 上下文，知识管理员不得提交对象键、桶名、端点、凭据或任意过滤表达式。 |
| 结构化数据集聚合 | `GovernedDataSource` 继续作为来源身份与状态机聚合根。`SourceRevision` 是不可变值事实：STRUCTURED_DATASET 必须且只能携带一个 `StructuredDatasetCsvDefinition`，其中包含私有 CSV 摘要、映射版本、主内容字段、可选标题字段、有序字段映射和行过滤策略。主内容与标题必须是允许检索的文本字段；`CONFIDENTIAL`、`RESTRICTED` 字段不能成为 M3 规范化检索文本。 |
| 结构化数据集协作 | `GovernedStructuredDatasetRegistrationService` 先以可信上下文校验 `knowledge:write`，将上传流严格暂存为 UTF-8，再通过专用私有 CSV 对象端口生成 `StructuredDatasetCsvReference`，最后以 `SourceRevision.structuredDataset` 原子登记；持久化失败会删除刚写入的对象。CSV 抽样、解析、字段策略、质量、发布和索引必须消费既有修订，不能重新解释或覆盖映射。 |
| 结构化数据集安全 | CSV 对象键不经 HTTP、事件、错误或读取投影公开；修订摘要覆盖对象位置、内容摘要、长度、媒体类型、映射版本、字段顺序、逻辑类型、敏感级别和行过滤。字段名重复、主内容或标题不存在、非文本、受限，或混用 FILE、OBJECT_STORAGE、STRUCTURED_DATASET 类型事实时失败关闭。 |
| 结构化数据集持久化 | `source_revision` 仅保存 CSV 对象事实和映射入口字段；`source_revision_dataset_field` 通过来源修订复合外键按序保存字段名、逻辑类型和敏感级别。仓储在单一注册事务中写入来源、修订和全部字段映射；读取时重建值对象并复核定义摘要，不推导 Schema 或修改映射。 |
| 结构化数据集验证方式 | 先以纯领域反例验证来源类型、重复字段、内容字段逻辑类型和敏感级别；再以真实 PostgreSQL 验证 CSV、映射顺序、摘要一致、租户隔离和原子写入；自动配置回归确保新增 Mapper 可装配。 |

## ADR-0034 领域设计卡：OBJECT_STORAGE 私有正文同步

| 规约维度 | 设计 |
| --- | --- |
| 统一语言与所有权 | “冻结范围选择”是 `SourceRevision` 中的 `ObjectStorageObjectCollection`；“平台正文映射”是基础设施专有的对象标识到内部位置映射；“规范化文本产物”是按冻结顺序聚合对象正文后生成的私有 `TextContentReference`。范围标识、对象标识和内部位置均不进入 HTTP、索引读取投影、事件或日志。 |
| 聚合与值事实 | `GovernedDataSource` 保持来源状态机聚合根，`SyncArtifact` 保持独立产物聚合根；`ObjectStorageSynchronization` 是命名领域服务，唯一负责 OBJECT_STORAGE 的状态、修订、产物、质量和不可变完成结果。`SourceRevision`、对象集合、质量报告和完成结果均为不可变事实。 |
| 输入与 seam | 应用层在事务外按 `SourceRevision` 与其成员 `PlatformObjectReference` 调用内部正文读取端口；端口必须验证对象属于该冻结选择，且内部位置永不穿透该端口。应用层读取后只将私有规范化正文暂存并写入 `TextContentObjectStoragePort`。 |
| 不变量与失败 | 只接受严格 UTF-8、`text/plain; charset=UTF-8` 且非空的冻结对象；按集合顺序以 `\n\n` 连接。任一映射、媒体类型、长度、摘要、编码或读取失败都会关闭失败，不创建部分产物；刚写入而未提交的私有产物必须删除，来源进入 `FAILED(SYNCHRONIZATION)`。成功时记录数必须等于冻结对象数，质量固定为 `object-storage-text-v1/PASS`。 |
| 发布与索引 | 发布复用显式同步产物发布的归属和质量边界；索引只读取 `SyncArtifact.content()` 冻结的私有产物，不重新读取范围或平台对象。 |
| 对象存储同步验证方式 | 纯领域反例覆盖类型、修订、状态与内容版本；应用回归覆盖授权、顺序、失败清理；真实 MinIO／PostgreSQL 覆盖映射、字节摘要核验、原子提交和租户隔离；自动配置、HTTP 与浏览器回归证明不泄漏内部位置。 |

## 本轮领域边界整改

已按 ADR-0031 完成已确认的首批整改：助手版本创建通过命名领域服务集中分配版本和快照；FILE 同步完成及产物发布通过不可变领域操作结果提交；成员认证事实收敛为读取投影；查询和运营配额收敛为 `DomainPolicy`。自动门禁禁止新增非聚合根实体和应用服务构造器领域状态依赖。

FILE 同步与发布实现的可复核记录见 [WP-0011 领域聚合操作边界整改证据](../evidence/WP-0011-domain-aggregate-operation-boundary.md)。该记录不构成 M3 完成或进入 M4 的批准。

## 约束

- 租户、资源、行列授权必须在同步、质量检查、索引构建和查询前生效；界面隐藏不能替代服务端拒绝。
- 数据正文、连接密钥、原始向量和未授权质量详情不得进入普通日志、审计摘要或无权限页面。
- 长时间对象读取、连接探测与嵌入调用不得占用数据库事务；重试必须消费冻结来源版本。
- 索引不得混用嵌入配置、修订、目录条目或向量维度；失效配置不得回退到其他范围模型。
- 产品经理浏览器验收只验证角色任务闭环，不代替后端、持久化、安全、性能和运行门禁。

## 验收标准

- 知识管理员可在其租户内完成数据源草稿、探测、同步、质量检查、索引构建、发布、重试、退役和重建；每一步都有稳定状态与恢复动作。
- 结构、敏感级别、来源版本、质量结果和索引冻结事实可审计且不可被后续编辑隐式覆盖。
- 无权限、跨租户、未发布、质量不通过、连接失败、过期和模型配置失效均关闭失败，且不得泄漏资源存在性或敏感内容。
- 索引构建、重试、激活和重建保持幂等、版本化和原子切换；索引与查询使用完全一致的嵌入配置快照。
- 企业控制台的“数据”区域通过知识管理员真实浏览器验收；M3 不新增平台管理或设备前端入口。
- M3 所有自动化、真实持久化、浏览器和运行证据完成后，必须经人工评审明确通过，方可进入 M4。

## 证据

在每个可验证的纵向切片完成后，登记设计决策、自动化测试、真实 PostgreSQL、浏览器任务、容器运行和失败恢复证据。已登记的 FILE 操作边界整改见 `project/evidence/WP-0011-domain-aggregate-operation-boundary.md`。未经 M3 人工评审批准，不得将这些证据用于进入 M4。

## 当前阻断

本地受控模型配置数据库存在 4 个已发布目录条目的 `EMBEDDING` 配置，但它们均为 `PERSONAL` 范围；不存在 `PLATFORM`／`TENANT` 范围的活动嵌入配置，也没有活动的模型配置授权记录。`UsableModelConfigurationLookupService` 会以令牌恢复的租户和成员再次校验可用性，因此知识管理员无法创建索引版本是正确的失败关闭。

恢复条件是平台运维通过既有受控模型配置流程提供已发布、活动、带加密凭据并对当前租户／成员可用的 `EMBEDDING` 配置；不得通过读取、复制、输出或提交既有凭据绕过该条件。配置就绪后依次完成 FILE、STRUCTURED_DATASET、OBJECT_STORAGE 的索引构建、发布和重建浏览器闭环，再恢复 WP-0011 的人工评审准备。

ADR-0031 已固定全平台领域设计规约，且助手版本、FILE 同步／发布、认证投影和配额策略的首批整改已完成自动验证。ADR-0030 的 `OBJECT_STORAGE` 范围、不可变对象集合、受控登记及范围探测已完成自动验证；ADR-0034 的私有正文映射、固定 `\n\n` 同步、PASS 质量、显式发布与控制台闭环已完成真实 MinIO／PostgreSQL、自动配置、HTTP 与前端客户端回归。控制台只提交平台签发范围标识与选择修订，不枚举或泄漏内部对象位置；真实浏览器已验证 OBJECT_STORAGE 的登记、探测、同步、PASS 与显式发布。历史同步产物升级保持其空内容引用且排除出索引候选；没有平台正文读取映射的部署不装配对象存储入口。ADR-0032 的结构化数据集私有 CSV／字段映射、登记即绪、同步、质量、显式发布与索引控制台已完成领域、应用、真实 PostgreSQL、HTTP 与前端客户端回归；控制台仅允许当前已发布同步产物创建和发布索引。CSV 多记录规范化文本固定以 `\n\n` 连接。本地浏览器现已验证可写知识管理员的 FILE 登记至显式发布，以及 STRUCTURED_DATASET 的标准 `text/csv` 登记。缺少受控 Embedding 运行时时，三类来源的索引创建均失败关闭；不得伪造模型配置或索引成功。恢复后，各来源类型仍需完成知识管理员真实浏览器索引构建、发布和重建闭环；结构化数据集不得接收外部端点、桶名、对象键或凭据，也不得自动发布或替换现有活动索引。
