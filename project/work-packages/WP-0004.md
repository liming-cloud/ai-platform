## 问题

已发布原始文本尚不能形成可确定重建、可按租户授权、可追踪模型版本的检索索引。
如果直接把分块和向量写入单一活动索引，将无法证明内容版本、嵌入模型、
维度和检索结果之间的关系，也无法安全切换模型或重建索引。

## 范围内

- 在编码前形成并接受索引生命周期 ADR。
- 从已发布文本对象读取内容，不绕过数据库发布事实。
- 定义确定性文本规范化、分块标识和分块元数据。
- 定义 `IndexVersion` 聚合及创建、构建、就绪、激活和失败状态。
- 使用平台 Embedding 契约调用确定性嵌入部署。
- 为每个索引版本固定嵌入部署版本、维度、分块策略和源内容版本。
- 使用 PostgreSQL 与 pgvector 保存首个可检索索引。
- 在 ingestion-worker 执行可重试且幂等的索引构建。
- 在租户与知识空间条件内完成高速候选检索。
- 为门店和校园固定检索用例生成可复核的命中证据。

## 范围外

- LLM 回答生成、引用文案和流式问答。
- Rerank、多路混合检索和结构化 Query DSL。
- 外部向量数据库厂商适配。
- PDF、网页、数据库连接器和增量同步。
- 非确定性生产模型路由。

## 公共接口与数据

公共接口和持久化结构必须先由索引生命周期 ADR 固定。预计最小任务入口为：

- 对已发布数据源请求构建新索引版本。
- 查询知识空间的索引版本与当前活动版本。
- 在受信租户上下文中执行候选检索。

公共契约不得暴露 Spring AI、pgvector、MyBatis-Plus 或任务执行器类型。

## 约束

- 同一索引版本不能混用嵌入模型、模型修订或向量维度。
- 分块标识对相同内容和相同策略必须稳定。
- 所有检索 SQL 必须显式包含租户和知识空间边界。
- 只有 `READY` 索引可以被激活，切换活动版本必须原子完成。
- 重试不能重复写入分块或向量。
- 失败索引不得污染当前活动索引。
- 原始文本、Embedding 请求和向量不得写入普通日志。
- 领域层只依赖 JDK；Spring AI 和 pgvector 只存在于适配器。

## 验收标准

- 相同内容和策略重复构建得到相同分块标识与顺序。
- 内容版本、策略或嵌入部署修订变化时产生新的索引版本。
- 嵌入维度不匹配、对象摘要不一致和模型不可用时构建关闭失败。
- 跨租户、跨知识空间和未发布数据均不能进入索引或检索结果。
- 并发构建和重试只产生一套完整索引事实。
- 激活新版本失败时旧活动版本保持可用。
- 门店与校园固定检索用例在各自租户内返回正确候选且无交叉泄漏。
- 后端、架构、容器、治理和数据质量门禁全部通过。
