# WP-0014 登录入口视觉与可用性整改设计

## 目的与边界

本切片回应 `project/evidence/M6-human-review-rejection.md`：当前裸表单不能帮助人员判断应进入的平台或租户工作区，也不具备企业控制台入口应有的视觉层级。改动仅限 `console-web` 的匿名登录入口，不改变 ADR-0048 的浏览器会话、ADR-0057 的能力投影、任何认证 HTTP 字段或服务端授权。

## 设计结论

设计解读：受监管 B2B 企业控制台的统一登录入口，采用 Fluent UI 的克制、可信、任务优先语言。设计方差为 3，动效强度为 2，信息密度为 4。

桌面布局使用深蓝产品说明区和浅色登录卡的双栏结构。说明区只解释两种真实工作区的边界，登录卡先要求选择目标，再展示该目标所需字段：

- 租户工作区显示并要求填写 `tenantCode`，说明其只用于建立当前租户会话。
- 平台管理不显示 `tenantCode`，提交时也始终忽略任何残留值。平台权限继续完全由服务端根据账户授权建立。
- 登录名和密码不再预填演示值；失败反馈继续不显示凭据或会话细节。
- 窄屏下双栏折叠为说明区在上、登录卡在下，保持可读性和完整操作路径。

这不是新增的前端授权状态。`LoginWorkspace` 只是入口字段显隐和请求组装模型，最终仍由服务端的双范围 HttpOnly 会话和能力清单决定工作区及导航。

## 真实浏览器复核与当前阻断

2026-08-14 使用本机 Chrome 的已登录标签页访问 `http://localhost:13000`，已复核以下视觉结果：

1. 桌面首屏展示明确的产品说明、平台管理和租户工作区层级，登录卡完整可见。
2. 初版标题因过窄最大宽度断成三行，属于实际视觉缺陷；将标题最大宽度改为 `24rem`、降低最大字号并使用 `word-break: keep-all` 后，标题保持完整一行，登录卡比例恢复正常。
3. 刷新后默认租户模式显示租户编码、登录名和密码，主按钮在必填字段缺失时保持禁用；切换平台管理时租户编码不出现。

同一次浏览器回归以完整 `platform.root` 登录名及本地验收口令提交后仍得到通用登录失败。通过同源 HTTP 复现确认：携带浏览器同源头、CSRF cookie 与 CSRF header 时服务端返回 `401`；只读核对当前 PostgreSQL 的 PBKDF2 摘要后确认，该摘要与本地验收口令不一致。此为本地账户凭据漂移，不是前端模式选择、反向代理或 CSRF 实现缺陷。

不得在未获得明确授权时重置账户口令。取得授权并将本地账户恢复到已确定验收口令后，仍须完成平台和租户两类账户登录、能力投影、导航与直接 URL 拒绝的浏览器复核，才能再次申请 M6 人工验收。

本记录不关闭 `WP-0014`，不改变 M6 进行中状态，也不构成 M6 人工验收通过。
