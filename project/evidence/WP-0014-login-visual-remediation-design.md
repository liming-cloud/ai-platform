# WP-0014 登录入口视觉与可用性整改设计

## 目的与边界

本切片回应 `project/evidence/M6-human-review-rejection.md`：当前裸表单不能帮助人员判断应进入的平台或租户工作区，也不具备企业控制台入口应有的视觉层级。改动仅限 `console-web` 的匿名登录入口，不改变 ADR-0048 的浏览器会话、ADR-0057 的能力投影、任何认证 HTTP 字段或服务端授权。

## 设计结论

设计解读：受监管 B2B 企业控制台的统一登录入口，采用 Fluent UI 的克制、可信、任务优先语言。设计方差为 3，动效强度为 2，信息密度为 4。

桌面布局使用深蓝产品说明区和浅色登录卡的双栏结构。说明区只解释两种真实工作区的边界，登录卡先要求选择目标，再展示该目标所需字段：

- 租户工作区显示并要求填写 `tenantCode`，说明其只用于建立当前租户会话。
- 平台管理不显示 `tenantCode`，提交时也始终忽略任何残留值。平台权限继续完全由服务端根据账户授权建立。
- 登录名和密码不再预填演示值；失败反馈继续不显示凭据或会话细节。
- 窄屏下双栏折叠为说明区在上、登录卡在下，保持可读性和完整操作路径。

这不是新增的前端授权状态。`LoginWorkspace` 只是入口字段显隐和请求组装模型，最终仍由服务端的双范围 HttpOnly 会话和能力清单决定工作区及导航。
