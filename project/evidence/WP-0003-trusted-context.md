# WP-0003 可信请求上下文契约证据

## 证据范围

- 新增主体标识、租户成员标识、凭据类型、访问渠道和权限编码公共值类型。
- 新增框架无关的 `TrustedRequestContext`。
- 权限快照不可变，权限判断使用精确值匹配，不支持通配符。
- 权限版本和追踪标识具有失败关闭的输入约束。
- 公共契约只依赖 JDK 和 `platform-kernel`，不暴露 Sa-Token 类型。

## 红绿验证

红灯命令：

```bash
./mvnw -q -pl backend/contexts/organization-access -am test
```

首次执行因可信请求上下文及相关值类型不存在而编译失败。

补充最小实现后执行同一命令和：

```bash
make backend-test
```

结果全部通过，覆盖权限集合防御性复制、精确权限判断、关闭通配权限、权限版本和追踪标识不变量。

## 六维判断

- 正确性：同一组测试完成红绿，权限判断结果可复核。
- 复杂度：只有六个直接表达认证事实的公共类型，无框架包装层。
- 冗余：租户继续复用平台 `TenantId`，没有创建重复租户类型。
- 性能：上下文为小型不可变对象，单次请求只复制有限权限集合。
- 架构：公共契约无 Sa-Token、Spring 或数据库依赖。
- 测试质量：测试只验证公共行为，不断言内部实现和调用顺序。

## 边界

本证据不表示 Sa-Token 登录、成员持久化或资源授权已经实现。下一切片必须从真实会话生成该上下文，禁止由 Controller 直接拼装。
