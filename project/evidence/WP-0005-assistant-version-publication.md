# WP-0005：助手不可变版本与发布闭环证据

## 结论

平台已经建立助手、助手版本和发布状态的完整纵向边界。助手版本在创建时冻结
对话模型部署修订、知识空间、活动索引修订、嵌入模型部署修订、系统指令、
引用策略和拒答策略；发布后不能修改。查询运行时可以通过公共快照契约读取
当前租户的已发布版本，不需要依赖助手领域内部类型。

实现提交：`700419e827c90671cf207766c72649190fe3840f`

## 已证明行为

- 助手名称在租户内唯一，不同租户之间相互隔离。
- 助手版本号由数据库事务顺序分配，并发创建不会得到重复版本号。
- 创建助手、创建版本和发布版本均支持幂等键；相同请求可安全重放，
  相同幂等键对应不同请求时会稳定拒绝。
- 助手版本只能从草稿发布一次，发布要求乐观版本匹配。
- 发布动作的重复请求返回原始结果，不重复产生状态迁移。
- 助手版本只能引用当前租户已发布的对话模型部署和活动索引。
- 版本同时冻结对话部署修订、索引修订、嵌入模型部署及其修订，
  后续模型或索引变更不会静默改变既有助手行为。
- 第一阶段强制使用“必须引用”和“证据不足时拒答”策略。
- 公共助手契约和领域层不暴露 Spring AI、Spring Boot、Sa-Token、
  MyBatis-Plus、Hutool 或数据库类型。
- 控制面接口从可信会话恢复租户和权限，不接受请求体提交租户。
- 演示租户权限已纳入助手读取和写入能力。
- 数据库迁移保持不可变：初始建表迁移与后续发布幂等迁移分离，
  已有演示数据库可以从前一版本向前升级。
