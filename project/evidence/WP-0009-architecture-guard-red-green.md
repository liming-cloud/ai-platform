# WP-0009 架构门禁红绿证据

## 目标

在大范围目录迁移前，先证明门禁能够识别本轮新增的架构债务，同时允许
`infrastructure` 成为经典领域驱动分层的一部分。

## 红灯

命令：

```bash
python3 -m unittest scripts.quality.test_backend_architecture_guard
```

新增测试首次运行得到 6 个预期失败：

- 旧门禁仍拒绝 `infrastructure`。
- 未识别新增上下文 `api`。
- 未识别新增上下文 `adapter`。
- 未识别新增 `backend/runtimes` 文件。
- 未识别新增游标列表契约。
- 未识别新增 XML 手工列表分页。

失败发生在门禁能力缺失，而不是测试环境或语法错误。

## 绿灯

门禁增加五类递减计数，并删除对 `infrastructure` 的错误禁令。相同命令随后通过
全部 12 项测试。

当前迁移基线：

| 债务 | 数量 |
| --- | ---: |
| 上下文 `api` 文件 | 124 |
| 上下文 `adapter` 文件 | 79 |
| `backend/runtimes` 文件 | 27 |
| 游标列表契约文件 | 54 |
| XML 手工列表分页语句 | 16 |

这些数量只允许下降。最终验收时前三类和游标列表契约必须为零；手工列表分页必须
为零，但事件续传、向量候选数量和任务批次不计入该规则。
