# WP-0014：M6 企业治理与发布制度影响分析

## 结论

M6 不能通过在现有租户请求、运营查询或助手发布方法上追加参数和条件分支实现。平台范围与租户范围拥有不同的可信身份、数据可见性和恢复语义；评测结论与发布决定也不能由现有 `AssistantVersion.publish(Instant)` 以当前配置临时推断。

首条纵向切片应先建立令牌派生的平台管理上下文和可恢复的租户生命周期。它为 ADR-0027 要求的平台管理范围提供唯一入口，但不读取租户正文、问答内容、模型密钥或运行详情。评测、预算、发布决定和审计导出在同一 M6 领域设计中登记为后续切片，等待各自的已接受 ADR 与产品阈值决定。

## 代码图谱探索与影响

| 查询／符号 | 代码图谱结论 | 设计影响 |
| --- | --- | --- |
| `SaTokenTrustedContextArgumentResolver.resolveArgument` | 仅从 `Authorization: Bearer` 恢复会话中的租户、主体、成员、凭据、渠道、权限版本和权限集合，并在服务端生成追踪标识。 | 平台范围不能以请求参数、Header 或前端状态指定；新增平台上下文必须由同一已验证会话恢复，并使用独立安全类型。 |
| `SaTokenTrustedContextArgumentResolver` 影响分析 | 影响自动配置、解析器单元测试和两个受认证 HTTP 回归，共 26 个符号。 | 后续实现必须先写“租户令牌不能取得平台上下文、伪造范围字段无效”的红灯测试，并同时回归既有解析器。 |
| `OperationsQueryService.usage`、`audit` | 服务以 `query.context().tenantId()` 读取 trusted-query 的汇总和审计事实；影响 Web Controller、自动配置与控制面 HTTP 回归，共 56 个符号。 | 平台运营不能复用该服务取得跨租户正文或详情。平台影响摘要需要独立的最小事实门面，且属于 M8，不纳入首条切片。 |
| `AssistantVersion.publish` | 现在只拒绝非 `DRAFT` 版本，发布时不消费评测结论、预算或审批决定。 | M6 评测门禁必须引入由 evaluation-operations 拥有的冻结结论和跨根领域服务；不得在本切片向 `publish(Instant)` 塞入临时阈值。 |
| `AssistantTestRun` | 它是 assistant-delivery 的独立聚合根，只保存目标、题目摘要、配额、最小引用、用量与终态。 | 后续评测只能受控消费其最小事实，不能把草稿测试正文或普通 `QueryRun` 重放成评测数据。 |
| `QueryFeedback` | 它是 trusted-query 的独立不可变根，记录租户、运行标识、请求成员、固定结果与原因。 | 反馈可成为后续治理读模型的最小输入，不改变其所有权或把它并入发布聚合。 |
| `ModelConfiguration.scope` | 模型配置已区分 `PLATFORM`、`TENANT`、`PERSONAL` 所有权。 | 配置范围不等于请求授权范围；不得把平台模型配置的枚举或管理权当作平台会话。 |

代码图谱还确认 `GovernedChatModelRoute` 是 assistant-delivery 中 `AssistantVersion` 的不可变 `ValueObject`，已经实现对应领域标记接口；M6 不改变其冻结路由、回退或调用轨迹语义。

## 受保护的现有 seam

| seam | 保持的责任 | M6 禁止变化 |
| --- | --- | --- |
| `TrustedRequestContext` | 租户请求的认证、归属和权限唯一来源。 | 不增加可由调用方提交的平台、租户、成员或权限字段。 |
| `SaTokenTrustedContextArgumentResolver` | 将已验证 Bearer 会话映射为租户请求上下文。 | 不把平台角色伪装为任意租户会话或回退到 Header。 |
| `OperationsQueryService` | 同租户受权的用量和审计投影读取。 | 不跨租户读取、不暴露正文、不承担平台运维。 |
| `AssistantVersion` | 助手版本与冻结模型／知识快照的生命周期。 | 不由页面、当前模型健康度或未冻结评测结果决定发布。 |
| `AssistantTestRun`、`QueryFeedback`、`ModelInvocationTrace` | 最小可审计运行、反馈和调用事实。 | 不保存或导出题目、回答、提示词、密钥、端点和供应商原始错误。 |

## 首条切片的两种接口方案

| 方案 | 接口与数据流 | 优点 | 拒绝原因或代价 |
| --- | --- | --- | --- |
| A：扩展 `TrustedRequestContext` 为可选平台／租户双范围 | 所有既有受认证 Controller 与应用命令处理可空租户和平台角色。 | 看似复用一个上下文。 | 租户标识从当前强制事实变成可空分支，扩大 26 个安全 seam 和所有租户授权调用方；容易让平台角色落入租户正文路径，违反 ADR-0027、ADR-0033。 |
| B：新增仅平台路由可注入的 `PlatformRequestContext` | 平台安全适配器从相同已验证会话恢复主体、凭据、渠道、权限和追踪标识；平台 Controller 只向平台治理应用服务传入该上下文与业务目标。 | 租户请求契约保持不变；平台入口、拒绝语义与角色测试局部化；没有调用方时不暴露给租户模块。 | 需要独立解析器、会话投影、自动配置与 HTTP 反例，但变化集中且可验证。 |

选择方案 B，详见 ADR-0041 提案。它只增加平台管理的可信入口；不创建全局双范围 DTO、通用切换参数或跨上下文数据库访问。

## 首条切片证据合同

ADR-0041 被接受后，必须先红后绿并在同一提交链中保留以下证据：

| 层级 | 必须证明的反例／结果 |
| --- | --- |
| 纯领域 | `TenantLifecycle` 拒绝从非 `PROVISIONING` 重复激活、从非 `ACTIVE` 挂起、从非 `SUSPENDED` 恢复；初始化管理员缺失或不属于租户时拒绝。 |
| 安全适配 | 缺失、无效、租户管理员令牌或伪造范围 Header／请求字段均不能产生 `PlatformRequestContext`。 |
| 应用编排 | 平台管理员只能创建、激活、挂起和恢复生命周期根；每个成功状态变化产生最小审计事实／发件箱事件，失败不产生半成品。 |
| 真实 PostgreSQL | 乐观并发下仅一个状态迁移提交；同一租户标识不可重复建立生命周期根；事务失败不留下生命周期、管理员初始化或发件箱的部分写入。 |
| 自动配置与 HTTP | 平台路由只注册平台解析器；租户路由仍只接受 `TrustedRequestContext`；角色撤销、跨范围访问和错误状态返回稳定失败。 |
| 浏览器 | 平台管理员完成建立、激活、挂起、恢复租户；租户管理员看不到平台导航且直达路径失败；平台运营不能读取租户知识或问答正文。 |
| 全量 | `make validate`、`make project-verify`、`git diff --check` 通过，并登记可复现环境与提交。 |

## 恢复与保留边界

- `SUSPENDED` 是可恢复状态：拒绝新的租户受权业务操作，但不在本切片删除租户业务数据；恢复必须保留原生命周期标识与审计链。
- 租户销毁、数据保留期限、法定删除、备份恢复和平台运营处置属于后续 M6／M8 决策，不能把 `SUSPENDED` 当作已删除。
- 平台生命周期审计只保留平台操作人、目标租户标识、动作、前后状态、时间、结果与恢复关联；不记录知识正文、问答、密钥、令牌或供应商错误。
