# WP-0002 前端工程与设计基线证据

## 证据范围

- 使用 npm 工作区管理前端依赖和统一锁文件。
- 建立 `console-web` 与 `query-web` 两个独立应用。
- 建立被两个应用共同消费的 `design-system` 包。
- 使用 Fluent UI React v9 单一设计系统。
- 顶级导航具有最多六项的自动化门禁。
- 提供空、加载、错误、拒绝、部分完成和陈旧状态的统一表达。
- 页面跟随系统深浅主题并支持减少动效设置。
- 控制台只围绕“完成首个可信助手”这一主任务组织内容。
- 问答入口在没有已发布助手时明确展示真实空状态，不伪造可用能力。

## 固定依赖

- React 19.2.8。
- Fluent UI React 9.74.4。
- Vite 8.1.5。
- TypeScript 6.0.3。
- Vitest 4.1.10。
- ESLint 10.8.0。

TypeScript 7.0.2 虽是当前最新正式版，但超出 `typescript-eslint` 8.65.0 声明的正式支持范围。工程选择支持范围内的最新正式版 6.0.3，未使用强制安装或忽略同级依赖。

## 自动验证

```bash
cd frontend
npm ci
npm run typecheck

npm run test
npm run build
```

结果：

- 依赖审计未发现漏洞。
- 类型检查通过。

- 顶级导航预算测试通过。
- 两个应用生产构建通过。

## 浏览器验收

本地验收地址：

- `console-web`：`http://127.0.0.1:4173/`
- `query-web`：`http://127.0.0.1:4174/`

已验证：

- 桌面导航保持单行。
- 390 像素宽度下导航可用且页面无横向溢出。
- 控制台主任务、演示限制和发布路径具有明确层级。
- 问答应用没有混入管理功能。
- 两个页面的浏览器错误和警告日志均为空。

浏览器验收期间发现并修复了移动端 `min()` 宽度表达式无效和网格最小内容宽度导致的横向溢出。

## 边界

该证据只证明前端工程、信息架构外壳和基础状态设计。真实认证、模型连接流程、查询流式事件、引用交互和端到端产品闭环仍未完成。
