# WP-0008 知识聚合雪花标识整改证据

## 结论

提交 `c51337b109716f94a2910e29d6dc5338f3a38e40` 已将知识空间、数据源和
索引版本三个业务标识从 UUID 改为正的 64 位长整型，并同步改造助手版本冻结引用、
可信查询引用、向量存储、对象存储、HTTP 契约、数据库迁移和前端测试数据。

本证据只覆盖知识聚合切片。模型、助手、查询等业务实体仍有 UUID，不能把本证据
解释为“主代码 UUID 已全部清零”。

## 领域与公共契约

- `KnowledgeSpaceId`、`DataSourceId` 和 `IndexVersionId` 构造时拒绝零和负数。
- 三个标识的 `parse` 只接受十进制正整数，拒绝旧 UUID 文本。
- 应用服务通过统一 `EntityIdGenerator` 生成标识，不再直接创建 UUID。
- HTTP 请求和响应将 64 位标识序列化为十进制字符串，避免浏览器数字精度损失。
- 助手版本冻结知识空间与索引版本时保留强类型语义。
- 检索候选、引用和证据再鉴权全链路使用长整型知识标识。

## 持久化与运行边界

- `knowledge_space_id`、`data_source_id`、`index_version_id` 以及对应业务
  `aggregate_id` 均改为 `BIGINT`。
- 事件标识和索引构建租约标识仍保留 UUID，因为它们不是本切片的业务实体标识。
- Mapper 方法、XML 参数、JDBC 读写和 pgvector 查询统一使用 `long`。
- MinIO 对象路径使用十进制租户与数据源标识。
- 控制面显式依赖 `platform-persistence`，雪花节点参数在非演示环境必须显式配置。
- 演示配置固定使用单节点编号；不对生产多副本分配策略作隐式假设。

系统采用绿地重建，不提供 UUID 数据迁移、兼容列或双写。
