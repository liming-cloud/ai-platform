# WP-0005：模型部署治理闭环证据

## 结论

模型部署已经形成可部署纵向闭环：租户管理员可基于已验证供应商连接创建部署，
冻结供应商修订和显式能力，经实际模型探测后验证并发布；应用、数据库和接口共同
保证租户隔离、幂等、配额、状态机和乐观并发。

实现提交：`e89b19a10`

## 已证明行为

- 模型部署只接受可信请求上下文中的租户与模型读写权限。
- 创建时固定供应商连接标识和已验证修订，不接收客户端伪造的供应商修订。
- 模型类型、能力、上下文窗口、输出上限和嵌入维度同时受领域与数据库约束。
- 对话部署必须声明对话能力与输出上限，嵌入部署必须声明嵌入能力与维度。
- 探测实际能力未覆盖部署声明时保持草稿，不写入虚假的验证事实。
- 只有验证状态可以发布，探测和发布均使用乐观版本。
- 创建接口支持幂等重放；同键异参、同租户同名和超出配额产生稳定错误。
- 模型部署通过同租户复合外键引用供应商连接，跨租户标识不可读取。
- 游标分页限制条数、编码长度、时间和标识格式。
- 控制面公共契约不包含 Spring AI、MyBatis-Plus 或数据库类型。
- 容器验收可重复执行，已发布部署不会因验收脚本重跑而重复发布。

## 红绿证据

应用测试首先因用例、命令、仓储端口和服务不存在而编译失败；最小应用实现后
5 项行为通过。PostgreSQL 测试随后因仓储和迁移不存在而编译失败；实现迁移与
仓储后首次运行暴露测试种子对 `Instant` 参数缺少显式数据库类型的问题，改为
时间戳后 4 项真实数据库合同通过。

```bash
./mvnw -q -pl backend/runtimes/control-plane -am \
  -DskipTests=false \
  -Dtest=DefaultModelDeploymentServiceTest,PostgresModelDeploymentRepositoryTest,ModelDeploymentApiTest \
  -Dsurefire.failIfNoSpecifiedTests=false test

make validate
make deploy-config
make deploy-up
make deploy-smoke
make acceptance-model-deployment
git diff --check
```

结果：

- 新增应用 5 项、PostgreSQL 4 项、控制面接口 2 项，共 11 项定向测试通过。
- 后端全量 140 项测试通过，失败 0、错误 0、跳过 0。
- 项目治理 7 项、前端 14 项、前端类型与规范检查、两个生产构建全部通过。
- 两个演示场景和 8 个检索用例的数据门禁通过。
- 保留既有演示数据卷从迁移 `202607270005` 成功升级到 `202607270006`。
- 五个应用入口健康检查通过。
- 模型部署容器验收连续执行两次通过，覆盖冻结修订、探测、发布和租户隔离。
- 代码图对 `ModelDeployment` 的三级影响检查覆盖 167 个符号，相关调用面已验证。
