# WP-0007 端到端容量与故障恢复证据

## 结论

在提交 `ea40372ae224d6898318ee1262d2b432c0f88022` 上，以源演示数据的隔离恢复副本
完成双租户端到端可信查询容量测试，并依次停止、启动 PostgreSQL、MinIO、查询运行时
和摄取进程。容量、错误率、重启恢复、重启后查询、源环境健康和资源清理均达到 M1
门禁。

报告和机器契约固定于提交
`9bb74304861db4a34d330cf3f733ccb2aff54848`。

本结果只适用于报告中的本机硬件、合成数据和本地确定性模型，不代表真实厂商模型、
互联网网络、生产流量或商业容量承诺。

## 容量场景

| 条目 | 固定值 |
| --- | --- |
| 租户 | 门店、校园，共 2 个 |
| 每租户并发 | 4 |
| 总并发 | 8 |
| 预热 | 每租户 5 次，共 10 次 |
| 采样 | 每租户 20 次，共 40 次 |
| 幂等 | 每次使用全新幂等键，历史重放禁止计入 |
| 请求路径 | 认证、助手目录、配额、模型解析、嵌入、授权检索、重排、生成、引用、事件与用量持久化 |
| 模型 | 本地确定性对话与嵌入模型 |
| 数据规模 | 2 个租户、3 个知识对象、22 个索引分块、21 个已发布助手版本 |

门禁和实测：

| 指标 | 门禁 | 实测 |
| --- | ---: | ---: |
| 错误数 | 0 | 0 |
| 幂等重放数 | 0 | 0 |
| 95 分位耗时 | 不超过 1000 毫秒 | 50.201 毫秒 |
| 99 分位耗时 | 记录 | 58.71 毫秒 |
| 最大耗时 | 记录 | 58.71 毫秒 |
| 总吞吐 | 不低于每秒 5 次 | 每秒 219.873 次 |

每个成功响应均为已回答状态，包含引用并命中对应场景的答案要点。测试没有把数据库内
候选池排序时间冒充端到端耗时。

## 故障恢复

故障演练只作用于带受控前缀的隔离恢复项目：

| 服务 | 停止后验证 | 恢复判据 | 恢复耗时 |
| --- | --- | --- | ---: |
| PostgreSQL | 容器不再运行 | 数据库就绪且三个后端入口恢复健康 | 1 秒 |
| MinIO | 容器不再运行 | 对象存储就绪 | 6 秒 |
| 查询运行时 | 入口随进程停止 | 查询运行时就绪 | 5 秒 |
| 摄取进程 | 入口随进程停止 | 摄取进程就绪 | 5 秒 |

四个服务恢复后，再次执行门店和校园各一次全新端到端查询，两次均通过。最终隔离环境
的容器、网络和三个卷全部删除，源环境五个应用入口继续健康。

## 失败关闭证据

第一次实际运行完成容量阶段后，故障脚本因新增文件缺少执行权限而返回非零状态。
退出陷阱删除了隔离容器、网络、卷和临时备份，随后 `make deploy-smoke` 证明源环境
仍然健康。修复包括：

- 将三个运维入口标记为可执行文件。
- 在自动测试中验证执行权限，防止打包或检出后再次退化。
- 提交实现后从头重新执行完整演练，未复用第一次结果。

因此最终报告只记录绑定已提交实现的完整成功运行。
