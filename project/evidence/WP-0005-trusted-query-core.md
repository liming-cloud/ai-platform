# WP-0005：可信查询内核与引用拒答闭环证据

## 结论

平台已经建立同步可信查询的完整后端纵向闭环。查询只接受当前租户已发布的
助手版本，严格使用版本中冻结的对话部署、嵌入部署、索引版本和策略；
运行状态、引用、拒答原因与令牌用量由 PostgreSQL 持久化。相同幂等请求
安全重放，不重复调用模型或产生第二条计量事实。

实现提交：`02580199fa97b8f9f5e4b7d71518dc75c2ac374d`

## 已证明行为

- 查询运行聚合只允许从运行中进入已回答、已拒答或失败终态。
- 已回答运行必须包含连续编号的引用；证据不足时不调用对话模型并明确拒答。
- 查询接口从可信会话取得租户、成员和权限，不接受请求体覆盖租户或模型。
- 缺少 `assistant:query` 或 `knowledge:read` 权限时不能进入模型调用。
- 已发布助手版本冻结嵌入维度，查询不会根据当前活动索引猜测维度。
- 检索绑定助手冻结的索引版本；该版本后来被替换后仍可被既有助手稳定读取。
- 索引创建必须显式选择当前租户已发布的嵌入部署，并冻结部署修订与维度。
- 摄取工作进程和查询运行时都通过模型目录按租户、类型和修订解析嵌入模型，
  不再依赖历史固定部署编号。
- 对话输出上限从助手版本传入模型调用适配器。
- 引用由已授权候选事实生成，不接受模型自行伪造引用标识。
- PostgreSQL 通过短事务认领幂等键；请求指纹冲突、运行中重试和终态重放
  分别产生稳定结果。
- 查询运行终态与引用在同一事务保存，并使用乐观版本防止重复完成。
- 门店与校园查询分别命中本租户冻结索引，跨租户读取查询运行返回资源不存在。
- 普通演示助手返回带引用回答；严格阈值助手在无足够证据时返回明确拒答。

## 根因修复证据

首次容器验收发现，旧索引创建流程把确定性嵌入模型的固定编号写入索引，
但模型目录没有对应部署，导致查询解析模型时返回“模型部署不存在”。
代码图追踪了 `DefaultIndexVersionService`、`DefaultIndexBuildWorker`、
`DefaultAssistantService`、`DefaultQueryRunService` 和
`DefaultModelRuntimeResolver` 的完整修订链。

修复没有增加演示后门，而是建立已发布嵌入部署只读快照：

1. 模型目录投影已发布嵌入部署的编号、修订和维度。
2. 索引创建接口要求显式选择该部署。
3. 索引版本冻结快照。
4. 摄取工作进程按冻结部署解析嵌入模型。
5. 助手版本冻结索引及嵌入快照。
6. 查询运行按同一快照生成查询向量并读取指定索引版本。

首次失败查询已经以失败终态保留，证明异常不会伪装成回答。
