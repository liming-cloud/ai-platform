## 红灯证据

```bash
npm test -- --run \
  apps/console-web/src/api/control-plane-client.test.ts \
  apps/console-web/src/features/knowledge-publication/publication-workflow.test.ts
```

首次执行时接口客户端和发布状态机尚不存在，两个测试文件均因目标模块缺失而失败。补充实现后，测试进一步暴露了测试网址前提和“上传完成但发布失败”应归类为部分完成的语义差异。

真实浏览器首次登录时又暴露浏览器原生 `fetch` 被作为未绑定函数调用，产生非法调用错误。将默认请求函数改为保留浏览器调用上下文的包装函数后，登录与知识空间查询恢复。

## 浏览器与体验验收

- 1440 × 900 桌面视口无横向溢出，任务进度与当前操作形成两列结构。
- 390 × 844 窄屏视口回落为单列，页面和导航无文档级横向溢出。
- 真实演示账号登录后进入已有知识空间选择，凭据和会话令牌不写入浏览器存储。
- 页面只保留“租户验证、知识空间、文本上传、发布核验”一条主任务，不新增导航或仪表盘卡片。
- 加载状态通过禁用当前表单和明确进行中文案反馈；空、错误、拒绝、部分完成和陈旧状态均有独立状态语义。
- 同一操作和相同载荷在重试时复用幂等键，载荷变化后生成新键，避免响应丢失造成重复写入或错误版本冲突。
- 所有可见文案通过中文复核，未使用长破折号装饰，表单标签、必填状态和密码自动填充语义完整。

## 代码结构

- 接口访问集中在控制平面客户端，不向页面泄漏后端框架类型。
- 单向发布状态机与视图组件分离，拒绝、陈旧、部分完成和普通错误不能静默推进业务阶段。
- 编排、进度和任务视图分为三个局部模块；主编排组件由 691 行降至 254 行。
- 代码图谱检查确认发布流程组件只被控制台数据任务引用，没有扩大到其他前端应用。

## 当前结论

控制台已经从静态占位页变为可运行、可恢复且受权限保护的知识数据发布任务流。WP-0003 仍保持进行中，下一项不可替代的交付证据是正式 MinIO 对象存储适配器及其容器内上传、元数据核验和发布终态。
