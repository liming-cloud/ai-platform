进度只按已验收结果和证据计算，不使用虚假的完成百分比。

| 里程碑 | 业务结果 | 进入条件 | 退出条件 | 负责人 |
| --- | --- | --- | --- | --- |
| M0 设计冻结 | 产品、交互、领域、接口、数据、安全、运行时、详细目录和治理设计可直接实施 | 项目章程确认 | 旧实现已清理，前端与全项目目录设计完整，WP-0001 人工评审和治理检查全部通过 | 产品 |
| M1 可部署演示 | 全新 Docker 环境证明权限、数据、模型、助手、查询、引用、审计和配额闭环 | M0 通过 | 演示验收和运行手册通过 | 全员 |
| M2 基座工程 | 组织、模型、数据源、公共契约和架构门禁达到产品级形态 | M1 通过 | 核心上下文通过模块、安全和契约门禁 | 后端 |
| M3 受治理数据 | 数据源、数据集、Schema、质量、同步、发布、退役、索引和重建形成角色化闭环 | M2 通过 | 参考数据可确定性重建，索引绑定受控 Embedding 配置 | 后端、产品 |
| M4 助手与可信查询 | 助手草稿、固定依赖、测试、授权检索、重排、拒答、引用、反馈和诊断达到指标 | M3 通过 | RAG、助手和权限安全门禁通过 | 后端、测试、产品 |
| M5 模型扩展 | 多厂商、多类型模型、工具、MCP、多模态、审核和音频形成受治理能力矩阵 | M4 通过 | 每个适配器通过统一契约、安全和路由测试 | 后端 |
| M6 企业治理与发布制度 | 组织权限、设备凭据、评测、审计、用量、成本、审批、运维和控制台信息架构闭环 | M5 通过 | 不安全助手版本无法发布，角色化六区控制台通过验收 | 产品、测试 |
| M7 渠道与同意 | 硬件渠道、连接器 SDK、画像同意和隐私控制支持参考场景 | M6 通过 | 设备与隐私威胁模型、同意撤回和 SDK 契约通过 | 全员 |
| M8 生产就绪 | 容量、灾备、安全、可运维、支持标准和运维工作台得到证明 | M7 通过 | 生产就绪评审通过 | 运维 |

依赖顺序：

`M0 -> M1 -> M2 -> M3 -> M4 -> M5 -> M6 -> M7 -> M8`

只有进入当前里程碑后才允许并行工作，且每个角色最多同时负责一个进行中的工作包。
