# 可信 RAG 基座前端设计

## 1. 设计方向

设计判断：这是面向企业管理员、知识运营、评测和审计人员的高密度可信控制台，并包含面向顾客、师生和设备渠道的轻量问答界面。整体采用克制、可靠、低动效的企业语言，以 Fluent UI React v9 为唯一设计系统。

这是强调可信、权限和效率的企业控制台与问答界面，不是营销式数据看板，也不能照搬后端模块树。

- 视觉变化度：3/10。
- 动效强度：2/10。
- 信息密度：7/10。
- 组件系统：只使用 Fluent UI React v9。
- 单一主题、单一强调色和统一设计 Token。

界面优先表达层级、状态、来源和下一行动，装饰不能替代信息。

## 2. 信息架构

顶级导航最多六项，并根据角色裁剪：

| 区域 | 用户意图 | 主要资源 |
| --- | --- | --- |
| 概览 | 查看当前需要处理的事情 | 任务、健康、发布、配额 |
| 数据 | 接入并发布可信信息 | 数据源、数据集、知识空间、同步和索引 |
| 助手 | 构建、测试、评测和发布 | 助手、版本、渠道、会话 |
| 评测 | 证明质量并定位失败 | 数据集、任务、比较、门禁 |
| 治理 | 管理权限、模型、审计和用量 | 组织、策略、供应商、部署、路由、审计 |
| 运维 | 运行和恢复平台 | 健康、队列、存储、备份、构建 |

无权访问的区域和操作直接移除，不展示为不可点击的功能目录。

## 4. 页面复杂度预算

- 每页只服务一个主要用户目标。
- 页面头部最多一个主按钮。
- 默认表格最多七个业务列。
- 单个表单分组最多七个可编辑字段。
- 下钻前最多展示五项摘要指标。
- 高级参数、厂商参数和模型诊断默认折叠。
- 超过五项的重复数据使用表格、树、列表框、折叠面板或合适的标签页，不使用通用卡片堆积。
- 危险操作进入次级菜单，明确说明影响并二次确认。
- 页面包含两个以上互不依赖的流程时必须拆分。
- 禁止用大量标签页掩盖职责混乱。

## 5. 应用框架

```text
┌───────────────────────────────────────────────────────────────┐
│ 产品  租户选择               搜索        帮助  用户          │
├─────────────┬─────────────────────────────────────────────────┤
│ 概览        │ 面包屑                                          │
│ 数据        │ 页面标题                         主操作         │
│ 助手        │ 结果或状态摘要                                  │
│ 评测        ├─────────────────────────────────────────────────┤
│ 治理        │ 当前任务内容                                    │
│ 运维        │                                                 │
└─────────────┴─────────────────────────────────────────────────┘
```

- 只有平台运营人员可以看到跨租户选择。
- 全局搜索只检索有权访问的平台资源，默认不搜索文档正文。
- 页面标题表达对象或任务，不使用技术模块名。
- 状态摘要必须指向下一步可行动作。

## 6. 关键流程

### 6.1 发布数据源

```text
数据源                                             [新增数据源]
┌─────────────────────────────────────────────────────────────┐
│ 名称       类型      已发布版本      新鲜度       状态      │
│ 校园问答   文件      v3              2 小时       健康      │
│ 门店数据   数据集    v7              5 分钟       健康      │
└─────────────────────────────────────────────────────────────┘

新增数据源
1 类型与负责人
2 连接或上传
3 Schema 与敏感级别
4 探测与确认
                                  [保存草稿] [执行首次同步]
```

首次同步不得自动发布。评审页必须显示成功、失败、重复、过期和越权数据。

### 6.2 配置模型

```text
模型 / 新增供应商
1 厂商与区域
2 地址与凭据
3 探测模型和能力
4 选择部署并发布

探测结果
连接 ✓        认证 ✓        延迟 340 毫秒
可用模型 8    能力冲突 0
凭据          已保存为密钥引用，永不回显
                                         [发布供应商]
```

只显示当前模型类型支持的参数，便携参数与厂商高级参数分区。

### 6.3 构建助手

```text
助手：门店导购                         草稿 v4
知识  模型  行为  渠道

必需能力：流式 Chat、结构化输出
知识范围：门店商品数据 + 门店问答
路由策略：中国区零售交互

[保存草稿]                                  [执行评测]
```

只有评测通过后，评测结果页才显示发布操作。

### 6.4 提问与查看引用

```text
商品 A 的价格和位置是什么？

商品 A 售价 39 元，位于 4 号通道 B 货架。       [1] [2]
库存信息在 4 分钟前更新。

[有帮助] [无帮助] [查看来源]

[1] 门店商品数据 · 版本 7 · 商品 A
[2] 门店布局 · 版本 3 · 4 号通道
```

证据不足时：

```text
没有找到能够回答该问题的已授权且有效的信息。
[查看检索范围] [换一种问法]
```

### 6.5 查询诊断

```text
查询 qry_...
已完成 · 2.8 秒 · 0.012 元 · 策略 v12

时间线  权限  证据  模型  用量
权限      允许 space-1、dataset-7；遮蔽 margin
检索      18 个候选 → 6 个已授权 → 4 个重排结果
生成      主模型 mdl-17；未回退
引用      2/2 校验通过
```

诊断只提供给有权限的运营和审计人员。

## 7. 模型治理交互

- 模型管理位于“治理”下。
- 凭据只写，保存后只显示配置状态和轮换时间。
- 发布供应商前必须成功探测。
- 能力标签表示实际探测结果，不表示厂商宣传。
- 路由模拟展示主模型、备用模型、拒绝原因、驻留、延迟和成本区间。
- 如果回退降低区域、内容安全或必需能力，禁止启用。
- 已发布模型部署不可修改，变更产生新版本。

## 8. 页面状态

每个读取数据的页面必须设计：

- 加载：使用与最终布局一致的骨架。
- 空状态：说明价值并给出唯一有效下一步。
- 错误：显示安全错误码、traceId 和可用恢复动作。
- 无权限：不泄漏资源是否存在。
- 部分成功：说明失败来源和结果是否可安全使用。
- 过期：显示最后成功时间和恢复动作。

流式问答状态：

- 已接受
- 规划中
- 检索中
- 生成中
- 已完成
- 已拒答
- 无权限
- 已取消
- 失败

断线后使用查询对账接口，并从最后一个 SSE 事件编号恢复。

## 9. 组件、可访问性与性能

- 功能组件不得使用原始颜色值，只使用 Fluent 语义 Token。
- 状态必须使用文字或图标加颜色表达。
- 表单使用持久标签、必要说明和可见错误。
- 图标只使用 Fluent UI 图标。
- 动效只用于导航、展开、进度和结果反馈，并支持减少动态效果。
- 满足 WCAG 2.2 AA、键盘操作、焦点可见和弹窗焦点恢复。
- 查询进度使用可访问实时区域，但不逐 Token 播报。
- 参考页面 LCP 小于 2.5 秒、INP 小于 200 毫秒、CLS 小于 0.1。
- 使用路由级拆包，诊断和图表按需加载。

## 10. 前端架构约束

- 功能按用户任务组织，不按后端包名组织。
- 数据请求由路由加载器、动作或查询 Hook 管理，视图组件不能直接散落调用 `fetch`。
- API 类型由已接受的 OpenAPI 契约生成。
- 视图模型隔离 API DTO 与组件。
- 权限同时控制路由注册和操作命令。
- 错误、配额和 SSE 是共享产品能力，不能在每页复制。
- 文件复杂时按任务 seam 拆分，不按组件数量机械拆分。

## 11. 设计验收

- 每条路由都能关联到目标追踪矩阵。
- 每页都有明确角色、任务、成功结果和恢复方式。
- 顶级导航不超过六项。
- 不向角色宣传其无权使用的功能。
- 页面复杂度预算全部通过。
- 凭据和敏感证据无法回显。
- 所有关键流程覆盖加载、空、错误、无权限、部分成功和过期状态。
- 键盘、读屏、减少动态效果和响应式评审通过。

## 12. 产品界面分层

前端不构建一个包揽所有角色的超级控制台，而是共享设计系统和身份能力的三个界面外壳：

| 界面 | 用户 | 主要任务 | 复杂度 |
| --- | --- | --- | --- |
| 企业控制台 | 平台管理员、平台运营、租户管理员、知识管理员、助手负责人、评测、审计和运维 | 配置、校验、评测、发布和诊断；按授权切换平台或租户范围 | 高密度，桌面优先 |
| 问答工作台 | 企业内部人员、校园师生 | 提问、查看引用、反馈和继续追问 | 中密度，自适应 |
| 设备问答界面 | 门店顾客、硬件设备使用者 | 快速提问、听取回答、定位商品或服务 | 低密度，触控和语音优先 |

三个外壳只能共享基础组件、身份上下文、查询协议和设计令牌，不能共享导航结构。设备界面不得出现供应商、索引、评测和审计概念。

渠道调用方通过 SDK/API 使用固定助手与授权范围，不构成第四个前端应用。除非形成开发者自主注册、密钥自助管理或集成诊断等已确认任务，否则不得提前建立开发者门户。

## 13. 角色、任务与页面

| 角色 | 首要任务 | 默认入口 | 主操作 | 成功结果 |
| --- | --- | --- | --- | --- |
| 平台管理员 | 管理租户与平台治理边界 | 平台管理概览 | 创建、停用或恢复租户 | 租户、安全基线与平台授权可审计地生效 |
| 平台运营 | 处理平台风险与容量问题 | 运维概览 | 进入待处理事项 | 风险有负责人和恢复动作 |
| 租户管理员 | 建立安全可用的租户边界 | 治理概览 | 邀请成员或配置凭据 | 人员、设备和配额生效 |
| 知识管理员 | 发布可信知识 | 数据源列表 | 新增数据源 | 已发布索引可被授权检索 |
| 助手负责人 | 交付可用助手 | 助手列表 | 新建助手 | 版本通过评测并发布 |
| 评测人员 | 证明质量并定位失败 | 评测任务 | 新建评测 | 失败分类和门禁决定明确 |
| 审计人员 | 解释访问和变更 | 审计记录 | 导出受控记录 | 事件与版本链可追踪 |
| 内部提问者 | 获得可信回答 | 问答工作台 | 提问 | 回答有引用或明确拒答 |
| 设备使用者 | 快速找到现场信息 | 设备问答 | 语音或触控提问 | 少步骤得到位置或服务答案 |

同一页面如果服务两个角色，必须保证任务相同，仅数据范围和操作权限不同。任务不同则拆分页面。

企业控制台在同一应用中提供平台管理范围与租户管理范围。平台范围只能由显式平台上下文进入，不能由请求参数或普通租户会话模拟；平台运营权限不隐含租户内容读取权限。完整角色边界见 ADR-0027。

## 14. 页面目录与闭环

### 14.1 概览

| 页面 | 页面目标 | 主操作 | 必备状态 |
| --- | --- | --- | --- |
| 我的工作 | 处理当前角色最重要的事项 | 打开首个待处理事项 | 无待办、部分失败、数据过期 |
| 租户概览 | 查看数据、助手、用量和风险摘要 | 进入阻断项 | 正常、降级、超额、无权限 |

概览只汇总可行动事项，不复制数据、模型、助手和运维各自的管理页面。指标最多五项，每项必须能够下钻到负责人、原因和处理动作。

### 14.2 数据

| 页面 | 页面目标 | 主操作 | 闭环终点 |
| --- | --- | --- | --- |
| 数据源列表 | 找到需要新增、同步或修复的数据源 | 新增数据源 | 数据源进入就绪或明确失败 |
| 新增数据源 | 定义来源、负责人、连接和安全范围 | 执行连接探测 | 形成可同步草稿 |
| 数据源详情 | 查看连接、同步、质量和版本 | 启动同步 | 产生同步报告 |
| 同步检查 | 处理成功、失败、重复、过期和越权记录 | 创建索引版本 | 产物进入待校验 |
| 数据集结构 | 定义字段含义、类型、查询和敏感级别 | 发布结构版本 | 结构不可变发布 |
| 知识空间 | 组合已校验来源并定义授权边界 | 发布索引 | 助手可绑定发布版本 |
| 索引版本 | 比较构建参数、质量和嵌入模型 | 发布版本 | 查询指向固定索引 |

列表默认列：

```text
名称 | 类型 | 负责人 | 已发布版本 | 新鲜度 | 状态 | 行操作
```

只有异常时增加“问题数”，不能为每种数据质量指标增加一列。

### 14.3 助手

| 页面 | 页面目标 | 主操作 | 闭环终点 |
| --- | --- | --- | --- |
| 助手列表 | 找到草稿、待评测或已发布助手 | 新建助手 | 创建空草稿 |
| 助手草稿 | 配置知识、能力、行为、工具和渠道 | 保存草稿 | 配置校验通过 |
| 助手测试 | 在固定版本下验证问题与引用 | 加入评测集 | 问题形成可复现样本 |
| 助手评测 | 查看质量、安全、延迟和成本 | 请求发布 | 形成门禁决定 |
| 发布记录 | 查看版本、批准人、证据和渠道 | 绑定渠道 | 渠道使用固定版本 |

知识、模型、行为和渠道不是四个独立产品模块，只是助手草稿中的分步配置。每一步只显示当前决定所需信息。

### 14.4 评测

| 页面 | 页面目标 | 主操作 | 闭环终点 |
| --- | --- | --- | --- |
| 评测数据集 | 管理问题、期望证据、拒答和权限样本 | 新增样本 | 数据集形成不可变版本 |
| 评测任务 | 选择助手和数据集版本运行评测 | 运行评测 | 生成可复现结果 |
| 结果比较 | 对比两个版本的改善和回退 | 形成门禁决定 | 发布、拒绝或限期例外 |
| 失败分析 | 按失败类别定位可修复原因 | 创建修复事项 | 失败关联工作包 |

评测结果先显示“能否发布”和阻断原因，再显示详细指标。禁止用综合分数掩盖越权、引用错误或错误拒答。

### 14.5 治理

| 页面 | 页面目标 | 主操作 | 闭环终点 |
| --- | --- | --- | --- |
| 组织与成员 | 管理组织单元、成员和角色 | 邀请成员 | 最小权限生效 |
| 访问策略 | 管理资源、行和字段范围 | 发布策略 | 新策略版本生效并撤销旧缓存 |
| 设备凭据 | 管理设备、助手和现场范围 | 创建凭据 | 凭据可撤销且受配额限制 |
| 供应商连接 | 配置地址、区域和密钥引用 | 执行探测 | 连接进入就绪 |
| 模型部署 | 确认模型类型、能力和限制 | 发布部署 | 助手可声明使用 |
| 路由策略 | 配置主模型、回退和预算 | 模拟策略 | 明确选择和拒绝原因 |
| 审计记录 | 查询访问、配置、发布和撤销事件 | 导出结果 | 形成受控审计证据 |
| 用量与配额 | 查看查询、Token、费用和限额 | 调整配额 | 新配额版本生效 |

治理首页按“访问安全、模型运行、审计与成本”三个任务组呈现入口，不能使用八个同质卡片铺满页面。

### 14.6 运维

| 页面 | 页面目标 | 主操作 | 闭环终点 |
| --- | --- | --- | --- |
| 平台健康 | 识别服务、依赖和租户影响 | 打开异常 | 异常有影响面和处理人 |
| 摄取队列 | 处理积压、失败和死信 | 重试安全任务 | 队列恢复到阈值内 |
| 模型健康 | 查看连接、限流、延迟和熔断 | 下线异常部署 | 路由不再选择异常模型 |
| 备份与恢复 | 查看最近备份和恢复验证 | 发起恢复演练 | 恢复证据可复核 |
| 发布版本 | 查看镜像、迁移、配置和提交 | 执行回滚 | 服务回到已验证版本 |

运维页面不向普通租户角色展示。平台运营只能看到租户影响摘要，除非另有授权，不能查看租户知识正文和问答内容。

## 15. 视觉令牌

### 15.1 颜色

- 默认使用浅色主题，M1 不提供独立暗色主题开关。
- 所有颜色通过 Fluent 语义令牌使用，禁止在功能组件写十六进制颜色。
- 页面底层使用画布色，工作区使用普通表面色，抽屉和弹窗使用浮层表面色。
- 只使用一个品牌强调色，用于主操作、当前导航和焦点。
- 成功、警告、危险和信息色只表达真实语义，不能用于装饰。
- 同一状态同时使用文本、图标或形状，不能仅依赖颜色。

### 15.2 字体

- 中文优先使用系统无衬线字体，随操作系统回退。
- 正文使用 Fluent 正文字号，表格与表单不小于 14 像素。
- 页面标题最多两级视觉层次，禁止用超大字号制造营销感。
- 数字、版本、延迟和费用可使用等宽数字特性，但不切换独立字体家族。
- 每行正文建议不超过 72 个中文字符，帮助说明不超过 48 个。

### 15.3 间距与形状

- 基础间距单位为 4 像素。
- 页面区块使用 24 或 32 像素间距，表单字段使用 16 像素间距，紧密工具栏使用 8 像素间距。
- 输入控件使用 Fluent 默认圆角。
- 面板和弹窗使用统一中等圆角。
- 标签和筛选项只有在语义需要时使用胶囊形状。
- 圆形仅用于头像、单图标按钮和真实状态标记。

### 15.4 层级

固定层级：

```text
页面内容
< 固定工具栏
< 抽屉
< 弹窗
< 全局提示
```

业务组件不得自行设置任意层级值。阴影只用于抽屉、弹窗和确有遮挡关系的浮层，数据区块使用间距和分隔线建立层级。

## 16. 布局与响应式

### 16.1 企业控制台

- 1440 像素及以上：固定侧边导航，内容最大宽度 1600 像素。
- 1024-1439 像素：收窄侧边导航，保留完整任务路径。
- 768-1023 像素：侧边导航收起为抽屉，表格保留关键四列，其余进入详情。
- 小于 768 像素：只支持概览、审批、告警处理和只读诊断等紧急任务。
- 数据源、模型和助手复杂配置在手机上显示只读说明，并引导到桌面继续，不能把七列桌面表格简单横向压缩。

### 16.2 问答工作台

- 桌面使用“会话列表、回答区、来源抽屉”结构。
- 平板隐藏会话列表，来源使用右侧抽屉。
- 手机使用单列回答流，来源使用全屏底部抽屉。
- 输入区固定在安全区域上方，键盘弹出后不能遮挡发送、停止和附件操作。

### 16.3 设备问答

- 触控目标不小于 48 乘 48 像素。
- 主要路径最多包含“开始、提问、回答、继续或结束”四个阶段。
- 默认大字号、高对比、少文本，不显示诊断信息。
- 语音状态明确区分等待、正在聆听、识别中、回答中和失败。
- 设备离线、网络慢和凭据失效必须提供现场可理解的恢复信息。

## 17. Fluent UI 组件约束

| 场景 | 首选组件 | 使用规则 |
| --- | --- | --- |
| 页面主操作 | `Button` | 每页最多一个 `primary` |
| 表单字段 | `Field` 与对应输入组件 | 标签常驻，错误位于字段下方 |
| 长列表 | `DataGrid` 或 `Table` | 列数受预算限制，支持键盘 |
| 筛选 | `Toolbar`、`Combobox`、`SearchBox` | 常用筛选常驻，高级筛选进入弹层 |
| 层级资源 | `Tree` | 只表达真实父子关系 |
| 详情补充 | `Drawer` | 不承载必须独立成页的流程 |
| 高风险确认 | `Dialog` | 说明影响、对象和不可逆结果 |
| 页面级问题 | `MessageBar` | 紧邻受影响区域，提供恢复动作 |
| 临时反馈 | `Toast` | 只用于无需后续处理的短暂结果 |
| 选项切换 | `TabList` | 选项共享同一任务与对象 |
| 加载 | `Skeleton` | 形状匹配最终内容 |
| 状态 | `Badge` 与文本 | 颜色与语义统一，不把标签当装饰 |

禁止：

- 混用其他组件库。
- 用通用卡片替代表格、表单分组或页面区块。
- 用抽屉隐藏完整的创建或发布流程。
- 用提示气泡承载关键操作说明。
- 使用只有图标、没有可访问名称的操作按钮。

## 18. 表单和发布动作

### 18.1 表单结构

每个创建或配置流程最多四步：

1. 明确对象与负责人。
2. 配置核心数据。
3. 探测或校验。
4. 检查影响并提交。

字段要求：

- 标签位于输入框上方。
- 必填依据业务规则，不使用大量星号制造噪声。
- 帮助文本解释为什么需要，而不是重复标签。
- 错误说明问题、原因和修复方式。
- 高级参数默认折叠，折叠标题显示已修改项数量。
- 离开未保存页面时提示草稿影响。

### 18.2 发布确认

发布确认必须显示：

- 将发布的资源和修订号。
- 影响的助手、渠道、索引或策略。
- 已通过和未通过的门禁。
- 回滚或替代方式。
- 操作权限和审计说明。

发布按钮只在门禁全部通过时可用。若用户无权发布，页面显示需要的角色和申请路径，不显示无法解释的禁用按钮。

## 19. 表格、筛选与详情

- 默认按最需要处理的状态和最近变化排序。
- 筛选条件反映用户语言，不使用数据库字段名。
- 筛选变化写入地址栏，刷新和分享后可恢复。
- 选择行只打开详情，不与复选框批量选择冲突。
- 行操作最多两个常用操作，其余进入菜单。
- 批量操作必须显示选择范围、跨页规则和不可处理项。
- 详情页保留对象标题、状态、版本、负责人和主操作。
- 详情中的历史、审计和技术诊断使用按需加载，不阻塞首屏。
- 空表格必须区分“尚未创建”和“当前筛选无结果”。

## 20. 状态与恢复动作矩阵

| 状态 | 页面表达 | 主恢复动作 | 禁止做法 |
| --- | --- | --- | --- |
| 加载 | 与最终布局一致的骨架 | 等待或取消长任务 | 全页旋转图标 |
| 空 | 解释价值和创建前提 | 唯一创建动作 | 放置多个无关入口 |
| 错误 | 安全错误码、traceId、影响和可重试性 | 重试、修改或联系支持 | 显示堆栈和内部地址 |
| 无权限 | 说明缺少的操作权限和申请路径 | 申请权限或返回 | 暗示无权资源内容 |
| 部分成功 | 成功数、失败数、可否安全使用 | 查看失败项 | 用绿色成功提示掩盖失败 |
| 过期 | 最后成功时间和当前影响 | 重新同步或继续使用旧版本 | 把过期数据显示为正常 |
| 冲突 | 当前版本、用户编辑版本和差异 | 重新加载并合并 | 静默覆盖 |
| 配额耗尽 | 使用量、重置时间和受影响功能 | 申请或调整配额 | 反复自动重试 |
| 服务降级 | 可用能力和暂不可用能力 | 使用安全替代或等待 | 静默降低安全和能力 |

## 21. 关键任务闭环

### 21.1 首次租户启用

```text
创建租户
-> 设置驻留和安全上限
-> 邀请管理员
-> 配置模型连接
-> 发布首个数据源
-> 创建并评测助手
-> 绑定受限渠道
-> 查看首次真实查询
```

概览按当前缺失条件显示一个下一动作，不能同时展示八个“开始配置”入口。

### 21.2 数据问题修复

```text
同步任务部分成功
-> 查看失败分类
-> 定位源记录
-> 修复连接、结构或数据
-> 使用原幂等范围重试
-> 重新校验
-> 创建新索引版本
```

旧已发布索引在新版本通过前继续可用，页面必须明确当前线上版本。

### 21.3 模型异常处置

```text
模型健康告警
-> 查看租户与助手影响
-> 模拟当前路由
-> 下线异常部署或发布新策略
-> 验证回退能力与驻留
-> 观察错误率恢复
```

不得提供绕过驻留、内容安全或能力要求的一键回退。

### 21.4 助手发布

```text
保存草稿
-> 固定依赖版本
-> 执行测试
-> 运行评测
-> 处理阻断项
-> 请求发布
-> 审批
-> 绑定渠道
-> 观察发布后指标
```

任何一步失败都保留已验证结果和返回入口，不要求用户从头重新配置。

## 22. 文案与本地化

- 默认界面语言为简体中文。
- 技术标识、协议字段、模型代码和路径保持原值。
- 操作使用“动词加对象”，例如“发布索引”“撤销凭据”。
- 状态使用已经发生的事实，例如“探测失败”“等待评测”。
- 错误文案包含发生了什么、影响什么、能做什么。
- 禁止使用“智能赋能”“一键升级”“无限可能”等空泛表达。
- 时间同时显示相对时间和可查看的绝对时间。
- 金额、时区、数字、单位和排序由租户地区配置决定。
- 删除、撤销、发布和回滚不能共用含糊的“确认”按钮。

## 23. 键盘与读屏

| 场景 | 键盘要求 | 读屏要求 |
| --- | --- | --- |
| 全局导航 | 可跳过导航并直接到主内容 | 宣告当前区域 |
| 数据表格 | 表头、行和操作顺序稳定 | 宣告列名、状态和排序 |
| 分步表单 | 前后步骤可控，错误后聚焦摘要 | 宣告步骤、字段错误和剩余要求 |
| 抽屉与弹窗 | 打开后聚焦标题，关闭后回到触发点 | 标题、描述和危险影响有关联 |
| 流式回答 | 停止按钮始终可达 | 按句或阶段播报，不逐 Token 播报 |
| 引用 | 回答与来源可双向跳转 | 宣告引用编号、来源和新鲜度 |
| 图表 | 提供同等信息的表格摘要 | 不依赖颜色和图形位置 |

页面必须支持 200% 缩放、键盘全流程、高对比模式和减少动态效果。

## 24. 前端模块边界

前端采用 npm 工作区，控制台、问答和设备界面是独立构建应用，共享包只有出现两个真实消费者时才创建。完整工作区目录和创建门槛见 `docs/architecture/foundation-repository-layout.md`。

```text
frontend/
├── apps/
│   ├── console-web/
│   ├── query-web/
│   └── device-web/
├── packages/
│   ├── design-system/
│   ├── api-client/
│   ├── auth/
│   ├── query-stream/
│   ├── telemetry/
│   └── test-support/
└── e2e/
```

边界规则：

- 应用不能导入其他应用内部源码。
- 控制台内部按 `capabilities/<task>` 组织，每个能力只有 `index.ts` 可以被外部引用。
- `design-system` 只包含品牌令牌和至少被两个应用使用的 Fluent 组合组件，不包装所有基础组件。
- 权限、SSE、追踪和生成接口客户端通过真实共享包统一处理。
- OpenAPI 生成类型位于 `api-client`，不能直接作为组件属性。
- 页面使用视图模型，将接口状态转换为用户任务状态。
- 路由级加载负责首屏数据，查询缓存只保存服务器事实。
- 表单草稿、弹窗和本地选择使用局部状态，不建立全局状态仓库。
- M1 只创建 `console-web` 和 `query-web`，`device-web` 到 M7 再创建。

## 25. 前端性能预算

| 项目 | M1 预算 |
| --- | --- |
| 控制台初始脚本压缩后 | 不超过 250 KB |
| 单一路由新增脚本压缩后 | 不超过 120 KB |
| 最大内容绘制 | 小于 2.5 秒 |
| 交互响应 | 小于 200 毫秒 |
| 累积布局偏移 | 小于 0.1 |
| 表格首次可用 | 参考数据下小于 1 秒 |
| 路由切换可见反馈 | 小于 100 毫秒 |

- 路由、图表、代码查看器和诊断模块按需加载。
- 大表格使用服务端游标和窗口化，不把全部记录载入浏览器。
- 流式事件批量更新视图，不为每个 Token 重绘完整回答树。
- 图标只从 Fluent 图标包按需导入。
- 首屏不加载评测图表、审计详情和模型高级参数。
- 性能预算进入构建门禁，超出必须说明原因和修复工作包。

## 26. 前端安全与隐私

- 浏览器不持久化模型密钥、设备密钥、完整权限策略或敏感证据正文。
- 凭据输入保存后立即清空，返回页面只显示引用状态和轮换时间。
- 所有 HTML、Markdown、引用和工具结果使用白名单渲染。
- 外部链接显示目标域名并使用安全打开方式。
- 下载和导出经过单独授权，并在文件中标记租户、时间和审计编号。
- 问答历史、诊断信息和反馈按租户保留策略处理。
- 前端权限只控制体验，后端仍是授权事实来源。
- 分析事件不记录问题正文、回答正文、密钥、个人画像和文档内容。

## 27. 设计交付与评审证据

每个实施工作包开始前，设计至少交付：

- 页面目标、角色和成功结果。
- 页面结构和主操作。
- 使用的 Fluent 组件及其组合规则。
- 加载、空、错误、无权限、部分成功和过期状态。
- 桌面、平板和手机行为。
- 键盘顺序、焦点、读屏名称和对比度说明。
- 接口依赖、权限点和审计事件。
- 可点击原型或可运行页面。

设计评审必须包含：

1. 产品按任务闭环验收。
2. 前端按组件、状态和性能预算验收。
3. 后端按接口、权限和失败语义验收。
4. 测试按可执行场景和证据验收。
5. 设计按一致性、可访问性和响应式验收。

没有角色、任务、恢复动作和验收证据的页面不得进入实现。
