# 可信 RAG 基座前端设计

## 1. 设计方向

这是强调可信、权限和效率的企业控制台与问答界面，不是营销式数据看板，也不能照搬后端模块树。

- 视觉变化度：3/10。
- 动效强度：2/10。
- 信息密度：7/10。
- 组件系统：只使用 Fluent UI React v9。
- 单一主题、单一强调色和统一设计 Token。

界面优先表达层级、状态、来源和下一行动，装饰不能替代信息。

## 2. 信息架构

顶级导航最多六项，并根据角色裁剪：

| 区域 | 用户意图 | 主要资源 |
| --- | --- | --- |
| 概览 | 查看当前需要处理的事情 | 任务、健康、发布、配额 |
| 数据 | 接入并发布可信信息 | 数据源、数据集、知识空间、同步和索引 |
| 助手 | 构建、测试、评测和发布 | 助手、版本、渠道、会话 |
| 评测 | 证明质量并定位失败 | 数据集、任务、比较、门禁 |
| 治理 | 管理权限、模型、审计和用量 | 组织、策略、供应商、部署、路由、审计 |
| 运维 | 运行和恢复平台 | 健康、队列、存储、备份、构建 |

无权访问的区域和操作直接移除，不展示为不可点击的功能目录。

## 4. 页面复杂度预算

- 每页只服务一个主要用户目标。
- 页面头部最多一个主按钮。
- 默认表格最多七个业务列。
- 单个表单分组最多七个可编辑字段。
- 下钻前最多展示五项摘要指标。
- 高级参数、厂商参数和模型诊断默认折叠。
- 超过五项的重复数据使用表格、树、列表框、折叠面板或合适的标签页，不使用通用卡片堆积。
- 危险操作进入次级菜单，明确说明影响并二次确认。
- 页面包含两个以上互不依赖的流程时必须拆分。
- 禁止用大量标签页掩盖职责混乱。

## 5. 应用框架

```text
┌───────────────────────────────────────────────────────────────┐
│ 产品  租户选择               搜索        帮助  用户          │
├─────────────┬─────────────────────────────────────────────────┤
│ 概览        │ 面包屑                                          │
│ 数据        │ 页面标题                         主操作         │
│ 助手        │ 结果或状态摘要                                  │
│ 评测        ├─────────────────────────────────────────────────┤
│ 治理        │ 当前任务内容                                    │
│ 运维        │                                                 │
└─────────────┴─────────────────────────────────────────────────┘
```

- 只有平台运营人员可以看到跨租户选择。
- 全局搜索只检索有权访问的平台资源，默认不搜索文档正文。
- 页面标题表达对象或任务，不使用技术模块名。
- 状态摘要必须指向下一步可行动作。

## 6. 关键流程

### 6.1 发布数据源

```text
数据源                                             [新增数据源]
┌─────────────────────────────────────────────────────────────┐
│ 名称       类型      已发布版本      新鲜度       状态      │
│ 校园问答   文件      v3              2 小时       健康      │
│ 门店数据   数据集    v7              5 分钟       健康      │
└─────────────────────────────────────────────────────────────┘

新增数据源
1 类型与负责人
2 连接或上传
3 Schema 与敏感级别
4 探测与确认
                                  [保存草稿] [执行首次同步]
```

首次同步不得自动发布。评审页必须显示成功、失败、重复、过期和越权数据。

### 6.2 配置模型

```text
模型 / 新增供应商
1 厂商与区域
2 地址与凭据
3 探测模型和能力
4 选择部署并发布

探测结果
连接 ✓        认证 ✓        延迟 340 毫秒
可用模型 8    能力冲突 0
凭据          已保存为密钥引用，永不回显
                                         [发布供应商]
```

只显示当前模型类型支持的参数，便携参数与厂商高级参数分区。

### 6.3 构建助手

```text
助手：门店导购                         草稿 v4
知识  模型  行为  渠道

必需能力：流式 Chat、结构化输出
知识范围：门店商品数据 + 门店问答
路由策略：中国区零售交互

[保存草稿]                                  [执行评测]
```

只有评测通过后，评测结果页才显示发布操作。

### 6.4 提问与查看引用

```text
商品 A 的价格和位置是什么？

商品 A 售价 39 元，位于 4 号通道 B 货架。       [1] [2]
库存信息在 4 分钟前更新。

[有帮助] [无帮助] [查看来源]

[1] 门店商品数据 · 版本 7 · 商品 A
[2] 门店布局 · 版本 3 · 4 号通道
```

证据不足时：

```text
没有找到能够回答该问题的已授权且有效的信息。
[查看检索范围] [换一种问法]
```

### 6.5 查询诊断

```text
查询 qry_...
已完成 · 2.8 秒 · 0.012 元 · 策略 v12

时间线  权限  证据  模型  用量
权限      允许 space-1、dataset-7；遮蔽 margin
检索      18 个候选 → 6 个已授权 → 4 个重排结果
生成      主模型 mdl-17；未回退
引用      2/2 校验通过
```

诊断只提供给有权限的运营和审计人员。

## 7. 模型治理交互

- 模型管理位于“治理”下。
- 凭据只写，保存后只显示配置状态和轮换时间。
- 发布供应商前必须成功探测。
- 能力标签表示实际探测结果，不表示厂商宣传。
- 路由模拟展示主模型、备用模型、拒绝原因、驻留、延迟和成本区间。
- 如果回退降低区域、内容安全或必需能力，禁止启用。
- 已发布模型部署不可修改，变更产生新版本。

## 8. 页面状态

每个读取数据的页面必须设计：

- 加载：使用与最终布局一致的骨架。
- 空状态：说明价值并给出唯一有效下一步。
- 错误：显示安全错误码、traceId 和可用恢复动作。
- 无权限：不泄漏资源是否存在。
- 部分成功：说明失败来源和结果是否可安全使用。
- 过期：显示最后成功时间和恢复动作。

流式问答状态：

- 已接受
- 规划中
- 检索中
- 生成中
- 已完成
- 已拒答
- 无权限
- 已取消
- 失败

断线后使用查询对账接口，并从最后一个 SSE 事件编号恢复。

## 9. 组件、可访问性与性能

- 功能组件不得使用原始颜色值，只使用 Fluent 语义 Token。
- 状态必须使用文字或图标加颜色表达。
- 表单使用持久标签、必要说明和可见错误。
- 图标只使用 Fluent UI 图标。
- 动效只用于导航、展开、进度和结果反馈，并支持减少动态效果。
- 满足 WCAG 2.2 AA、键盘操作、焦点可见和弹窗焦点恢复。
- 查询进度使用可访问实时区域，但不逐 Token 播报。
- 参考页面 LCP 小于 2.5 秒、INP 小于 200 毫秒、CLS 小于 0.1。
- 使用路由级拆包，诊断和图表按需加载。

## 10. 前端架构约束

- 功能按用户任务组织，不按后端包名组织。
- 数据请求由路由加载器、动作或查询 Hook 管理，视图组件不能直接散落调用 `fetch`。
- API 类型由已接受的 OpenAPI 契约生成。
- 视图模型隔离 API DTO 与组件。
- 权限同时控制路由注册和操作命令。
- 错误、配额和 SSE 是共享产品能力，不能在每页复制。
- 文件复杂时按任务 seam 拆分，不按组件数量机械拆分。

## 11. 设计验收

- 每条路由都能关联到目标追踪矩阵。
- 每页都有明确角色、任务、成功结果和恢复方式。
- 顶级导航不超过六项。
- 不向角色宣传其无权使用的功能。
- 页面复杂度预算全部通过。
- 凭据和敏感证据无法回显。
- 所有关键流程覆盖加载、空、错误、无权限、部分成功和过期状态。
- 键盘、读屏、减少动态效果和响应式评审通过。
