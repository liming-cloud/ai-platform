# 领域与公共契约基线

状态：已接受。负责人：产品、后端、安全。以下主题把现行边界指向已接受 ADR，取代旧大文档中并存的草案契约；不生成新 API、表或状态值。具体端点与失败语义以对应 ADR、上下文源码和契约测试为准。

## 公共边界

租户/主体/成员/权限事实从服务端验证的会话恢复，业务请求不能伪造。平台请求上下文与租户上下文分别强制，不以可空租户切换身份。浏览器 Cookie/CSRF 依据 ADR-0048 及后续调整，机器协议不能据旧例子扩展权限。

标识及领域不变量、ErrorCode/ErrorType、分页与自动配置以 ADR-0022 为准。普通资源采用页码、页大小、总数，默认20、最多100；MyBatis-Plus 类型留在 infrastructure。协议事件序号和检索候选不冒充分页。领域只依赖 JDK/shared-kernel，跨上下文使用 application facade/Port。

## M6 固定实现目标

多格式接入到 EXTRACTED 归 WP-0020，分块/索引/READY 归 WP-0022，助手发布归 WP-0023；评测与共用真实流式能力由 WP-0021 前移。不得用旧“知识接入一步 READY”或同步回答回放替代当前合同。

配额默认3库、1000文档/库、10GB/库、单文件50MB、粘贴1MiB；服务端原子预留，不低于用量。登录策略、分块区间、dense/sparse、RRF、重排和上下文窗口参数完整保留于 ADR-0079；各实现切片须引用并测试，不在多份文档复制可漂移数值表。

评测每库至少100题，安全泄漏0、Recall@10≥0.85、引用≥0.95、拒答≥0.98，混合检索p95<800ms、用户端首Token p95<4s；五次一致性与版本变化重测。旧小型演示不能证明这些目标完成。

## 数据、安全与外部影响

仓储、迁移、发件箱与事务由拥有数据的上下文负责；应用服务编排事务，领域维护不变量，基础设施不决定角色或状态。旧锚点、历史回填和知识产物兼容链路按对应 ADR 处理，不借文档整理删除数据或批量改外键。

凭据经专属安全适配器处理，禁止进入响应、审计、索引、日志及任务证据。供应商错误、SSRF、超时/重试和出站域名受控。权限撤销覆盖输出、引用和历史，不只隐藏菜单。结构化查询只接受受控 DSL，不执行模型任意 SQL。

M7 设备/同意和 M8 正式发布、TLS、密钥托管等仍按长期路线和环境门禁，不因当前设计基线整理获得实施授权。
