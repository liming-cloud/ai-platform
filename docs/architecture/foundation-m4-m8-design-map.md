# 可信 RAG 基座 M4 至 M8 设计路线图

## 目的与边界

本文在 M3 人工评审通过后，固化 M4 的设计前沿和 M5 至 M8 的依赖边界。它不激活 M5 至 M8 工作包，不改变已接受 ADR，也不授权实现尚未接受的公共契约。

M4 的唯一产品结果是：助手负责人能在受治理的模型和已发布知识基础上测试草稿；最终用户能获得可恢复、带核验引用的问答并提交受控反馈；有权限的人员能查看脱敏诊断。评测门禁、发布审批、模型路由、平台管理、渠道 SDK、设备和生产运维都明确不属于 M4。

## 已确认的继承约束

| 约束 | 设计含义 |
| --- | --- |
| 助手版本与可信回答（ADR-0016） | 普通查询只能使用 `PUBLISHED` 助手版本；知识、模型、索引和引用在查询中冻结并再次鉴权。 |
| 浏览器会话与恢复（ADR-0017） | 浏览器只保存内存令牌；按事件序号恢复；未验证正文不能作为最终回答展示。 |
| 配额与候选检索（ADR-0018、ADR-0019） | 普通查询的配额、幂等和候选选择保持服务端强制，页面不能覆盖。 |
| 受控模型配置（ADR-0023） | 草稿或查询均只能引用当前主体有权使用、已启用且已冻结的配置，不接收端点或密钥输入。 |
| 领域和登录态（ADR-0031、ADR-0033） | 跨根不变量使用命名领域服务和操作结果；登录状态只从令牌恢复，不能出现在接口或命令中。 |

## M4 领域设计卡

| 项目 | 设计 |
| --- | --- |
| 语言与所有权 | `AssistantVersion` 的 `DRAFT` 状态表达可编辑草稿；`AssistantTestRun` 表示草稿的可复现受控测试；`QueryFeedback` 表示对已完成查询的受控反馈；`QueryDiagnostic` 是受权只读投影。助手草稿和测试归 assistant-delivery；普通查询、反馈事实和诊断投影归 trusted-query。评测结论、发布批准和渠道绑定明确排除。 |
| 聚合 | `Assistant` 与 `AssistantVersion` 沿用 ADR-0016；普通 `QueryRun` 保持只读已发布版本。`AssistantTestRun` 与 `QueryFeedback` 的独立根、状态机、幂等与保留规则由 ADR-0036 接受后冻结。`QueryDiagnostic` 不作为写入聚合。 |
| 协作 | 草稿测试在授权、事务外 I/O 与受控模型调用编排后，复用可信检索、证据再鉴权、引用验证和失败关闭规则；普通查询、测试和反馈之间仅以稳定标识关联。跨上下文只消费已发布索引、受控模型快照与助手版本公开契约。 |
| 安全 | 所有身份、租户、成员、渠道和权限仅来自 `TrustedRequestContext`；草稿、诊断、反馈均先按令牌上下文授权。反馈和诊断不复制原始问题、回答、提示词、证据正文、对象位置或密钥；跨租户与无权限路径失败关闭。 |
| 持久化 | 测试运行和反馈若被接受为持久化事实，各自使用聚合根仓储、乐观版本和最小不可变快照；诊断只从既有查询事实派生。基础设施只映射、锁和原子提交，不能补写草稿、引用、归属或状态机业务判断。 |
| 证据 | 实现前先对 ADR-0036 的反例写红灯；随后覆盖领域、应用、真实 PostgreSQL、HTTP／事件恢复和浏览器。测试至少包含草稿不可经普通查询访问、未知引用拒答、反馈越租户、诊断越权、断线续传和旧会话响应丢弃。 |

## M4 先决决策与退出边界

ADR-0036 处于“提议”状态，是 M4 实现的唯一设计阻断：它解决“草稿测试”与 ADR-0016 的“普通查询只接受发布版本”之间的冲突，并定义反馈与诊断的最小事实边界。它未被接受前不得创建接口、表、事件或浏览器入口。

ADR-0036 被接受后，M4 的实现顺序固定为：先草稿测试和可信引用反例，再完成事件恢复与反馈／诊断，再形成助手负责人、最终用户和受权审计人员的浏览器验收。M4 退出仍需自动证据、控制面登记和人工评审；不得以“已能测试草稿”替代 M6 的评测门禁或发布审批。

## M5 至 M8 的边界和前置物

| 里程碑 | 设计结果 | 依赖 M4 的稳定事实 | 明确不前置实现 |
| --- | --- | --- | --- |
| M5 模型扩展 | 在受控目录下增加多厂商、多类型、工具、MCP、多模态、音频、路由、回退、驻留、健康、延迟和成本策略。 | 已冻结的助手／查询模型快照、可信引用和失败分类。 | 不允许用户新增厂商或任意端点；不提前改变 M4 的普通查询语义。 |
| M6 企业治理与发布制度 | 平台与租户双范围、组织策略、设备凭据、评测、成本预算、发布审批、审计导出和运营工作台。 | M4 的测试运行、反馈与诊断最小事实可被受控消费，但不能反写普通查询。 | M4 不创建评测通过、版本比较或发布记录。 |
| M7 渠道与同意 | 设备问答、渠道／连接器 SDK、画像同意与撤回、隐私控制和设备威胁模型。 | 已发布助手版本、受权查询和稳定引用终态。 | 不在 M4／M5 建立开发者门户或让设备访问草稿。 |
| M8 生产就绪 | 运维工作台、发布回滚、容量、灾备、漏洞和支持签署。 | 版本、审计、查询终态与发布决定的可追溯事实。 | 不把 M1 演示演练或 M4 浏览器验收表述为生产签署。 |

## 评审清单

- M4 是否只新增已接受 ADR 所允许的聚合、投影和跨上下文契约？
- 草稿测试是否与普通已发布查询、公开渠道、计量和发布审批严格隔离？
- 反馈、诊断和事件恢复是否遵守最小留存、令牌派生登录态与未验证正文不展示的边界？
- M5 至 M8 的范围是否仅作为依赖地图，而非已激活的实施承诺？
