# ADR-0017：查询渠道助手目录与浏览器状态边界

## 状态

已接受

## 日期

2026-07-27

## 决策负责人

产品负责人批准的 M1 计划，由前后端负责人共同实施并以自动证据验收。

## 背景

可信查询运行、引用拒答和可重放状态事件已经具备，但最终用户查询站点仍是
静态空页面。现有管理端助手列表只表达助手身份和最新草稿计数，既不能告诉
查询者哪个版本已经发布，也不应该向查询渠道暴露系统指令、模型、索引或
知识空间配置。

浏览器使用持有者令牌访问查询运行时。原生 `EventSource` 不能可靠附加
自定义认证请求头，且登录替换、注销和异步响应交错时可能让旧身份的数据
重新进入页面。

## 决策

### 查询渠道助手目录

1. 查询运行时新增：
   `GET /api/v1/query-assistants?cursor={cursor}&limit={limit}`。
2. 接口只返回当前可信租户内，每个助手版本号最大的已发布版本。
3. 每项只包含：
   - 助手标识。
   - 助手显示名称。
   - 已发布助手版本标识。
   - 版本号。
   - 发布时间。
4. 接口不返回草稿、系统指令、模型部署、索引版本、知识空间、策略参数或
   创建人。
5. 读取必须同时具备 `assistant:query` 和 `knowledge:read` 权限。
6. 查询按发布时间和稳定标识排序，使用服务端不透明游标分页。
7. 没有可用助手时返回空集合，不把管理端创建或发布操作放入查询站点。

### 浏览器会话与异步隔离

8. 查询站点通过同源反向代理登录，令牌只保存在当前页面内存，不写入
   本地存储、会话存储、地址、日志或分析事件。
9. 登录、身份替换和注销都会递增本地会话修订并取消旧请求。
10. 异步结果提交视图前必须同时核对请求信号和会话修订；旧身份产生的
    助手目录、查询结果、错误或事件不得恢复到新身份页面。
11. 查询站点的反向代理只把认证路径发送到控制面，其余查询路径发送到
    查询运行时；两个服务都不直接暴露给浏览器脚本。

### 查询任务状态

12. 页面只承担“选择已发布助手并获得可信回答”一个主要任务，不增加
    管理入口、历史记录假入口或模型参数。
13. 页面状态固定为：
    - 等待登录。
    - 正在验证身份。
    - 正在加载助手。
    - 没有已发布助手。
    - 可以提问。
    - 正在查询。
    - 已回答。
    - 已拒答。
    - 查询失败。
    - 无权限。
    - 会话失效。
14. 创建查询必须使用由“助手版本和问题正文”稳定生成的幂等键；相同问题
    的安全重试复用键，问题或助手变化后生成新键。
15. 回答、拒答和引用以持久化终态事件为准，不以暂定模型文本为准。
16. 浏览器使用带认证请求头的 `fetch` 读取服务端事件流，按事件编号记录
    恢复游标；连接中断时只从最后确认事件之后恢复，不重新创建查询。
17. 引用正文按纯文本渲染，不解释为 HTML；回答中的 Markdown 在 M1
    不启用。
18. 读屏按查询阶段和最终结果播报，不逐令牌播报；来源与回答之间保持
    双向可定位关系。

## 主要备选方案及拒绝原因

### 前端读取管理端助手列表并猜测最新发布版本

拒绝。管理端列表没有发布事实，继续扩张它会向查询者泄漏配置状态并把
领域判断放入浏览器。

### 在演示页面硬编码助手版本标识

拒绝。编号会随租户、数据和发布变化，无法形成可部署产品闭环，也不能证明
租户隔离。

### 使用本地存储保存持有者令牌

拒绝。演示便利不能扩大令牌暴露面；刷新后重新登录是 M1 可接受的取舍。

### 使用原生事件源并把令牌放进查询参数

拒绝。查询参数可能进入历史、代理和访问日志。带认证头的流式读取更加明确。

### 直接使用创建查询响应渲染最终回答

拒绝。这样会绕过已经建立的可重放事件合同，断线恢复和后续异步执行也会形成
第二条前端路径。

## 后果与验收

- 助手与交付上下文增加最小已发布目录投影，不改变助手聚合。
- 查询运行时增加只读目录入口，管理控制面契约保持不变。
- 查询站点增加内存会话、查询客户端、状态机和单任务页面。
- 必须测试草稿过滤、每个助手只返回最新发布版本、权限、租户隔离、游标、
  登录替换、注销取消、旧响应丢弃、幂等重试、事件续传、回答、拒答和错误。
- M1 不提供查询历史、反馈、逐令牌恢复、Markdown、附件或语音。
