# ADR-0011：租户认证与持久化隔离边界

## 状态

已接受

## 背景

WP-0003 首次引入登录态、租户数据和真实 PostgreSQL 持久化。若租户来自请求参数、Controller 直接调用 Sa-Token 或仅依赖 MyBatis-Plus 自动改写 SQL，任何一处绕过都可能造成跨租户数据泄漏。

## 决策

1. Sa-Token 只存在于认证入站适配器和运行时装配中。
2. Sa-Token 登录标识使用租户成员标识；人员在不同租户中的成员身份不能共享登录态。
3. 认证适配器把登录态转换为平台 `TrustedRequestContext`，包含租户、主体、成员、凭据类型、渠道、权限版本和追踪标识。
4. 租户标识只来自服务端会话和成员事实，不信任调用方提交的租户请求头或请求字段。
5. 入口权限检查不能代替资源授权。应用用例在加载资源时同时使用租户标识和资源标识，无权限与不存在对外保持不可区分。
6. 每张租户业务表包含 `tenant_id`；唯一约束、查询索引和仓储条件包含租户边界。
7. MyBatis-Plus 租户插件作为纵深防御，仓储端口和适配器查询仍显式携带租户条件。
8. 拦截器顺序固定为租户、乐观锁、危险 SQL 阻断，禁止业务代码忽略租户插件。
9. 只使用 Flyway 管理数据库结构，迁移靠近所属上下文，禁止跨上下文外键和直接 Mapper 查询。
10. 持久化验收使用真实 PostgreSQL，验证提交、回滚、并发失败和最终审计可见性。

## 影响

- 组织与权限上下文负责生成可信请求上下文和权限决定。
- 知识与数据上下文不依赖 Sa-Token，通过平台上下文和公开授权端口工作。
- MyBatis-Plus 实体、Mapper、Wrapper 和注解只能出现在持久化适配器。
- 控制面启动依赖 Flyway 成功完成迁移。
- 认证、租户和持久化任何公共边界变化都必须新增 ADR。
