# ADR-0072：租户知识库所有权、工作区边界与可恢复生命周期

## 状态

已接受。

## 日期

2026-08-30

## 决策负责人

用户，代表产品、架构、安全、平台运营与租户运营负责人。

## 背景和待消除的矛盾

后端已经把 `KnowledgeSpace` 定义为携带强制 `TenantId` 的租户聚合，创建、分页读取和后续数据源操作也从 `TrustedRequestContext` 派生租户身份。现有控制台却把知识库创建隐藏在“首份文本发布”向导中，并以“数据”作为扁平入口，导致用户无法清楚判断知识库属于谁、从哪里创建以及如何持续维护。

平台管理员必须能治理租户生命周期、平台模型供应链和平台签发的基础设施范围，但这种平台治理权不能转化为任意租户知识库的内容访问权。租户管理员需要一个一等、可恢复、可重复进入的知识库工作区，普通用户只能通过已授权且已发布的问答能力消费知识。

## 决策内容

1. 产品术语“知识库”由知识数据上下文中的 `KnowledgeSpace` 聚合承载。每个知识库必须且只能属于一个租户，`TenantId` 是创建、持久化、查询和后续操作不可缺失的安全边界；知识库不得在租户间移动或共享。
2. `PLATFORM_ADMINISTRATOR` 不获得知识库创建、列举、读取、修改、发布、索引或正文访问能力。平台会话不得转换或伪装成租户会话；同一人员即使同时拥有平台与租户身份，也必须显式进入目标租户会话后才能执行租户任务。
3. 平台范围只治理租户生命周期、平台账户、平台模型供应链、平台基础设施连接与可授权范围，以及不含知识库名称、来源名称、正文、引用或成员明细的安全聚合。平台签发对象存储范围不代表平台拥有租户登记后的数据来源。
4. `TENANT_ADMINISTRATOR` 在当前租户内创建、列举、选择和维护知识库，并在所选知识库内登记来源、同步与质量检查、发布数据、构建及发布索引、绑定助手。所有操作继续由服务端能力与租户谓词授权，前端隐藏入口不构成授权。
5. `TENANT_USER` 不获得知识库管理入口。其 `knowledge:read` 只服务可信问答中的授权资料和引用读取，不得用于列举知识库管理目录；其唯一知识消费路径是使用已授权助手发起可信问答、核验允许披露的引用并提交反馈。
6. 租户控制台将知识库作为一等父任务。默认入口是知识库目录，创建成功后保留明确的知识库选择；数据来源、处理与质量、索引发布和快速入门是当前知识库下的后续任务。知识库选择必须编码在可恢复 URL 中，刷新页面不能改变租户或静默切换到其他知识库。
7. “首份文本发布”降级为可选快速入门，不再承担唯一的知识库创建入口。其内部仍可复用受控上传、发布和索引能力，但完成后必须回到同一租户知识库的正式管理路径。
8. 产品生命周期按可核验业务事实表达：先创建知识库草稿，再登记来源并完成探测、同步和质量检查，随后显式发布数据，构建并发布索引，最后才允许已授权助手消费活动索引。刷新和重入必须以服务端最新状态恢复。
9. 所有知识库仓储读取、存在性检查、幂等和配额必须包含 `TenantId`。跨租户标识、平台会话和缺少相应能力的请求必须失败关闭，并使用不泄露资源是否存在的安全错误投影。

## 公共契约与界面边界

- 租户知识库 HTTP 契约只接受由可信租户会话解析的上下文，不接受客户端提交租户标识、成员标识、权限或平台身份。
- 知识库管理目录的创建和读取均要求租户知识管理能力；`knowledge:read` 保留给可信问答中的授权资料与引用读取。
- 知识库目录使用服务端页码、页大小、总数和前后页事实；知识库选择控件本身不模拟独立分页工具条。
- 平台导航不得出现“知识库管理”或租户数据来源操作。租户导航以“知识库”呈现知识库目录及其后续任务。
- 页面、日志和证据不得披露跨租户知识库名称、对象位置、正文、引用、凭据、内部错误码或供应商原始响应。
- 现有 `/api/v1/knowledge-spaces` 可以继续作为内部技术路径；浏览器产品路由必须体现租户知识库任务，不得放入 `/platform/**`。

## 主要备选方案及拒绝原因

### 方案 A：平台统一创建和维护所有租户知识库

拒绝。该方案把平台生命周期治理误扩展为租户正文访问，破坏 ADR-0027、ADR-0041、ADR-0048、ADR-0067 和 ADR-0068 的最小披露与双会话边界。

### 方案 B：保留扁平“数据”入口，仅在首份文本发布中隐式创建知识库

拒绝。一次性向导不能承担日常知识库管理，无法清晰表达知识库所有权、当前选择、来源生命周期和索引发布状态。

### 方案 C：租户知识库一等入口，平台只提供受控基础设施与安全聚合

接受。该方案复用现有后端租户聚合与能力授权，同时把产品入口、责任边界和后续生命周期恢复为可理解、可验证的任务。

## 后果与验证

- 先以红绿 TDD 证明知识库目录和创建是租户管理员的一等任务，普通用户无管理入口，平台管理员直接 URL 和 API 均失败关闭。
- 使用真实 PostgreSQL 证明租户 A 创建的知识库不会出现在租户 B 的分页结果中，幂等、配额和存在性判断均受租户谓词约束。
- 使用同源 HTTP 与 Compose 证明平台会话和普通用户不能调用知识库管理契约，租户管理员可以创建和列举当前租户知识库。
- 使用真实浏览器分别以平台管理员、租户管理员和普通用户执行角色任务，并续证 1024×768、390×844、真实 200% 缩放、键盘导航与 `prefers-reduced-motion`。
- 本 ADR 不授权跨租户知识共享、知识库硬删除、平台代运营正文、生产发布或绕过人工浏览器验收。
