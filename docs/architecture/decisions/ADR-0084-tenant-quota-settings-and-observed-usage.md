# ADR-0084：租户资源配额独立编辑与已用量下限

## 状态

已接受。用户于 2026-09-28 选择在本切片聚合现有来源的只读用量，允许下调至不低于核实用量；既有 ADR-0079、ADR-0080 和固定 OpenDesign 原型决定其余产品边界。

## 背景

WP-0017 已保存五项带版本的租户配额，但生产只有读取接口，固定原型 `platform-tenant-quotas` 有独立编辑、取消、保存、刷新和已用量提示。当前知识数据上下文存在旧知识库及文本来源，WP-0020 的统一文档计量和原子预留尚未交付。把未知用量当作零、跨上下文直接读表，或把保存配置称为已执行资源限制，均会产生错误结论。

## 决定

1. 复用 `GET /api/v1/platform/tenants/{tenantId}/quotas` 的五项配置及版本；增加独立的只读用量投影 `GET /api/v1/platform/tenants/{tenantId}/quotas/usage`，仅返回三个下限：知识库数量、每库有效文档数量的最大值、每库保留原始内容字节数的最大值，以及计量是否完整。平台身份须持有租户治理权限。接口不返回知识库名称、来源、对象键、正文或人员资料。
2. `PUT /api/v1/platform/tenants/{tenantId}/quotas` 严格接收五项完整配额和非负 `expectedVersion`。数量是正整数，容量是十进制整数字节串；单文件上限不得超过每库容量。请求不接受权限、租户身份或额外字段。成功只更新目标租户的配额和递增版本，返回新配置；版本过期以脱敏冲突拒绝，不静默覆盖。
3. 保存前由 `knowledge-data` 的公开 facade 提供当前已核实用量；`organization-access` 完成平台授权、正数和组合约束、下限比较、版本检查及事务提交。当前已知旧来源以未删除知识库、已有内容的文本来源和所有保留的文本内容版本计量。已落库但不能按当前三项口径可靠量化的受治理来源，使计量标记为不完整；此时不得降低知识库、每库文档或每库容量任一旧上限，仍可增加上限。读取失败不得按零用量继续保存。
4. 单文件与粘贴文本的上限降低只影响后续新增内容，不要求既有内容缩小；页面按固定原型说明这一点。页面刷新和重新进入均从服务端读取配置及用量，取消不写入，保存失败保留输入并显示可行动错误，成功显示新版本事实。真实会话、CSRF 与权限仍使用现有安全机制。
5. 本片的下限检查约束保存时已核实事实，不声称已让旧知识写入路径消费新的逐租户配置。WP-0020 负责统一多格式文档与原始字节计量、并发原子预留和消费配置；其落地时替换 facade 内部投影并复验下调竞态，不复制第二份配额配置。查询配额继续独立、只读。
6. OpenDesign 固定版本为 `21b45c347a4008f5959b1b972e3ffd8a5aadcc6f`，项目 `249f81f2-6f1a-46ff-988c-da3cdedb35e7`。生产页承接原型结构、文案、控件与响应式；安全错误和未知用量属于真实数据边界，不修改原型或模拟状态。截图只放 `/private/tmp`。

## 验证

- 先以测试证明当前缺少写入与用量接口；修复后覆盖权限先于查询、未知字段、数值边界、单文件组合约束、低于已用量、未知用量下调、旧版本冲突、成功递增、数据库事务可见性和跨租户隔离。
- 使用真实 PostgreSQL 验证旧知识库与文本内容版本的聚合，不读取秘密或正文；受治理来源使不完整状态失败关闭。
- 生产浏览器在受控 Compose 中覆盖编辑、取消、保存、刷新、冲突和权限；对照原型三尺寸、200% 文字、键盘与 reduced-motion。配置编辑验收不代替 WP-0020 的预留验收，也不表示 WP-0017 整包或 M6 完成。
