# ADR-0029：已发布同步产物与索引来源快照

## 状态

已接受

## 背景

M3 的 `FILE` 来源已经能生成不可变 `SyncArtifact` 和 `QualityReport`，但现有索引仓储只从 M1
`text_data_source` 的 `PUBLISHED` 内容冻结来源。若把同步成功直接视为可索引发布，会绕过质量处置；若
把 M3 产物伪装成 M1 内容版本，又会丢失来源类型、修订和产物身份。

## 决策

1. `SyncArtifact` 与“可用于新索引”的事实分离。知识管理员必须显式发布一个质量非阻断的产物；
   `PASS` 与 `WARN` 可发布，`BLOCK` 永远拒绝。同步成功不自动发布。
2. 发布记录固定租户、知识空间、受治理来源、来源修订、同步产物、质量规则版本和发布时间；同一来源
   的新发布以乐观修订替换“当前可选产物”，但绝不修改历史发布记录或已创建索引快照。
3. 索引来源快照显式区分 `LEGACY_TEXT_CONTENT` 与 `GOVERNED_SYNC_ARTIFACT`。后者冻结来源标识、
   来源修订、产物标识、对象事实、内容摘要、长度、媒体类型和质量结论；不得仅以数值数据源标识推断
   来源类型。
4. 新建索引在同一事务内读取当前租户、知识空间中 M1 已发布文本和 M3 已发布、质量非阻断的产物，
   以稳定的“来源类型、来源标识、发布事实”顺序冻结快照与构建指纹。索引构建只读取该快照，不读取
   可变来源配置或当前发布指针。
5. `RETIRED` 来源保留历史发布、质量和索引事实供审计与已激活索引读取，但禁止新的同步发布或新索引
   选择。重建只能选择仍有效的已发布来源。
6. M1 文本发布、历史索引、查询和助手路径保持兼容；不得把旧文本内容隐式迁移为 M3 同步产物。

## 影响

- 新增发布产物领域事实、真实 PostgreSQL 迁移与受控发布用例；需证明质量阻断、租户隔离、并发发布
  与退役后的失败关闭。
- `IndexVersionRepository`、来源快照持久化和构建队列须演进为类型化来源快照。所有外部对象读取和
  嵌入调用仍在数据库事务外执行。
- 公共 HTTP 仅接收来源、产物和预期修订；不接收对象键、正文、连接参数或租户标识。

## 验收

- `BLOCK` 产物不能发布、建索引或进入查询；同步成功本身不能改变当前发布事实。
- 同一索引版本可冻结 M1 文本与 M3 受治理产物，且每条快照可追溯到唯一来源类型和不可变事实。
- 质量、发布、索引、退役和模型配置失效的跨租户、无权限、并发及回滚反例均关闭失败。
