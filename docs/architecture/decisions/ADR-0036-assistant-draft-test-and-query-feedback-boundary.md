# ADR-0036：助手草稿测试与查询反馈边界

## 状态

已接受

## 日期

2026-07-30

## 决策负责人

用户，代表产品与架构负责人。

## 背景和难以逆转的约束

M4 需要让助手负责人以草稿配置完成可复现测试，并让问答工作台提交反馈和受权诊断。ADR-0016 已固定普通 `QueryRun` 只接受 `PUBLISHED` 助手版本，且查询终态、引用、计量和恢复事件均是持久化事实。把草稿测试伪装为普通线上查询会绕过已发布边界；把反馈或诊断复制为浏览器状态又会失去租户、引用和脱敏约束。

本决策只处理草稿测试、查询反馈和诊断的领域边界。评测数据集、评测门禁、发布审批、版本比较、成本预算、渠道绑定和设备调用仍属于 M6 或后续里程碑。

## 决策内容

1. `Assistant` 继续是身份和版本容器，`AssistantVersion` 继续是独立聚合根。可编辑草稿就是状态为 `DRAFT` 的助手版本，不新建语义重叠的 `AssistantDraft` 聚合。
2. 草稿测试建立独立的 `AssistantTestRun` 聚合根，不复用公开 `QueryRun`，也不让普通查询接口接受草稿。它冻结草稿版本、知识／索引、受控模型配置和测试输入摘要；每次结果必须经过与普通查询相同的授权检索、证据再鉴权和引用验证，失败关闭语义相同。持久化事实只保存题目摘要、冻结依赖、终态、用量和最小引用标识；题目与回答只在本次受权响应中返回，不作为测试历史正文留存。
3. 草稿测试只能由拥有助手配置权限且在同一租户、知识空间范围内的主体发起；它不得成为对外查询渠道、不得自动发布助手、不得形成 M6 的评测通过结论或发布批准。它使用独立的、部署侧固定的每日和并发测试配额快照，不能占用或改写最终用户 `QueryRun` 的配额、事件和运营汇总；M4 不提供配置该配额的接口。
4. `QueryFeedback` 是关联已完成 `QueryRun` 的独立、不可变聚合根。每个“查询运行 + 请求成员”最多接受一条反馈；反馈只能保存正负结果和受控原因枚举，不允许自由文本、修改或撤回。它必须随其 `QueryRun` 的保留边界删除，不得复制问题正文、回答正文、提示词、证据正文或令牌，也不得在 M4 自动进入评测数据集。
5. 查询诊断是从 `QueryRun` 及其受控事件派生的只读投影，不是可写领域对象。它只通过既有 `audit:read` 门面向审计人员开放，展示的候选数、权限决定、模型修订、引用校验和用量均须脱敏；不得向最终用户公开内部策略、资源标识、正文或密钥。
6. 流式恢复继续遵守 ADR-0016 与 ADR-0017：恢复的是持久化事件序号和已验证终态，不在引用验证完成前发布暂定模型正文。M4 不引入逐令牌业务恢复。

## 主要备选方案及拒绝原因

### 方案 A：让普通 `QueryRun` 接受草稿版本

拒绝。它会直接打破 ADR-0016 的已发布版本边界，并使公开渠道、计量和草稿测试混为一条不可审计的路径。

### 方案 B：仅在浏览器调用模型测试草稿

拒绝。浏览器不能替代服务端的租户、证据再鉴权、引用验证、密钥和审计边界，也无法复现失败原因。

### 方案 C：把反馈正文和完整诊断复制为查询记录

拒绝。它会扩散原始问题、回答、证据和可能的敏感信息，违反既有最小留存与脱敏原则。

### 方案 D：让草稿测试共用普通查询配额和运营汇总

拒绝。草稿测试不是对外查询渠道；复用 `QueryRun` 配额事实会把测试成本、终态和最终用户运营数据混在一起，并迫使普通查询放宽已发布版本限制。

## 后果和后续证据

- WP-0012 必须补齐领域设计卡、纯领域反例、应用编排、真实 PostgreSQL、HTTP／事件与浏览器角色任务证据。
- 必须证明草稿测试不能经普通查询或渠道访问，且独立测试配额不污染普通查询用量；反馈不能越租户、不能重复、不能复制敏感正文；无权限诊断不泄漏资源存在性；事件恢复不展示未验证正文。
