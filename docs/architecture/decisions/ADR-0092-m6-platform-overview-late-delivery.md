# ADR-0092：M6 平台概览后移与成员授权前沿

## 状态

已接受

## 日期与接受依据

2026-10-06。用户选择方案 2：“调整 M6 顺排：平台概览留待 M6 后段补齐，先冻结调整决定，再推进 WP-0018 成员授权”。本决定接受责任与顺序调整，不接受修改原型、减少 M6 范围或提前实现 M8 写操作。

## 背景

基线 `8920e5d41e7ac25814a2f4386a2ca1d36b4e145b` 的 WP-0017 已有 11 个入口、20 项生产操作的独立验收绑定；剩余 `platform-overview:0` 仍未冻结契约。已接受原型的平台概览依赖服务健康、摄取积压、模型延迟告警、备份校验事实，操作进入平台运行状态、摄取队列、模型健康与备份恢复。当前运营接口只有租户、模型、知识、查询业务摘要，不能把这些计数伪装成上述运行事实。

平台概览属于 M6，目标运维页面及其写操作属于 M8。推迟该入口能先推进其他 M6 能力，但不能消除其依赖冲突或把它从全量验收中排除。

## 决策

1. 新增 WP-0027“平台治理概览”，承接 `platform-overview` 和 `platform-overview:0`。二者继续为 M6 / production / pending-contract；来源 Pointer、操作 ID、原文、已接受原型及其哈希不变。WP-0017 调整为 11 个入口、20 项生产操作，其他责任与已验证事实不变。
2. 现行顺序为 WP-0017 → WP-0018 → WP-0019 → WP-0020 → WP-0021 → WP-0022 → WP-0023 → WP-0024 → WP-0025 → WP-0027 → WP-0026 → WP-0014 人工复评。WP-0027 的编号不决定执行位置；WP-0026 保持全量复验职责，不增加业务实现。
3. WP-0017 不因责任转移自动完成。收口必须逐项核对全部 11 个入口、20 项操作的真实切片证据和完整源码提交，执行当前源码回归及实际部署的集成复验。写行为沿用原真实切片证据时，必须核对后续改动及其回归覆盖，不把新的只读复验描述为本轮写操作验收。缺失证据或新回归失败仍阻断收口，不重跑会创建业务对象的开户流程来整理文档。
4. WP-0017 收口提交后才能激活 WP-0018。WP-0018 的首个前沿为成员归属、原子开户、密码重置和版本化授权的生产契约设计；ADR-0078 只证明原型，不接受生产事务。不得从顺序授权推导出未冻结接口、数据结构或成员功能已交付。
5. WP-0027 开始时重新核对 M6 实际事实与原型依赖，先接受专属生产 ADR，明确读取模型、鉴权、缺失/过期语义及四个目标入口的只读承接。M8 写操作不由本决定授权；如完整原型闭环需要扩大阶段或改变边界，须先取得对应决定，依赖未解决时保持受阻。禁止修改原型、伪造健康数据、空链接或删减验收来收口。
6. M6 覆盖仍为 78 个原型入口、155 组操作中的 66 个生产入口；其余 2 个暂缓、4 个 M7、6 个 M8 入口及各操作分类不变。WP-0027 未闭合时不得开始 WP-0026，也不得接受 M6 或激活 M7。

## 替代范围

仅调整 ADR-0079 第 1 项中平台概览的责任包、WP-0017 入口数及顺排位置；其原文和历史证据保留。ADR-0079 的原型、角色、质量、安全、执行、真实会员、证据预算和人工门禁全部继续有效。既有切片证据中的“当时整包未完成”仍是原时点事实，不改写为新验收。

## 验证

先用反例验证旧控制面无法拒绝跳过前置包和带未验证操作的虚假完成，再补充顺序及矩阵门禁。执行 `make decisions-sync`、`make project-status`、`make project-verify`、`make architecture-guard`、`make resume-context`。任务索引呈现真实顺序；矩阵保持 66 个 M6 入口，历史 650 项仍可恢复；OpenDesign、业务数据与部署不因本决定改变。
