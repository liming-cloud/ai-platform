# ADR-0067：三角色产品边界与能力投影

## 状态

已接受。

## 日期

2026-08-16

## 决策负责人

用户，代表产品、架构、安全、平台运营与租户运营负责人。

## 背景

ADR-0057 与 ADR-0061 为企业 RBAC 建立了多种平台固定角色、六种租户内置角色和租户自定义角色。人工复核进一步确认，当前产品没有这些职责拆分的真实用户任务，继续暴露它们会让平台管理员无法从单一入口完成平台初始化，也会让租户管理员面对不必要的授权配置。

当前产品处于纯本地研发阶段，没有历史迁移包袱。角色收敛必须保留服务端授权、会话撤销、最后管理员保护和导航能力投影，不能退化为前端隐藏菜单。

## 决策内容

1. 产品端到端只保留三种人员角色：`PLATFORM_ADMINISTRATOR`、`TENANT_ADMINISTRATOR` 与 `TENANT_USER`。
2. `PLATFORM_ADMINISTRATOR` 是唯一平台角色模板，可分配给多个活动账户；它拥有平台会话、平台账户、租户生命周期、平台模型供应链、平台目录和脱敏平台运营读取能力。最后一个活动平台管理员仍受保护。
3. `TENANT_ADMINISTRATOR` 是租户内唯一管理角色，拥有成员、知识数据、模型、助手、评测、查询、用量、审计与脱敏租户运营读取能力。最后一个活动租户管理员仍受保护。
4. `TENANT_USER` 只能发起可信问答、查看已授权引用并提交反馈，不获得租户管理能力。
5. 租户自定义角色及旧平台账户管理员、租户治理员、运营员等角色不再属于产品公共契约；本地空库不迁移或兼容这些绑定。相关接口、页面、数据库约束和无调用方实现按独立红绿切片退役。
6. 权限码继续是后端授权点的稳定语言。浏览器会话只返回由当前角色模板派生的有效能力；导航仍是“已发布路由要求”与“会话有效能力”的交集。
7. 平台管理员只能读取全平台总量及按租户分组的脱敏运营摘要，不得读取租户问题、回答、引用正文、成员明细、知识正文或凭据。

## 取代关系

本 ADR 在角色种类、自定义角色和产品导航方面取代 ADR-0057、ADR-0061 与 ADR-0065 的多角色部分；这些 ADR 的服务端授权、版本化权限、会话撤销、最后管理员保护、账户生命周期和模型供应链边界继续有效。

## 后果与验证

- 先以领域、应用与 HTTP 红灯证明旧角色代码和自定义角色接口不再可用，三种角色拥有准确能力，跨范围与旧会话失败关闭。
- 本地基线只初始化一个 `PLATFORM_ADMINISTRATOR` 账户，其余账户、租户和成员由页面建立。
- 统一 SPA 只显示三角色对应的任务入口；直接 URL 和 API 仍由服务端拒绝。
- 本决策不授权服务账户、身份联邦、M7、M8 或租户正文读取。
