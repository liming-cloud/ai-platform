# ADR-0016：动态模型运行时、不可变助手版本与可信引用回答

## 状态

已接受

## 日期

2026-07-27

## 决策负责人

产品负责人批准的 M1 计划，由后端负责人实施并以自动证据验收。

## 背景与难以逆转的约束

平台已经建立可信租户会话、受治理内容、版本化索引和授权候选检索。
下一步需要接入多租户模型配置并生成回答。供应商配置会变化，模型调用具有外部副作用和
不确定延迟，助手一旦发布则必须可重现，模型自行生成的引用又不能视为可信事实。

Spring AI 提供跨厂商模型接口、同步与流式 `ChatClient`、顾问链和观测能力，
但不会自动提供本平台的租户权限、索引版本、引用真实性和计量幂等语义。
研究依据见 `docs/research/WP-0005-spring-ai-runtime.md`。

## 决策

### 控制面聚合

1. `ProviderConnection` 属于模型目录与运行时上下文，字段至少固定：
   - 租户、厂商类型、显示名称、端点、区域和认证类型。
   - 密钥引用、网络策略、配置修订、探测状态和最近探测事实。
   - 状态为 `DRAFT`、`VERIFIED`、`DISABLED`；只有最新修订可继续修改。
2. 数据库和事件只保存密钥引用。密钥值仅在一次模型对象构造或探测期间存在，
   使用后立即关闭，禁止进入返回值、异常、日志、指标和缓存键。
3. `ModelDeployment` 属于同一上下文，字段至少固定：
   - 供应商连接标识与修订、模型代码、模型类型、显示名称。
   - 显式能力、上下文和输出上限、便携选项、厂商选项模式版本。
   - 嵌入维度、配置修订、探测状态和发布状态。
4. 模型能力来自探测并由管理员确认，不根据厂商类型或模型名称推断。
   M1 的模型类型只包括 `CHAT` 和 `EMBEDDING`。
5. 发布模型部署会冻结其全部配置。修改已发布部署必须创建新修订；
   旧修订继续服务已发布助手和索引，不能原地改变。

### 模型运行时

6. 模型运行时公开框架无关的 `ChatModelPort`、`EmbeddingModelPort` 和流式事件契约。
   每种模型类型使用独立工厂，禁止巨型供应商适配器。
7. Spring AI 模型对象和 `ChatClient` 按
   `租户 + 供应商连接修订 + 模型部署修订 + 模型类型`
   缓存。缓存必须有最大容量和空闲过期时间；配置发布或禁用时定向淘汰。
8. 缓存值是可重建基础设施对象，不是业务事实。构造失败不能缓存为永久失败，
   也不能改变已发布配置状态。
9. M1 提供确定性、OpenAI Compatible 和 Ollama 的对话与嵌入实现。
   默认容器使用确定性实现；真实厂商测试由显式环境开关和密钥引用启用。
10. 便携参数先经过平台上限和能力校验，再由适配器转换为 Spring AI 选项。
    厂商专属参数使用版本化模式、白名单和范围校验，禁止任意映射透传。
11. M1 显式关闭 Spring AI 自动工具执行。提示词和回答正文的观测开关保持关闭；
    只记录模型部署修订、调用类型、状态、令牌、耗时和稳定错误分类。

### 助手版本

12. `Assistant` 是可编辑身份和版本容器；`AssistantVersion` 是不可变发布快照。
13. 助手版本固定：
    - 助手、租户和版本号。
    - 已发布对话部署及其修订。
    - 知识空间和发布时活动索引版本。
    - 系统指令、生成限制、引用策略和拒答策略。
    - 配置摘要、状态和发布时间。
14. 只有 `DRAFT` 版本可编辑。发布后只能新建下一版本，
    查询只接受 `PUBLISHED` 版本。
15. 发布时在单一数据库事务内验证模型部署、知识空间和索引均属于当前租户且可用，
    并使用乐观修订防止并发发布覆盖。

### 查询任务与固定流水线

16. `QueryRun` 在接受时冻结租户、操作者、助手版本、模型部署修订、索引版本、
    原始问题摘要、状态、幂等键和配额占用事实。
17. 查询应用服务固定按以下顺序执行：

    `可信上下文 -> 配额 -> 策略 -> 助手版本解析 -> 活动索引校验
    -> 候选检索 -> 证据再鉴权 -> 安全提示构造 -> 模型生成
    -> 引用校验 -> 查询事实与计量`

18. 可信上下文、配额、权限、索引解析、证据再鉴权、引用校验和计量由平台应用服务
    显式执行，不隐藏在 Spring AI 顾问中。
19. Spring AI 顾问只承担提示构造、安全生成约束和调用观测。
    顾问顺序是代码常量并由架构测试校验，页面不能增删、拖动或覆盖。
20. 同步和流式调用复用同一查询计划和验证规则。
    流式文本在引用验证完成前属于暂定内容；最终完成事件只发布已验证答案。

### 引用与事件事实

21. 候选证据由平台分配本次查询内稳定编号，并包含不可伪造的内部证据标识。
    模型只能返回证据编号，不能直接创建可信网址、文档名或分块标识。
22. 引用验证必须确认每个编号都来自本次候选，且证据仍属于可信租户、知识空间、
    冻结索引和当前授权范围。
23. 以下情况必须产生稳定拒答，不展示未经证明的回答：
    - 没有授权证据或证据低于策略阈值。
    - 模型引用未知、越权或已失效证据。
    - 策略要求引用但回答没有引用。
    - 模型输出无法解析或验证。
24. `QueryRunEvent` 是持久化事实，序号在单个查询内从 1 单调递增。
    事件类型至少包含接受、检索、生成、拒答、失败和完成。
25. 完成、拒答、失败和计量均采用数据库唯一约束保证只写一次。
    服务端事件流支持按最后事件序号续传，不重新执行已完成查询。
26. M1 不把逐令牌内容作为可恢复业务事实；只发送受控进度事件和一个最终已验证答案。
    后续若需逐令牌恢复，必须另立事件保留、内容保护和背压决策。

## 主要备选方案及拒绝原因

### 每个租户在启动配置中注册一组 Spring AI Bean

拒绝。租户和部署是运行时数据，数量和修订持续变化；全局 Bean 会造成启动耦合、
配置泄漏和无法定向失效。

### 直接把 Spring AI 类型作为领域和接口契约

拒绝。厂商选项、顾问、响应和流式类型会扩散到控制器及领域，
使适配器变化成为全系统变化。

### 完全依赖 Spring AI 原生检索顾问

拒绝。原生顾问无法拥有本项目的可信会话、活动索引版本、证据再鉴权和引用事实，
也不能替代已建立的授权候选检索。

### 允许页面编辑顾问链顺序

拒绝。顺序会改变权限、检索和安全语义，无法形成稳定验收基线。

### 发布助手时只保存模型和知识空间的当前引用

拒绝。后续配置或活动索引变化会使同一助手版本产生不同结果，无法审计和复现。

### 把模型生成的链接直接展示为引用

拒绝。模型可以幻觉或篡改链接；可信引用必须映射到本次已授权候选证据。

### 先流式展示全部文本，结束后再删除不合格引用

拒绝。用户已经看到的越权或不可信内容无法撤回。M1 只在验证后发布最终答案。

## 后果与后续证据

- 模型目录与运行时上下文新增供应商连接、模型部署、工厂和缓存边界。
- 助手与交付上下文新增助手及不可变版本；可信查询上下文新增查询任务和事件事实。
- OpenAI Compatible 与 Ollama 必须通过同一合同、端点策略、密钥和脱敏测试。
- WP-0005 必须提供跨租户、未发布、无权限、超额、未知引用、无引用、模型异常、
  幂等重试和事件续传反例。
- 确定性演示证据只证明闭环，不得在评测或产品材料中表述为真实模型准确率。
- 多模型路由、工具调用、逐令牌可恢复流和真实模型质量进入后续独立决策。
