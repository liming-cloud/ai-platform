# ADR-0019：查询感知的候选扩召回与混合重排

## 状态

已接受

## 日期

2026-07-27

## 决策负责人

后端负责人依据已批准的 WP-0006 验收目标实施，并以固定评测集和容器证据验收。

## 背景与问题

M1 使用确定性字符片段嵌入，只用于证明权限、索引、检索和引用闭环，不代表真实
语义模型质量。固定评测发现，字段型比较问题“最近 30 天卖得最多的是哪件商品”
在向量前五名中混入数据说明和服务说明，三个待比较商品只有一个进入证据。

把助手检索条数直接调大可以覆盖目标记录，但会把更多无关内容交给生成模型并增加
无效引用。只改演示数据或降低评测阈值则会掩盖真实召回缺陷。

## 决策

1. 可信查询在现有租户、知识空间、冻结索引、嵌入部署和修订过滤内扩大候选池，
   候选池数量为助手检索条数的四倍，且不超过 100 条。
2. 候选池仍由 pgvector 精确余弦检索产生，扩召回不能放宽任何租户、权限、索引
   版本或模型修订条件。
3. 应用层使用查询感知的混合相关性对候选池重排：
   - 向量相关性从 `[-1, 1]` 归一化到 `[0, 1]`。
   - 字面相关性使用 Unicode 规范化后的字符二元片段覆盖率。
   - 混合分数固定为向量相关性 `0.55` 加字面相关性 `0.45`。
4. 最低分数应用于混合相关性，最终只保留助手版本冻结的检索条数。
   引用中的分数记录本次选择实际使用的混合相关性，便于解释和复现。
5. 排序必须确定：先按混合相关性降序，再按原始向量候选顺序升序。
6. 选择器只接收已经完成租户过滤和授权的候选，不能自行访问数据库、模型、会话
   或跨上下文资源。
7. 该实现是 M1 的可复现基线，不宣称代替生产重排模型。M4 引入 `RerankPort`
   时必须以同一固定评测集比较质量、延迟和降级行为，再决定是否替换。
8. 结构化数据的全量聚合、排序和数值比较仍由后续受控查询 DSL 实现；本决策不允许
   大语言模型生成或执行任意 SQL。

## 备选方案及拒绝原因

### 把助手检索条数提高到全部文档

拒绝。它会提高目标召回，但同时扩大无关证据、提示长度和引用噪声。

### 只优化确定性嵌入中的演示问题同义词

拒绝。针对固定问题写入同义词会形成不可推广的用例特判，无法说明真实产品行为。

### 在向量存储端增加查询文本

暂不采用。它会修改知识上下文公开检索契约和存储适配器合同。M1 可在可信查询内部
完成有限候选重排，后续若引入数据库全文索引再单独决策。

## 后果与验收

- 单次查询最多读取 100 个已授权向量候选，性能验收必须覆盖扩大候选池后的延迟。
- `minimumScore` 的含义变为本次证据选择的混合相关性，不再等同于原始余弦分数。
- 必须新增单元测试证明候选池上限、比较问题多记录召回、最终条数限制和严格阈值拒答。
- WP-0006 固定评测必须达到目标命中、引用完整、答案要点和预期拒答全部通过，
  跨租户记录命中保持为零。
