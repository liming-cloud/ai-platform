# ADR-0086：租户登录策略独立保存与执行

## 状态

已接受。2026-09-28。依据已接受的 ADR-0048、ADR-0079、WP-0017 和 OpenDesign 固定提交 `21b45c347a4008f5959b1b972e3ffd8a5aadcc6f`；本决策把既定产品值落到生产登录与保存边界，不改变平台登录策略。

## 问题

原型的“登录安全”页可查看并独立编辑三项值，但当前生产租户会话使用部署级固定时长，也没有每租户失败观察与锁定事实。只保存页面数值会造成虚假安全控制。平台登录不属于租户设置，不能被目标租户策略改变。

## 决定

1. `organization-access` 拥有每租户一份策略：`sessionHours` 为 1～24 的整数、初始 8；`failedAttempts` 为 3～10 的整数、初始 5；`lockMinutes` 为 5～60 的整数、初始 15。失败观察窗口固定为首次失败起 15 分钟；窗口过期重新计数。隔离、权限检查、密码不回显、CSRF 和平台范围会话不可配置。迁移显式回填现有租户，新租户开户同事务写入；缺失或损坏的策略失败关闭，不能凭原型或部署默认值补成功。
2. 平台治理会话经 `GET/PUT /api/v1/platform/tenants/{tenantId}/security` 读取和完整替换三项设置。`PUT` 只接受三项整数与非负 `expectedVersion`，拒绝未知、缺失、越界或类型错误。只有实际变更递增目标租户版本；旧版本冲突拒绝，取消零写入，刷新重读服务端事实。无权请求在读取任何租户事实之前拒绝。
3. 统一浏览器租户登录及既有租户口令登录均执行同一策略。只对已存在且启用的目标租户成员资格计数，以租户和主体为键；平台登录、未知身份及错误租户目标不写入锁定事实。达到阈值后，即使密码正确也在锁定时长内拒绝；锁定结束后正确登录清除失败计数。错误口令、被锁定及无效身份使用同一通用认证失败响应，不向客户端暴露主体存在性。状态事实仅保存标识、次数和时间，不保存口令、摘要或令牌。
4. 租户会话签发使用该租户当前 `sessionHours` 作为绝对有效期；平台会话保持部署级独立配置。成功改变策略时立即撤销目标租户所有已签发的租户范围会话，不撤销平台会话或其他租户会话。撤销失败使配置写入回滚，不能报告成功。浏览器能力清单的有效期提示与对应实际范围会话相符。
5. 生产页沿用固定原型的独立路由、三项顺序、值单位、摘要、弹窗、取消/保存、反馈及响应式结构。按 ADR-0079，保存前明确提示目标租户旧会话会立即失效；这一安全提示不改变三项原型值或安全底线。原型的合成存储和模拟认证不进入生产，截图只存 `/private/tmp`。

## 实施与验证

先以失败测试固定范围、并发版本、两种租户登录、固定观察窗口、锁定与解锁、每租户绝对会话时长、撤销失败回滚、跨租户和平台隔离。失败计数由 PostgreSQL 的行锁保护；这条原子计数使用基础设施 SQL，普通配置单表读写继续使用 MyBatis-Plus。受控 Compose 的实际浏览器、真实 PostgreSQL/Redis、只读数据库事实、三尺寸固定原型对照和登录回归均通过后，才关闭 `platform-tenant-security:0`。本决策不完成 WP-0017 整包或 M6。
