# ADR-0033：登录状态必须由令牌恢复

## 状态

已接受

## 日期

2026-07-30

## 决策负责人

产品与架构负责人

## 背景和难以逆转的约束

可信 RAG 平台以 `TrustedRequestContext` 表示一次已认证请求的登录状态。该上下文包含租户、主体、成员、凭据类型、访问渠道、权限版本和权限集合；它决定资源归属、租户隔离和授权结果，不能由调用方选择。

当前 `SaTokenSessionGateway` 将这些事实保存到服务端 Sa-Token 会话，并只在校验通过的令牌上恢复；`SaTokenTrustedContextArgumentResolver` 仅从 `Authorization: Bearer` 读取令牌，向控制器提供可信上下文，同时在服务端生成追踪标识。若把同类字段放入路径、查询参数、请求体、表单、Header 或应用命令中，调用方可能伪造归属或造成令牌与参数不一致，且会让后续接口难以收回该安全债务。

## 决策内容

- 登录状态只由已校验令牌恢复为 `TrustedRequestContext`。租户、主体、成员、凭据类型、访问渠道、权限版本和权限集合不得作为公共 HTTP 接口参数，也不得由前端、SDK、事件负载或应用命令传入。
- HTTP 控制器只把框架注入的 `TrustedRequestContext` 传给应用层；应用层据此执行权限、租户与资源归属校验。公共请求对象只能包含业务目标和业务数据，不能声明或透传上述登录状态字段。
- 受认证保护的接口只接受 `Authorization: Bearer` 中的访问令牌。访问令牌不得作为路径、查询参数、请求体、表单字段或业务命令处理，也不得写入日志、审计摘要、错误响应或读取投影。
- 资源标识、乐观版本、筛选条件和业务内容仍可作为接口参数，但必须在令牌恢复的可信上下文范围内加载与授权；它们不是登录状态，也不能替代租户、主体或成员身份。
- 缺失、无效、过期或会话事实不完整的令牌必须失败关闭。不得以请求中的身份、租户、权限、渠道或自定义 Header 作为回退来源；服务端追踪标识同样不得接受调用方输入。
- 后续新增或修改公共接口时，自动和 HTTP 回归必须证明：伪造的登录状态字段不会参与鉴权或租户归属；有效令牌对应的可信上下文是唯一授权依据。已有接口若发现这类字段，须在所属工作包中删除并补齐回归，不能以兼容参数或 allowlist 保留。

## 主要备选方案及拒绝原因

### 方案 A：由令牌恢复全部登录状态

接受。令牌会话是单一可信来源，身份、归属和权限可在同一边界校验，并能保持应用命令与业务输入无关。

### 方案 B：令牌与请求参数共同决定租户或主体

拒绝。两个来源会产生不一致和越权歧义；即使比较两者是否相等，也会把可伪造字段扩散为公共契约。

### 方案 C：通过自定义 Header 传递登录状态

拒绝。自定义 Header 仍由调用方控制，不能替代经过校验的令牌会话；它还会使网关、SDK 和审计边界出现多套身份协议。

## 后果和后续证据

本 ADR 约束 WP-0011 及后续工作包的所有受认证接口、应用命令和跨上下文契约。它不改变登录接口提交凭据以换取令牌的语义，也不改变业务资源参数；它只禁止把登录结果再次作为业务接口输入。

WP-0011 后续安全回归须覆盖受认证数据源接口的伪造租户、主体、成员、权限与渠道字段，并记录令牌上下文为唯一授权来源的证据。该 ADR 不接受 ADR-0032，也不表示 M3 已完成或可以进入 M4。
