# ADR-0059：统一企业控制台、服务端分页与注意力保护

## 状态

已接受。

## 日期

2026-08-09

## 决策负责人

用户，代表产品、前端、架构、安全、可访问性与平台运营负责人。

## 背景和难以逆转的约束

ADR-0027 将企业控制台和问答工作台设计为两个浏览器应用，ADR-0048 通过同源 HttpOnly 双范围会话解决了重复登录与跨页签身份问题。但是当前 `ConsoleApp` 仍使用本地状态切换静态导航，查询使用独立应用跳转；资源页面存在把多个技术任务、长表单和结果同时放在主页面的倾向。虽然后端共享 `PageQuery`／`PageResult`，前端客户端也声明分页字段，页面仍缺少统一分页控制和 URL 可恢复状态。

企业管理员需要在高密度资源中持续作出有风险的决定。把全部数据、全部表单和全部操作平铺在一个页面，会制造无关刺激、滚动迷失和误操作；把数据全部载入浏览器再切片则破坏性能、权限重验和服务器权威事实。

## 决策内容

选择方案 A：人员浏览器产品收敛为一个统一企业 SPA；全部普通资源集合使用标准前后端分页；页面以列表、详情和受控弹层渐进披露，保护操作人员注意力。

1. `console-web` 成为人员浏览器产品的唯一 SPA 和唯一根路由，统一承载平台管理、租户管理与可信问答；问答作为 `/ask` 路由进入同一产品外壳。现有 `query-web` 在迁移完成后退役，不再拥有独立登录、会话、导航或产品壳。设备问答界面仍按 ADR-0027 在 M7 保持独立，SDK/API 仍不是浏览器门户。
2. 路由和选定工作区是可恢复产品状态。浏览器刷新、深链接和前进后退必须恢复页面、筛选、排序和页码；不得以 `useState`、页签内存或 `window.location.assign` 作为主要导航事实。
3. 所有普通资源列表必须使用后端 `PageQuery` 与 `PageResult` 语义：页码从 1 开始，默认每页 20，最大每页 100，并返回总数、总页数和前后页事实。筛选、排序和页码由前端提交给服务器并写入 URL；禁止一次读取全部记录后在浏览器分页。
4. 事件序号、向量候选、任务批次和明确不需要总数的流式协议继续使用各自既有合同，不强行伪装为页码分页。任何例外必须能指出业务语义和已接受契约，不能以“数据暂时较少”为理由绕过分页。
5. 列表页只展示识别、状态、所有者、最近变化、关键风险和行操作所需的摘要列。完整配置、历史、审计和诊断进入详情页、详情抽屉或按需加载区域；禁止把对象全部字段、所有历史记录或所有子资源连续平铺在主页面。
6. 简短创建和编辑任务使用 Fluent UI `Dialog` 或 `Drawer`：单一对象、单一提交、字段组不超过页面复杂度预算，且关闭后能够安全回到原列表上下文。需要探测、预览、影响检查、多个步骤或可独立分享 URL 的流程使用独立路由，不把完整发布流程塞进弹窗。
7. 高风险操作必须使用 `Dialog` 说明对象、影响、不可逆结果、恢复方式和审计责任。抽屉用于补充详情或上下文编辑，不承载必须独立成页的长期流程。禁止嵌套弹窗；任一时刻只能有一个主模态任务。
8. 弹层打开后背景内容必须不可交互，初始焦点进入标题或首个错误字段，关闭后焦点回到触发点。支持键盘、读屏、200% 缩放和减少动态效果；不能用 Toast 承载需要用户决策或后续处理的失败。
9. 每页只承担一个主要任务，页头最多一个主操作。常用筛选常驻，高级筛选进入弹层；每行最多两个常用操作，其余进入菜单。批量操作必须明确是否跨页、实际选择范围和不可处理项，不能默认作用于未加载页面。
10. 每个分页资源页面必须覆盖骨架加载、首次为空、筛选无结果、错误、无权限、数据过期、冲突和部分成功状态。写入成功后以服务器重读更新列表和详情，不把本地乐观对象当作最终业务事实。
11. 导航只消费 ADR-0057 定义的能力投影。无权菜单和操作从界面移除，直接 URL 与 API 仍由后端失败关闭。菜单、权限和页面状态不能各自维护互相冲突的身份事实。

## 主要备选方案及拒绝原因

### 方案 A：单一 SPA、服务器分页与渐进披露

接受。一个路由树、一套会话、一套服务器状态和一套 Fluent UI 交互语言能够保持角色任务连续；分页、详情和弹层把复杂度限制在当前决策所需范围内。

### 方案 B：保持多个人员 SPA，只共享登录 cookie

拒绝。它解决凭据复用但保留导航、路由、错误、工作区和设计状态分裂；跨应用跳转仍打断任务，并迫使公共能力在多个客户端重复。

### 方案 C：一次加载全部数据并使用前端分页或无限滚动

拒绝。它不能保证总数、并发更新、权限变化和大数据量性能，也会把未查看数据扩大到浏览器内存。企业资源管理需要明确页码、范围和可恢复位置。

### 方案 D：所有创建和编辑都使用主页面内联长表单

拒绝。它会把浏览、筛选、详情和编辑同时暴露，增加误操作与认知负担。弹层与独立任务路由必须按任务复杂度分工。

## 后果和后续证据

- 本 ADR 在人员浏览器产品范围内部分取代 ADR-0027 的 `console-web`／`query-web` 双应用边界；设备界面和 SDK/API 渠道边界保持不变。
- 实施前先以路由、服务器状态、分页契约和迁移顺序设计卡证明不会丢失现有查询、CSRF、跨页签注销与失败关闭语义。
- 前端自动门禁必须拒绝普通资源列表的无分页 API、客户端全量切片、页面级大数组平铺、嵌套弹窗和没有加载／空／错／无权限状态的新增资源页。
- 角色浏览器验收至少覆盖：一次登录切换授权工作区、分页筛选深链接、创建弹层焦点恢复、复杂模型探测独立流程、直接 URL 无权限失败和写后服务器重读。
- 接受本 ADR 不表示 M6 完成，不授权 M7 设备界面、开发者门户或 M8 生产运营能力。
