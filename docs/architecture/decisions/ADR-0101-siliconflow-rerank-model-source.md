## 决定

1. 仅为硅基流动 RERANK 增加显式发现配置 `SILICONFLOW_RERANK_MODELS_API`。运行协议仍为 `VENDOR_POST_PROCESSOR`，`ProviderKind` 不新增品牌枚举；其他 NONE 预设不变。新预设版本与配置必须成对校验，不按地址或模型名称隐式选适配器。该项细化 ADR-0070 的来源规则：真正 NONE 仍不伪造发现成功；硅基流动改用其实际存在的权威列表。
2. 读取目标固定为受控 `GET https://api.siliconflow.cn/v1/models?sub_type=reranker`，不由任意用户 Endpoint 裁剪推导。平台推理 Key 仅在出站校验后短期解析，结束后清零；不复用 AK/SK 或租户 Key。零自动重试、拒绝重定向、私网、超时和畸形／过大响应；失败使用稳定分类，不记录原始响应、认证材料或外部追踪 ID。
3. 当前账户列表必须包含精确 ID，才形成当前连接修订的候选。版本化受控映射为 `BAAI/bge-reranker-v2-m3` 声明 RERANK，使用 `CONFIRMED_BY_CONTROLLED_MAPPING`；映射缺失的真实列表项保留 `REQUIRES_ADMIN_CONFIRMATION`。分类声明不是能力验证，缺失显示名称保持未知，供应商编码只作选择值，不从名称猜测或静默丢弃候选。
4. 候选冻结精确连接修订、发现 ID／配置、模型 ID、分类、列表来源、映射版本／摘要、时间及失效时间。新增来源绑定必须可从正式候选和草稿输入恢复，先提供必要迁移与事务反例，不把来源塞进参数说明或普通投影中的技术秘密。既有来源事实不补写为新映射事实。
5. 保持平台写权限、当前发现／连接独立发布／创建草稿的顺序。成功列表只证明本账户列表可读，空列表不造模型；真实重排仍需独立 Port、三样本及预算验证和精确执行授权。读取成功不自动发布连接或部署，不授予租户可用供应。
6. 预设版本递增，新增连接显式选择新组合。已有 NONE 连接不自动升级、回填候选或改历史；若后续需要改用新配置，必须显式修订并递增连接版本，使旧发现、确认和验证失效，并单独核对对象操作授权。本轮不对已有数据操作。
7. 轮换、来源／映射变化、过期、失败和停用阻断新使用。真实提交必须复核精确来源、并发与迟到结果，审计失败回滚；不保留旧候选冒充本次成功。扩展仅依赖公开 port/out 与 facade，无反向上下文依赖。

## 比较与实施门禁

受控静态目录本身不能证明账户级可用性，仍需要单独的 NONE 连接验证／发布合同；本次选择已有官方只读列表，复用平台现有供应顺序。拒绝自由模型编码绕过来源，也不把通用 OpenAI 列表配置偷换为重排协议。
