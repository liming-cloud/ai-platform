# ADR-0065：平台模型目录管理与已发布部署快照绑定

## 状态

已接受。

## 日期

2026-08-12

## 决策负责人

用户，代表产品、架构、安全、平台与租户运营负责人。

## 背景和约束

ADR-0058 规定平台受控模型目录必须由平台模型管理员维护，且租户模型配置只能引用已发布目录与已验证部署能力。
现有实现已具备受控目录领域、HTTP 入口、租户连接、发现和部署，但没有可分配的
`model-platform:write` 权限来源；目录创建请求还直接接收 Endpoint、模型编码和能力，不能证明它们来自
已发布部署。因此，当前浏览器可完成连接、发现、探测和发布部署，却不能安全地把该结果提供给租户配置。

当前 M6 只需要完成一个可信的本地供应链，不为多区域、灰度或多环境复用预设第二条目录路径。

## 决策内容

选择以下最小闭环：

1. 新增固定平台角色 `PLATFORM_ADMINISTRATOR`，它拥有
   `platform-session:access`、`platform:accounts:manage`、`tenant-governance:write` 与
   `model-platform:write`。原有账户管理员、租户治理员和运营员保持各自最小权限，不被扩权。
2. 平台管理员在统一 SPA 的独立目录任务中，只能从当前页已发布、健康且验证未到期的模型部署创建目录条目；
   浏览器不提交 Endpoint、厂商类型、模型编码或能力参数。
3. 目录条目持久化绑定一个 `PUBLISHED` 部署标识和部署修订，并冻结该部署的厂商类型、连接修订、模型编码、
   模型类型与实测能力。目录发布后不可原地修改；变更连接、模型或能力必须建立、探测并发布新部署，再建立新目录条目。
4. 目录创建与目录发布都在服务端重新验证部署状态、健康、验证有效期和修订。任一条件不满足时失败关闭；
   部署停用、连接修订漂移或验证过期后，关联目录条目不再可用于新模型配置或新运行时调用。
5. 租户模型配置选择器继续只读取已发布且当前可用的目录与已启用、已配置凭据的模型配置。它不读取平台连接、
   部署、Endpoint、凭据或探测原始结果。

## 备选方案及拒绝原因

### 方案 A：平台管理员维护部署快照目录

接受。它把平台模型治理职责统一放在一个可审计的固定角色，并使租户可选目录具有可验证的已发布部署来源。

### 方案 B：复用 `PLATFORM_ACCOUNT_ADMINISTRATOR` 维护目录

拒绝。账户生命周期与模型供应链是不同职责；把 `model-platform:write` 添加到账户管理员会扩大既有账户治理角色，
违反 ADR-0057 的最小权限边界。

### 方案 C：保留自由 Endpoint、模型编码和能力参数的目录表单

拒绝。它会重新引入 ADR-0058 已拒绝的自由 Endpoint、能力伪造和供应链断裂；数据库记录也不能证明目录来自真实探测。

### 方案 D：发布部署时自动生成目录条目

拒绝。部署发布与向所有租户开放可选模型是不同治理动作；自动公开会绕过平台管理员的明确目录发布和审计确认。

## 后果与验证

- 先以红绿测试证明只有 `PLATFORM_ADMINISTRATOR` 能管理目录，其他平台和租户角色均失败关闭，且角色变更撤销旧会话。
- 目录 API 必须仅接收已发布部署标识；伪造修订、草稿／停用／过期部署、跨租户部署和直接 Endpoint 参数必须拒绝。
- 数据库迁移必须保存部署绑定与冻结快照；读取查询只返回安全目录摘要，并保持服务端分页。
- 统一 SPA 必须提供平台管理员目录任务、部署选择分页、单一创建确认和目录发布确认；租户页面仍只显示可用配置与模型。
- 在当前本地 Compose 中完成平台管理员建立、连接、发现、部署探测、部署发布、目录建立／发布、模型配置启用、
  知识首份发布、PostgreSQL／MinIO／HTTP／浏览器回归。该决定不授权 M7、动态插件、自由 Endpoint、服务账户或生产环境例外。
