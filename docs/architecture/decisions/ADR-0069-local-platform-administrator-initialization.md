# ADR-0069：本地固定平台管理员初始化凭据

## 状态

已接受。

## 日期

2026-08-17

## 决策负责人

用户，代表本地研发与 M6 人工验收负责人。

## 背景

ADR-0063 要求本地基线只初始化一个平台超级管理员，ADR-0067 又将该角色收敛为
`PLATFORM_ADMINISTRATOR`。现有实现只保留了数据库中的密码摘要，仓库没有可发现的本地登录口令；
明文无法从 PBKDF2 摘要恢复，导致每次需要人工登录时都依赖聊天记录或一次性数据库修复。

ADR-0064 原本明确本地 repeatable migration 不写入账户、角色或凭据。用户现确认产品仍处于纯本地研发、
没有历史迁移包袱，并要求固定且容易使用的平台管理员初始化密码，因此必须显式调整该边界，而不能通过
临时 SQL 或未记录的口令继续绕过初始化契约。

## 决策内容

1. `local` profile 的空库初始化同时建立唯一活动账户 `platform.root`、活动
   `PLATFORM_ADMINISTRATOR` 绑定和平台授权修订事实。
2. 固定本地登录密码为 `admin123456`。它是公开的本地演示凭据，不是秘密，不得用于共享、测试、预发布、
   生产或任何真实数据环境；可发现值登记在 `deploy/compose/.env.example`。
3. 数据库只保存由现有 `Pbkdf2PasswordAdapter` 契约生成的 `pbkdf2-sha256` 摘要，不保存明文。初始化 SQL、
   登录日志、HTTP 响应、Cookie 和证据文件不得输出摘要或会话材料。
4. 初始化必须在同一 Flyway 事务内写入主体、授权修订和角色绑定；只有主体、租户及成员均为空时才执行。
   任一事实已存在时不得自动覆盖、补写或重置密码。
5. 默认、`demo`、测试、共享、预发布和生产 profile 不扫描 `db/local/organization-access`，继续不拥有固定
   平台账户或固定密码。
6. 当前本地 Compose 数据库已经存在唯一 `platform.root`，本次授权一次性把其摘要更新为同一固定口令并
   推进账户修订；该操作不是可移植迁移，不得写入正式 migration。

## 取代关系

本 ADR 只在 `local` 空库初始化账户、授权与角色方面取代 ADR-0064 第 2 条，并把 ADR-0063 的“受控种子”
具体化。ADR-0061 的 PBKDF2、会话撤销与非自助重置边界，以及 ADR-0048 对真实环境凭据不得进入版本库的
要求继续有效；`admin123456` 被明确分类为不可用于真实环境的公开开发默认值。

## 后果与验证

- 先以真实 PostgreSQL 红灯证明 local migration 尚未建立三项身份事实，再实现最小 SQL 并用现有密码
  校验器验证固定口令。
- 证明标准 migration 不建立账户，已有租户或主体的数据库不会被 local migration 改写。
- 当前 Compose 更新后，以真实 HTTP 和 Chrome 登录验证 `platform.root`，同时确认租户、成员、模型、知识、
  助手和查询仍为零。
- 本决策不授权弱化生产密码策略、返回密码、保存真实凭据、进入 M7 或把本地公开口令用于任何其他环境。
