# ADR-0038：查询诊断最小事实投影

## 状态

已接受

## 日期

2026-07-30

## 决策负责人

用户，代表产品与架构负责人。

## 背景和难以逆转的约束

ADR-0036 要求受权 `QueryDiagnostic` 从 `QueryRun` 及其受控事件派生，并仅向 `audit:read` 人员展示候选数、权限决定、模型修订、引用校验和用量。当前 `QueryRun` 及其重放事件只保存运行终态、最小引用、拒答原因和用量；候选数、授权结论与模型修订没有被保存。现有运营审计投影也只读取摘要、终态和用量。

若直接在诊断读取时重新检索或重新解析当前助手版本，会把历史诊断替换为当前状态，且可能触发模型、检索或资源读取。若把内部诊断字段加入终端用户的 `QueryRunEvent`，则会破坏 ADR-0016／ADR-0017 的最小事件和未授权信息边界。若输出猜测值，审计结论将不可复核。

## 决策内容

1. trusted-query 在 `QueryRun` 进入终态时写入一条内部 `QueryDiagnosticFact` 投影事实。它不是领域实体、聚合根或公开事件，也不参与查询配额、幂等、运营汇总或最终用户读取。
2. 事实以 `(tenant_id, query_run_id)` 唯一关联运行，包含：经受权候选检索得到的候选数量、固定枚举 `AUTHORIZED` 的检索授权结论、聊天与嵌入部署修订号、固定枚举的引用校验结论和创建时间。终态的令牌用量直接从 `QueryRun` 读取，不能重复写入。不得保存候选正文、候选或知识资源标识、问题、回答、提示词、对象位置、原始权限集合、供应商错误、密钥或令牌。
3. `ANSWERED` 运行必须记录 `VALIDATED` 引用结论；`REFUSED` 与 `FAILED` 只能记录 `NOT_APPLICABLE`。只有已通过普通查询权限、已占用配额且已创建 `QueryRun` 的请求可以拥有诊断事实；权限拒绝且没有运行记录的请求不创建诊断。
4. `QueryRun` 终态、最小引用和诊断事实在同一数据库事务中写入；任何一项失败都不得留下半成品。删除 `QueryRun` 时，诊断事实使用外键 `ON DELETE CASCADE` 删除。
5. `QueryDiagnostic` 是只读应用投影。`GET /api/v1/query-runs/{queryRunId}/diagnostic` 仅允许当前租户的 `audit:read` 角色访问；缺失、跨租户或无权限统一失败关闭，不泄漏运行是否存在。它不在普通查询事件、最终用户问答接口或 M4 外部渠道中出现。

## 主要备选方案及拒绝原因

### 方案 A：诊断读取时重新执行检索或读取当前助手版本

拒绝。历史运行与当前索引、权限和模型修订可能不同，会让诊断不可复核，并增加不必要的外部 I/O 与泄漏面。

### 方案 B：把诊断字段加入 `QueryRunEvent`

拒绝。事件面向最终用户恢复，增加候选、策略和模型内部信息会破坏最小披露边界。

### 方案 C：在诊断页面推断或填充缺失值

拒绝。当前事实不足以得出候选数、授权结论或模型修订；猜测结果不能作为审计证据。

## 后果和后续证据

- WP-0012 在接受后先写红灯，证明不允许用现有运行／事件伪造诊断事实、错误终态引用结论和无 `audit:read` 访问。
- 随后补真实 PostgreSQL 原子终态、级联保留、自动配置和 HTTP 回归，证明诊断没有正文、资源标识、密钥或令牌字段。
- 本决策不改变 ADR-0036 的草稿测试、反馈、配额、普通查询事件或 M5 至 M8 范围；未接受前不得创建诊断事实表、读取接口或改变查询完成协议。
