# ADR-0074：M6 可信 RAG 产品与研发基线重建

## 状态

已接受

## 日期

2026-09-02

## 背景

M6 已形成四层依赖、版本化索引、受控模型配置和三角色治理基础，但产品主路径仍存在同步生成伪流式、一次性问答、普通用户入口缺失、旧新实现并行、文档恢复上下文失控和决策索引漂移。AssistantVersion、QueryRunService 与 IndexVersion 的影响面较大，不能通过全仓重写恢复一致性。

## 决策

1. WP-0014 只作为 M6 总控与人工评审门禁；WP-0015 至 WP-0020 按控制面、原型、知识接入、检索、问答、质量的顺序形成连续闭环。currentFrontier 每次只指向一个子工作包。
2. STATE.yaml 的 latestEvidence 最多保留 8 条；当前前沿最多引用 12 个 ADR；DECISIONS.md 从 ADR 元数据生成并校验；resume-context 输出不得超过 12 KiB。
3. 生产前端暂停扩张。WP-0016 必须先用锁定版本的 OpenDesign 完成关键流程高保真原型并经人工确认，后续工作包才能逐闭环修改生产前端。
4. 普通用户沿用同一 SPA 和浏览器会话基础，新增 QUERY_APP 渠道与 /app/login、/app/assistants、/app/conversations/:conversationId。该入口替代 ADR-0059 中仅以 /ask 承载问答的临时形态，不改变统一 SPA 和服务端权威授权原则。
5. 小型试点默认限制为每租户 3 个知识库、每知识库 1,000 个有效文档与 10 GB 原始内容、单文件 50 MB、粘贴文本 1 MiB；配额必须由服务端原子预留。
6. 稳定 Assistant 永久绑定一个知识库；AssistantVersion 冻结 IndexVersion、Chat、Embedding、Rerank、检索、引用和拒答策略。会话创建时固定已发布版本，旧会话不随新版本漂移。
7. 首版不建设独立会话记忆库或用户长期记忆。模型上下文最多使用最近 6 个已完成轮次且不超过 3,000 tokens 做独立问题改写，超出部分使用有版本、可重建的摘要。
8. Embedding 模型、维度、距离度量、解析器或分块策略变化时创建新的非活动 IndexVersion；Chat 或 Rerank 变化只创建新的 AssistantVersion。任何新索引必须经评测和授权后原子激活。
9. 标准 Chat 和 Embedding 调用只经内部 Port，由 Spring AI 的 OpenAI-compatible 实现适配。Rerank 使用最小 RerankerPort 接入检索后处理 seam。供应商发现、控制面和非标准多模态 HTTP 只允许位于 infrastructure，并受域名、超时、重试、脱敏和 SSRF 约束。
10. 问答提交快速返回 QueryRun，真实生成通过 TOKEN_DELTA 增量事件持久化并支持 Last-Event-ID 恢复；不得继续把同步生成结果包装成 SSE 回放。
11. Java 只使用仓库 release 对应的正式 JDK 特性。领域值对象优先使用 record；Lombok 仅用于基础设施、配置和测试样板，禁止以 Data、公共 Setter 或 builder 绕过领域不变量。
12. 触及的上下文必须先清理旧新并行分支、可空依赖、兼容构造器、Java 内联 SQL、手工分页和框架泄漏，再新增能力。未触及债务只登记责任工作包和退出条件。

## 影响

- WP-0015 只恢复控制面与架构基线，不实施新产品能力。
- WP-0016 只产出可丢弃原型、设计令牌、夹具和截图；人工确认前不得修改生产前端。
- 多格式解析、索引激活、会话模型、真实流式事件和成员级授权必须分别在后续 ADR 中冻结公共契约、状态机和失败语义。
- ADR-0059 的统一 SPA、服务端权威能力投影和登录安全边界继续有效；一次性 /ask 只作为待迁移遗留入口，不再作为目标产品契约。

## 备选方案

### 方案 A：继续在 WP-0014 内逐问题修补

拒绝。工作包和恢复上下文已经失去边界，会继续放大任务中断和事实漂移。

### 方案 B：全仓重写 RAG 与前端

拒绝。关键类型影响面达到数百符号，既有四层门禁、版本化索引和 Spring AI 适配仍有价值，大爆炸重写无法提供可审计的迁移证据。

### 方案 C：按连续闭环工作包重建基线

接受。每包只有一个用户或工程闭环，先测试、再实现、再登记证据和提交，并以人工原型确认阻止前端返工。
