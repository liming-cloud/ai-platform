# ADR-0013：知识空间租户、幂等和配额事务边界

## 状态

已接受

## 背景

WP-0003 需要提供知识空间创建和列表公共接口。知识空间是数据源、索引版本和助手授权的上游边界，若租户来自请求参数、权限只在页面或控制器校验，或者幂等、配额和插入分属不同事务，将产生跨租户访问、重复资源和并发突破演示配额的问题。

## 决策

1. 知识空间属于且只属于一个租户。租户标识只从服务端恢复的 `TrustedRequestContext` 取得，公共请求体、查询参数和路径不接受租户标识。
2. 创建和列表用例接收可信请求上下文，并在应用层分别校验 `knowledge:write` 和 `knowledge:read`；控制器或前端的权限展示不能替代用例授权。
3. 知识空间领域模型只依赖 JDK 和平台内核值类型，不依赖 Spring、Sa-Token、MyBatis-Plus、Hutool 或 Web 类型。
4. 创建接口必须提供 `Idempotency-Key`。服务端只持久化键的 SHA-256 摘要和规范化请求指纹，不保存原始键。
5. 同一租户、同一幂等键和同一请求重复提交时返回同一知识空间；同一键对应不同请求时失败，不创建第二个资源。
6. 单租户配额检查、知识空间插入和幂等结果登记必须处于同一 PostgreSQL 事务。适配器使用租户级事务锁串行化同一租户的创建竞争，不能依赖应用进程内锁。
7. 演示环境默认最多创建 3 个未删除知识空间。配额是运行时配置，但不得由调用方覆盖。
8. 持久化表的唯一约束和查询条件必须显式包含 `tenant_id`。知识空间名称在同一租户内唯一，不要求跨租户唯一。
9. 列表按 `created_at`、`id` 的稳定顺序使用不透明游标分页；禁止使用无限制全量列表或偏移分页作为公共契约。
10. 未登录、权限不足、跨租户探测、幂等冲突和配额超限使用稳定错误码，错误内容不泄漏其他租户资源是否存在。

## 公共契约

- `POST /api/v1/knowledge-spaces`
  - 请求头：`Authorization`、`Idempotency-Key`
  - 请求体：名称、可选说明
  - 响应：知识空间标识、名称、说明、状态、版本和创建时间
- `GET /api/v1/knowledge-spaces`
  - 请求头：`Authorization`
  - 查询：可选不透明游标和受上限约束的条数
  - 响应：当前租户可见的知识空间和下一页游标

## 影响

- `knowledge-data` 可以依赖 `organization-access` 的公开认证契约，但不能访问其应用内部或适配器包。
- 控制面需要统一的 Bearer 令牌解析和 `TrustedRequestContext` 参数解析器。
- PostgreSQL 持久化测试必须覆盖同键重放、同键异参、并发配额和两个租户同名资源。
- 本决策不包含数据源内容、MinIO 对象、分块、向量索引或查询权限过滤。
