# ADR-0045：历史租户生命周期状态的合法回填

## 状态

已接受

## 日期

2026-08-03

## 决策负责人

用户，代表产品、架构与安全负责人。

## 背景和难以逆转的约束

ADR-0041 将 `TenantLifecycle` 固定为 `PROVISIONING → ACTIVE → SUSPENDED → ACTIVE` 的
唯一合法状态机，且每次建立、激活、挂起或恢复都必须留存最小审计事实与版本化生命周期事件。
ADR-0044 要求历史回填不得改变既有租户会话语义，但历史
`organization_access.tenant.status` 只记录 `ENABLED` 或 `DISABLED`，没有生命周期根和状态迁移
事实。

若回填直接把历史状态写入 `TenantLifecycle.status`，会绕过聚合根状态机并伪造未发生的领域行为；
若一律停在 `PROVISIONING`，则会把原本已启用的租户降级，并违反 ADR-0044 的会话语义约束。

## 决策内容

选择严格方案 A：历史状态只决定回填操作的**最终目标状态**，不允许直接设置聚合状态。
每一条完整、有效的人工 `tenantId → SubjectId` 映射均在同一受控部署事务中执行以下合法领域操作：

| 历史 `tenant.status` | 合法领域操作序列 | 最终 `TenantLifecycle.status` | 最终修订 |
| --- | --- | --- | --- |
| `ENABLED` | `provision`、确认初始管理员成员资格、`activate` | `ACTIVE` | `1` |
| `DISABLED` | `provision`、确认初始管理员成员资格、`activate`、`suspend` | `SUSPENDED` | `2` |

`provision` 保留历史租户标识、编码、显示名称与创建时间；领域事件的发生时间是本次受控回填的
执行时间。每个上述合法操作都按 ADR-0041 写入最小审计事实和版本化生命周期事件。因此，已启用
历史租户会得到建立与激活事实；已禁用历史租户还会得到挂起事实。事件不含初始管理员主体、成员详情、
正文、令牌、密钥或供应商错误。

`TenantLifecycleBackfill` 是 organization-access 的无状态领域服务：它只接受已验证的历史租户事实、
人工确认的主体标识与回填时间，返回不可变操作结果。应用层只编排受控部署事务、加载事实、调用服务
并提交结果；基础设施只执行锁、映射、原子写入、发件箱和技术异常转译。映射本身仍不得进入版本库、
日志、令牌、HTTP 请求或应用配置。

未知历史状态、缺失或重复映射、跨租户主体、禁用主体、非成员主体、重复生命周期根、成员角色更新
失败或任一事件写入失败均使整个批次回滚；不得留下部分根、角色或事件。新租户继续使用
`TenantProvisioning`，不复用历史回填路径。

## 主要备选方案及拒绝原因

### 方案 A：以合法状态迁移达到与历史状态一致的最终状态

接受。它以状态机可证明的操作形成完整的回填审计轨迹，保留既有会话语义，并让历史与新建租户最终
遵循同一生命周期模型。

### 方案 B：全部回填为 `PROVISIONING`，由人工逐一激活

拒绝。它会让原本已启用的租户失去原有可用性，造成迁移期间的产品语义倒退；同时无法将历史
`DISABLED` 的语义映射到受治理状态。

### 方案 C：直接以历史状态构造 `ACTIVE` 或 `SUSPENDED` 根

拒绝。它绕过 `TenantLifecycle` 的合法转换和对应事件，令持久化状态无法证明其领域来源。

## 后果和后续证据

- 纯领域反例必须证明未知历史状态拒绝，且 `ENABLED` 只经 `PROVISIONING → ACTIVE`、`DISABLED`
  只经 `PROVISIONING → ACTIVE → SUSPENDED` 到达最终状态；不得存在直接状态注入入口。
- 真实 PostgreSQL 必须证明两种历史状态均在单一事务提交生命周期、初始管理员成员角色和完整最小事件
  序列；任何失败均无残留。
- 自动配置、平台 Bearer HTTP 与浏览器回归必须继续证明操作者只来自 `PlatformRequestContext`，历史映射
  不是公共登录状态参数。
- 接受本 ADR 不授权邀请、密码重置、销毁、正文读取、评测、发布审批或 M7／M8 实现。
