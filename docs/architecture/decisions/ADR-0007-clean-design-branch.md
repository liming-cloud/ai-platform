# ADR-0007：在设计分支清理旧实现

## 状态

已接受

## 背景

ADR-0001 已决定绿地重建，但原计划把旧源码清理放到 M0 之后。用户现已明确要求在继续补充前端设计前清理项目，避免旧后端、旧前端、旧部署和旧文档继续形成错误的事实来源。

旧实现仍可通过 Git 历史恢复，因此删除受版本控制的旧文件是可恢复操作。未受版本控制的本地配置、密钥和个人文件不在自动清理范围内。

## 决策

在 `codex/trusted-rag-foundation-design` 分支执行以下清理：

- 删除旧 `backend/`、`frontend/` 和 `deploy/` 受版本控制内容。
- 删除描述旧实现的交付、架构、设计、工程和部署文档。
- 删除只验证旧实现的脚本、构建目标和流水线任务。
- 保留 `project/`、`docs/adr/`、可信 RAG 基座设计文档、项目治理脚本、根规则和 Git 历史。
- 设计分支继续只承载控制面和设计，不创建绿地产品源码。
- 不自动删除未受版本控制的 `.env`、个人配置或其他可能包含本地信息的文件。

## 影响

- 仓库当前提交不能构建或部署旧产品，这是有意结果。
- M0 人工评审只面对一个明确的绿地设计事实来源。
- M0 通过后，WP-0002 从空源码边界建立新的后端、前端和 Docker 工程。
- 如果需要查阅旧实现，只能使用 Git 历史或固定旧提交，不能复制回当前目录作为兼容层。
