# ADR-0056：评测期望证据稳定标识

## 状态

已接受（方案 A）。

## 日期

2026-08-05

## 决策负责人

产品、架构、安全、知识负责人、助手负责人和评测负责人。

## 背景和难以逆转的约束

ADR-0051 将 Recall@10 和引用正确率的分子定义为与 `expectedEvidenceStableIds` 匹配的稳定证据标识，
ADR-0053 却只将该 JSON Lines 字段定义为非重复字符串数组，当前暂存校验也仅拒绝空白和重复字符串。

知识上下文的 `ParagraphWindowChunker` 已确定地产生 64 位小写 SHA-256 `chunkId`：规范输入为来源身份摘要、
`paragraph-window-v1`、分块顺序和分块文本摘要。该值是一个索引版本内 `index_chunk` 的主键组成部分，
`IndexCandidate` 与可信回答引用均可不携带正文地返回它。`dataSourceId/contentVersion/chunkId/ordinal` 的复合
定位符则会额外暴露资源标识，并要求另行固定编码与转义规则。

没有统一格式时，数据集作者可登记任何文本而运行只会在之后失败，且两个上下文无法证明“命中”指同一个证据。
这会把可复核性推迟为隐含实现选择，不能在 ADR-0055 的执行门面中静默决定。

## 决策内容

接受方案 A，冻结 `chunkId` 作为 ADR-0053 的 `expectedEvidenceStableIds` 和 ADR-0055 输出稳定证据标识的唯一编码。

`expectedEvidenceStableIds` 的每一项必须是知识索引 `ParagraphWindowChunker` 产生的 64 位小写 SHA-256
`chunkId`。受限评测执行门面返回候选和引用的 `chunkId` 集合；评测运行只比较集合，不读取正文。
数据集登记在写入私有对象前拒绝非此格式的值，但不检查其是否已存在于当前索引：目标助手版本冻结的索引
可能稍后建立或更新；运行时未命中仍失败关闭。任何分块策略或 `chunkId` 规范变化必须创建新数据集版本，
并与目标冻结的索引版本一起重新评测。

## 主要备选方案及拒绝原因

### 方案 A：`chunkId`

接受。它已经由已发布的索引契约产生且在冻结索引内唯一，不含正文、端点、密钥、令牌或成员信息；格式校验
简单，跨上下文只交换一个固定 SHA-256 值。

### 方案 B：复合资源定位符

拒绝。它需要新增字符串语法、转义与版本治理，并扩大评测数据和结果中的资源标识暴露；现有质量指标无需
这些额外字段即可在冻结索引内判断命中。

### 方案 C：继续接受任意字符串

拒绝。它不定义“稳定”含义，允许无法与候选或引用匹配的数据集进入已发布状态，并把数据契约错误延迟到
运行失败。

## 后果和后续证据

接受方案 A 后，先写红灯证明非 64 位小写 SHA-256 的期望证据标识不能登记；受限执行仅输出 `chunkId`，
不输出资源标识或正文；未知但格式正确的期望标识不导致泄漏、仅使运行结论失败。随后才实现 ADR-0055
受限执行、评测运行和质量门禁应用链路。
