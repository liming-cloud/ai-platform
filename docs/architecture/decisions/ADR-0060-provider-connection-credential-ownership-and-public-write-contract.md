# ADR-0060：厂商连接凭据所有权与公开写入契约

## 状态

已接受。

## 日期

2026-08-10

## 决策负责人

用户，代表产品、架构、安全、模型治理、平台运营与租户运营负责人。

## 背景和待消除的矛盾

ADR-0023 规定 API Key 只能在创建、编辑或轮换时写入，公共契约不得暴露
`credentialReference`；ADR-0058 又把厂商连接定义为供应链中保存密钥引用、接受探测和
模型发现的受管实例。

代码图谱确认，当前 `ProviderConnectionRequest`、`CreateProviderConnectionCommand`、
`ProviderConnection` 和 `ProviderConnectionService` 都把 `credentialReference` 作为创建输入，
并由浏览器控制台消费该接口。该字段是密钥存储实现，不是操作者可管理的业务资源；继续开放会让
浏览器能够伪造、猜测或绑定任意内部引用，也无法形成“录入 API Key 后不可查看、可轮换、旧探测
自动失效”的完整产品闭环。

`ModelConfigurationCredentialService` 已证明写入专用 `SecretValue`、加密写入器和原子事务是现有
代码库可复用的安全 seam，但其凭据记录归属于模型配置，不能直接成为厂商连接的公开存储模型。

## 提议的决策内容

接受方案 A：**厂商连接拥有其访问凭据的业务生命周期，公开 API Key 只写入厂商连接命令，
内部 `CredentialReference` 永不离开 model-runtime。**

1. `ProviderConnection` 是厂商接入账户、受控 Endpoint、认证方式与连接状态的聚合根；它只持有
   私有 `CredentialReference`。该引用只能由同一上下文的凭据写入器产生、替换和解析，不能出现在
   HTTP 请求、响应、前端状态、日志、错误、审计或幂等响应中。
2. 创建连接的公共请求仅提交受控厂商类型、显示名称、受控 Endpoint、区域、认证方式和写入专用
   `apiKey`。`apiKey` 不得进入幂等指纹、异常文本、审计、领域事件或任何读取投影；接口响应只返回
   `credentialConfigured`、凭据版本、最近轮换时间与不可逆指纹。
3. 轮换是独立命令 `POST /api/v1/model-providers/{providerConnectionId}/credential-rotation`，请求体只含
   `apiKey`。它必须验证 token 派生的当前租户和 `model:write`，原子替换连接私有引用、递增连接修订、
   清除最近探测成功事实并使该修订的发现与能力探测失效。并发版本不匹配、跨租户、停用连接、空或
   不合法 API Key 一律失败关闭。
4. `ProviderConnectionCredential` 是 model-runtime 基础设施拥有的独立加密记录，不是面向浏览器的
   可枚举“密钥资源”。其密文、nonce、主密钥版本与不可逆指纹遵守 ADR-0023 的加密和短生命周期
   `SecretValue` 约束；每条连接只关联当前有效的一条记录，历史材料不得读取或恢复。
5. 已有 `ModelConfigurationCredential` 继续只服务 ADR-0023 的三层模型配置；它与厂商连接凭据不
   共享、不互相引用。后续把模型配置绑定至已验证部署时只消费发布的连接／能力快照，不能通过模型
   配置绕过连接的凭据、探测或失效状态。
6. 创建和轮换由应用层完成授权、`SecretValue` 生命周期、事务和 I/O 编排；领域服务负责“新凭据使
   旧探测失效”的状态不变量；基础设施只负责加密、映射、锁与原子提交。探测和模型发现仅在已完成
   授权与状态复核后短暂解析凭据。

本提议只澄清 ADR-0023 在**厂商连接**上的公开 API Key 边界，不改变其模型配置凭据所有权、主
密钥、加密算法、运行时释放或生产 KMS/Vault 要求。

## 主要备选方案及拒绝原因

### 方案 A：厂商连接自有、不可复用的访问凭据

接受。厂商账号、Endpoint、认证方式、探测与发现全部随连接修订共同失效，调用方只提交一次
API Key，且不会看见内部引用。接口小、迁移局部，并能直接复用现有写入专用秘密与原子事务 seam。

### 方案 B：建立可复用的独立“厂商凭据”业务资源

暂不接受。它允许一个凭据绑定多个连接或模型配置，适合未来共享服务账户与复杂授权，但现在会新增
凭据目录、可见性、跨范围绑定、删除、影响分析、审批和多连接轮换的产品与安全语义。当前没有这类
已确认调用方，提前实现将形成第二套无业务闭环的 ACL。

### 方案 C：继续让客户端提交 `credentialReference`

拒绝。它直接泄漏持久化模型，并允许调用方绕过密钥录入、归属和轮换策略，违反 ADR-0023。

### 方案 D：把 API Key 放进每个模型配置，厂商连接不持有凭据

拒绝。连接验证和模型发现发生在模型配置之前；同时录入同一厂商 API Key 会制造重复秘密与不一致的
探测事实，不能解释凭据轮换应使哪些连接与发现失效。

## 后果和后续证据

- 接受后，先以红灯证明请求或响应包含 `credentialReference` 被拒绝；创建／轮换 API Key 不回显、不
  进入幂等指纹和审计；轮换使旧连接修订、模型发现与部署验证失败关闭。
- 随后补齐纯领域反例、应用事务、真实 PostgreSQL 加密与回滚、自动配置、HTTP、服务器分页投影和
  统一控制台的创建弹层、轮换高风险确认与独立探测路由证据。
- 当前连接数据迁移只允许服务端将已有私有引用回填为连接凭据关联；不得要求浏览器重传秘密、输出
  旧引用或把秘密写入迁移日志。
- 接受本 ADR 不授权自由 Endpoint、动态厂商插件、共享凭据目录、服务账户、外部秘密管理 UI、M7 或
  M8 实现。

## 人工接受补充

用户于 2026-08-10 接受本 ADR，并确定首条实现仅覆盖**租户范围**厂商连接；平台共享连接在具备真实
平台模型管理授权点后另行切片。成功的模型能力验证有效期固定为 `PT24H`，与 ADR-0058 的冻结有效期
保持一致；该值不表示网络请求超时、浏览器会话期限或凭据轮换周期。
