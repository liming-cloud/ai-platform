# ADR-0102：S2 平台部署目录的名称／摘要搜索

## 状态

已接受。2026-10-23 用户明确要求“部署目录搜索以已接受原型的‘名称／摘要’为准，先登记决策再实现并补齐验收”。调查和实施输入为 `583c08aa39878f01743cf980dfe72b50b7ec4f79`，责任任务为 WP-0019／S2。本决定将此前暂缓的搜索纳入独立子任务，不表示搜索、S2 或 M6 已验收通过。

## 依据与决定

1. 唯一设计来源是 OpenDesign Cloud 原项目 `249f81f2-6f1a-46ff-988c-da3cdedb35e7`、已接受版本 `f3216dffe717e194e96fa20b4afee7983a9ff420` 的平台部署目录。搜索沿用“搜索当前目录”和“按名称或摘要搜索”。用户已选择以该标注确定搜索字段；通用原型演示器的整行匹配不扩大生产搜索范围，不修改原项目或另建副本。
2. `GET /api/v1/platform/model-supply/deployments` 增加可选 `q`，只匹配公开部署名称 `displayName` 与驻留摘要 `inputs.residency`。缺失的驻留不补演示值。不匹配供应商模型编码、能力、状态、操作文字、内部 ID、连接秘密、租户名称或其他租户内容。
3. 复用 ADR-0096 的有界字面语义：省略或首尾空白后为空表示不筛选；最多 64 个 Unicode 码点，单个连续词组、不区分大小写的包含匹配。`%`、`_` 和反斜线按字面处理，不接受通配符、正则、动态字段或排序。保留现有平台会话与 `model-platform:write` 权限，不把搜索变成新的授权入口。
4. 范围和搜索谓词均在 PostgreSQL 分页前执行，数据和总数使用相同条件，保持现有固定排序。保留 `pageNumber`、`pageSize`、`PageResult` 及分页边界；不在浏览器拉全量筛选，不增加手工 SQL 分页、索引表、缓存或通用搜索框架。
5. URL 保存规范化查询及页大小；搜索词或页大小改变回第一页，刷新、前进后退、精确详情返回目录保留查询位置。越界页根据真实总数恢复并规范 URL；旧请求或旧会话不能恢复旧结果。
6. 搜索零匹配显示原型“没有匹配记录，请调整筛选条件或返回目录。”，保留搜索和清除恢复能力；不显示真实空目录或推断无部署。页头供应摘要仍是全目录独立事实，不改为匹配数；辅助失败及实例只读状态沿用 ADR-0100，不借搜索新增状态触发。

## 实施与验收

先以最小失败测试覆盖名称／驻留命中、排除字段、字面特殊字符、Unicode 上界、跨页筛选和同范围总数，再局部修改查询、持久化及 URL／页面。真实 PostgreSQL、HTTP 权限、前端读取／路由与最新部署只读浏览器分别验证。原型一致性只复核新增搜索区域、零匹配和恢复，不重复已通过的 S1、草稿表单或七态全景验收。

验收不删除或修改现有业务数据，不创建云端资源，不触发真实推理、发布或赋权。复用受保护的 `pwd.txt`，秘密不进入日志或证据；截图只在 `/private/tmp`。账号暂缺的真实厂商合同及正式发布后的完整原型流程仍独立未完成。搜索子任务通过不增加 S2 的四项责任操作完成数，仍为 2／4，WP-0019 为 7／29，不进入 S3。
