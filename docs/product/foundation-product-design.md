# 可信 RAG 基座产品设计

## 1. 产品定义

可信 RAG 基座是面向企业的多租户 AI 平台，把经过授权的结构化与非结构化数据转化为快速、可信、可引用、可审计的回答。它是可扩展基座，不是行业页面集合。

参考场景：

- 连锁门店顾客通过硬件设备查询商品位置、价格和销量，系统组合结构化商品数据与受治理文档回答。
- 高校师生查询校规、图书馆资源和服务信息，系统引用有效来源，证据不足或无权访问时拒答。

平台负责组织、数据源、模型、助手、查询、评测和运维能力；客户负责其数据含义、授权和质量。

## 2. 产品原则

1. **可信优先于流畅。** 简短且有依据的回答优于无依据的流畅回答。
2. **权限属于检索过程。** 权限不是前端过滤，也不是生成后的补救。
3. **发布不可变版本。** 数据源、索引、模型部署、助手和评测都以明确版本发布。
4. **依赖能力而非厂商名称。** 产品只声明能力和策略，厂商差异留在治理层。
5. **渐进披露。** 普通用户只看到任务，专业人员按需展开诊断。
6. **证据决定完成。** 没有验收证据，资源和里程碑都不能宣布完成。
7. **企业基础先于业务闭环。** 账户、角色权限、菜单投影、厂商连接、模型探测和平台可观测性没有形成管理员可操作闭环前，不以新增助手、评测或问答页面宣称产品可用。

## 3. 角色与任务

| 角色 | 主要任务 | 成功结果 | 不应看到 |
| --- | --- | --- | --- |
| 平台管理员 | 管理平台范围与租户生命周期 | 租户、安全基线、平台模型授权和全局预算受控生效 | 租户正文与问答内容，除非另有内容读取授权 |
| 平台运营 | 保证平台健康和受治理 | 模型、队列、容量、备份与发布风险得到处置 | 未授权租户内容 |
| 租户管理员 | 管理组织、权限、凭据和配额 | 人员与设备获得最小必要权限 | 其他租户 |
| 知识管理员 | 接入、校验和发布数据 | 数据可搜索、质量和血缘清晰 | 模型密钥 |
| 助手负责人 | 配置、测试、评测和发布助手 | 版本通过质量、安全、延迟、成本门禁 | 明文凭据 |
| 评测人员 | 维护黄金集并分析失败 | 评测可复现，发布决策有依据 | 未批准的生产内容 |
| 审计人员 | 解释谁在何时访问了什么 | 权限、配置、发布、用量可追溯 | 凭据材料 |
| 渠道调用方 | 在固定助手和范围内提问 | 快速回答、引用和安全拒答 | 管理能力 |
| 演示访客 | 在受限场景评估价值 | 理解产品价值且用量受控 | 租户管理和敏感诊断 |

## 4. 六条产品主线

### 4.1 组织与权限

- 租户、组织单元、成员、角色和权限策略。
- 资源授权、行过滤和字段遮蔽。
- 人员会话、服务 API Key、设备凭据。
- 即时撤销、配额和审计。

### 4.2 数据源与知识空间

- 文件、对象存储和结构化数据集。
- 连接配置、探测和同步。
- Schema、质量规则、敏感级别、血缘和新鲜度。
- 解析、切片、索引、发布、退役和重建。
- 知识空间作为可授权边界。

### 4.3 模型目录与运行时

- 供应商连接和密钥引用。
- 以能力描述的模型部署。
- 连接探测、模型探测和健康状态。
- 便携参数、厂商参数、路由、回退、驻留、延迟和成本。
- Token、调用、失败和费用统计。

### 4.4 助手与交付

- 草稿和不可变发布版本。
- 知识、模型、提示词、记忆、工具、渠道和配额策略。
- 网页、API 和硬件设备交付。
- 明确的会话保留策略。

### 4.5 可信查询

- 可信请求上下文。
- 查询分类和结构化/非结构化计划。
- 授权混合检索、重排和证据再次鉴权。
- 生成、引用校验和拒答。
- 流式生命周期、取消、对账、反馈、审计和计量。

### 4.6 评测与运维

- 版本化评测数据集。
- 检索、事实依据、引用、拒答、安全、延迟和成本指标。
- 发布门禁和签署决策。
- 健康、指标、链路、队列、预算、备份和恢复状态。

## 5. 核心闭环

核心闭环必须在企业基础验收门通过后展开。验收门至少证明：管理员无需修改数据库即可建立人员账户、分配角色与权限、验证菜单和直接 URL 的一致授权；能够配置厂商连接、写入密钥、执行连接与模型能力探测、发布并授权模型；人员使用一个登录入口和一个企业控制台完成授权任务。任一前置能力缺失时，产品状态仍为不可用，不能用演示夹具或技术 API 代替。

### 5.1 数据到回答

1. 知识管理员创建数据源并定义或确认 Schema。
2. 平台探测连通性和权限，但不自动发布。
3. 同步任务产生不可变产物和质量报告。
4. 管理员检查成功、失败、重复、过期和越权数据。
5. 创建并发布索引版本。
6. 查询只搜索已发布且经过授权的版本。
7. 回答引用数据源、版本和定位信息。
8. 反馈与评测把问题归入可行动的失败类别。

### 5.2 模型到助手

1. 租户管理员使用密钥引用创建供应商连接。
2. 探测 DNS、TLS、认证和最小模型调用。
3. 注册模型部署并确认探测到的能力。
4. 助手绑定必需能力和路由策略。
5. 测试固定助手、模型、索引和策略版本。
6. 评测门禁决定是否允许发布。
7. 每次查询记录实际模型和回退原因。

### 5.3 权限变化

1. 管理员修改成员、角色、资源范围或设备凭据。
2. 产生新的策略版本并撤销受影响的会话和缓存。
3. 新查询立即使用新策略。
4. 进行中的流式查询在下一次受保护证据或工具调用前停止。
5. 审计记录查询与确切策略版本的关系。

## 6. 资源状态

| 资源 | 草稿或处理中 | 已发布 | 终止 |
| --- | --- | --- | --- |
| 数据源 | 草稿、探测中、就绪、失败 | 活跃、降级 | 已退役 |
| 同步任务 | 排队、运行中 | 成功、部分成功 | 失败、已取消 |
| 索引版本 | 构建中、校验中 | 已发布 | 已替代、失败 |
| 供应商连接 | 草稿、探测中 | 就绪、降级 | 已禁用 |
| 模型部署 | 草稿、探测中、已校验 | 已发布、降级 | 已禁用、已退役 |
| 助手版本 | 草稿、测试中、评测中 | 已发布 | 已拒绝、已退役 |
| 查询任务 | 已接受、规划中、检索中、生成中 | 已完成 | 已拒答、无权限、失败、已取消 |
| 评测任务 | 排队、运行中 | 已通过 | 未通过、已取消 |

状态变化必须通过有权限和审计的命令完成，禁止直接修改状态字段。

## 7. 一周演示范围

- 全新 Docker 部署。
- 租户管理员、知识管理员、助手负责人和演示用户。
- OpenAI 兼容与 Ollama 两类协议。
- Chat 和 Embedding 两类模型。
- 文件和结构化数据集。
- 门店与校园两套合成数据。
- 数据发布、助手测试、评测、发布、问答、引用、反馈、审计、用量和配额。

演示配额：

| 项目 | 限制 |
| --- | --- |
| 每账号每日查询 | 50 |
| 每账号每分钟查询 | 5 |
| 每账号并发查询 | 1 |
| 每租户知识空间 | 3 |
| 每租户助手 | 1 |
| 每租户文档 | 200 |
| 每租户原始数据 | 100 MB |

演示站点不代表生产可用性、客户数据就绪、全部厂商支持或生产灾备能力。

## 8. 产品指标

- 未授权证据暴露、引用正确率、正确拒答率、权限解释完整度。
- Recall@10、事实依据、回答有用性、失败类别分布。
- 结构化检索、混合检索、首 Token、完整回答延迟。
- 每次查询 Token、模型调用、工具调用和成本。
- 从创建数据源到首次发布回答的时间。
- 从助手草稿到通过发布门禁的时间。
- 查询完成、拒答、无权限和失败比例。

## 9. 产品验收规则

- 没有角色、任务、结果和测试的能力不得进入导航。
- 没有不可变版本和发布决策的资源不得发布。
- 没有完成权限与证据解析不得生成回答。
- 没有探测成功的供应商和模型不得发布。
- 没有通过评测门禁的助手不得发布。
- 没有仓库证据不得声明工作完成。
