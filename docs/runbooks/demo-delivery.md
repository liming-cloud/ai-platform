# M1 受限演示站点交付运行手册

## 交付目标

本手册用于从全新 Docker 项目、网络和空数据卷启动可信 RAG 基座，完成门店与校园
两条演示任务，并验证权限、引用、配额、用量、审计和注销闭环。

这是一套本地受限演示，不是生产部署方案。

## 环境与入口

默认源演示环境包含 8 个服务和 5 个应用入口：

- 管理控制台：`http://127.0.0.1:13000`
- 最终用户问答站点：`http://127.0.0.1:13001`
- 控制面健康入口：`http://127.0.0.1:18080`
- 查询运行时健康入口：`http://127.0.0.1:18081`
- 摄取进程健康入口：`http://127.0.0.1:18082`

演练入口使用独立项目名、网络、卷和 `2xxxx` 端口，不覆盖默认源环境。

## 自动交付验收

前置条件：

- Docker 和 Docker Compose 可用。
- 仓库中的演示环境配置已由交付负责人确认。
- `28080`、`28081`、`28082`、`23000`、`23001` 未被占用。
- 默认源演示环境处于健康状态。

先执行：

```bash
make project-status
make delivery-operations-test
make deploy-smoke
```

再执行完整演练：

```bash
make delivery-demo
```

该命令会：

1. 创建全新项目名、网络和三个空卷。
2. 构建并启动 PostgreSQL、Redis、MinIO、三个后端和两个前端。
3. 确认业务表初始事实数为零。
4. 通过公共接口发布门店和校园知识。
5. 配置、探测并发布确定性对话和嵌入模型。
6. 构建并激活双租户索引，发布两个助手。
7. 验证带引用回答、拒答、事件恢复和租户隔离。
8. 运行 8 个固定评测问题、每日配额、用量与脱敏审计验收。
9. 验证门店和校园会话退出登录后立即失效。
10. 记录 8 个镜像内容摘要、事实计数和耗时。
11. 删除隔离容器、网络和卷，并确认源环境继续健康。

任何一步失败都会返回非零状态，不能手工改写成功报告。

## 门店演示任务

1. 在问答站点使用门店演示租户登录。
2. 确认只显示“门店可信导购助手”。
3. 提问“青柚气泡水在哪里，价格是多少”。
4. 核对回答包含货架位置，且至少有一条引用。
5. 进入管理控制台治理页，查看真实查询用量和脱敏审计。
6. 退出登录。
7. 确认原会话不能继续读取助手目录。

## 校园演示任务

1. 在问答站点使用校园演示租户登录。
2. 确认只显示“校园可信问答助手”。
3. 提问“中心图书馆周末开放到几点”。
4. 核对回答包含周末开放时间，且至少有一条引用。
5. 确认页面不能看到门店助手、商品位置或门店审计。
6. 进入管理控制台查看校园租户自己的用量和审计。
7. 退出登录并确认会话失效。

## 演示限制

- 每日查询上限：100 次每租户。
- 同时查询上限：4 次每租户。
- 只使用门店与校园合成数据。
- 只使用本地确定性模型，不代表真实厂商模型质量、时延和成本。
- 端口只绑定本机回环地址，不对互联网开放。
- 不提供生产高可用、跨区域灾备、正式证书或外部密钥库。
- 不允许把演示账号、环境配置或机器报告用作生产凭据。
- 机器报告不包含密码、令牌、租户标识、问题正文或答案正文。

## 失败处置

若自动演练失败：

1. 保留错误步骤和非秘密日志。
2. 不复制登录响应、令牌、问题正文或对象内容到任务记录。
3. 确认失败资源属于本次带受控前缀的隔离项目。
4. 使用恢复清理脚本删除该隔离项目。
5. 执行 `make deploy-smoke` 确认源环境健康。
6. 修复根因后从空卷重新执行，不跳过失败步骤。

## 受控升级

M1 单机演示环境升级采用“先备份、再重建应用、由数据库迁移工具校验、最后评测”的
停机窗口策略。禁止跳过备份直接替换现有数据卷上的应用。

自动升级演练：

```bash
make upgrade-demo
```

该命令会：

1. 确认源环境 8 个服务健康。
2. 停止写入口并生成 PostgreSQL 与 MinIO 一致回滚备份。
3. 基于当前提交重新构建并创建应用容器，复用既有三个数据卷。
4. 等待 5 个应用入口恢复健康。
5. 比较升级前后关键事实和数据库迁移计数。
6. 运行 8 个固定评测问题。
7. 记录新镜像内容摘要和升级耗时。
8. 只有全部通过后才销毁临时回滚备份。

如果升级失败，脚本返回非零状态并保留机密回滚备份，终端会给出其绝对路径。该目录
不得提交或转发；操作人员应依据备份恢复手册在隔离环境先验证，再决定恢复源环境。
升级成功报告只包含不可逆摘要、计数、时长和真假结果。

M1 只证明同一基座版本在既有数据卷上的受控重部署流程。跨数据库不兼容版本升级、
零停机升级、自动回滚和多节点滚动发布属于后续生产门禁。

## 交付边界

自动报告证明技术与任务闭环，但 M1 退出仍需要产品、测试和运维职责对最终清单进行
人工确认。未获得人工确认前，`WP-0007` 不能标记完成，也不能进入 M2。
