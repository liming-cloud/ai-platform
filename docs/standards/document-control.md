# 文档与任务控制规范

状态：已接受。依据：ADR-0081 及用户 2026-09-21 执行计划。负责人：治理。

## 稳定基线

foundation 说明目标，standards 说明横切规则，architecture 说明允许的边界与依赖，design 说明已接受具体设计。任务提案只放 tasks，不覆盖稳定基线。既有 ADR 保留决策原文；主题规范明确当前生效条款和替代依据，旧时点“当前”不决定现状。

基线以 Git SHA 固定。事实错误按证据修正；产品、安全、公共契约及风险接受仍由相应人工决定。任务发现的可复用改进先登记，另行整理基线，不把每次实现过程写成规范。

## 唯一恢复源

STATE schemaVersion=2 只保存 productVersion、currentMilestone、productFrontier、currentTask、updatedAt、updatedBy。产品前沿必须是 WP；当前执行任务可为 WP 或 GOV。里程碑总控和产品前沿不因治理任务启动而误切换。

任务 README 的元数据表保留 ID、状态、负责人、分支、里程碑、ADR、证据、提交。活动任务增加输入提交、基线提交和人工验收。正文包含问题、范围内/外、公共接口与数据、约束、验收标准、验证、证据、下一前沿；记录已确认决定、读取基线、工作区保护与阻断。

状态沿用待开始、进行中、受阻、已完成。完成必须绑定真实提交及证据；受阻说明事实、责任人与解除条件。人工验收独立表达“不适用”“待人工验收”“已接受”“已拒绝”，不把技术通过代替人工接受。里程碑任务必须有人工依据，普通局部任务不新增人工审批。

任务开始、前沿变化、出现阻断、准备交付时刷新恢复入口。正文保存结果和下一动作，不追加逐命令日记。待办沿用原工作包编号，激活时才补齐执行上下文。已完成旧包从固定 Git 恢复，不重新判定其当时结果。

## 证据与历史

任务的“证据”章节最多列 8 个当前恢复所需引用；当前执行任务与产品前沿分别最多引用 12 个 ADR。resume-context 至多 12 KiB。生成的任务/决策索引不接受手工状态编辑。

新证据元数据写明责任任务、验证提交和验证范围；人工验收另外记录接受来源。涉及部署分别写前端与后端 revision、镜像、原型项目/版本、时间和限制。源码测试、部署功能、视觉一致性、只读事实分开结论。

history-index 为一次迁移的逐文件清单：完整来源提交、原路径、SHA-256、处置、原因、引用和保留目标。来源提交是文件定位，证据中的被验证提交是被测对象，二者不能混用。旧任务的短 SHA 只按原文交给 Git 验证唯一提交，不补造历史记录；新完成结论必须使用完整 SHA。原证据索引绑定从 Git 原文计算，不信任新索引自称完成。保留原文的证据可有历史路径，校验按原位置及索引恢复；现行文档必须链接现存目标。

明确失效或重复且已受控的文件才能删除。删除前验证恢复对象、引用、必要信息和验收依赖；当前树不维护整份旧资料的平行副本。重要纠错记最小摘录、来源、原因、影响和修复提交。秘密不得以历史取证为由复制。

## 执行和交付

查询与校验使用 `python3 -B`，不写字节码、账本、状态或报告。`make decisions-sync` 显式更新生成索引。`make project-verify` 检查历史摘要、引用、状态、证据与实现矩阵；`make architecture-guard` 保持代码约束。

先最小失败测试，再局部修复；变更公共契约先接受 ADR。涉及里程碑按章程人工门禁，未满足不得推进。工作区人工修改独立保护，精确路径提交，中文 doc/bug/feat/build 前缀。不因文档整理重跑创建业务对象的验收。
