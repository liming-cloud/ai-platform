# ADR-001：deploy 是唯一本地部署基线

状态：已接受
日期：2026-07-17

## 决策

所有本地部署、数据库初始化、依赖健康、集成测试、端到端验收、重置和故障演练入口都必须位于 `deploy/`，并以 `deploy/docker-compose.yml` 为唯一拓扑事实源。

根 Makefile 可以提供不改变语义的快捷入口，但只能调用 `deploy/`；不得在 `scripts/`、后端启动配置或历史 artifacts 中维护第二套本地基线。生产部署可有独立实现，但不能被称为本地验收事实源。

## 原因

此前存在多套 SQL 和部署入口，已有 volume 会掩盖空库问题，无法判断哪套结果可信。当前项目按全新数据库交付，因此只保留一个最终 schema 和一个基础 seed。

## 约束

- 最终 schema、基础 seed、运行账号授权和初始化校验在 `deploy/` 内闭环。
- 空卷初始化、重复启动、依赖未就绪和恢复都必须可测试。
- reset/delete volume 必须要求显式 project 与确认，不接受宽目录、通配符或未解析环境变量。
- local secrets 由 `.env` 显式注入或 deploy 初始化生成；示例值不能被误认为生产安全。
- backend readiness 必须反映关键依赖，Compose 用 `service_healthy` 而非只看启动顺序。

## 后果

优点是本地与 CI 验收可复现、数据库结构事实唯一。代价是已有数据卷不会获得自动结构升级，结构变化后应使用空卷重新验收；任何绕过 deploy 的“快速本地方案”都不受支持。
