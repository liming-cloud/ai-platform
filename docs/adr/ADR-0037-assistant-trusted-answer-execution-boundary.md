# ADR-0037：助手可信回答执行边界

## 状态

待接受

## 日期

2026-07-30

## 决策负责人

待产品与架构负责人确认。

## 背景和难以逆转的约束

ADR-0036 要求草稿 `AssistantTestRun` 与普通 `QueryRun` 经历相同的授权检索、证据再鉴权、模型快照复核、引用验证和失败关闭语义，同时又明确禁止二者共用运行根、配额、事件、运营汇总或历史正文。

代码图谱和 Maven 依赖显示 `trusted-query` 已单向依赖 assistant-delivery 以读取助手快照；assistant-delivery 不能反向依赖 `trusted-query`，否则形成构建与上下文循环。直接复制 `QueryRunService` 中的可信链路会让排序、提示词约束、模型快照复核和引用验证日后发生语义漂移。

## 决策内容

1. assistant-delivery 提供唯一的应用层 `AssistantTrustedAnswerExecutor` 门面，拥有“冻结助手目标 → 受控嵌入 → 受权候选检索 → 确定性证据选择 → 受控对话 → 引用核验”的顺序。它不创建或持久化任何聚合根，不占用配额，不写事件，也不产生运营投影。
2. 门面输入只接受由令牌恢复的 `TrustedRequestContext`、已冻结的助手执行快照和本次问题正文；不接受租户、主体、成员、权限、渠道、令牌、厂商、端点、密钥或任意检索范围参数。输入快照必须同时支持既有发布版本的兼容模型部署事实和新受控模型配置事实，不能降低现有 `QueryRun` 的兼容路径。
3. 门面返回不可变、仅本次调用可用的回答结果：已验证回答正文、连续引用所需的候选元数据和用量，或者证据不足的拒答结论。候选正文与回答正文不得进入该门面的持久化输出、事件、审计或读取投影。
4. `QueryRunService` 继续拥有普通查询的 `PUBLISHED` 检查、幂等、普通查询配额、`QueryRun` 终态和事件恢复；它调用该门面后再映射为自身事实。`AssistantTestRunService` 继续拥有 `DRAFT` 检查、独立测试配额和 `AssistantTestRun` 终态；它调用同一门面后只保存 ADR-0036 允许的最小事实。
5. 任何模型、检索、证据或引用校验异常均由调用方把已占额的运行提交为各自的失败终态后再失败关闭；门面不得泄漏密钥、对象位置、未授权候选或厂商失败细节。

## 主要备选方案及拒绝原因

### 方案 A：由 `AssistantTestRunService` 复制普通查询流水线

拒绝。虽然不会形成依赖循环，但两套提示词、候选选择、快照复核与引用验证会在后续修改时产生可信语义漂移，无法证明“相同路径”。

### 方案 B：让 assistant-delivery 反向调用 `QueryRunService`

拒绝。`trusted-query -> assistant-delivery` 已存在；反向依赖会形成 Maven 和上下文循环，并让草稿测试错误地获得普通运行生命周期能力。

### 方案 C：将草稿版本直接送入 `QueryRunService`

拒绝。它违反 ADR-0016 与 ADR-0036 的 `PUBLISHED` 边界，并污染普通查询的配额、事件与运营事实。

## 后果和后续证据

- 接受后，WP-0012 先以红绿应用测试证明两种受控助手快照均通过同一门面，草稿测试只接受 `DRAFT`、普通查询继续拒绝草稿，且各自持久化事实互不混写。
- 随后补真实 PostgreSQL、HTTP、事件和浏览器证据，证明测试题目／回答只在当前响应中出现，普通查询事件不含草稿测试，草稿测试也不会成为公开查询渠道。
- 本 ADR 不改变 ADR-0036 的聚合、保留或配额边界；未接受前不得创建该公共执行门面或迁移普通查询路径。
