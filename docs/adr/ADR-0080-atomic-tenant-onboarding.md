# ADR-0080：租户与初始管理员原子开户

## 状态

已接受

## 日期

2026-09-14

## 决策依据

用户已确认原型、ADR-0078/0079 的身份职责与持续实施计划。本记录冻结该方向的生产合同，不增加角色、认证库、自动邀请或区域调度能力。

## 决策

1. 原型的三个步骤为租户信息、资源配额、管理员凭据。最后一次提交同时创建全局唯一身份、租户、管理员成员资格、固定角色绑定、配额和生命周期事件；成功直接可用。取消及任何失败不得遗留其中部分事实。取代 ADR-0041 在新开户路径要求选择既有主体、返回准备中状态的合同；历史准备中租户仍可显式激活，已有生命周期迁移不变。
2. 复用 `POST /api/v1/platform/tenants`，只接受 `tenantCode`、`displayName`、`administrator`、`quotas`。`administrator` 严格包含 `loginName`、`password`；`quotas` 严格包含 `knowledgeBases`、`documentsPerKnowledgeBase`、`bytesPerKnowledgeBase`、`maxFileBytes`、`maxTextBytes`。拒绝旧 `initialAdministratorSubjectId`、调用者身份、角色、区域及未知字段；不提供旧新请求分支。继续返回原生命周期响应，成功为 `ACTIVE`，版本为领域正常激活后的版本。
3. 数量为 1～2,147,483,647 的整数，容量为 1～9,223,372,036,854,775,807 字节的十进制字符串，防止 JavaScript 整数精度损失；这些只是表示边界，不是承载承诺。界面以 GB、MB、MiB 输入并精确换算成整数字节；默认沿用 3、1000、10 GB、50 MB、1 MiB。容量不能容纳单文件时拒绝。配额在独立租户配额事实中保存版本 0。
4. `GET /api/v1/platform/tenants/{id}` 返回现有生命周期投影；`GET /api/v1/platform/tenants/{id}/quotas` 返回五项配额及版本，只供有租户治理读取权限的平台身份复核。开户成功进入只读新租户概览并提供租户登录入口；后续配额编辑另一个切片实现，不让开户接口兼做设置更新。
5. 数据迁移为既有租户明确建立 ADR-0079 默认配额，不修改已有身份、密码、租户状态、正文或索引。新开户必须显式插入其提交值。此处交付配置事实，不宣称 WP-0020 接入预留和计量已实现；后续配额调整必须结合实际用量防止下调越界。
6. 应用服务只保留一个外部调用的事务入口，授权先于密码计算及写入；复用 `PasswordHasher` 和统一 `SubjectIdentity`。密码只在请求/短生命周期字符数组中使用，所有路径清理数组，不出现在 `toString`、响应、日志或审计。身份、租户编码的唯一约束由数据库裁决并发，冲突返回稳定脱敏的 409，不使用先查再写作为并发保障。
7. 领域服务在既有生命周期合法转换上完成开户，操作结果验证主体、成员、角色、租户和配额的一致性。基础设施提交完整结果，不在 infrastructure 决定角色或激活规则。生命周期事件仅记录最终状态、版本与时间，不含登录名、密码、配额正文或成员信息。
8. 新开户只读写生命周期事实作为认证权威；现存 `tenant` 行在本片仍是被其他上下文外键引用的标识锚点，不增设可变状态同步或回退分支。本片移除旧候选主体读取及接口内事务自调用，不扩展与本包无关的 ADR-0028/0029 知识来源兼容链路。不得为清理锚点删除现有数据或批量重写跨上下文外键。开户在写入前检查 ADR-0046/0064 的既有认证切换事实；未就绪返回脱敏 503 并保持零写入，不能用开户自动补写切换事实，也不改变认证 SQL。现有 deploy 已确认就绪；其他环境仍按原有受控初始化/回填流程准备，不借本片绕过历史映射要求。
9. 前端保留已验收三步布局；非秘密草稿绑定当前操作者，在同一浏览器会话内支持刷新与回退，取消、成功及退出时清除。密码不写草稿、本地存储、URL、证据或原型。回退到前两步、取消、失败或成功时清除密码。提交中的重复点击被禁止，取消或失败不会预先创建人员账户；失败后非秘密内容保留并让用户重填密码。成功提供明确的租户登录入口，切换身份需先退出当前平台会话。
10. 原型的“华东受控区”为合成演示，无生产区域设置或部署路由依据。本片不显示虚构驻留区域，不收集无实际效果的区域选择。租户名称/编码的界面新建约束沿用已验收原型的 2～40 字符、3～20 位，后端历史读取保留原有合法长度，不破坏既有租户。

## 验证与交付

- 先证明 HTTP 所用服务入口在发件箱故障时整体回滚，再实现原子新开户。覆盖重复租户编码、重复登录名、并发同名、未知字段、数值边界、未授权与 CSRF、密码及摘要不外泄。
- 真实 PostgreSQL 断言身份、锚点、生命周期、成员、角色、配额与事件全成或全败；新管理员通过既有租户登录获得正确能力，平台活动资格不被授予。
- 生产浏览器覆盖三步骤、上一步、取消、密码清除、提交失败和成功、390/1024/1440、键盘、200% 文字与 reduced-motion；只使用真实 API，不复制合成状态。
- 固定提交构建现有 deploy 环境镜像，保留数据卷并登记运行提交、镜像与登录回归；不把独立开户切片当作 WP-0017 整包完成。

## 2026-09-20 原型验收边界补充

状态：已接受。用户针对两项已展示的冲突明确确认“1. 以原型为准 2.允许”。

1. 新租户概览按固定 OpenDesign 原型不展示额外资源配额区。五项开户配额及版本仍通过正式 `GET /api/v1/platform/tenants/{id}/quotas` 与精确对象的只读数据库事实核验；移除旧概览展示断言并增加无额外配额区的原型断言，不删除业务保存、版本和授权校验。概览也不再为未展示的数据读取配额，避免无关依赖阻断基本信息。
2. 正常字号继续采用已验收原型的步骤圆圈基线；200% 文字时允许圆圈随文字自适应，满足无裁切、键盘和触控要求。该明确许可只覆盖此适配，不扩大为导航、文案、间距或其他响应式例外，不修改 OpenDesign。
3. 本补充不改变开户 HTTP、领域、权限、持久化及配额编辑边界。必须以新的实际部署候选重新完成开户、登录、只读事实和视觉对照后，才能关闭本独立切片；WP-0017 整包与 M6 保持进行中。
