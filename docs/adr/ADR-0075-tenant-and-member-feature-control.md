# ADR-0075：租户功能上限与普通成员对话功能控制

## 状态

已接受

## 日期

2026-09-03

## 背景

WP-0016 人工复核指出租户开通、成员管理和权限原型无法闭环。产品负责人进一步明确：平台管理员配置租户可使用的功能，租户管理员控制普通成员可使用的功能；普通成员聚焦选择助手和对话，不建设通用权限管理产品。产品验收遵循“功能能用 → 功能好用”。

## 决策

1. 保留 ADR-0067/0073 的三种固定角色，不引入租户自定义角色、菜单权限树或内部 API 勾选树。角色负责管理职责边界，功能授权负责该边界内的可用能力。
2. 平台管理员配置每个租户的功能上限。租户管理员只能在平台已开放范围内操作，不能自行开启平台未开放的功能；平台不得借配置入口读取租户知识或会话正文。
3. 租户管理员管理普通成员的对话相关功能和已授权助手范围。普通成员功能保持精简，以助手选择、发起对话、查看及继续本人历史会话、查看已授权引用为原型基础，不延伸到模型、知识库或助手发布管理。
4. 有效权限是角色职责、租户已开放功能、成员授权及对象授权的交集。导航由有效能力派生，隐藏菜单不代替服务端接口授权；撤销权限后，直接路由、历史与引用访问同样失败关闭。后续实施必须沿用既有会话撤销和租户隔离规则。
5. 平台独占租户管理员生命周期治理，租户管理员只能管理普通成员，不能创建、提权或停用其他管理员。最后一位管理员保护继续有效。
6. 原型中的功能配置必须能保存、取消、刷新恢复，并展示配置后的有效结果；不能只有可勾选外观。更改上级功能后，下级不得显示为仍有效，也不得因为重新打开上级功能而擅自授予此前没有的成员权限。
7. 先验证功能能用：输入、校验、状态变化、持久化恢复、失败恢复和越界拒绝均有证据；再验证功能好用：命名、布局、反馈、键盘、响应式和可访问性。页面数量或通用确认框不能代替操作闭环。

## 影响与边界

- 本 ADR 补充 ADR-0067 的能力投影，不改变固定角色和 ADR-0073 的管理员治理边界。
- WP-0016 仅实现合成状态的可丢弃原型，不新增真实 API、数据库或生产权限实现。后续工作包须冻结功能目录、依赖关系、默认授予规则和服务端持久化契约，并按本 ADR 验证。
- 安全隔离、授权检查和密码不回显不是可关闭的租户功能。可配置安全策略、配额调整规则及新账户邀请交付仍须另行确认，不因本 ADR 自动获得授权。
- 全局人员账号、密码不可查看和仅平台重置的 ADR-0042/0047/0061 规则继续有效。
- 全套原型继续处于人工验收不通过状态，不推进 WP-0017。

## 备选方案

- 租户自定义角色与内部 API 勾选：不采用，超出普通成员聚焦对话的产品范围，增加配置和理解成本。
- 仅隐藏菜单：不采用，无法构成权限边界，也无法证明功能控制生效。
- 两级功能控制与固定角色：采用，职责清楚且符合产品负责人本次确认。
