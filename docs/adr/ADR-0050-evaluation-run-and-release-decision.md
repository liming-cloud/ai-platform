# ADR-0050：冻结评测运行与发布决定边界

## 状态

已接受。

## 日期

2026-08-05

## 决策负责人

产品、架构、安全、助手负责人、评测负责人和租户运营负责人。

## 背景和难以逆转的约束

ADR-0016 只允许 `PUBLISHED` 的 `AssistantVersion` 进入普通查询，当前
`AssistantVersion.publish(Instant)` 只校验草稿状态。它不能以当前模型、当前阈值、页面结果或临时
布尔值证明待发布版本已经通过评测，也不能保存可复核的拒绝或例外事实。

M4 已有 `AssistantTestRun`、`QueryFeedback` 与 `QueryDiagnostic`，M5 已有最小
`ModelInvocationTrace`。这些分别属于 assistant-delivery、trusted-query 和 model-runtime，且只保存
冻结目标、摘要、最小引用、用量和终态；它们不能被反读为题目、回答、提示词、端点、密钥或供应商错误。
ADR-0031 因此要求评测结论与发布决定不能作为 `AssistantVersion` 的未归属子实体，也不能由应用层
自行拼装跨根规则。

M6 已确认需要评测、预算、发布审批和审计导出，但尚未决定指标阈值、预算计量、例外审批职责、
保留期限和导出字段白名单。直接实现任一阈值、货币核算或正文导出会把未获产品确认的规则固化为
不可逆公共行为。

## 决策内容

接受方案 A：evaluation-operations 拥有独立、不可变的 `EvaluationRun` 与
`ReleaseDecision` 聚合根；assistant-delivery 只在命名领域服务 `ReleaseAuthorization` 给出与目标
版本完全匹配的不可变授权结果后，才执行既有版本发布状态迁移。

1. `EvaluationRun` 固定目标 `AssistantVersion` 的稳定标识与修订、`EvaluationDataset` 版本、
   评测策略版本、冻结模型路由标识和指标实现版本。它只保存最小指标结果、终态和完成时间；运行失败、
   输入缺失或证据版本不完整一律不能产生通过结论。
2. `ReleaseDecision` 固定目标助手版本、唯一支持它的 `EvaluationRun`、政策版本、结论、决定时间和
   最小理由摘要。它是独立可审计事实，不是可修改的版本状态，也不从当前阈值重新计算历史结论。
3. `ReleaseAuthorization` 是无状态领域服务，只接收已加载的发布目标、决定和当前时间，返回不可变
   操作结果。目标版本、版本修订、租户、评测状态、政策版本或结论不匹配时失败关闭；应用层只负责
   令牌派生权限、加载、事务和提交，不得把规则塞入 Controller、仓储或 `AssistantVersion.publish`。
   `AssistantVersion.publish(Instant)` 继续只拥有从 `DRAFT` 到 `PUBLISHED` 的本地状态迁移；它不读取
   评测、预算、审批或当前策略。评测和决定必须绑定发布前的草稿修订，授权通过后才调用该状态迁移，
   因而发布产生的新修订不会反向改变已冻结的评测证据。
4. 本 ADR 草案仅冻结对象边界和失败关闭方向，不设数值阈值，也不把令牌用量伪装为货币预算。预算
   计量、周期、币种、范围、超额补救、例外审批人及期限必须由后续已接受 ADR 定义。
5. 评测输入只经 assistant-delivery、trusted-query 与 model-runtime 的最小只读门面取得；
   evaluation-operations 不读取其他上下文的表或可变对象。跨上下文契约不得包含问题、回答、提示词、
   证据正文、对象位置、成员详情、令牌、密钥、端点或供应商原始错误。
6. 审计导出、成员资格列表、邀请、授权委派、正文读取、租户预算、平台运营工作台、M7 和 M8 不在
   本 ADR 范围内。

## 主要备选方案及拒绝原因

### 方案 A：独立冻结评测运行与发布决定，并由领域服务复核

接受。`EvaluationRun`、`ReleaseDecision` 与 `AssistantVersion` 分别具有独立标识、保留、并发、
撤销和变化压力；发布入口只得到一项小而可验证的授权结果。阈值、数据集和例外规则可以在
evaluation-operations 内演进，而不泄漏到助手版本、页面或查询路径。

### 方案 B：在 `AssistantVersion.publish` 中直接读取当前评测、预算和审批状态

拒绝。当前状态和阈值会覆盖历史发布证据；助手版本将拥有跨上下文的规则和查询依赖，也无法表达
拒绝、例外和保留的独立事实，违反 ADR-0031 的聚合边界。

### 方案 C：由控制台页面或应用服务在发布前提交“已评测”布尔值

拒绝。调用方可伪造该字段，且会把身份、版本匹配和失败关闭规则扩散到 HTTP、前端与多个服务；
它不能证明评测输入、实现版本或结论来源。

## 后果和后续证据

本 ADR 只接受对象边界和失败关闭方向。下列会改变产品结果的参数仍须先由后续 ADR 确认；在确认前
不得创建生产聚合、迁移、公开接口、
前端路由或修改助手发布语义：

- 评测数据集的内容分类、允许答案／拒答期望和版本保留规则；
- 指标集合、每项最低阈值、样本不足与运行失败的失败关闭语义；
- 发布决定的权限主体、例外是否允许、例外期限和补救工作包要求；
- 预算的计量单位、作用域、周期、币种／价格快照、超额与恢复语义；
- 审计导出的字段白名单、授权范围、产物保留和清除规则。

接受后必须先写红灯，至少证明：不匹配助手版本／修订／租户的决定不能发布；失败或不完整评测不能
产生通过；过期例外、当前阈值或页面状态不能替换冻结决定；跨上下文输入不含正文或密钥。随后才补齐
纯领域、应用、真实 PostgreSQL、自动配置、HTTP／事件、角色浏览器和全量验证证据。

现有 `PUBLISHED` 版本继续按 ADR-0016 的冻结事实运行，不追溯补造评测或发布决定；本草案只约束本
ADR 接受后的新发布命令。若接受后需要对现有 `DRAFT` 版本设置过渡期、重新评测或废弃规则，必须在
实施前写入迁移方案并由产品负责人确认。
