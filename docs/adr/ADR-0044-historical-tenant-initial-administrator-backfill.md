# ADR-0044：历史租户初始管理员的显式回填边界

## 状态

提议

## 日期

2026-08-03

## 决策负责人

待用户代表产品、架构与安全负责人确认。

## 背景和难以逆转的约束

ADR-0041 要求每个 `TenantLifecycle` 都拥有可验证的初始管理员主体，且只有完成初始化的
租户可以激活。ADR-0042 已把凭据收回 `SubjectIdentity`，ADR-0043 已建立独立平台治理会话。

代码图谱和 `V202607270001`／`V202608030001` 证明历史 `organization_access.tenant` 仅含租户
状态，`tenant_membership` 也没有“该成员是首次管理员”的历史事实。任何按最早成员、现有权限、
登录名或平台管理员猜测主体的迁移，都不能证明初始管理员归属，并会把当前数据偶然形态写成
不可逆的治理事实。

## 决策内容

提议选择方案 A：在生命周期持久化迁移前，由拥有历史租户责任的人工运营方提供逐租户、显式、
可审计的 `tenantId → SubjectId` 初始管理员映射。该输入只允许引用已经存在、处于 `ACTIVE` 状态且
已经属于目标租户的主体；迁移在单一事务中验证映射完整性和唯一性，建立 `TenantLifecycle`，并将该
成员资格显式确认为 `TENANT_ADMINISTRATOR`。

映射输入不进入版本库、日志、令牌、HTTP 请求或应用配置。部署变更记录必须保存输入负责人、
复核人、租户数量、映射摘要和执行结果，但不得记录密码摘要、令牌、正文或密钥。只要任一历史
租户没有唯一有效映射，整次回填失败关闭，不创建部分生命周期根，也不改变原有租户会话语义。

新建租户不使用回填路径，仍由 `TenantProvisioning` 与平台治理会话在同一事务建立生命周期和
初始管理员成员资格。

## 主要备选方案及拒绝原因

### 方案 A：人工确认的显式主体映射

提议接受。初始管理员是治理责任归属而非可由数据形状推断的技术字段；逐租户映射保留业务负责人
的明确确认，并能在迁移前验证主体状态、租户成员归属和完整覆盖。

### 方案 B：按最早成员、现有成员角色或权限自动推导

拒绝。历史成员资格没有初始管理员事实，且 `membership_role` 是 ADR-0042 后的默认值，不能回溯
证明建立时的责任归属。自动推导会将偶然数据固定为不可逆治理事实。

### 方案 C：为历史租户创建没有初始管理员的生命周期，或全部默认激活

拒绝。它违反 ADR-0041 的初始化和激活前置条件；后续平台挂起／恢复、审计和管理员登录将失去
可复核责任主体。

## 后果和后续证据

- 接受后先写红灯：缺失、重复、跨租户、禁用主体或非成员映射均必须导致整批回填回滚，且没有
  `TenantLifecycle`、成员角色变更或发件箱残留。
- 真实 PostgreSQL 必须证明映射完整时，生命周期、初始管理员成员资格和最小事件同一事务提交；
  并发建立失败方不覆盖既有租户。
- 平台 HTTP 路由只能从 `PlatformRequestContext` 取得操作者；路径中的 `tenantId` 是业务资源目标，
  映射中的 `SubjectId` 是经审计的初始管理员事实，二者都不是可伪造登录状态参数。
- 接受本 ADR 不授权平台授权管理、邀请、密码重置、租户销毁、正文读取、评测、发布审批或 M7／M8
  实现。
