# ADR-0055：私有评测执行的明文内存边界

## 状态

提案。

## 日期

2026-08-05

## 决策负责人

产品、架构、安全、助手负责人和评测负责人。

## 背景和难以逆转的约束

ADR-0050 要求评测输入通过 assistant-delivery 的可信回答能力执行，同时禁止
evaluation-operations 与 assistant-delivery 的跨上下文契约持有问题、回答、提示词、证据正文、
对象位置、成员详情、令牌、密钥、端点或厂商原始错误。ADR-0051 和 ADR-0053 又使
evaluation-operations 成为私有合成评测条目的唯一所有者。

现有 `AssistantTrustedAnswerExecutor` 必须接收问题文本，`AssistantTestRunService` 会建立用户测试运行、
持久化终态并返回回答，均不能用于评测。直接由 evaluation-operations 调用执行器会让问题穿过既有
跨上下文 seam；让 assistant-delivery 读取评测对象则会泄漏私有对象位置并破坏数据集所有权。

因此，在不新增明确边界前，任何评测运行应用服务都会违反至少一项已接受 ADR，不能以实现细节绕过。

## 待决策内容

选择下列一项作为唯一的正文执行边界；选择后才可创建评测执行应用服务、持久化、HTTP 或浏览器入口。

### 方案 A：命名的受限内存评测执行门面

允许 `EvaluationAssistantExecution` 作为唯一例外：evaluation-operations 逐条在内存中向
assistant-delivery 传递私有评测输入，assistant-delivery 在同一调用内执行并仅返回结果类别、
候选数量、稳定证据标识集合和失败类别。该门面不得持久化、日志记录、审计投影或 HTTP 返回输入、
回答、提示词、证据正文、对象位置、令牌、密钥、端点、成员详情或厂商原始错误。调用结束后双方均不
保留明文；任何解析、执行或缩减失败均形成无正文的失败类别，评测运行失败关闭。

该例外只适用于同租户、`DRAFT` 且受控模型绑定的助手版本，以及 `SYNTHETIC` 私有数据集；它不改变
普通查询、草稿人工测试或发布路径。

### 方案 B：保持 ADR-0050 的绝对禁止

不允许跨上下文传递任何评测题目。必须另行决定执行能力、数据集所有权或运行时的共同归属后才能开放
评测执行。

## 主要备选方案及拒绝原因

### 方案 A：受限内存门面

候选。它保留数据集归 evaluation-operations、模型和可信回答归 assistant-delivery 的所有权，同时把
明文暴露压缩到不可持久化的单次调用；缩减后的跨上下文结果仍严格不含正文。

### 方案 B：绝对禁止

候选。它具有最强的字面隔离，但在当前已接受的对象所有权下没有可执行路径，会阻止 ADR-0050 已要求
的评测运行，直至重新分配一个上下文的关键职责。

### 方案 C：复用 `AssistantTestRunService`

拒绝。该服务拥有人工草稿测试的配额、请求者、终态持久化和回答输出语义；评测不能伪装为用户测试，
也不能存储或返回正文。

### 方案 D：evaluation-operations 直接读取助手表或 model-runtime

拒绝。它会越过 assistant-delivery 的草稿、受控绑定和可信回答边界，并把模型配置与运行时内部结构泄漏
到评测上下文。

## 后果和后续证据

若接受方案 A，先写红灯证明：门面输入与输出模型不包含被禁止字段；跨租户、非草稿或非受控模型目标
拒绝；执行异常不携带原始错误且使运行失败；评测结果和所有持久化／HTTP 投影不含正文。随后补齐纯领域、
应用、真实 PostgreSQL、自动配置、HTTP 与浏览器角色回归。

若选择方案 B，WP-0014 保持“正文读取、评测执行和发布授权未开放”，并须另开 ADR 决定执行与数据集的
共同边界；不得用 controller、仓储或共享表绕过该决定。
