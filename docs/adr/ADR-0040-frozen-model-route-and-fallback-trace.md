# ADR-0040：冻结聊天模型路由与回退调用轨迹

## 状态

已接受

## 日期

2026-08-02

## 决策负责人

用户，代表产品与架构负责人。

## 背景和难以逆转的约束

ADR-0016、ADR-0023 与 ADR-0037 已将助手／查询所用的受控模型事实冻结，并要求可信回答经过受权检索、证据选择、受控对话和引用核验。当前 `AssistantTrustedAnswerExecutor` 对单一聊天绑定进行调用；当该模型发生瞬态故障时，系统只能把已经占额的运行失败关闭。

M5 需要多厂商和路由／回退能力，但由当前可用模型临时替换历史冻结目标会使回答、诊断和后续审计不可复核。让调用方分别实现回退也会复制可信链路；让嵌入模型回退则可能与已发布索引的维度和构建事实不兼容。M4 的 `QueryDiagnostic` 又明确禁止向最终用户或审计读取投影暴露模型标识、供应商错误、问题或回答。

## 决策内容

1. 每个新发布 `AssistantVersion` 可冻结一个有序的聊天路由：一个主候选和最多两个后备候选。每个候选必须是同租户、已启用、`CHAT` 类型的受控模型配置，并冻结配置、目录与能力修订；候选不得重复。现有历史版本保持单一聊天绑定兼容语义。
2. assistant-delivery 拥有聊天路由作为 `AssistantVersion` 内不可变值对象，并通过既有公开快照将其传给 model-runtime。model-runtime 提供唯一无状态的 `ChatRouteExecutor` 应用门面，负责按顺序调用候选；调用方不得循环、猜测或自行选择后备。
3. 仅在尚未向调用方交付模型正文、且失败已被 model-runtime 标准化为可回退瞬态调用失败时，执行下一个已冻结候选。权限拒绝、请求无效、配置冻结不匹配、检索／证据／引用校验失败以及任何非标准化失败均不得回退，保持现有失败关闭语义。
4. 嵌入绑定保持单一且与已发布索引兼容；本 ADR 不允许嵌入回退。工具、MCP、多模态和音频也不属于本 ADR。
5. 每次路由调用产生不可变内部 `ModelInvocationTrace`：只记录所属运行稳定标识、候选顺序、候选配置与目录修订、标准化结果、最小用量和延迟。它不得记录问题、回答、提示词、候选正文、对象位置、供应商原始错误、端点、密钥或令牌。
6. `QueryRun` 与 `AssistantTestRun` 各自在提交终态、最小引用、用量和既有事件时，同一事务提交其调用轨迹；任一写入失败整体回滚。`QueryDiagnostic` 的既有对外字段不扩张，且不得由轨迹重新计算或暴露模型标识。
7. 路由候选的可用性、权限和冻结能力在每次调用前复核；若主候选已不再可用，只有其失败满足第 3 条的标准化可回退条件时才可尝试后备。任何回退都不能读取当前助手版本、当前路由、当前索引或请求附带的模型数据。

## 主要备选方案及拒绝原因

### 方案 A：由 model-runtime 维护可变的全局路由策略

拒绝。它会把一次历史查询实际使用的模型选择隐含在当前健康状态或中心规则中，无法由助手版本冻结事实复核，也会让 M6 的审计和发布审批失去明确归属。

### 方案 B：让 `QueryRunService` 与 `AssistantTestRunService` 各自循环尝试模型

拒绝。两条路径会复制失败分类与回退顺序，破坏 ADR-0037 的唯一可信执行门面，并容易让草稿测试与普通查询发生语义漂移。

### 方案 C：同时回退聊天和嵌入模型

拒绝。嵌入向量维度和索引构建配置是知识版本兼容事实；查询时替换嵌入模型会改变候选空间，无法保证既有引用和索引可复核。

### 方案 D：把完整请求、响应和供应商错误写入诊断或事件

拒绝。它违反 ADR-0036、ADR-0038 与 ADR-0039 的最小留存、最小披露和事件边界。

## 后果和后续证据

- 接受后，先以红灯证明：助手版本拒绝重复、错误类型或未冻结候选；非瞬态失败不回退；嵌入绝不回退；调用轨迹不含正文、端点、密钥或供应商错误；任一轨迹写入失败不留下终态半成品。
- 随后补齐 model-runtime 的失败标准化与路由执行、assistant-delivery 的版本冻结与草稿测试、trusted-query 的原子终态、真实 PostgreSQL、自动配置、Bearer HTTP／事件、浏览器角色任务和 `make validate` 证据。
- 接受本 ADR 不授权工具、MCP、多模态、音频、用户配置厂商／端点／密钥、M6 预算／审批或 M7／M8 功能；这些能力须各自先有范围与 ADR。
