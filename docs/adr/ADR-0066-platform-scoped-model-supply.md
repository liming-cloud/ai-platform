# ADR-0066：平台范围模型供应链

## 状态

已接受。

## 日期

2026-08-13

## 背景

ADR-0065 已确定全局模型目录必须绑定已发布部署的冻结能力快照。现有 `ProviderConnection` 与
`ModelDeployment` 都属于租户：连接、凭据轮换、探测、停用和可见性均以 `TenantId` 为边界。若把租户部署
直接发布到全局目录，一个租户即可改变其他租户的新模型配置和调用可用性，既违反租户隔离，也无法明确谁拥有
供应商凭据和停用责任。

本提案不以“同一模型定义复用于开发、测试、生产等多个运行环境”为目标。当前产品只有一套本地研发环境；
这里的部署是实际可调用的模型端点、凭据、实测能力及其生命周期，不是平台运行环境。需要解决的当前产品问题
是：全局目录不能引用任一租户拥有的模型部署。

## 提议决策

新增平台范围的连接和部署供应链，且它是全局目录的唯一来源：

1. 平台范围连接、模型发现、部署、能力验证和发布只由 `PLATFORM_ADMINISTRATOR` 通过平台会话维护，使用
   `model-platform:write`；租户会话和租户模型角色不得读取、创建、探测、发布或停用它们。
2. 平台范围凭据、连接和部署不带 `TenantId`，而带稳定的平台所有权范围；租户范围实体维持现有模型与数据，
   不迁移、不复用、不提升为全局资源。
3. 平台目录只能从当前 `PUBLISHED`、`HEALTHY` 且验证未到期的平台部署建立，并冻结部署标识、修订、连接修订、
   厂商类型、模型编码、模型类型与实测能力。平台部署停用、连接修订变化或验证到期后，目录仍保留审计事实，
   但不得用于新的模型配置或运行时调用。
4. 平台目录、平台部署与租户模型配置只通过安全快照和稳定标识协作；不得跨上下文读取租户连接、凭据、原始
   探测结果或可调用客户端。
5. 当前本地验收按“平台管理员建立确定性平台连接 → 发现 → 发布嵌入部署 → 建立并发布目录 → 租户建立并
   启用模型配置 → 首份发布”的完整链路完成。不得以直接 SQL 建立目录或借用租户部署。

## 非目标

- 不新增开发、测试、生产等多运行环境的编排、同步或跨环境复制。
- 不允许租户部署提升为平台资源，也不改变既有租户模型调用的所有权和费用归属。

## 备选方案

### 方案 A：新增平台范围供应链

接受。平台全局目录拥有独立、可审计的供应来源；租户隔离与凭据所有权保持不变。

### 方案 B：允许租户部署发布到全局目录

拒绝。租户停用、凭据轮换或验证失效会影响其他租户，且会将租户所有的供应商关系提升为平台共享资源。

### 方案 C：全局目录不关联真实部署

拒绝。目录无法证明模型经当前真实探测与发布，违反 ADR-0058 和 ADR-0065 的供应链约束。

## 实施与验证条件

- 先以红绿测试证明平台／租户范围互不可见，平台目录拒绝租户部署、草稿部署、过期验证和伪造快照。
- 平台管理员角色变更必须撤销旧平台会话；租户模型管理员仍只获得现有租户模型菜单。
- PostgreSQL、HTTP 和 SPA 均使用服务端分页，不暴露 Endpoint、凭据、密文或原始供应商响应。
- 实施必须以平台范围表结构、公共 HTTP 路由和独立目录实现为边界；不得把租户资源原地提升或扩权。
