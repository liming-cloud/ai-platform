# ADR-0057：企业账户、角色权限与导航能力投影

## 状态

已接受。

## 日期

2026-08-09

## 决策负责人

用户，代表产品、架构、安全、平台运营与租户运营负责人。

## 背景和难以逆转的约束

ADR-0042 已建立全局 `SubjectIdentity` 与只引用主体的租户成员资格，ADR-0048 已建立统一浏览器登录和最小工作区能力清单。但是当前租户成员角色只有 `MEMBER` 与 `TENANT_ADMINISTRATOR`，平台权限语言也只覆盖平台会话和租户生命周期治理。账户建立、启停、凭据重置、成员资格、角色、权限授予、撤销和会话失效仍没有面向管理员的企业闭环。

现有导航由前端静态数组和少量工作区类别决定。若另建一套“菜单权限”，页面可见性会与后端授权分裂；若继续硬编码角色，新增知识管理员、模型管理员、评测人员或审计人员时只能修改代码和演示夹具，无法由企业管理员治理。

## 决策内容

选择方案 A：由 organization-access 拥有版本化的账户、成员资格、角色、权限目录和角色绑定；platform-security 只从已验证会话恢复有效权限与权限版本；前端导航是有效能力的只读投影，不是授权事实。

1. `SubjectIdentity` 继续是全局可认证人员账户的唯一凭据所有者。M6 企业账户管理必须提供建立、启用、禁用和受控凭据重置；禁用、凭据重置或权限收回必须撤销受影响会话。明文口令只存在于写入请求和校验调用期，不返回、不记录、不复制到成员资格。
2. 租户成员资格只表达主体在一个租户内的参与关系，不保存登录名或凭据。平台授权、租户成员资格和资源授权不能互相隐式推导。
3. 权限目录以稳定 `PermissionCode` 表达“资源类别 + 操作”，并声明适用的 `PLATFORM`、`TENANT` 或明确资源范围。新增权限必须有真实后端授权点、角色任务和失败关闭测试；没有调用方的权限不得提前创建。
4. 角色分为不可删除的内置角色模板和租户可管理的自定义角色。角色绑定一组版本化权限，成员通过角色绑定取得权限；首条切片不提供绕开角色的个人直接授权。平台角色与租户角色分别治理，不能以租户角色取得平台范围。
5. 权限变更产生新的权限版本并撤销受影响会话或使旧会话在下一次解析时失败。前端缓存、浏览器标签页和长连接都不能继续使用旧权限事实。
6. `browser-session` 只返回导航所需的最小能力代码、允许进入的工作区类别、显示角色和会话期限，不返回完整策略、成员详情、凭据或 token。每个业务接口继续执行服务端授权，伪造能力清单、菜单状态或 URL 不改变结果。
7. 菜单配置不是第二套 ACL。管理员在角色页面配置权限，并可预览该角色的菜单、路由和操作能力；实际导航由“已发布路由所需能力”与“当前会话有效能力”的交集生成。菜单隐藏只保护注意力，不授予或撤销权限。
8. 所有账户、角色、权限和绑定变更必须记录不含口令、token、正文或完整策略快照的审计事实。管理员可以解释某项能力来自哪个角色及适用范围，但不能由该解释接口读取无权资源。
9. 人员账户与浏览器角色治理属于本 ADR。服务账户、外部身份联邦、邮件邀请、设备凭据和开发者 API Key 具有不同凭据与撤销语义，仍须独立 ADR，不能复用人员口令或浏览器会话实现。

候选内置角色至少覆盖平台管理员、平台运营、租户管理员、知识管理员、模型管理员、助手负责人、评测人员、发布审批人、审计人员和问答用户。每个角色的准确权限集合必须在实施设计卡中由实际任务和后端授权点推导，不能把候选名称直接当作权限。

## 主要备选方案及拒绝原因

### 方案 A：版本化 RBAC 与服务端能力投影

接受。账户、角色、权限和导航各有单一所有者；角色可以由企业治理，导航自动反映当前权限，后端仍保持最终授权。权限变化集中在组织访问和安全会话边界，能够通过版本与会话撤销即时生效。

### 方案 B：分别配置后端权限和菜单权限

拒绝。两套配置必然产生“有菜单无接口权限”或“有接口权限无入口”的漂移，且菜单隐藏无法阻止直接 URL 或 API 调用。

### 方案 C：继续使用固定角色枚举和前端静态菜单

拒绝。它不能支持企业自定义职责与最小权限，也会迫使每次角色变化同时修改数据库夹具、后端常量和前端代码。

### 方案 D：允许个人直接授权作为默认路径

拒绝。个人散授难以解释、回收和审计，会让角色失去治理意义。确有例外授权场景时，必须另行定义期限、批准和回收规则。

## 后果和后续证据

- 实施前先建立账户、角色、权限目录、角色绑定和能力投影的领域设计卡，并以红灯证明跨平台／租户范围、旧权限版本、禁用账户、伪造菜单能力和直接 URL 访问均失败关闭。
- 随后补齐真实 PostgreSQL、会话撤销、自动配置、HTTP、统一控制台角色任务和浏览器多页签失效证据。
- 管理员必须能够在不修改数据库和配置文件的情况下建立人员账户、分配成员资格与角色、预览有效菜单、撤销权限并验证会话失效。
- 接受本 ADR 不表示 M6 完成，不授权服务账户、外部身份联邦、设备凭据、M7 或 M8 实现。
