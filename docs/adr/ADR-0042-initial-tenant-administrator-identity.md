# ADR-0042：初始租户管理员的身份凭据边界

## 状态

已接受

## 日期

2026-08-03

## 决策负责人

用户，代表产品、架构与安全负责人。

## 背景和难以逆转的约束

ADR-0041 已接受平台请求上下文、租户生命周期和“初始管理员必须是既有受控主体”的边界。代码图谱与现有 PostgreSQL 迁移确认：`organization_access.tenant` 已存在；`subject_id` 只存在于 `membership_credential`，没有全局主体表、全局凭据或平台主体关系。现有登录以 `tenantCode + loginName + password` 查询单一租户成员，签发的会话必含该租户与成员。

因此，当前系统不能同时证明“初始管理员是既有主体”与“新租户管理员能够安全登录”：只复制 `subject_id` 没有可验证凭据；复制任意现有成员密码哈希会把租户成员凭据悄然变成跨租户身份，且没有全局唯一性、撤销或审计边界。邮件邀请、密码设置和外部身份联邦又被 ADR-0041 明确排除。

## 决策内容

本 ADR 选择方案 A：初始租户管理员及平台管理员使用全局主体与凭据聚合。无论选择何方案，租户、成员、平台范围、权限、渠道和令牌仍只能由已验证会话恢复，不能成为公共业务参数。

## 主要备选方案及拒绝原因

### 方案 A：引入全局主体与凭据聚合，并让成员资格仅引用主体

接受。organization-access 建立 `SubjectIdentity` 聚合根，拥有不可变 `SubjectId`、受控登录名、凭据摘要、状态和修订；平台授权成为主体的独立最小授权事实，租户成员只保存 `SubjectId`、租户角色和成员修订。平台登录与租户登录均从同一主体凭据验证，再按会话类型恢复 `PlatformRequestContext` 或 `TrustedRequestContext`。

建立租户时只能引用已启用主体；`TenantProvisioning` 以该主体创建初始管理员成员资格。凭据轮换、禁用和审计在主体层一次生效，避免复制密码哈希。现有 `membership_credential` 须经版本化迁移拆分为主体与成员资格，保留历史登录语义和可回滚迁移说明。

代价是增加 M6 的身份数据迁移、登录读取模型和实际角色浏览器回归，但它是唯一能以明确身份、凭据、撤销和审计边界满足 ADR-0041 的方案。

### 方案 B：从任意现有租户成员复制密码哈希到新租户成员

拒绝。它把租户成员凭据静默升级为全局主体凭据，且不能证明同一 `subject_id` 的唯一性、来源、撤销一致性或跨租户归属；密码轮换会产生不一致和越权恢复风险。

### 方案 C：创建没有可登录管理员的租户，日后通过邀请或密码初始化补齐

拒绝。它违反 ADR-0027 的“初始化租户管理员”和 ADR-0041 的激活前置条件；邀请、邮件、密码初始化或外部联邦均不在已接受范围内。

## 后果和后续证据

- 接受方案 A 后，ADR-0041 首条切片扩展为全局身份迁移、平台／租户会话恢复、生命周期和初始成员资格的单一可验收链路；实现前先更新 M6 领域设计卡与 TDD 证据合同。
- 红灯至少证明：相同登录名不能跨主体歧义；主体禁用或凭据轮换同时阻断平台与租户会话；租户管理员与平台运营不能取得平台上下文；租户建立不复制密码哈希；并发建立和初始化失败不留下半成品。
- 接受本 ADR 不授权邮件邀请、外部身份联邦、租户销毁、评测、预算、发布审批、审计导出或 M7／M8 功能。
