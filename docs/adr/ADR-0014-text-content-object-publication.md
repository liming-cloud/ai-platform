# ADR-0014：文本内容暂存、对象写入与发布一致性

## 状态

已接受

## 背景

WP-0003 需要把受治理文本数据源的原始内容保存到 MinIO，并在 PostgreSQL 记录对象引用、SHA-256 和发布版本。数据库和对象存储之间不存在单一原子事务；若先提交数据库再上传对象，查询可能读到不存在的内容；若直接把请求流写入最终对象且数据库失败，会留下不可追踪对象。把最多 20 MB 的内容整体读入堆内存还会放大并发上传时的内存风险。

## 决策

1. 文本数据源属于一个知识空间和一个租户。租户只来自服务端可信请求上下文，数据源和内容查询必须同时约束 `tenant_id`、`knowledge_space_id` 和 `data_source_id`。
2. 首个数据源类型只支持 UTF-8 纯文本。上传接口拒绝空内容、畸形 UTF-8、超过 20 MiB 的内容和不允许的媒体类型，不执行字符集替换或静默转码。
3. 上传内容通过受限暂存端口流式写入运行时临时目录，同时计算字节数和 SHA-256，并使用严格 UTF-8 解码器验证。应用层和领域层不依赖 Servlet、MinIO 或本地路径类型。
4. 最终对象使用内容寻址键，组成至少包含租户、知识空间、数据源、内容版本和 SHA-256。对象键由服务端生成，调用方不能提交桶名或对象键。
5. 原始内容写入私有桶，不生成匿名或长期公开地址。数据库只保存对象引用、摘要、字节数、媒体类型和版本，不保存原始文本。
6. 一次上传按以下顺序执行：
   1. 暂存、限制大小、验证 UTF-8 并计算摘要。
   2. 以内容寻址键幂等写入对象存储。
   3. 在单一 PostgreSQL 事务中校验租户、知识空间、数据源、乐观锁和幂等键，然后登记内容版本。
   4. 数据库失败时保留未引用的内容寻址对象，由定期孤儿清理按引用和保留期回收；不得在请求线程中盲目删除可能被并发请求引用的对象。
7. 同一租户、数据源、幂等键和同一内容摘要返回原内容版本；同键不同摘要失败。
8. 发布操作只允许从“内容已就绪”状态进入“已发布”，在同一数据库事务中增加数据源版本和发布版本。发布前必须使用对象存储元数据核验对象存在、摘要和字节数。
9. 数据源创建、内容登记和发布分别使用独立幂等记录；更新使用数据库版本条件，失败方不得产生成功发布记录。
10. 对象存储端口只暴露放置、读取元数据和受治理删除能力。MinIO 客户端、桶初始化、凭据和网络配置只存在于适配器与运行时。
11. MinIO 凭据只从部署 Secret 进入运行时，不写入数据库、日志、错误响应和审计详情。演示桶在启动时检查并创建，生产环境由运维预置并最小授权。

## 公共契约

- `POST /api/v1/data-sources`
  - 创建指定知识空间下的文本数据源。
- `POST /api/v1/data-sources/{id}/content`
  - 使用 `text/plain; charset=UTF-8` 流式上传原始内容。
- `POST /api/v1/data-sources/{id}/publish`
  - 发布当前已就绪内容。
- `GET /api/v1/data-sources`
  - 按知识空间和不透明游标列出当前租户数据源。

所有写操作要求 `Idempotency-Key`；请求体和查询参数不接受租户标识、桶名、对象键或本地路径。

## 影响

- 控制面需要受限暂存目录和对象存储运行时配置，容器继续保持根文件系统只读，只使用现有 `/tmp` 临时文件系统。
- 对象写入成功但数据库失败时允许短期孤儿对象存在，必须在后续运维工作包提供可审计清理任务。
- 本决策只覆盖原始文本发布，不包含分块、Embedding、索引版本或检索。
- MinIO Java 客户端的正式版本和具体接口必须在读取官方资料后由适配器实现证据固定，不进入领域契约。
