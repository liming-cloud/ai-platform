# ADR-0020：演示数据备份与隔离恢复契约

## 状态

已接受

## 日期

2026-07-27

## 决策负责人

产品负责人批准的 M1 计划，由运维负责人按 `WP-0007` 实施并以实际恢复演练验收。

## 背景

M1 已经形成 PostgreSQL、MinIO 和 Redis 三类持久化状态，但三者的事实语义不同：

- PostgreSQL 保存租户、成员、权限、知识元数据、内容引用、索引版本与向量、
  模型配置引用、助手版本、查询结果、引用、配额和用量事实。
- MinIO 保存数据库内容引用指向的受治理原始文本，对象键包含租户、知识空间、
  数据源、内容版本和内容摘要。
- Redis 保存 Sa-Token 会话。查询计量、配额和模型配置缓存都不以 Redis 为事实源。

当前 Docker Compose 固定了项目名、网络名、卷名和宿主端口。如果直接用同一编排
执行恢复，会复用或覆盖现有演示环境，无法证明备份可恢复，也存在破坏当前数据的风险。

## 决策

### 状态分类

1. PostgreSQL 与 MinIO 共同组成必须一致恢复的业务备份集。
2. PostgreSQL 是领域状态、幂等、配额、用量和审计事实来源。完整逻辑备份必须包含
   所有业务模式、Flyway 历史和 pgvector 数据。
3. MinIO 是受治理原始内容事实来源。备份必须保存对象键、对象字节、字节数、
   内容摘要和恢复所需的用户元数据。
4. Redis 只保存短期认证会话，不进入备份集。恢复后 Redis 必须为空，既有会话全部
   失效，用户通过 PostgreSQL 成员凭据重新登录。
5. 模型运行时缓存、临时上传文件、构建产物和容器文件系统是可重建状态，不进入备份。
6. 镜像摘要、Git 提交和非秘密运行参数进入备份清单；数据库密码、对象存储密码、
   Redis 密码、模型密钥值和会话令牌不得进入清单或证据。模型密钥引用仍属于
   PostgreSQL 业务配置。

### 备份一致性与保护

7. M1 使用短暂停写备份：停止控制面、查询运行时和摄取进程，确认进程停止后依次
   生成 PostgreSQL 自定义格式逻辑备份、对象清单和对象副本，最后恢复原服务。
8. 备份脚本必须设置严格文件权限、失败关闭，并用退出陷阱恢复原服务。不得删除、
   重建或改名源卷。
9. PostgreSQL 备份使用镜像内与服务端同主版本的 `pg_dump`；恢复使用同镜像内的
   `pg_restore`。备份完成后必须验证归档目录可读取。
10. 对象清单以 PostgreSQL 的内容引用为准。每个对象下载后校验字节数和 SHA-256；
    缺失、摘要不符或存在未被清单覆盖的恢复对象均导致失败。
11. 备份目录属于机密运行产物，可能包含密码摘要、回答、引用和企业原文，不能提交
    到 Git、进入普通日志或作为验收附件。目录权限为仅当前用户可访问，文件权限为
    仅当前用户可读写。
12. 可提交证据只包含表级计数、对象数量、不可逆摘要、耗时、镜像摘要、Git 提交和
    验证结果，不包含业务正文、对象键、人员标识、密码摘要、密钥引用或令牌。

### 隔离恢复

13. Docker Compose 的项目名、网络名、三个卷名和五个宿主端口必须支持显式覆盖，
    默认值保持现有演示环境不变。
14. 恢复只允许使用符合固定前缀的独立项目名，并在启动前确认目标卷不存在。
    源项目名、源卷名和源端口不能作为恢复目标。
15. 恢复顺序固定为：

    `创建隔离基础设施 -> 恢复 PostgreSQL -> 恢复 MinIO 对象与摘要元数据
    -> 确认 Redis 为空 -> 启动三个后端与两个前端 -> 执行恢复验收`

16. 恢复验收至少验证：
    - 所有 Flyway 迁移已成功并与备份一致。
    - 两个租户、知识空间、发布内容、活动索引、模型部署和助手版本事实存在。
    - 查询用量和脱敏审计计数与备份清单一致。
    - 每个数据库内容引用都能在 MinIO 找到相同字节数和摘要的对象。
    - 门店与校园管理员可以重新登录，且不能读取另一租户助手或查询事实。
    - 旧 Redis 会话没有被恢复。
17. 恢复演练结束后，只能按已经验证的隔离项目名显式删除恢复容器、网络和卷。
    清理前后都要确认源环境健康。

### 目标和边界

18. M1 的演示恢复点目标不超过 24 小时，恢复时间目标不超过 60 分钟。
19. 本决策证明单机 Docker 演示备份可恢复，不代表生产级持续备份、加密归档、
    高可用、跨区域灾备或零数据丢失。
20. 生产环境必须另立备份加密、密钥托管、保留周期、离站副本、恢复授权和定期演练
    决策，不能直接沿用演示凭据或临时目录。

## 主要备选方案及拒绝原因

### 直接复制三个 Docker 卷

拒绝。运行中的 PostgreSQL 和 MinIO 卷复制没有应用一致性保证，也会把 Redis
短期会话误当成业务事实，且恢复结果依赖容器内部布局。

### 只备份 PostgreSQL

拒绝。数据库只保存原始文本的对象引用和摘要，缺少 MinIO 对象后无法重建索引或
核验已发布内容。

### 同时恢复 Redis

拒绝。会话是短期可撤销凭据，恢复旧会话会扩大令牌有效期并与恢复时间点后的权限
变化冲突。查询配额和用量已经由 PostgreSQL 单事务保存。

### 在当前项目名下恢复后再比较

拒绝。固定卷名会直接复用现有数据，既不能证明备份有效，也可能破坏演示站点。

### 把完整备份提交为验收附件

拒绝。完整备份包含企业原文、密码摘要、回答和引用，Git 不是机密备份存储。
验收只提交不可逆摘要、计数和恢复结果。

## 后果与验收

- 编排文件需要增加默认不变的隔离参数，并增加配置门禁。
- `scripts/operations/` 提供备份、隔离恢复、验证和显式清理能力。
- 运行手册明确数据分类、权限、故障恢复、剩余风险和生产边界。
- WP-0007 必须提供一次真实隔离恢复的时间、事实计数、对象完整性、租户反例、
  Redis 空状态、源环境健康和清理证据。
