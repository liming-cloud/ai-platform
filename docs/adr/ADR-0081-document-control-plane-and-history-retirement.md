# ADR-0081：统一文档控制面与可验证历史退役

## 状态

已接受

## 日期与接受依据

2026-09-21。用户确认“整体设计、控制面先落地”“统一到 docs”“保留现有门禁粒度”“精简工作树，Git 保留历史”，并明确要求执行《仓库重设计与文档精简计划》。本记录只接受该计划，不接受新的业务功能、部署或数据操作。

## 决策

1. 文档统一到 docs 的 foundation、standards、architecture、design、tasks。稳定正文只表达当前有效内容，任务设计不覆盖已接受基线；明确事实错误按证据修正，产品、安全及公共契约取舍仍需已接受 ADR。
2. 产品前沿与当前执行任务分离。产品仍为 M6 / WP-0017，文档整理为 GOV-0001；WP-0014 继续承担 M6 人工门禁。工作包状态、独立切片结果和人工结论分别记录，不因迁移升级历史验收事实。
3. 任务 README 是恢复源；STATE 只保存全局指针；任务和决策索引由工具生成。保留最近证据最多 8 条、当前任务与产品前沿分别最多 12 个 ADR、恢复上下文最多 12 KiB。不维护两份可编辑状态。
4. 先盘点文件、来源提交、摘要、引用和处置原因，再合并、修正或删除。已退休资料通过完整 Git 提交与原路径恢复；历史证据定位提交与被验证源码提交不同，不得混用。保留关键人工接受、当前验收和机器依赖，不按日期、编号或扩展名批删。
5. 不建立全量旧文档归档目录。历史索引集中保存逐文件处置与恢复定位；校验必须实际读取 Git 对象、验证摘要及原证据绑定。当前引用必须有效，历史原文不改写；重要错误以最小 correction 说明。
6. 保留现有 make 治理入口和业务验收 WP、SLICE 参数。查询与校验只读，只有显式同步命令写生成索引。支持当前文件与固定 Git 历史两种证据定位，不降低完成门禁。
7. 后端六上下文、三个启动模块、经典四层和前端唯一 React/Fluent SPA 不因文档整理迁移或重写。代码问题登记责任、证据和退出条件，另按独立切片处理。
8. OpenDesign 固定项目、入口与版本仍为产品基线；不得修改原型迁就生产。截图仅 /private/tmp，秘密不进入文档、索引或日志。五项用户 fixture 暂存重命名不纳入本次提交。

## 替代范围

本 ADR 替代 ADR-0004 的 project/ 路径与状态重复维护方式，以及 ADR-0008 中文档、项目控制面和跨系统验证资料的目录约定；不替代它们的所有权、可追溯和局部变更原则。ADR-0022 的后端结构、ADR-0059 的单 SPA、ADR-0074/0079 的证据预算、顺序与人工门禁继续有效。旧 ADR 保留原文，其时点状态不是当前任务状态。

## 验证

拒绝无 Git 对象、摘要不匹配、证据绑定伪造、虚假整包完成、缺失人工接受、当前指针冲突和无效引用。执行治理单测、M6 矩阵检查、受影响脚本测试、project-status、project-verify、architecture-guard、resume-context；不重跑业务开户，不部署或重置数据。
