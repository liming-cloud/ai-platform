# ADR-0047：新租户初始管理员选择契约

## 状态

已接受

## 日期

2026-08-03

## 决策负责人

用户，代表产品、架构与安全负责人。

## 背景和待消除的矛盾

ADR-0041 要求公共业务请求不得携带平台范围、租户、主体、成员、权限、渠道或令牌，以保证当前
登录态只能从 Bearer 会话恢复。ADR-0042 同时要求新租户的初始管理员是一个显式指定、已启用且
既有的 `SubjectIdentity`，并明确拒绝默认复制平台操作者或复制凭据。

新租户建立因此需要表达一个**目标主体选择**，但该目标不是调用方当前身份。若把两类主体混为
一谈，要么客户端可伪造当前平台操作者，要么服务端只能错误地把平台操作者默认设为初始管理员，
两者都破坏最终产品语义。代码图谱确认 `TenantProvisioning` 目前没有应用调用方；此问题必须在
创建平台 HTTP、持久化入口或浏览器任务前确定。

## 决策内容

选择方案 A：仅对“创建租户”这一平台治理命令，允许请求携带
`initialAdministratorSubjectId` 作为**既有受管业务资源目标**。它不表示登录态，也不能覆盖或参与
`PlatformRequestContext` 的主体、权限、渠道、凭据类型或追踪标识。

该命令的最小契约为 `tenantCode`、`displayName` 与 `initialAdministratorSubjectId`；不接受
`tenantId`、当前主体、成员标识、平台角色、权限、令牌、渠道、凭据或任意范围切换字段。服务端
必须在已解析的 `PlatformRequestContext` 具有 `tenant-governance:write` 后，锁定并加载所选主体：

1. 主体不存在、已禁用或不适合建立初始成员资格时，统一失败关闭；响应、审计事实和日志不得泄露
   该主体的登录名、凭据摘要、既有租户成员关系或其他个人详情。
2. 应用层只执行授权、时间与标识分配、受锁读取、调用 `TenantLifecycle.provision` 与
   `TenantProvisioning`、以及单事务提交；不得把建立规则、成员角色或状态机转移到控制器或仓储。
3. 原子提交至少包含遗留 `tenant` 兼容行（固定为不可认证的 `DISABLED`）、`PROVISIONING`
   生命周期根、初始管理员成员资格与最小 `TenantProvisioned` 状态事实。认证切换后，旧列不参与
   新租户认证；只有后续合法激活到 `ACTIVE` 才能恢复租户会话资格。
4. 此例外只澄清“业务资源目标”可被提交；所有调用方当前登录态仍一律从令牌恢复。它不授权主体
   列表、主体详情、邀请、密码初始化、外部身份联邦、正文读取或租户销毁。

## 主要备选方案及拒绝原因

### 方案 A：以受管 `SubjectId` 表示初始管理员业务资源目标

接受。它使“谁创建租户”和“谁成为该租户初始管理员”保持两个明确概念：前者由令牌恢复，后者
由受控业务命令选择并由服务端验证。领域模型继续只引用稳定标识，不复制登录名或凭据。

### 方案 B：默认把平台操作者设为初始管理员

拒绝。它把操作授权与租户治理责任静默合并，违反 ADR-0042 的显式初始管理员约束；平台操作者也
可能不应获得目标租户管理权限。

### 方案 C：禁止一切主体目标字段，改由 HTTP 或前端推断

拒绝。现有令牌只证明当前操作者，不能推导另一名既有主体；前端缓存、Header 或查询参数推断只会
形成不可审计的隐式规则。

### 方案 D：创建没有初始管理员的租户，后续再初始化

拒绝。它重新引入 ADR-0042 已拒绝的不可登录租户，并会使生命周期激活缺少可证明的责任主体。

## 后果和后续证据

- 接受后先写红灯：无平台治理权限、伪造当前身份字段、未知或禁用目标主体、重复租户编码、并发建立
  与任一成员／发件箱写入失败均不得留下兼容租户行、生命周期根、成员资格或事件残留。
- 真实 PostgreSQL、自动配置、Bearer HTTP 与浏览器角色回归必须证明：平台会话的主体只来自令牌，
  请求中的目标主体不能改变操作者；租户管理员和平台运营均不能调用建立命令；建立结果在
  `PROVISIONING` 时不能签发租户会话。
- 接受本 ADR 不授权主体搜索／详情、邀请、密码初始化、正文读取、评测、预算、发布审批或 M7／M8
  实现。
