# ADR-0010：模型供应商密钥与出站访问边界

## 状态

已接受

## 背景

模型供应商探测需要读取租户密钥并访问外部地址。当前公共请求虽然只允许 `secret://` 引用，但仍使用裸字符串，扩展层也没有统一的密钥生命周期和出站地址校验。若由每个厂商自行处理，容易产生密钥日志泄漏、内网探测和云元数据访问风险。

## 决策

1. 在 `platform-security` 中建立与业务无关的安全契约：
   - `SecretReference` 负责引用语法和值语义。
   - `SecretResolver` 只按引用解析秘密，不接受任意存储地址。
   - `SecretValue` 使用可擦除字符数组保存短生命周期明文，实现关闭后清零，字符串表达始终返回脱敏值。
   - `OutboundEndpointPolicy` 在任何网络客户端创建或调用前验证目标地址。
2. `ProviderProbeRequest` 使用 `SecretReference`，并携带完成最小真实调用所需的模型编码；公共契约不得包含明文密钥或 Spring AI 类型。
3. OpenAI 兼容扩展必须按固定顺序执行：
   `验证出站地址 -> 解析秘密 -> 创建 Spring AI 模型 -> 最小调用 -> 关闭并清零秘密`。
4. 默认出站策略只允许 HTTPS 公网地址，拒绝用户信息、片段、环回、链路本地、站点本地、私有地址和云元数据地址。DNS 解析失败时关闭失败。
5. 本地确定性扩展不解析秘密、不访问网络。测试中的本地 HTTP 服务只能通过显式测试策略放行，不能替换生产地址校验逻辑。
6. 异常、日志、审计和公共结果只允许稳定错误码，不能包含密钥值、认证头或原始响应体。

## 影响

- 模型供应商扩展统一依赖 `platform-security` 公共契约。
- 密钥存储实现作为独立 `secret-stores` 扩展接入，模型上下文不感知 Vault、环境变量或云厂商类型。
- Ollama 等受信私网部署需要后续 ADR 定义运维授权的网络策略，不能通过租户请求直接绕过公网策略。
- 真实供应商测试必须验证密钥清零、异常脱敏、私网拒绝和超时行为。
