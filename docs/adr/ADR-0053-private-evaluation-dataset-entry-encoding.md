# ADR-0053：私有评测数据集条目编码与服务端校验

## 状态

提案（待人工选择）。

## 日期

2026-08-05

## 决策负责人

产品、架构、安全、助手负责人和评测负责人。

## 背景和难以逆转的约束

ADR-0051 已定义评测数据集的私有性、`SYNTHETIC` 分类、条目语义和质量门禁，但未定义条目如何编码、
由谁计算摘要和条目数、以及上传时如何拒绝语法错误。ADR-0052 只授权同租户 `assistant:write` 发起
受控登记，不把调用方提交的租户、身份、正文读取权或评测结论变为可信事实。

当前 `8a3bb5841` 已提供格式中立的私有对象存储、摘要校验和 PostgreSQL 清单；它刻意不开放 HTTP，
也不把调用方给出的 `entryCount` 当作已验证的评测事实。若现在为对象键、MIME 或 HTTP 静默选择 JSON、
CSV 或任意文件，会改变后续评测可复核性、条目引用解析、错误响应和测试集演进边界。

## 提案内容

推荐采用方案 A：私有内容使用严格 UTF-8 JSON Lines。每个非空行恰好表示一个条目对象，包含：

1. `input`：评测输入；
2. `expectedEvidenceStableIds`：稳定证据标识的非重复数组；
3. `expectedOutcome`：`ANSWER` 或 `REFUSE`；
4. `allowedAnswers`：仅 `ANSWER` 可选的私有允许答案集合。

服务端在写入私有对象前流式验证 UTF-8 和逐行 JSON 结构，计算 SHA-256 与有效条目数；只有当
`ANSWER` 的期望证据集合非空、`REFUSE` 不含允许答案且所有稳定标识合法时，才能形成
`EvaluationDatasetRegistrationContent` 和发布清单。空行、重复稳定标识、未知字段、畸形 JSON、
空数据集、非合成分类或任何读取／校验失败均拒绝，且不得留下可发布清单。请求体不再提交摘要或条目数。

HTTP 只接收私有 multipart 内容和保留策略标识；租户、主体、成员、权限、分类、摘要、条目数、版本和
追踪标识只从 `TrustedRequestContext`、服务器校验和领域创建过程取得。成功投影至多返回无正文的标识、
摘要、条目数、分类、状态、修订和创建时间；不得创建正文读取、导出、普通列表或日志路径。

## 主要备选方案及拒绝原因

### 方案 A：严格 UTF-8 JSON Lines 与服务端计数

推荐。嵌套的期望证据稳定标识和可选允许答案保持显式类型，不依赖分隔符转义约定；逐行校验可以在不把
正文写入关系表、事件、错误响应或前端状态的条件下稳定计算摘要和条目数。单条坏记录能够以无正文错误码
失败关闭，数据集版本之间的差异仍由私有摘要表达。

### 方案 B：RFC 4180 CSV 与列映射

拒绝。CSV 的多值期望证据和允许答案仍需第二层列表编码；引号、换行和分隔符会让稳定标识集合的规范化、
错误定位和跨实现一致性依赖额外约定。CSV 多记录的标准分隔是 RFC 4180 的记录终止符，不是 `\n\n`；
采用本方案必须另行确定列、嵌套字段和规范化规则，不能由现有数据源 CSV 语义自动继承。

### 方案 C：保持不透明文件并信任调用方摘要和条目数

拒绝。它无法证明私有内容满足 ADR-0051 的 `ANSWER`／`REFUSE` 语义，调用方计数可与实际对象不一致，
且会让后续质量门禁从未经验证的输入推导通过结论。

## 后果和后续证据

接受后，先以红灯证明：畸形 UTF-8／JSON、空集、空 `ANSWER` 证据、`REFUSE` 允许答案、重复证据标识、
伪造摘要或条目数、无 `assistant:write` 与跨租户请求均不能登记；再实现私有暂存／校验操作结果、真实
MinIO／PostgreSQL 失败补偿、自动配置、令牌派生 multipart HTTP 和无正文浏览器回归。评测运行、发布决定、
`AssistantService.publishVersion` 接入、正文读取、预算、人工例外、审计导出、M7 和 M8 仍不在本 ADR 授权范围。
