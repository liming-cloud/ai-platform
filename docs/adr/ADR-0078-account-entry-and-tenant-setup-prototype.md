# ADR-0078：平台账户与租户开通职责拆分原型

## 状态

已接受

## 日期

2026-09-07

## 背景

用户再次拒绝 WP-0016 人工验收：平台账户页面实际管理全局人员，租户开通依赖预先创建的人员账户，租户登录入口不清晰，租户详情堆叠多种保存任务。

## 决策

1. 仅在 WP-0016 可丢弃原型中，平台账户页面只展示和创建平台管理员账户。租户管理员由平台在对应租户的管理员页面治理，不出现在平台账户目录中。“认证版本”保留为内部会话失效机制，不作为日常列表列。
2. 新增租户直接填写管理员登录名与初始密码，不再选择全局人员目录中的账户。先填写租户信息和配额，最后填写凭据并确认；租户、人员身份和管理员资格一次提交，任何校验或存储失败均不留下部分对象。
3. 保持统一人员身份、全局唯一登录名、固定三角色及平台/租户身份互斥。不建立第二套密码库，不自动迁移、删除或重新启用现有演示身份。原型只接受公开合成口令，不保存明文、摘要或用户真实凭据。
4. 提供平台登录、租户管理员登录和普通用户问答登录的明确入口。共用认证机制，入口不代表授权；错误入口不能把已登录的平台管理员切换为租户管理员。新增租户完成后可进入明确的租户登录入口，仍须本人认证。
5. 租户详情拆为概览、管理员、资源配额、可用功能、登录安全五页。每页仅保存自己的字段，URL 固定租户标识，取消与刷新不能影响其他设置。隔离、权限校验和密码不回显仍不可关闭。
6. 普通成员账号是否由租户管理员直接创建、重置和停用，仍等待本轮单独确认。本 ADR 不授予租户管理员重置他人凭据的新权限，也不扩展到邮件邀请、自助注册或管理员提权。

## 边界与后续

- 本决定替代 ADR-0042、ADR-0047 中“创建租户只能引用已有主体”的原型交互限制；统一主体和安全底线保持不变。生产 API、凭据处理与原子事务合同留待对应实施工作包冻结，不在本轮修改。
- ADR-0075 的平台配置租户功能、租户配置成员对话权限继续有效。资源配额和三项登录策略沿用 ADR-0076。
- 普通目录遵循 ADR-0059，原型用完整合成行模拟页码、大小、跳页、筛选和空结果；事件记录与消息仍按序号分批加载，不新增第二套目录分页。
- 本轮原型与代码继续由同一 OpenDesign 项目保存；人工拒绝仍有效，不能因机器验证通过进入 WP-0017。

## 验证

覆盖平台目录角色隔离、原子开通与失败回滚、重复登录名和口令不一致拒绝、凭据不入存储、三入口角色边界、租户上下文固定、独立设置保存，以及 390/1024/1440 和键盘操作。
