# ADR-0046：租户生命周期认证切换

## 状态

提议

## 日期

2026-08-03

## 决策负责人

待用户，代表产品、架构与安全负责人确认。

## 背景和难以逆转的约束

ADR-0041 规定 `TenantLifecycle` 是租户建立、激活、挂起和恢复的治理状态机；ADR-0044 与
ADR-0045 已使历史租户在受控映射完整时取得合法生命周期根。代码图谱显示，现有
`TenantMembershipMapper#findEnabled` 仍只依据旧 `organization_access.tenant.status = ENABLED`
签发租户会话，`PersonAuthenticationService` 直接消费该投影。

直接把认证 SQL 改为依赖生命周期根，会在历史回填完成前拒绝全部历史登录；永久同时判断旧状态与
生命周期状态，则会维持两个可变真相，特别是历史 `DISABLED` 租户恢复后会因旧状态仍为
`DISABLED` 而继续无法登录。两种做法都不满足产品最终一致性和 ADR-0044 的失败关闭要求。

## 决策内容

提议选择方案 A：引入一个不含租户、主体、成员或凭据详情的全局**生命周期认证切换事实**。
它只记录“历史回填是否已经完整且原子完成”：

1. 切换未激活前，认证保持当前旧 `tenant.status` 语义；历史回填失败、缺失映射或任一写入失败时
   不得激活切换，因此既有会话语义不变。
2. `TenantLifecycleBackfillService` 仅在同一事务内成功写入全部历史生命周期根、初始管理员角色和
   最小状态事实后，才激活切换事实；任一失败同时回滚该事实。
3. 切换激活后，`TenantMembershipRepository#findEnabled` 只以已验证成员资格、主体和
   `TenantLifecycle.status = ACTIVE` 恢复登录资格；旧 `tenant.status` 不再参与认证判定。
4. 新租户在 `PROVISIONING`、挂起租户在 `SUSPENDED` 时均不能取得新租户会话；激活和恢复后的
   `ACTIVE` 根是唯一授权状态来源。旧 `tenant.status` 仅保留迁移兼容列，不得再由状态迁移写入或
   被新业务读取。
5. 切换事实只能由回填原子提交基础设施读写，不提供 HTTP、令牌、配置、前端或普通运营接口；
   平台管理员仍只通过 `PlatformRequestContext` 操作具体租户生命周期，不获得正文读取能力。

## 主要备选方案及拒绝原因

### 方案 A：完成回填后以原子切换事实改用生命周期根作为唯一认证状态

提议接受。它把历史兼容窗口与最终单一事实源明确分开；回填未完成不改变登录，完成后认证与治理均
由同一生命周期根驱动。切换事实不含敏感数据，也不扩大公共接口。

### 方案 B：认证永久同时判断旧 `tenant.status` 和生命周期状态

拒绝。两个状态需要持续双写或双重解释；恢复历史禁用租户时任一遗漏都会造成错误拒绝或状态分裂。

### 方案 C：部署生命周期表后立即改为 INNER JOIN 生命周期根

拒绝。人工映射未完成时会把所有历史租户的正常登录变成失败，违反 ADR-0044 的会话语义约束。

## 后果和后续证据

- 先写红灯：未切换时保留旧认证；切换激活前的任何回填失败不改变认证；切换后只有 `ACTIVE`
  生命周期可签发会话，`PROVISIONING` 与 `SUSPENDED` 必须失败关闭。
- 真实 PostgreSQL 必须证明切换事实与整批回填同一事务提交，发件箱失败、并发失败或不完整映射均
  不会激活切换；切换后不再读取旧状态列。
- 自动配置、Bearer HTTP 和浏览器角色回归必须证明租户管理员不能越过 `SUSPENDED` 状态，平台管理员
  不能用平台会话读取租户正文。
- 接受本 ADR 不授权邀请、密码重置、销毁、正文读取、评测、发布审批或 M7／M8 实现。
