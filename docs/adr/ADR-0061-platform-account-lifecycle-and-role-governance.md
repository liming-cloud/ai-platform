# ADR-0061：平台账户生命周期与平台角色治理

## 状态

已接受。

## 日期

2026-08-10

## 决策负责人

用户，代表产品、架构、安全、平台运营与租户运营负责人。

## 背景和难以逆转的约束

ADR-0042 已将登录名与密码摘要收归全局 `SubjectIdentity`；ADR-0048 已将登录态只从 cookie 中
恢复；ADR-0057 又要求企业账户的建立、启用、禁用和受控凭据重置均撤销受影响会话。但现有
`SubjectIdentityRepository` 只读取已启用账户供认证，`PlatformAccessGrant` 仍把权限直接赋给主体，
平台没有账户目录、平台角色绑定或全局会话族撤销的管理员闭环。

把全局账户状态混入租户成员资格会使一个租户管理员影响其他租户；仅删除当前浏览器 cookie 又会让
其他标签页和已签发范围会话继续有效；继续以直接平台授权替代角色会与 ADR-0057 的可解释 RBAC
模型分裂。这些都是账户安全与权限回收的不可逆边界，必须先决策再实现。

## 提议的决策内容

接受方案 A：**organization-access 拥有全局人员账户与平台角色绑定；platform-security 只提供
全局主体的范围会话族撤销；平台账户管理员通过实际平台角色取得账户治理能力。**

1. `SubjectIdentity` 是唯一全局人员账户聚合根，拥有登录名、密码摘要、`ACTIVE`／`DISABLED`
   状态和并发修订。平台账户管理员可建立、启用、禁用账户或重置目标账户密码；明文口令仅在 HTTP
   写入请求、强度校验和摘要生成期间存在，绝不返回、审计、记录、复制或进入幂等指纹。首条切片
   不提供自助重置、邮件邀请、外部身份联邦或服务账户。
2. 平台访问改为不可删除的内置 `PlatformRole` 模板与 `PlatformRoleBinding`。首条模板只包含已有
   真实任务所需的 `PLATFORM_ACCOUNT_ADMINISTRATOR`、`PLATFORM_TENANT_GOVERNOR` 与
   `PLATFORM_OPERATOR`；`platform:accounts:manage` 只有在对应账户治理 HTTP 入口存在时才发布。
   历史 `PlatformAccessGrant` 只可由版本化迁移回填为等价角色绑定，不能继续作为并行授权来源。
   平台自定义角色因其能影响全部租户，另需独立 ADR，不能由本条提前引入。
3. 账户状态、密码摘要或平台角色发生有效变化时，应用层在同一治理操作中请求
   `PersonSessionFamilyRevoker` 撤销该主体的**全部**平台与租户会话族；撤销失败不得返回成功。
   新登录只读取活动主体及其当前平台角色能力。会话、导航缓存、长连接和直接 URL 都不能因旧权限
   或旧密码继续取得能力。
4. 禁用与角色撤销必须保护最后一个有效 `PLATFORM_ACCOUNT_ADMINISTRATOR`；同一账户不能以自身
   禁用、撤销其最后账户治理角色或以无平台能力的租户会话操作平台账户。密码重置只允许治理其他
   活动或禁用账户；是否允许管理员重置自身密码留作后续自助凭据 ADR，当前明确不提供。
5. HTTP 只接受 token／cookie 派生的平台上下文。账户目录使用页码、页大小和总数；建立、状态变更、
   密码重置和角色绑定使用独立 Dialog 命令，并在写后重新读取服务器投影。请求不得提交平台范围、
   主体身份、权限、会话、token 或菜单能力；目标 `subjectId` 只能出现在受授权资源路径中。
6. `browser-session` 继续只返回有效能力、显示角色和工作区类别。平台账户工作区及其菜单只由已发布
   路由能力与当前会话能力相交得到；预览不授予能力，服务端授权仍是最终事实。
7. 账户、角色和绑定审计只记录操作者、目标、操作类型、发生时间、结果与非秘密修订标识；不得保存
   口令、token、完整权限快照、正文或原始会话材料。

## 主要备选方案及拒绝原因

### 方案 A：全局账户根、内置平台角色和全局会话族撤销

提议接受。它与 ADR-0042 的单一凭据所有者、ADR-0048 的 token 派生登录态和 ADR-0057 的版本化
RBAC 一致；跨租户账户影响只由平台能力触发，且密码或权限回收能立即覆盖所有范围会话。

### 方案 B：由租户成员资格禁用账户或重置密码

拒绝。成员资格只表达一个租户的参与关系，无法解释同一主体的其他租户和平台会话，也会把全局凭据
复制回租户模型。

### 方案 C：保留直接 `PlatformAccessGrant`，只新增账户管理接口

拒绝。它会形成“平台直授权、租户角色授权”两套语义，不能由角色页面解释能力来源或可靠地回收权限。

### 方案 D：只清除当前浏览器 cookie 或等待会话自然过期

拒绝。其他标签页、设备和范围 cookie 仍可能使用旧密码或旧权限，违反 ADR-0057 的撤销要求。

### 方案 E：首条同时开放平台自定义角色、服务账户与身份联邦

拒绝。它们分别需要跨租户影响分析、秘密生命周期和外部身份撤销协议；当前没有已确认调用方，提前
实现会扩大账户安全面并延误基础闭环。

## 后果和后续证据

- 接受后，先以纯领域红灯证明：禁用或重置后账户修订推进；禁用账户不能认证；最后平台账户管理员
  不可被禁用或撤销；停用平台角色不能再绑定；跨范围目标与伪造上下文失败关闭。
- 随后实现可锁定账户与角色的 PostgreSQL 原子提交、历史直接授权迁移、`PersonSessionFamilyRevoker`
  的 Sa-Token 适配、自动配置、无秘密 HTTP 投影和服务端分页目录；会话撤销失败必须有事务回归。
- 统一控制台只新增平台账户目录、建立／状态／重置／角色 Dialog、角色预览和高风险二次确认；写后重读，
  不平铺数据、不把菜单作为 ACL、不在前端缓存口令或身份事实。
- 接受本 ADR 不授权平台自定义角色、个人直接授权、服务账户、邮件邀请、外部身份联邦、正文读取、M7
  或 M8。
