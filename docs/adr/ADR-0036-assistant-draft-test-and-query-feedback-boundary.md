# ADR-0036：助手草稿测试与查询反馈边界

## 状态

提议

## 日期

2026-07-30

## 决策负责人

产品与架构负责人待确认。

## 背景和难以逆转的约束

M4 需要让助手负责人以草稿配置完成可复现测试，并让问答工作台提交反馈和受权诊断。ADR-0016 已固定普通 `QueryRun` 只接受 `PUBLISHED` 助手版本，且查询终态、引用、计量和恢复事件均是持久化事实。把草稿测试伪装为普通线上查询会绕过已发布边界；把反馈或诊断复制为浏览器状态又会失去租户、引用和脱敏约束。

本决策只处理草稿测试、查询反馈和诊断的领域边界。评测数据集、评测门禁、发布审批、版本比较、成本预算、渠道绑定和设备调用仍属于 M6 或后续里程碑。

## 提议的决策内容

1. `Assistant` 继续是身份和版本容器，`AssistantVersion` 继续是独立聚合根。可编辑草稿就是状态为 `DRAFT` 的助手版本，不新建语义重叠的 `AssistantDraft` 聚合。
2. 草稿测试建立独立的 `AssistantTestRun` 聚合根，不复用公开 `QueryRun`，也不让普通查询接口接受草稿。它冻结草稿版本、知识／索引、受控模型配置和测试输入摘要；每次结果必须经过与普通查询相同的授权检索、证据再鉴权和引用验证，失败关闭语义相同。
3. 草稿测试只能由拥有助手配置权限且在同一租户、知识空间范围内的主体发起；它不得成为对外查询渠道、不得自动发布助手、不得形成 M6 的评测通过结论或发布批准。
4. `QueryFeedback` 是关联已完成 `QueryRun` 的独立、不可变聚合根。它只保存提交主体、正负反馈、可选受控分类和经过长度／敏感信息规则处理的说明；不得复制问题正文、回答正文、提示词、证据正文或令牌。重复提交、修改、撤回、保留期限与进入评测的规则须在本 ADR 接受时一并确定。
5. 查询诊断是从 `QueryRun` 及其受控事件派生的只读投影，不是可写领域对象。它只向已有审计或运营权限开放，展示的候选数、权限决定、模型修订、引用校验和用量均须脱敏；不得向最终用户公开内部策略、资源标识、正文或密钥。
6. 流式恢复继续遵守 ADR-0016 与 ADR-0017：恢复的是持久化事件序号和已验证终态，不在引用验证完成前发布暂定模型正文。M4 不引入逐令牌业务恢复。

## 主要备选方案及拒绝原因

### 方案 A：让普通 `QueryRun` 接受草稿版本

拒绝。它会直接打破 ADR-0016 的已发布版本边界，并使公开渠道、计量和草稿测试混为一条不可审计的路径。

### 方案 B：仅在浏览器调用模型测试草稿

拒绝。浏览器不能替代服务端的租户、证据再鉴权、引用验证、密钥和审计边界，也无法复现失败原因。

### 方案 C：把反馈正文和完整诊断复制为查询记录

拒绝。它会扩散原始问题、回答、证据和可能的敏感信息，违反既有最小留存与脱敏原则。

## 后果和后续证据

- 本 ADR 被接受前，M4 只允许完成设计、测试案例和接口影响分析，不得实现草稿测试、反馈或新增诊断接口。
- 接受后，WP-0012 必须补齐领域设计卡、纯领域反例、应用编排、真实 PostgreSQL、HTTP／事件与浏览器角色任务证据。
- 必须证明草稿测试不能经普通查询或渠道访问；反馈不能越租户、不能复制敏感正文；无权限诊断不泄漏资源存在性；事件恢复不展示未验证正文。
