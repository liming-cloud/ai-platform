# ADR-0012：演示人员密码摘要与验证边界

## 状态

已接受

## 背景

WP-0003 需要提供受限演示租户的人员登录入口。密码验证属于高风险安全边界，不能使用明文、可逆加密或快速消息摘要，也不能把具体密码算法泄漏到领域模型和登录用例。摘要中的工作因子如果不受限制，还可能被恶意数据利用，耗尽认证线程。

## 决策

1. 密码验证通过应用层 `PasswordVerifier` 端口完成；领域层和登录用例不依赖密码库、Sa-Token 或持久化框架。
2. 首个适配器使用 JDK 正式 API 提供的 PBKDF2-HMAC-SHA256，每条摘要使用 16 字节随机盐、32 字节派生结果和不少于 600000 次迭代。
3. 摘要使用带算法、参数、盐和结果的版本化自描述格式。验证端只接受已批准的算法标识、固定字段数量、受控字符集和长度。
4. 验证端为迭代次数、摘要总长度、密码字符数和编码后字节数设置上下限；在执行高成本计算前拒绝畸形或超限输入。
5. 派生结果使用常量时间比较。处理完成后清除临时口令字符数组和 `PBEKeySpec` 内部副本。
6. 登录失败统一返回认证失败，不向调用方区分租户、账号、成员状态、摘要格式或密码错误。
7. 数据库只保存摘要，不保存明文、可逆密文或独立盐字段。密码、摘要和会话令牌禁止写入日志、审计详情和接口响应。
8. 摘要格式保留算法版本；后续升级工作因子或切换 Argon2id 时新增适配器，并在成功登录后受控换新，不能原地改变旧格式语义。

## 依据

- OWASP 密码存储指南要求使用强、缓慢的密码散列和每个密码独立盐；在需要 PBKDF2 时，PBKDF2-HMAC-SHA256 的建议工作因子为 600000 次。
- JDK 26 正式接口原生提供 `PBKDF2WithHmacSHA256`，无需为首个演示闭环引入额外密码实现或本地库。

## 影响

- 演示登录的单次密码验证目标耗时需要在部署硬件上测量，并限制并发和登录速率，避免形成计算型拒绝服务入口。
- 本决策只覆盖人员密码摘要，不定义设备凭据、单点登录或模型供应商密钥。
- 若未来确定非 FIPS 场景统一采用 Argon2id，需要以新 ADR 明确依赖、参数、容量测试和摘要换新策略。
