# ADR-0028：受治理数据源、同步产物与质量生命周期

## 状态

已接受

## 日期

2026-07-29

## 决策负责人

M3 产品范围已由产品负责人批准；后端负责人据此固定数据生命周期与公共契约边界。

## 背景

现有 `TextDataSource` 仅覆盖 UTF-8 文本的创建、上传和发布。它已经证明租户隔离、对象完整性、幂等写入和索引来源冻结，但不能表达文件、对象存储和结构化数据集的连接探测、同步、Schema、敏感级别、质量报告、重试和退役。

若继续向 `TextDataSource` 追加所有来源、连接配置和处理状态，任何一种连接器的重试、Schema 或质量规则都会扩散到其他类型，且无法保证索引只消费经过校验的不可变产物。

## 决策

### 1. 受治理数据源与不可变产物

- `GovernedDataSource` 表示可长期管理的来源身份，固定租户、知识空间、类型、显示名称、负责人、安全范围、生命周期状态和当前修订。
- `SourceRevision` 表示一次不可变的来源定义，冻结类型化连接配置、Schema 版本、敏感级别、质量规则集和创建者；已提交修订不得原地修改。
- `SyncArtifact` 表示一次同步得到的不可变输入产物，冻结来源修订、内容或记录摘要、对象引用、计数、新鲜度、同步时间和失败分类。
- `QualityReport` 只附属于一个 `SyncArtifact`，记录规则版本、通过/阻断/警告计数和受控问题摘要；不得记录敏感正文或连接凭据。
- 索引构建只能选择当前租户、知识空间内质量通过的已发布 `SyncArtifact`，并继续按 ADR-0023 冻结已授权的 Embedding 配置快照。

### 2. 类型化连接器与同步流程

首批受支持来源类型为 `FILE`、`OBJECT_STORAGE` 和 `STRUCTURED_DATASET`。每个类型实现独立的类型化连接器端口；领域和公共 HTTP 契约不得接收任意 URL、任意 JDBC 字符串或厂商 SDK 类型。

- `FILE`：管理员上传受控文件，由平台保存为来源产物。
- `OBJECT_STORAGE`：管理员从平台批准的对象存储范围选择对象或前缀；探测验证访问和元数据，不自动发布内容。
- `STRUCTURED_DATASET`：管理员提交受控数据集定义和字段映射；连接、抽样和 Schema 探测由同步工作进程执行。

数据源状态固定为：

`DRAFT -> PROBING -> READY -> SYNCING -> READY`，或由 `PROBING`、`SYNCING` 进入 `FAILED`；
`READY -> RETIRED`。同步成功只产生新的 `SyncArtifact` 和 `QualityReport`，不自动发布；发布和退役均为带预期修订的显式操作。

- `FAILED` 必须保存最后失败操作（`PROBE` 或 `SYNCHRONIZATION`），但不得保存外部错误正文、连接地址或凭据。重试只能回到该操作对应的运行状态，不能把探测失败伪装成同步重试；状态更新以来源修订乐观并发控制。

### 3. Schema、敏感级别、质量与索引

- Schema、字段类型、字段语义、查询资格和敏感级别以 `SchemaVersion` 冻结；结构化来源的行和字段策略在同步、质量检查和检索候选产生前执行。
- 质量规则由稳定标识和版本组成，最小结果分为 `PASS`、`WARN`、`BLOCK`。`BLOCK` 产物不得进入发布、索引或查询。
- 同步、质量和索引均由工作进程在数据库事务外执行外部 I/O；状态、租约、幂等键和最终事实在事务内原子登记。
- 索引来源快照由已发布的产物、Schema 版本、质量报告、分块策略和 Embedding 配置快照组成；重建创建新索引版本，不能覆盖活动版本。

### 4. 权限、失败与前端任务

- 所有读取和操作都从 `TrustedRequestContext` 获取租户与主体；无权限与不存在保持不可区分。
- 探测、同步、发布、退役、重试和索引构建必须独立授权、审计且具备稳定失败代码和恢复动作。
- 知识管理员在企业控制台的单一“数据”任务流中完成来源登记、探测、同步检查、质量处置和索引发布。页面不展示连接密钥、原始敏感数据、向量或无权资源。
- 平台管理员的对象存储批准范围、租户生命周期和跨租户管理不属于 M3，按 ADR-0027 留在 M6。

## 备选方案

### 扩展 `TextDataSource` 为全部来源的统一聚合

拒绝。它会把上传流、对象探测、结构化 Schema、重试和质量失败统一塞进单一状态机，调用方需要理解大量与当前类型无关的可空字段和非法组合；连接器变化也会反复改动既有文本路径。

### 每种来源建立一套独立数据源、质量和索引领域

拒绝。索引、授权、质量门禁和前端列表会重复实现，并使知识空间无法以统一方式组合已发布产物。

## 后果与验收

- M3 首个纵向切片先实现 `GovernedDataSource` 的登记、`FILE` 探测与不可变 `SyncArtifact`/质量事实；它不自动发布或替换既有活动索引。
- `OBJECT_STORAGE` 与 `STRUCTURED_DATASET` 只能在首个切片的公共契约、权限、质量和重试门禁通过后接入。
- 迁移保留 M1 文本数据源和索引事实；新 M3 索引不得通过隐式映射混用旧文本内容版本与新产物。
- 测试必须覆盖：跨租户、无权限、重复请求、并发修订、探测失败、同步失败、质量阻断、退役、模型配置失效和索引原子切换。
- 知识管理员须通过浏览器完成成功、失败、无权限和恢复路径；M3 全部证据完成后仍需人工评审才可进入 M4。
