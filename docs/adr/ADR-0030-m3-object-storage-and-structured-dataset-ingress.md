# ADR-0030：M3 对象存储与结构化数据集首版接入边界

## 状态

待产品确认

## 日期

2026-07-29

## 背景

ADR-0028 已把 `OBJECT_STORAGE` 和 `STRUCTURED_DATASET` 纳入 M3，但只固定了“平台批准的对象范围”和“受控数据集定义与字段映射”这两项约束。当前代码仅有 FILE 的平台对象事实，尚未存在可供租户管理员配置外部桶、云账号、JDBC 数据源或数据集连接凭据的平台管理能力；该能力按 ADR-0027 属于 M6 平台管理范围。

如果 M3 直接接受对象键、桶名、任意 URL、任意 JDBC 连接串或厂商 SDK 参数，会绕过平台批准范围，且会把连接密钥、网络出口、SSRF 和跨租户对象枚举风险带入知识管理员页面，与 ADR-0028 相冲突。

## 待决策事项

M3 首版需要确定 `OBJECT_STORAGE` 与 `STRUCTURED_DATASET` 的实际接入形态，确保其能完成草稿、探测、同步、质量、发布、索引和退役闭环，同时不提前实现 M6 的平台外部连接管理。

## 方案

### 方案 A：平台托管对象范围与上传 CSV 数据集（推荐）

- `OBJECT_STORAGE` 仅从平台托管、已按租户和知识空间授权的对象范围选择对象或前缀。浏览器和 HTTP 只传递平台签发的不可猜测范围标识与选择修订，绝不接收桶名、对象键、端点或凭据。
- 探测在工作进程中验证范围授权和冻结的对象元数据；同步将实际选中的对象集合、摘要、长度、媒体类型和新鲜度写为不可变产物，不把可变前缀作为索引输入。
- `STRUCTURED_DATASET` 首版接收上传至平台私有对象存储的 UTF-8 CSV，强制声明主内容字段和可选标题字段；字段名、逻辑类型、敏感级别、行过滤与映射版本随来源修订冻结。
- 同步在事务外解析 CSV、执行字段策略和质量规则，产物只保留可检索的规范化文本片段与受控统计，不记录原始敏感字段。
- 不提供 S3、OSS、COS、数据库或任意 HTTP 连接器；这些连接器在 M6 平台对象范围和凭据管理能力完成后再按类型单独决策。

### 方案 B：M3 直接接入外部对象存储与数据库

知识管理员输入云桶、端点、访问密钥、JDBC 或数据集 URL，平台在 M3 保存并探测这些配置。

拒绝。它违反平台批准范围和 M6 平台管理边界，并会扩大密钥、出站网络、SSRF、数据库方言、Schema 漂移和审计范围。

### 方案 C：只保留类型枚举，推迟两类来源

拒绝。WP-0011 明确要求实现三类来源，且产品主张结构化与非结构化数据共享受治理生命周期。

## 推荐决策与后果

推荐接受方案 A。它以最小可用的受控对象选择和 CSV 字段映射完成 M3 产品范围，复用既有私有对象存储、来源生命周期、质量产物和索引快照，同时避免把 M6 的平台连接与密钥治理提前塞入租户控制台。

接受后需新增并验证：

1. 不可变的对象范围／对象集合修订和 CSV Schema／字段映射修订；
2. 对象范围探测、CSV 抽样与质量结果，以及失败后按操作恢复；
3. 租户、知识空间、范围和字段敏感级别在同步、质量、索引和查询前的失败关闭；
4. 知识管理员浏览器中成功、空、无权限、质量阻断和恢复任务；
5. 真实 PostgreSQL、对象存储和索引快照证据。

在本 ADR 被明确接受前，不得新增这两类来源的公共 HTTP、持久化或连接器契约。
