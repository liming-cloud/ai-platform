# ADR-0035：来源快照作用域的索引分块标识

## 状态

已接受

## 日期

2026-07-30

## 决策负责人

产品与架构负责人

## 背景和难以逆转的约束

ADR-0015 要求稳定分块标识由来源摘要、分块策略、顺序和块摘要生成；ADR-0029 又允许同一索引版本同时冻结 M1 文本与 M3 已发布同步产物。当前实现把私有正文的内容摘要直接作为分块器的来源摘要。两个不同来源发布相同正文时，会生成相同 `chunk_id`，违反索引版本内向量表唯一性，并错误地丢失来源级引用事实。

正文相同不表示来源相同：来源类型、来源标识、冻结修订和发布产物均是可信引用与审计边界。以内容摘要去重会让查询无法明确返回哪个已发布来源支持该候选，且不能通过应用层跳过其中一个来源修复。

## 决策

1. 新建或重建索引的分块标识使用“来源快照身份摘要、分块策略、顺序和块摘要”计算；私有正文摘要只作为内容完整性与块摘要输入，不单独充当来源摘要。
2. 来源快照身份摘要必须覆盖来源类型、数据源标识、冻结来源修订、已发布同步产物标识（仅受治理来源）及其冻结正文摘要；字段采用稳定、无歧义的编码顺序。
3. 相同正文来自不同已发布来源时，必须保留为不同分块及不同 `data_source_id` 引用；查询候选和引用继续返回其实际来源，不执行跨来源内容去重。
4. 已完成的历史索引保持只读且不修改其分块标识。仅新建或重建索引使用此规则；索引版本、来源快照和构建摘要继续保持不可变。
5. 向量表继续以索引版本与 `chunk_id` 唯一，不新增跨上下文表或公共 HTTP 字段。实现只能在 knowledge-data 的冻结快照与分块入口之间生成该摘要。

## 主要备选方案及拒绝原因

### 方案 A：以来源快照作用域生成分块标识

接受。它保留每个来源的可追溯引用，符合 ADR-0015 的来源摘要语义，并将变化局限在新索引构建。

### 方案 B：在构建时按正文摘要跳过重复来源

拒绝。它会让一个合法已发布来源无索引证据，且没有可审计的来源选择规则。

### 方案 C：将向量表主键扩展为包含数据源标识

拒绝。它只掩盖分块身份错误，仍使同一候选标识对应多个来源；查询与引用契约将继续含糊。

## 后果和后续证据

- `IndexSourceSnapshot` 必须公开框架无关的来源快照身份摘要，构建工作器只将该摘要传入分块器。
- 需以纯领域测试证明相同正文的不同来源产生不同稳定分块标识；同一来源快照重建保持相同标识。
- 需以真实 PostgreSQL 证明混合来源索引可原子完成、发布、重建并返回各自来源引用。
- M3 浏览器验收需覆盖 FILE、STRUCTURED_DATASET、OBJECT_STORAGE 的索引构建、发布与重建；本 ADR 不代表 M3 已完成或可进入 M4。
