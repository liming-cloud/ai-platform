# ADR-0018：演示查询配额与运营事实投影

## 状态

已接受

## 日期

2026-07-27

## 决策负责人

产品负责人批准的 M1 计划，由后端、前端和测试负责人按 `WP-0006` 实施并
以自动证据验收。

## 背景

查询运行已经持久化租户、请求成员、助手版本、问题摘要、状态、令牌用量和
时间，但接受查询前尚未强制执行服务端限额，也没有面向租户管理员的用量和
脱敏审计接口。

查询配额是并发一致性问题，不能依赖“先统计、后插入”的应用层检查。运营读取
如果另建同步写入的审计表，又会让查询事实和审计事实在失败时产生分歧。
M1 需要证明受限演示闭环，但不需要提前建设商业计费、通用审计平台或在线
评测产品。

## 决策

### 配额来源与周期

1. M1 使用部署配置定义每个租户共享的：
   - UTC 自然日最大接受查询数。
   - 最大同时运行查询数。
   - 运行占用租约时长。
2. 配置是非秘密运行参数，必须为正数并在启动时校验。M1 不提供在线修改、
   套餐继承或临时扩容接口。
3. 每日限额只在首次接受查询时占用。查询最终回答、拒答或失败均不返还；
   被限额拒绝的请求不建立查询运行。
4. 并发限额只统计租约尚未过期的运行中查询。完成会释放占用，进程崩溃后
   租约到期自动释放。

### 原子接受与幂等顺序

5. 查询仓储的接受操作必须在单一 PostgreSQL 事务内依次执行：
   - 取得租户级事务顾问锁。
   - 查询幂等记录。
   - 已存在且请求摘要一致时返回原运行，不重复计量。
   - 已存在但摘要不一致时返回幂等冲突。
   - 统计当前周期接受量和有效运行租约。
   - 任一限额达到时拒绝。
   - 插入查询运行、冻结配额事实并写入开始事件。
6. 配额检查发生在助手解析、检索和模型调用之前。被拒绝请求不能触发任何
   外部模型副作用。
7. `QueryRun` 冻结接受时的 UTC 周期起止、每日限额、当日占用序号、
   并发限额和运行租约截止时间。后续部署配置变化不能改写历史解释。
8. 完成查询和写入终态事件在同一事务中清除有效运行租约。重复完成依靠
   乐观版本和唯一事件约束保持一次。
9. 超额统一返回 `429 QUERY_QUOTA_EXCEEDED`。安全详情只包含限额类型、
   固定限额和重置或重试时间，不返回租户、其他成员或其他查询事实。

### 审计与用量读取

10. M1 将 `query_run` 作为查询审计与令牌用量的唯一事实来源，不增加需要
    双写的通用审计表。
11. `GET /api/v1/audit-records` 要求 `audit:read`，按接受时间和查询运行
    标识组成稳定不透明游标，只返回当前可信租户的脱敏查询事实。
12. `GET /api/v1/usage` 要求 `usage:read`，按请求时间范围汇总当前可信
    租户的状态数量与令牌用量，并返回当前配额快照。
13. 两个接口都不返回原始问题、回答、提示词、引用正文、模型配置、密钥、
    租户标识或其他租户是否存在。
14. 问题摘要是审计相关标识，不是可逆正文；普通日志不得记录原始问题和
    返回正文。
15. M1 的审计投影只覆盖查询运行。配置修改、发布、撤销和导出进入后续
    通用审计上下文，不把本投影表述为完整企业审计。

### 最小评测

16. M1 使用版本控制的门店与校园合成数据和固定用例执行确定性离线评测，
    记录数据摘要、助手版本、索引版本、模型部署版本和代码提交。
17. 发布门禁至少校验：
    - 目标租户候选命中。
    - 跨租户命中为零。
    - 回答引用完整。
    - 证据不足时明确拒答。
18. 确定性模型结果只证明流水线回归和权限边界，不作为真实厂商模型准确率、
    召回率或用户效果声明。

## 主要备选方案及拒绝原因

### 在应用服务中先查询计数再创建查询

拒绝。并发请求可同时通过检查并突破限额，无法形成可证明的演示限制。

### 使用 Redis 自增作为唯一计量事实

拒绝。查询运行和计数跨存储提交会产生不一致，幂等重放和故障恢复也更难
解释。M1 使用 PostgreSQL 单事务换取清晰正确性。

### 被拒答或失败的查询返还每日额度

拒绝。模型和检索资源已经被消耗，返还会造成真实消耗与演示限制不一致。

### 为审计和用量各写一张事件表

拒绝。当前所需字段已由查询运行持久化，额外双写没有增加 M1 业务价值。

### 在运营页面展示原始问题和回答

拒绝。运营任务只需要状态、摘要和计量事实；展示正文会扩大企业知识与个人
信息的访问面。

### 在 M1 建设在线评测平台

拒绝。当前里程碑只需确定性发布门禁。评测编排、模型裁判和人工标注属于
后续企业运营能力。

## 后果与验收

- 查询仓储接受合同和 `QueryRun` 持久化结构需要升级，并补充真实 PostgreSQL
  并发、租约和增量迁移测试。
- 查询运行时新增稳定限额错误；控制面新增审计和用量只读入口。
- 演示角色新增 `audit:read` 和 `usage:read`，权限反例与跨租户反例必须覆盖。
- 控制台治理页必须消费真实接口，不能以静态数字或假成功状态代替。
- 配额锁会串行化同一租户的查询接受；M1 以正确性优先，容量阶段再用性能
  证据决定是否引入分片计数器。
- 完整通用审计、商业计费、多区域配额和在线评测必须另立决策。
