# ADR-0041：平台请求上下文与租户生命周期边界

## 状态

提议

## 日期

2026-08-02

## 决策负责人

产品、架构、安全、平台与租户运营负责人待人工确认。

## 背景和难以逆转的约束

ADR-0027 要求 M6 交付平台／租户双范围、平台管理员租户生命周期和严格的平台运营内容读取边界。ADR-0033 已固定：`TrustedRequestContext` 只能从 Bearer 令牌恢复租户、主体、成员、凭据、渠道和权限，不能以请求参数或 Header 伪造。

当前 `SaTokenTrustedContextArgumentResolver` 正确地只从已验证会话恢复租户请求上下文；`OperationsQueryService` 也只按该上下文的租户标识读取同租户汇总与审计投影。将平台角色、平台范围或目标租户塞进这些现有路径，会使租户标识可空或可伪造，并可能让平台运营通过运行权限读取内容。

平台建立、激活、挂起和恢复租户是跨 `TenantLifecycle` 与初始管理员成员根的业务操作。若由应用服务自行创建根、成员和事件，状态机、恢复语义与审计原子性将分散到 HTTP 和仓储层，违反 ADR-0031。

## 决策内容

若本 ADR 被接受，M6 首条纵向切片采用以下边界：

1. 新增仅供平台管理路由使用的 `PlatformRequestContext`。它只能由 platform-security 适配器从同一已验证 Bearer 会话恢复主体、凭据类型、渠道、权限版本、权限集合和服务端追踪标识；它不含租户、成员、目标资源或调用方追踪标识。
2. `TrustedRequestContext` 保持租户范围强制事实，现有租户 Controller、应用命令和授权策略不得改为接受可空范围、平台角色或范围切换参数。平台上下文、租户、主体、成员、权限、渠道和令牌均不得出现在公共业务请求对象中。
3. platform-security 仅在会话具有明确平台治理权限时解析 `PlatformRequestContext`；缺失／无效令牌、租户管理员令牌、平台运营令牌或任意伪造 Header、查询参数和请求体均必须在读取资源前失败关闭。
4. organization-access 新增 `TenantLifecycle` 聚合根，由 `TenantId` 标识，状态只能为 `PROVISIONING`、`ACTIVE` 或 `SUSPENDED`。仅允许 `PROVISIONING → ACTIVE → SUSPENDED → ACTIVE`；挂起不删除租户数据，销毁和保留另行决策。
5. 建立租户与初始化管理员使用无状态命名领域服务 `TenantProvisioning`，接收已加载的根、不可变初始管理员事实与时间，返回不可变操作结果。应用层只负责平台上下文授权、事务、加载、调用和原子提交；基础设施只负责映射、锁、发件箱与技术异常转译。
6. 每次成功建立、激活、挂起或恢复写入最小审计事实并以事务发件箱发布版本化生命周期事件。事件只含目标租户标识、前后状态、聚合版本、操作时间和最小恢复关联；不得包含正文、问答、提示词、成员详情、令牌、密钥或供应商错误。
7. 首条切片不授权评测数据集、评测任务、预算、发布决定、审计导出、平台运营摘要、平台模型目录页面、租户正文读取、邮件邀请或租户销毁。它们继续按 `foundation-m6-enterprise-governance-design.md` 的后续切片，经独立 ADR 决定。

初始管理员的主体来源采用保守前提：只能引用已存在且可被受控验证的主体。若产品需要邀请、电子邮件验证、密码初始化或外部身份联邦，必须先补充 ADR；不得将其隐含进建立租户接口。

## 主要备选方案及拒绝原因

### 方案 A：将 `TrustedRequestContext` 扩展为可选的平台／租户双范围对象

拒绝。当前租户上下文的强制租户事实会变成可空分支，所有租户授权调用方需要理解平台状态。它扩大认证 seam，容易让平台角色通过租户内容路径，违反 ADR-0027 与 ADR-0033。

### 方案 B：为平台路由使用独立、令牌派生的 `PlatformRequestContext`

提议接受。平台路由拥有独立的注入入口和失败关闭语义，租户上下文及既有 Controller 不变。安全适配、自动配置、HTTP 反例和浏览器角色任务的变更面集中在真实调用方。

### 方案 C：以 `tenantId` 参数、Header 或前端选中的范围切换平台身份

拒绝。调用方控制的值不能决定登录状态；即使与令牌比较，也会把可伪造身份协议扩散为公共契约，直接违反 ADR-0033。

### 方案 D：由应用服务分别创建生命周期根、初始成员、审计和事件

拒绝。跨根不变量、状态机和失败补偿将泄漏到编排层，难以保证并发、恢复和原子提交。应由 `TenantProvisioning` 返回不可变操作结果。

## 后果和后续证据

- 接受后先写红灯：租户令牌和平台运营令牌不能解析平台上下文；伪造范围字段无效；生命周期非法迁移、重复建立、管理员不完整和并发写入均失败关闭。
- 随后补齐纯领域、应用编排、真实 PostgreSQL、自动配置、Bearer HTTP／事件、平台管理员／租户管理员／平台运营浏览器任务，以及 `make validate`、`make project-verify` 与差异检查证据。
- 平台管理员只能对作为业务资源目标的租户生命周期执行授权操作；这不授予其以租户管理范围读取任意租户知识或问答正文。平台运营也不因运行权限取得内容读取能力。
- 接受本 ADR 不表示 M6 完成，也不激活 M7。评测、预算、发布门禁、审计导出和 M8 平台运营仍须各自完成设计、ADR、自动验收和人工评审。
