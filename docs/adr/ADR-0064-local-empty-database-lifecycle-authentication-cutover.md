# ADR-0064：本地空数据库的租户生命周期认证切换

## 状态

已接受。

## 日期

2026-08-12

## 决策负责人

用户，代表产品、架构、安全、平台与租户运营负责人。

## 背景和约束

当前产品只在本地研发环境运行，不存在需要保留的历史租户、成员或授权数据。ADR-0063 已允许清理本地
关联数据并由页面重新建立人员、角色和租户；ADR-0046 的认证切换事实却只规定在“历史回填完整提交”时
建立。新租户的兼容 `tenant.status` 依 ADR-0046 固定为 `DISABLED`，其真实认证状态在
`TenantLifecycle`。因此空本地库若不建立切换事实，已激活的新租户仍不能登录。

本决定仅解决本地空数据库的初始化，不改变 ADR-0046 对共享、测试、预发布或生产环境历史回填原子性的
要求，也不把本地例外扩展为认证 SQL 的新分支。

## 决策内容

选择方案 A：`local` profile 在 Flyway 完成正式迁移后额外扫描一个仅本地的 repeatable migration。

1. 该 migration 只在 `organization_access.tenant` 为零行时写入唯一
   `tenant_lifecycle_authentication_cutover` 事实；已有任一租户时不得写入，保持失败关闭。
2. migration 只写入 `singleton_key` 和发生时间；不写入账户、租户、成员、权限、凭据、会话或演示数据。
3. 它只能由 `application-local.yml` 显式引入。默认、`demo`、共享、测试、预发布和生产 profile 不得扫描
   该资源，继续只允许 ADR-0046 的历史回填原子路径建立切换事实。
4. 本地重置必须先重建数据库，再启动当前 `local` profile，使切换事实在页面建立首个租户前已存在；不得
   对已有本地库手工补写，避免掩盖“是否为空历史库”的前提。
5. 认证仍只由既有 `TenantMembershipMapper` 在切换事实存在后读取 `TenantLifecycle.ACTIVE` 判定；不保留
   双状态认证，不修改兼容 `tenant.status`，也不开放 HTTP、控制台或令牌写入口。

## 备选方案及拒绝原因

### 方案 A：local profile 的空库 repeatable migration

接受。它把纯本地、无历史数据的事实限制在部署 profile 与数据库空集断言内，复用已有认证单一事实源，
且不会扩大公共接口或改变共享环境。

### 方案 B：在认证 SQL 中对有生命周期根的租户优先读取生命周期

拒绝。它永久改变 ADR-0046 的全局切换语义，并重新引入“切换前两套状态解释”的路径。

### 方案 C：平台页面或普通启动代码自动补写切换事实

拒绝。平台治理请求不应承担环境初始化；普通启动 Bean 难以证明 profile 隔离并会突破 bootstrap 的最小装配边界。

### 方案 D：继续要求历史回填清单

拒绝。与已确认的纯本地、无历史迁移包袱相矛盾。

## 后果与验证

- 先以真实 PostgreSQL Flyway 红绿测试证明空库会建立事实，已有租户则不会建立事实。
- `application-local.yml` 必须只扫描正式迁移和本地初始化资源，不得加载 `db/demo/`。
- 本地数据库重置后，平台页面建立并激活的首个租户必须能够取得租户浏览器会话；`PROVISIONING` 与
  `SUSPENDED` 仍须失败关闭。
- 该决定不授权删除历史迁移文件、修改共享 profile、降级 Cookie 属性、开放切换管理接口或进入 M7。
