# ADR-0063：M6 本地身份基线重置与浏览器验收边界

## 状态

已接受。

## 日期

2026-08-11

## 决策负责人

用户，代表产品、架构、安全、平台与租户运营负责人。

## 背景

ADR-0062 的清单迁移用于不能丢失既有成员授权的环境，但当前目标是本地研发基线：允许清理已有成员，
只建立平台超级管理员，再由平台管理员按功能建立角色、账户、菜单能力与接口权限。将生产迁移机制用于
可丢弃的本地演示数据会持续保留不需要的兼容路径。

ADR-0048 要求正式 HTTPS 受信任浏览器证据，但本地 `localhost` 证书不受标准浏览器信任。产品负责人
决定该证据不再阻断 M6 自动验收或人工评审；同时 M6 仍必须有真实浏览器的角色、导航和接口权限操作证据。

## 决策内容

1. 仅对当前本地 Compose 开发数据库执行身份基线重置：删除所有历史租户成员、全局主体、直接权限、
   角色绑定和相关会话事实，再以受控种子建立唯一平台超级管理员。不得将此操作用于任何共享、测试、
   预发布或生产数据源。
2. 平台超级管理员之外的账户、平台／租户角色、菜单能力和接口权限都必须经既有受权功能建立与分配；
   不再为历史成员保留 `membership_permission` 兼容授权或自动生成角色。
3. ADR-0062 的方案 A 保留为非本地、需保留既有授权环境的迁移策略；它不再是当前本地 M6 基线的实施路径。
   已开始但未连接持久化、HTTP 或运行时的清单迁移代码必须移除，避免形成无调用方的第二条路径。
4. M6 本地浏览器验收允许使用显式隔离的 `http://localhost` 非生产环境，以验证登录、角色分配、菜单投影、
   直接路由拒绝和会话失效。该环境继续签发 `Secure`、`HttpOnly`、`SameSite=Lax` 及 `__Host-` cookie；
   浏览器对 localhost 的 `Secure` cookie 适用本地开发例外，不得为验收删除安全属性、变更 cookie 名称，或将
   降级配置写入镜像默认值、常规 Compose 配置或版本库中的真实凭据。
5. 受信任 TLS、生产 cookie 属性、跨页签自然过期与正式证书链证据移入后续发布／环境验证风险；它们不再
   阻断 M6 自动验收、M6 人工评审或 M7 的前置条件。

## 后果

- 清理前必须先只读列出目标数据库、Compose 项目、成员与主体数量，确认命令只指向本地项目容器；清理后
  必须证明仅存在平台超级管理员基线及无历史直接权限。
- 新的本地浏览器验收要绑定当前镜像、隔离 cookie 配置、角色操作和服务端拒绝结果；不得把该证据描述为
  生产 TLS 或 cookie 属性证据。
- M6 自动验收仍要求已接受 ADR 范围内的真实 PostgreSQL、Redis、MinIO、HTTP、前端和浏览器功能证据，
  不能以本 ADR 代替未完成的功能回归。
- 本 ADR 不授权删除仓库历史、Docker 全局缓存、其他 Compose 项目、共享环境或生产环境数据。
