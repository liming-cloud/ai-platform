# WP-0016 业务闭环整改

## 状态

2026-09-03 第二次人工复核不通过，当前人工结论继续有效。本轮候选已完成下述明确切片及 Node、Chromium、静态和 OpenDesign lint 门禁，但 68 个页面和自动断言不等于 68 个业务任务闭环；取得新的人工明确结论前不得申请整套原型通过。

## 本次直接修正

1. 导航使用 Microsoft Fluent System Icons 的真实 SVG 图片资源，锁定来源与许可；不再用小字、首字或 emoji 代替图标。
2. 专属页面与通用页面共用一份导航配置、同一个渲染入口；详情页高亮所属目录，模型管理归入治理任务，不能进入知识库后突然换一套菜单。
3. “创建新修订”改为“更新文档”；来源详情改为“文档详情”，修订在用户界面称“版本”。更新内容、重新处理和重新建立索引必须区分，不能把创建历史版本当作用户任务。
4. 在已接受账号规则内，成员操作应为“添加成员”，即选择已有可用账户并授予普通成员资格，不是邮件邀请。提供搜索、选择、确认、重复/资格校验、成功后目录更新、停用/恢复和刷新恢复。管理员只读，不允许租户提升或停用管理员。
5. 为全部 68 页建立操作覆盖账本，区分导航、真实模拟状态变更、无行为控件和待决策操作。普通按钮必须有具体结果，不能统一弹框后只关闭，也不能把跳到另一个模块算作完成操作。
6. 平台人员账户页闭环创建、初始密码、重置密码、平台管理员设置、停用与恢复；密码不回显、不持久化，敏感变更撤销会话，人员范围冲突、自操作和最后管理员均失败关闭。
7. 全库重建页冻结来源清单、Embedding、维度、距离度量、解析器和分块策略；索引详情按五阶段推进，运行冻结评测后才能由授权管理员原子激活。构建、评测、取消和保存失败期间旧索引持续服务。
8. 模型治理按平台与租户职责闭环：平台建立、探测并发布供应商连接和可授权部署；租户只发现被授权目录，建立并启用版本化配置和部署，再经同租户、同能力、同驻留路由模拟后发布。一次性密钥不落状态，Embedding 关键配置只建立索引重建候选，Chat/Rerank 只要求助手重新评测。
9. 助手交付按稳定身份闭环：创建时永久关联一个存在活动索引的知识库，草稿冻结索引、三类模型配置修订和策略，单题测试结果进入冻结评测集，全部质量与安全门禁通过后确认发布；发布只影响新会话，旧会话继续固定原版本。
10. 独立评测治理按数据集、运行、对比和修复事项闭环：数据集版本达到 60/20/10/10 样本门槛后冻结发布；运行固定同知识库助手、索引、模型修订和数据集；只有同一稳定助手、同一数据集版本且无安全、质量、性能或一致性回退的对比可以放行；失败事项不复制问题、回答或引用正文。
11. 结构化数据与对象范围形成独立闭环：CSV 字段规则经过保存、抽样预检和不可变发布；对象范围只接受平台为当前租户签发的文本范围，登记后形成待探测来源，不接收或披露对象位置与凭据。

当前 `ACTION-LEDGER.json` 登记 118 个操作或待设计任务：33 个导航、74 个状态变更、7 个读取、1 个待决策、2 个未实现和 1 个禁止项；其中 3 个已登记项尚未闭环。清单尚未穷举全部控件，不能作为全平台剩余量。

## 平台运行状态

原页面“平台健康”是平台管理员的运行异常入口，不是 RAG 质量评测，也不是租户知识正文查看入口。它应回答：哪条业务链路受影响、影响有多大、何时开始、下一步如何处理、是否恢复。

原型闭环：按查询、文件处理、模型调用等业务链路查看状态 → 选择具体异常 → 查看脱敏影响和最近事件 → 进入对应处理记录 → 重试或重新检查 → 看到恢复/仍异常结果。仅展示可理解的运行事实；不堆无来源指标，不允许“打开异常”总是跳到固定队列。

该模块属于 M8 前置原型，本轮只模拟固定故障和恢复结果，不授权生产运维动作。

## 备份与恢复

侧栏应命名“备份与恢复”，不是含义不明的“恢复”。业务目标是验证数据出故障时能否恢复，不是撤销页面操作或恢复被停用租户。

本原型仅演示：选择备份 → 检查完整性 → 固定隔离演练目标 → 确认影响 → 查看演练进度 → 校验报告。明确备份时间、可恢复时间点、校验结果和失败重试；不提供生产覆盖恢复，不跳到发布页面伪装成功。运行范围仍为 M8 前置原型。

## 创建租户、账号与配置

已接受事实：

- ADR-0042/0047/0061/0073：账号是全局人员身份，租户没有一个多人共用的“租户密码”。平台创建人员账户并设置或重置密码，再选择符合资格的初始租户管理员；租户管理员只能治理普通成员资格。
- 已设置密码不允许查看、返回、持久化到原型或日志；只能重置。原型仅使用合成账号，不执行实际凭据写入。
- 创建租户必须明确组织名称、租户编码、初始管理员，结果显示管理员已分配及待启用/已启用事实；不允许跳过管理员选择。
- “企业标准 v3”“受限试点 v2”“中型团队”没有可复核定义，不能作为已接受配置方案。基础安全边界（租户隔离、权限校验、凭据不回显）是不可关闭的保障。
- ADR-0074 已冻结小型试点默认值：每租户 3 个知识库；每知识库 1,000 个有效文档、10 GB 原始内容；单文件 50 MB，粘贴文本 1 MiB。必须显示单位与归属，不能只写“小型试点”。

ADR-0076 已确认：平台管理员可编辑租户资源配额、会话有效期、登录失败次数和锁定时长；配额不能低于已用量，租户隔离、权限校验和密码不回显没有关闭入口。原型只验证合成配置，不冒充生产认证策略。

待确认的产品设计，不得当作既有能力：

- 新用户邮件/链接邀请、自助激活及设置密码，当前 ADR 明确不包含。若需要应独立确认账号交付流程，而不是把“添加已有账户”叫作“邀请”。

## 已确认的两级功能控制

产品负责人已确认 ADR-0075：平台管理员控制租户可用功能，租户管理员控制普通成员可用的对话功能。不引入自定义角色和内部 API 勾选树。

- 平台租户详情提供“可用功能”配置，保存后影响该租户工作台的实际可见与可用入口；取消不生效，刷新后恢复已保存配置。
- 租户成员提供“对话权限”配置及已授权助手选择；普通成员只能选择助手、发起对话、查看或继续本人历史、查看有权访问的引用，不获得管理端能力。
- 有效功能取角色职责、租户开放功能、成员授权和对象授权的交集。上级关闭后下级不可绕过，直接路由也拒绝；菜单只是结果，不是权限边界。
- 管理员治理仍由平台独占。普通成员配置不能提权为租户管理员，不能借此停用管理员。
- 原型可模拟前端有效状态与拒绝路径，不得宣称已经实现真实后端安全控制。

## 验收规则

每个操作必须记录角色、入口、输入、校验、结果、后续可见状态、失败恢复与测试证据。模拟写操作必须更新同一合成状态源，支持刷新恢复和清除演示数据，不能保存密码。

验收先“功能能用”，再“功能好用”。前者要求每个动作确实改变或读取正确状态，取消不写入、失败可恢复；后者要求统一导航、自然中文、明确反馈、键盘与多尺寸布局。静态断言通过不能替代两层验收。
