# WP-0016 模型治理原型

## 产品任务

模型治理分为平台供应链和租户使用链，两者不能合并成一个“模型配置”页面。

- 平台管理员建立供应商连接，完成安全探测后发布连接版本；再从发现目录建立平台部署，执行能力、预算与安全样本验证，并显式选择可发现该部署的租户。
- 租户管理员只能发现平台已发布且授权给本租户的目录模型；随后建立租户配置、验证并启用配置版本，再建立、验证和发布租户部署。
- 路由策略只允许当前租户内、同能力、同驻留的两个不同已发布部署。模拟通过后才可发布，不能跨 Chat、Embedding、Rerank 或租户静默回退。

## 页面闭环

| 范围 | 页面 | 可验证结果 |
| --- | --- | --- |
| 平台 | 模型连接目录、连接探测 | 创建连接草稿；一次性访问密钥不回显、不落状态；探测通过后发布 |
| 平台 | 平台部署目录、部署发布 | 冻结已发现模型和租户授权；验证通过后进入授权目录，不自动创建租户配置 |
| 租户 | 供应商目录、发现结果 | 只显示本租户可用模型；底层地址、认证和供应商原始响应保持隐藏 |
| 租户 | 配置目录、配置向导 | 创建、验证、启用配置；轮换密钥或参数时旧启用版本继续服务 |
| 租户 | 部署目录、部署验证 | 仅引用已启用配置；验证后发布；停用前核对助手和路由影响 |
| 租户 | 路由策略 | 模拟成本、延迟和失败边界；通过后发布可刷新恢复的策略版本 |

## 版本影响

- Chat 或 Rerank 配置版本启用后不重建向量，只记录助手重新评测要求。
- Embedding 维度、规范化或距离度量变化时，为同租户知识库建立新的不可变全库索引候选；活动索引保持不变，不能自动激活。
- 平台部署发布只增加租户可发现范围；租户配置和部署发布都不会自动切换助手版本。
- 已发布连接重新探测失败或目录变化时，当前已发布模型标识和运行关系保持稳定；后续替换应通过新版本，不原地改写。

## 失败关闭与非目标

- 所有写操作先检查平台管理员或当前租户管理员权限；租户停用、成员停用或模型治理功能关闭时拒绝。
- 配置启用时重新检查平台部署仍已发布且仍授权当前租户，不能仅依赖创建时快照。
- 停用被助手或路由引用的部署必须显式确认，之后受影响调用失败关闭，不自动换成不同能力模型。
- 原型中的 HTTPS 主机检查、能力探测、供应商调用和安全样本均为合成行为，不代表生产 SSRF、凭据托管或真实模型合同已经实现。
- Rerank 明确使用独立检索后处理适配，不伪装成 Spring AI 已统一支持的 OpenAI rerank 标准。
