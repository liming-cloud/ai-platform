# WP-0016 视觉整改简报

## 设计问题与选择

用户已拒绝旧原型。要验证的问题是：移除评审说明、使用场景化业务内容并统一布局基线后，68 页是否能够像实际产品一样完成任务，而不依靠解释理解页面。

保留 Fluent UI 企业语言，采用 `DESIGN_VARIANCE=7`、`MOTION_INTENSITY=5`、`VISUAL_DENSITY=7` 的候选方向。拒绝仅放大字体或堆叠装饰卡片的表面方案。先检查登录、知识目录、模型向导、索引详情、发布确认和会话六类代表页，再把规则应用到全 68 页。

## 内容与视觉要求

- 目标路径、任务合同、原型范围和审核提示放入审查工具；`review=0` 不显示这些工程说明。M7/M8 的未授权标记仍在审查工具中明确显示，不改变生产范围。
- 产品正文只保留对象事实、动作、必要帮助与安全告知。页头不重复面包屑、分组名和任务解释；每个事实只显示一次。
- 表单按租户、成员、模型、知识、助手、评测任务提供实际字段，不再用通用“关联对象”套全部流程。
- 风险操作必须简洁地明确本次对象、影响、恢复与审计责任；不能为减少文字删除关键安全信息。
- 统一 4/8px 间距体系、标题基线、工具栏控件高度、表头与数据列、数字对齐和操作列；使用现有绿色强调与分层中性色，不使用渐变、玻璃效果、营销英雄区。
- 有效信息密度提高：紧凑目录和事实行、明确的主次布局、清晰留白；不以更小字体或更长说明实现密度。
- 控件、菜单、抽屉和状态切换使用 160-240ms 的 opacity/transform 反馈；不使用循环装饰动画，`prefers-reduced-motion` 时关闭非必要动画。
- 保留 68 个页面、7 状态、3 宽度、三角色、唯一主任务和最多一个普通分页。设备界面继续低密度，不机械套用管理端密度。

## 验证信号

1. 先建立红灯：产品模式仍出现工程说明、向导使用无关知识库字段、事实重复或页面丢失时失败。
2. 生成候选后跑静态门禁和 OpenDesign lint；静态与 HTTP 结果不得代替视觉结论。
3. 经浏览器授权后，检查全部页面 DOM，截图六类代表页的 390/1024/1440 状态，并执行完整工作包浏览器矩阵、键盘与 reduced-motion。
4. 仅用户明确复验通过后才能关闭 WP-0016。所有代码均为可丢弃原型，不进入生产。
