# WP-0016 全平台页面原型清单

## 目的

本清单回答“后续实现需要以哪些已渲染页面为视觉和任务基线”。它覆盖当前产品蓝图中三种人员角色、三个前端外壳以及 M6 至 M8 已规划页面，防止研发在没有实际原型的情况下继续扩张页面。

机器可校验的唯一页面集合位于 `page-inventory.json`。本文只解释范围、分组和门禁，不重复维护第二份页面表。

## 范围解释

- `M6` 页面属于当前可信 RAG 产品原型门禁，人工确认后才允许相应工作包进入生产前端实现。
- `M7` 与 `M8` 页面是信息架构和视觉前置原型，只用于避免后续偏移；它们不授权设备、SDK、生产运维或新公共契约的实现。
- SDK/API 渠道不是第四个前端应用；没有开发者自主注册、密钥自助管理或集成诊断任务，因此不设计开发者门户。
- 平台范围只显示脱敏运营事实，不提供租户知识正文、成员明细、问题、回答或引用正文入口。
- 原型中的目标路径是页面识别标签；`prototype-only` 路径不是已经发布的 HTTP 契约。

## 页面分组

`page-inventory.json` 将页面分为以下十组：

1. 共享访问：企业控制台登录。
2. 平台治理：平台运营摘要、租户生命周期、平台账户与模型供应链。
3. 租户访问与知识：租户概览、成员、角色、策略、设备凭据和知识接入。
4. 知识处理与索引：Schema、对象存储范围、质量、同步、索引版本与重建。
5. 租户模型：供应商、模型配置、部署和路由策略。
6. 助手交付：助手目录、草稿、测试、评测、发布和渠道绑定。
7. 评测与治理：评测数据集、运行、比较、失败分析、用量、审计和受权诊断。
8. 普通用户问答：独立登录、获授权助手目录和可恢复会话。
9. 设备问答：开始、同意、提问和简洁回答。
10. 平台运维：健康、摄取队列、模型健康、容量、备份恢复和发布回滚。

## 页面成立条件

每个清单项必须在 OpenDesign 中满足以下条件，才能算“已有实际原型”：

- 有可直接打开的 `screen`，不能只在文档中出现名称。
- 成功态展示与该页面唯一主任务相符的真实信息层级、主要操作和业务结果。
- 可切换 `loading`、`empty`、`error`、`denied`、`partial`、`disabled`、`success`。
- 一个页面最多一个普通目录分页；事件、消息、步骤和候选选择不伪装成第二个页码分页。
- 390、1024、1440 宽度无文档级横向滚动，页面仍能完成主要任务。
- 无权限态不加载受保护摘要，错误态不显示内部标识、Endpoint、对象键、trace 或厂商原始响应。
- 高风险写入只有一个确认层；不存在嵌套 Dialog。

## 页面与弹层边界

以下内容不是独立页面，不得为了“页面齐全”制造额外导航：

- 简短创建、改名、停用、恢复和撤销操作使用单一 Dialog。
- 高级筛选、补充详情和移动端会话历史使用 Drawer。
- 引用核验、反馈和会话版本提示属于会话阅读流。
- 复杂探测、同步结果、评测运行、索引激活、租户建立和恢复演练使用独立页面。

## 漂移门禁

- 新增生产页面前，必须先向 `page-inventory.json` 增加页面，并在 OpenDesign 生成可操作成功态与必要异常态。
- 删除或合并页面必须先说明被替代的用户任务和恢复路径，不能仅因实现方便修改信息架构。
- 原型验证脚本必须比较页面清单、审查器选项和实际渲染页面；任一侧缺失直接失败。
- 人工确认绑定页面清单版本、OpenDesign 项目修订与提交；后续原型变更必须在 OpenDesign 中重新验收受影响页面。
