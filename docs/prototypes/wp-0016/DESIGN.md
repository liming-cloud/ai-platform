# WP-0016 可信 RAG 高保真原型设计

## 状态与边界

- 状态：候选原型，等待人工确认。
- 工作包：`WP-0016`。
- 设计系统：Fluent UI React v9 的信息层级、组件语义和既有 Foundation Token。
- 交付形式：OpenDesign 项目中的可操作 HTML 原型、设计令牌、脱敏 fixtures、自动检查和截图。
- 生产边界：本目录是可丢弃设计产物，不进入生产构建，不创建真实 API，不修改前端路由或授权实现。
- 人工门禁：产品任务、信息架构和视觉基线未明确确认前，不得推进 `WP-0017`，也不得把本原型代码复制到生产前端。

## Design Read

这是三角色可信 RAG 产品的任务流重构，不是营销站、数据看板或后端模块浏览器。视觉继续采用克制、可信、较高信息密度的 Fluent UI v9 企业语言。

- `DESIGN_VARIANCE=4`：布局稳定，使用少量非对称建立主次关系。
- `MOTION_INTENSITY=2`：仅保留状态切换、流式回答和焦点反馈；减少动态效果时即时完成。
- `VISUAL_DENSITY=6`：桌面支持日常运营扫描，移动端保留完成任务所需的最小信息。
- 强调色：延续现有深绿色语义强调，不使用 AI 紫、渐变、玻璃效果或营销式大标题。
- 参考方向：OpenDesign `tech-utility` 的高信息密度、细边界、表格扫描和状态标签姿态；组件与可访问性仍以 Fluent UI 为准。

## 已审计事实

### 保留

- 单一 SPA、HttpOnly 浏览器会话、URL 可恢复状态和服务端能力投影。
- `ProductShell` 的桌面侧栏、紧凑侧栏、移动导航和统一账户菜单。
- Foundation 的画布、表面、边界、文字、深绿色强调、`8px` 控件圆角和 `12px` 面板圆角。
- 普通目录使用服务端页码分页；事件、消息和向量候选不伪装成页码。
- 状态必须说明业务影响、下一行动和安全边界。

### 关闭的断层

- 退役 `/ask?assistantPage=N` 的“助手下拉框 + 助手分页 + 一次性问题 + 结果区”组合。
- 知识库不再由“首份文本发布”隐式创建；它是租户管理员的一等父任务。
- 数据来源、处理结果、索引版本和助手发布不再平铺在同一页面。
- 普通用户不进入管理控制台；其入口、助手目录和会话历史形成独立任务路径。
- 聊天消息使用事件序号加载更早内容，不出现第二套页码分页。

## 页面清单驱动的信息架构

`page-inventory.json` 是页面集合、状态集合和视口集合的唯一事实源。`prototype.js` 运行时加载清单并建立合法 screen、页面元数据、十个审查器 `optgroup` 和目标路由标记；`page-fixtures.json` 为每个 screen 提供中文标题和脱敏成功态数据。文档、静态审查器和验证脚本不得再维护第二份页面数组。

当前基线共 68 页，分为十组：共享访问、平台治理、租户访问与知识、知识处理与索引、租户模型、助手交付、评测与治理、普通用户问答、设备问答、平台运维。页面使用三种外壳：

1. 企业控制台：同一 SPA 内明确区分平台范围与租户范围；桌面侧栏、1024 紧凑导航、390 底部任务导航。平台范围只展示脱敏聚合。
2. 普通用户问答：独立登录、授权助手目录、左侧历史与中央消息流；移动端历史进入 Drawer，消息按事件序号加载。
3. 设备问答：触控和语音优先的低密度外壳，只保留开始、同意、提问、回答或拒答、继续。

页面根据唯一任务使用目录、详情、向导、运行结果、时间线或高风险确认六种最小模式。每个成功态必须同时显示目标路径、唯一任务、主要操作和领域信息结构。


平台管理员导航不得出现知识库、来源、引用正文或用户会话正文入口。租户管理员默认也不读取普通用户正文，只能查看脱敏运营指标；原型不提供越权入口。

## 原型路由与单页任务

原型使用 `screen` 查询参数承载 68 个审查场景，目标产品路由、唯一任务、主要操作与是否允许普通分页全部直接来自 `page-inventory.json`。`state` 用于切换七类状态，不代表生产 API。任何产品页面最多有一个 `.pagination`；助手、知识库、模型和数据集关联使用可搜索名称选择器，事件、消息、步骤、候选和时间线不伪装成页码分页。

简短创建、改名、停用、恢复和撤销使用一个 Dialog；高级筛选、补充详情和移动会话历史使用 Drawer；复杂探测、同步、评测、索引激活、租户建立与恢复演练使用独立页面。禁止嵌套 Dialog。

M6 页面是当前人工门禁范围。M7 设备问答与 M8 平台运维页面必须完整呈现，但统一显示“原型前置，不代表实现授权”；它们不授权生产设备、SDK、运维自动化或新公共契约。

## 闭环流程

### A. 知识接入与索引

1. 租户管理员从知识库目录创建“员工服务手册”，创建结果是可恢复草稿。
2. 进入该知识库的数据来源页，使用唯一主操作“添加数据”。
3. 添加任务选择粘贴文本或本地文件；原型列出 TXT、Markdown、DOC/DOCX、XLS/XLSX、CSV、PDF、PNG、JPEG、WebP。
4. 页面明确展示 `SCANNING -> EXTRACTING -> EXTRACTED -> CHUNKING -> INDEXING -> READY`，失败显示结构化业务原因和安全重试点。
5. 单文件“重新索引”创建新来源修订，不修改活动索引。
6. 全库“重建索引”进入独立索引详情，完成构建和评测后才显示“激活此版本”。
7. Embedding、维度、距离度量、解析器或分块策略变化时，页面标记“需要全量重建”，但不自动激活。

### B. 助手评测与发布

1. 稳定助手永久显示其唯一知识库，不提供切换入口。
2. 版本摘要冻结索引、Chat、Embedding、Rerank、检索策略、引用策略和拒答阈值。
3. 发布页先回答“能否发布”，再展示 Recall@10、引用正确率、拒答准确率、越权泄漏和延迟。
4. 任一安全门禁失败时主操作保持禁用，并给出可行动原因。
5. 发布确认说明旧会话继续固定旧版本，新会话才使用新版本。

### C. 普通用户问答

1. `/app/login` 只解释普通用户问答边界，不展示平台或租户管理入口。
2. `/app/assistants` 使用可搜索目录；选择助手后创建固定已发布版本的新会话。
3. 会话页桌面固定左侧历史、中央消息流、顶部助手信息；移动端历史进入非模态抽屉。
4. 提交后先显示已接受和检索状态，再以真实 `TOKEN_DELTA` 语义逐步补充回答；原型用确定性 fixture 模拟，不调用模型。
5. 引用最终化后才可打开；访问时再次显示授权检查结果。
6. 断线状态从最后事件序号恢复，最终回答、引用和终态作为同一完成事实展示。
7. 新助手版本发布时，旧会话显示提示，但不会静默漂移；用户可明确开启新会话。

## 状态矩阵

每个 `screen` 都可用 `state` 切换下列状态；原型审查器和自动检查直接访问对应 URL。

| 状态 | 用户可见事实 | 恢复动作 |
| --- | --- | --- |
| `loading` | 与最终布局一致的骨架，保留页面标题和结构 | 自动完成或返回 |
| `empty` | 说明为什么为空，不伪造样例数据 | 唯一有效下一步 |
| `error` | 说明当前任务未完成及是否可安全重试 | 重试，不显示内部错误码 |
| `denied` | 不确认资源是否存在，不泄露正文或引用 | 返回已授权目录或退出 |
| `partial` | 成功与失败分区，说明结果是否可继续使用 | 只重试失败项或恢复事件 |
| `disabled` | 控件不可用并有相邻原因，不只依赖 tooltip | 先满足明确前置条件 |
| `success` | 展示服务器权威完成事实和下一任务 | 进入下一独立页面 |

会话的 `partial` 特指流式回答或断线恢复；知识来源的 `partial` 特指部分文件失败；发布页的 `disabled` 特指质量或安全门禁未通过。

## 布局规则

### 1440 宽度

- 管理端：`240px` 侧栏，内容最大宽度 `1180px`，表格保持稳定扫描列。
- 会话端：`272px` 历史栏，消息内容最大宽度 `780px`，顶部助手信息与中央消息同轴。
- 页头最多一个主操作；表格每行最多两个常用操作。

### 1024 宽度

- 管理侧栏压缩到 `80px` 并保留可见 tooltip/`aria-label`，内容列不产生文档级横向滚动。
- 会话历史栏压缩到 `240px`；引用与回答纵向排列。
- 表格转为保留列标题的可扫描行，不增加第二套分页。

### 390 宽度

- 管理导航折叠为底部任务导航，页面主操作保持在页头后第一焦点区域。
- 会话历史由顶部“会话记录”打开抽屉；中央消息和输入框保持单列。
- 表格切换为带字段标签的行列表，不伪装成同质卡片网格。
- 使用 `min-height: 100dvh`，不使用 `100vh`；正文和操作在 200% 缩放下不被固定容器裁切。

## 键盘与无障碍

- 首个 Tab 到“跳到主要内容”，随后按视觉顺序到页面主操作、筛选和结果。
- 搜索结果使用单选列表语义；方向键移动候选，Enter 选择，Escape 关闭移动端历史抽屉。
- 对话输入使用 Enter 发送、Shift+Enter 换行；发送中按钮禁用并显示原因。
- “加载更早消息”保持当前阅读锚点，不抢焦点。
- 所有状态同时使用文字与形状，不只用颜色；引用按钮包含来源名称。
- 动态状态使用 `aria-live=polite`，逐 Token 内容不逐字符播报，只在阶段变化和完成时播报。
- `prefers-reduced-motion: reduce` 下关闭骨架扫光、消息进入和流式光标动画。
- 颜色按 WCAG 2.2 AA 目标设计；正文、辅助文字、边界和焦点环均使用语义 Token。

## Token 与 Fluent 映射

`tokens.css` 是原型锁文件，值延续 `frontend/packages/design-system/src/styles/tokens.css` 并补充状态、焦点、数据表和会话布局 Token。生产实现必须映射回 Fluent UI React v9 Token，禁止复制原型类名建立第二套组件库。

| 原型语义 | Fluent 生产映射 |
| --- | --- |
| `.button.primary` | `Button appearance="primary"` |
| `.field` | `Field` + `Input` / `Textarea` / `Combobox` |
| `.status-tag` | `Badge` 的语义颜色与文本 |
| `.dialog-surface` | `Dialog` 或复杂任务独立路由 |
| `.drawer-surface` | `Drawer`，只承载会话历史或补充信息 |
| `.table-shell` | `Table`，普通集合使用服务端 `PageResult` |
| `.state-panel` | 现有共享 `StatePanel` |

## Fixtures 与安全

- 所有名称、成员和内容均为合成数据，不含真实租户、个人、凭据、Endpoint、对象键或内部错误码。
- `AssistantVersion`、`IndexVersion`、来源修订、会话和消息都使用不可变公开标识。
- 引用 fixture 只包含用户已授权可见的标题、页码和摘录；`denied` 状态不加载这些字段。
- 模型名称只作为脱敏目录标签，不包含密钥、Base URL 或厂商响应。
- 原型不接受远程 URL、不上传文件、不发网络请求到 OpenDesign daemon 以外的第三方。

