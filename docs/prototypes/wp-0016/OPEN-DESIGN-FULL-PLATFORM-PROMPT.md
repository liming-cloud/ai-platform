# OpenDesign 任务：补齐可信 RAG 全平台高保真原型

## 目标

在现有 `WP-0016 可信 RAG 高保真原型` 项目中补齐 `page-inventory.json` 定义的全部 68 个页面。最终每个页面都必须有可直接打开、可真实渲染、能表达唯一用户任务的高保真成功态，不能只在清单、导航、说明或占位卡片中出现。

这是可丢弃原型。只修改当前 OpenDesign 项目目录，不修改生产前端、后端、API、数据库、部署或其他工作包。

## 必须先读取

1. `DESIGN.md`：既有视觉、产品、安全和可访问性基线。
2. `PAGE-INVENTORY.md`：页面成立条件、弹层边界和漂移门禁。
3. `page-inventory.json`：页面唯一事实源。
4. `index.html`、`prototype.js`、`prototype.css`、`tokens.css`、`fixtures.json`：当前已确认原型和交互。
5. `scripts/verify-and-capture.cjs`：现有自动检查与截图合同。

## 不可变设计原则

- 延续当前 Fluent UI v9 语义、深绿色强调、浅色高密度企业界面；不使用渐变、玻璃效果、AI 紫、大数字营销看板、装饰性卡片海洋或 emoji 图标。
- 一个页面只承担一个主要任务，页头最多一个主操作。
- 一个页面最多一个普通目录分页。消息、事件、步骤、候选选择和时间线不得伪装成第二套页码分页。
- 简短创建、改名、停用、恢复、撤销使用一个 Dialog；复杂探测、同步、评测、索引激活、租户建立和恢复演练使用独立页面；禁止嵌套 Dialog。
- 关联知识库、助手、模型、数据集等对象使用可搜索名称选择器，不要求用户输入内部标识。
- 平台管理员页面只展示脱敏聚合和安全摘要，绝不出现租户知识正文、成员明细、问题、回答、引用正文、凭据、Endpoint 或厂商原始响应。
- 普通用户问答继续保持左侧会话历史、中央消息流、顶部助手信息；移动端历史进入 Drawer；消息按事件序号加载更早内容。
- 设备问答是独立低密度外壳，只包含开始、同意、提问、回答与继续，不暴露供应商、索引、评测或审计概念。
- M7/M8 页面必须清晰显示“原型前置，不代表实现授权”，但页面本身仍需完整高保真，不能显示“敬请期待”。

## 实现要求

### 页面清单驱动

- `prototype.js` 必须加载 `page-inventory.json`，由清单建立合法 screen、页面元数据和审查器分组选项。
- 清单中的 68 个 `screen` 都必须能通过 `?screen=<screen>&state=success&review=0` 打开。
- 保留当前 `login`、`assistants`、`conversation`、`knowledge-directory`、`knowledge-sources`、`index-detail`、`assistant-release` 的已验证行为和关键 data attribute。
- 每个成功态必须展示清单中的目标路径、唯一任务、主要操作，以及至少一个符合该业务域的真实信息结构。允许复用布局函数，不允许 68 个页面都落到同一份泛化占位内容。
- 审查器按十个页面分组使用 `optgroup`，显示阶段、页面中文名和 screen，支持搜索或快速跳转；状态仍可独立切换。

### 三种外壳

1. 企业控制台：平台范围与租户范围导航必须明显区分；桌面侧栏、1024 紧凑导航、390 底部任务导航。
2. 普通用户问答：独立登录、助手目录和会话阅读流。
3. 设备问答：触控和语音优先的低密度界面。

### 页面模式

按页面任务使用最小合适模式：

- 目录：筛选工具栏、摘要列/行、唯一分页和清晰行操作。
- 详情：版本/状态摘要、任务事实、风险或依赖、单一主操作。
- 向导：可恢复步骤、当前输入、提交前影响核对，不在一页平铺所有步骤。
- 运行结果：先显示能否继续或能否发布，再显示指标和失败分类。
- 时间线：事件序号和阶段，不使用页码。
- 高风险操作：说明对象、影响、恢复方式与审计责任。

### 状态与无障碍

- 68 个页面都支持 `loading`、`empty`、`error`、`denied`、`partial`、`disabled`、`success`。
- 状态文案必须结合当前页面任务和主要操作，不能重复显示无语义的通用占位语。
- `denied` 不渲染受保护摘要；`error` 不显示内部错误码、trace、对象键、内部 ID 或厂商原始响应。
- 首个 Tab 到 skip link；焦点顺序与视觉顺序一致；所有控件具有可见名称。
- 390、1024、1440 宽度无文档级横向滚动；200% 缩放仍可完成主要任务。
- `prefers-reduced-motion: reduce` 关闭骨架扫光、消息进入、流式光标和非必要过渡。

### 真实可操作闭环

至少实现并验证以下原型导航：

1. 平台租户目录 → 建立租户三步向导 → 租户详情。
2. 知识库目录 → 知识库概览 → 数据来源 → 添加来源 → 来源详情 → 处理与质量 → 同步结果 → 索引目录 → 索引详情/重建。
3. 平台模型连接 → 连接详情 → 平台部署目录 → 部署详情。
4. 租户模型供应商 → 模型配置 → 模型部署 → 路由策略。
5. 助手目录 → 创建助手 → 草稿 → 测试 → 评测 → 发布 → 渠道绑定。
6. 评测数据集 → 发起评测 → 运行详情 → 版本比较 → 失败分析。
7. 普通用户登录 → 授权助手 → 新会话 → 引用核验 → 历史切换 → 续问与断线恢复。
8. 设备开始 → 同意 → 语音/触控问题 → 回答/拒答 → 继续。
9. 平台健康 → 摄取队列/模型健康/容量 → 备份恢复 → 发布回滚。

## Fixtures

- 扩展 `fixtures.json` 或新增被 `prototype.js` 明确加载的脱敏 fixture 文件。
- 只使用合成名称和内容，不含真实租户、成员、凭据、Endpoint、对象键或内部错误。
- 目录、版本、状态、指标、时间线、失败分类和恢复动作必须足以支持每个页面的独特成功态。
