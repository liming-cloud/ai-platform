# WP-0016 租户创建与配置原型切片

## 当前目标

修复人工指出的长表单、固定配额、不自然措辞与同排输入框错位。保持 7/5/7 与既有 OpenDesign 项目。可丢弃原型只使用合成状态，不修改生产代码，不代表人工验收通过。

## 当前边界

- 将租户创建改为“租户信息 → 管理员 → 配额设置”三步，仅显示当前步骤。前后切换与刷新保留输入，取消清除创建草稿，创建失败保留输入并定位错误。
- 所有设备保留可达的下一步/上一步/创建操作；不将多节长表单仅加一个无功能步骤条。桌面和平板不需要向下翻找当前步骤的字段。
- “选择已有合资格账户”改成“选择租户管理员”；“创建稳定助手”改成“创建助手”；“永久绑定知识库”改成“关联知识库”，简短说明创建后不可更换即可。
- 平台管理员可编辑五项资源配额；不再展示固定配额说明卡。创建采用已接受的小型试点值预填，可修改；租户详情能修改、取消、保存和刷新回显。正数校验，数量为整数，不能低于已用量；降低单文件或粘贴限制只约束后续新增，不删除已存内容。
- 现有租户用量仅显示合成聚合，不暴露平台无权读取的知识库、成员或会话正文。租户端只读平台分配配额，不能提权修改。
- 用户已确认开放会话有效期、登录失败次数与锁定时长。租户详情使用独立编辑弹窗，避免增加创建步骤的长度；正整数校验，支持保存、取消、刷新和失败重试。合成预填 8 小时、5 次、15 分钟，不代表生产推荐值。租户隔离、权限校验、密码不回显保持强制约束。
- 本轮先闭合租户创建/配置和共享表单。其余账户、知识、索引、助手发布与评测继续按账本推进，不能把导航包装成已完成业务。

## 实施 seam

- 沿用 `#tenant-create-form`、`#tenant-organization-name`、`#tenant-code`、`#tenant-administrator`。
- 当前步骤使用 `[data-tenant-step]`，隐藏其他步骤。步骤 1/2 的唯一主要操作为“下一步”，步骤 3 为“创建租户”，最终提交需明确确认摘要。
- 合成状态仍由 `prototype-state.js` 管理：`tenantSetup` 保存 step、organizationName、tenantCode、administratorAccountId 和 quotas。`updateTenantSetup(patch)`、`discardTenantSetup()` 更新/清除白名单字段；`createTenant(input)` 支持 quotas 并在成功后清除草稿。
- `saveTenantQuotas(tenantId, quotas, actorRole)` 只接受合成 `platformAdministrator` 角色；配额与当前用量由 `getTenantQuotas(tenantId)` 投影。此模拟角色参数不是生产认证合同。
- 数字字段元数据使用导出的 `TENANT_QUOTA_FIELDS`，默认值使用导出的 `DEFAULT_QUOTAS`；UI 与状态校验共用字段 key。
- 本切片公共 seam 仅指可丢弃原型的测试入口，不新增真实 API、领域或数据库合同。

## 验收

先运行 `scripts/tenant-setup.browser.test.cjs` 保存红灯；再新增状态用例，验证非默认配额、非法输入、保存/取消/刷新、存储失败回滚和跨角色拒绝。最终运行 WP-0016 全部既有测试、静态、浏览器矩阵与 OpenDesign lint，保留 390/1024/1440 三档截图和键盘证据。用户截图覆盖的助手输入框作为回归样例；不隐藏帮助文案以制造对齐。
