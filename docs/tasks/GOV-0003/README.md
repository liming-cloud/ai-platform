## 目标与边界

使上下文之间只通过公开 facade、扩展只通过公开 port 与扩展契约编译依赖；守卫能检查 Maven 图与 Java 导入。产品前沿保持 WP-0017，M6 结论不变。

不实施新的可信 RAG 功能，不部署、不修改数据库或 OpenDesign，不运行创建业务对象的验收。

## 问题

仅靠无环的 Maven 图不能证明上下文隔离：编译时直接访问他方领域对象、内部服务或自动配置，会使业务边界随实现细节变化。原守卫没有检查这类依赖。

## 范围内

修正现有跨上下文与扩展编译引用、公开调用契约及内部映射；增加 POM 图与 Java 导入守卫，修正受影响的自动配置和测试，并登记 ADR-0082。

## 范围外

业务 API 与数据库格式变更、产品功能、部署、开户验收、原型修改及 WP-0017/M6 的完成结论。

## 公共接口与数据

公开调用经所属上下文的 `application/.../facade`；扩展经 `application/.../port/out` 和专用 facade 请求/结果类型。领域对象在拥有者内部映射，业务身份、租户隔离、异常与校验语义不改变；数据库迁移不涉及。

## 约束

先以失败反例确认边界漏洞，再做局部修复。不引入通用权限框架、无调用方的抽象模块或宽泛白名单；不改写 ADR-0022 历史事实。源码改动只在隔离工作树，合并前复核原工作区。

输入提交有 15 条上下文编译依赖、6 条扩展编译依赖，Maven 图无环；存在跨上下文 `domain`、内部 application、infrastructure 和自动配置引用。旧 `make architecture-guard` 通过，但未覆盖这些边界。
