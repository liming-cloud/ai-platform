## 修复与验证

固定原型的重置弹窗有默认折叠的演示说明。生产身份流程依 ADR-0078/0079 不能展示或回退公开演示口令，因此新候选加入同位置、默认折叠的“密码安全说明”，只解释旧密码不可查看及新密码应安全交付。移动端“操作”标签对齐原型的标签列右缘。原 Fluent 密码输入包装器在 200% 文字下按固有宽度溢出；将其局部约束为列宽，并在正式验收中检查弹窗内容区与两个密码输入包装器的真实边界和横向滚动，覆盖 390、1024、1440 三种视口，不降低字号或裁切容差。Fluent 另有 600px 桌面弹窗上限，局部解除后按固定原型达到 608px；390px 仍为 352px。

先以旧 CSS 在独立 Chrome 复现 390px 内容区右侧溢出 50px、1024/1440 溢出 101px；固定原型输入为 `width:100%`，三种视口同场景无越界。修复后的本地新资源对照中，三种视口普通字号及 200% 文字的内容区 `scrollWidth=clientWidth`，两个密码输入与原生输入均在内容区内，Tab 与 2px 焦点外环保持可见。第一次本地预览意外读到旧 Vite CSS；通过实际 HTTP CSS 响应确认缓存滞后，改用全新端口且确认新规则已加载后才采信修复结果。该过程的截图仅存 `/private/tmp/wp0017-safety-readonly.DYsqPE/`，不进入仓库。

最终镜像 `9060c3ad1dff9ecd2a2092a4e5dd8f4cacbc7a67` 上的独立只读 Chrome 对照以本轮前一组甲租户 `2103016319363317761` 执行，截图和无秘密几何指标仅保存在 `/private/tmp/wp0017-final10-visual.VAhEfRQd/`。390/1024/1440 页面无横向溢出，重置弹窗宽度分别为 352/608/608px；原型也是 352/608/608px。390px、200% 文字时密码输入完整、提交按钮可达，部分下方内容需要在弹窗内部纵向滚动；没有把“一次性全可见”当作验收事实。正文 16px、Georgia/中文宋体标题、暖色主题、移动端“操作”标签右对齐、键盘与 reduced-motion 均已核对；只读探针拦截到的业务写入为 0。弹窗高度仍有原型 390px 565.8px／生产 568.9px、原型桌面 446.6px／生产 445.3px 的差距，不报告像素级完全一致。

最终镜像上，以最终验收脚本执行 `make acceptance-work-package WP=WP-0017 SLICE=admins` 的 **9/9** 场景通过，包括正式接口创建独立合成租户、管理员目录与分页筛选、跨租户和旧版本拒绝、资格停用／恢复、所属租户登录、受控密码重置、键盘与三尺寸 200% 文字无裁切。安全说明默认折叠，Enter 展开、Space 收起；没有向浏览器输出演示口令。以本轮新建甲租户管理员及既有平台身份组成的受控输入执行 `SLICE=login`，**15/15** 登录回归通过。受控凭据目录 `/private/tmp/wp0017-admins-final11.8hthUM6q/` 为 0700、输入及输出为 0600；只登记非秘密标识，不提交凭据或截图。

新镜像首次正式验收在前八组通过后，被刚增加的 390px 弹窗宽度断言挡住。独立只读 Chrome 复现表明，断言在 Fluent 入场缩放到 0.85 倍的瞬间读取盒宽；50ms 后稳定为原型的 352px，桌面稳定为 608px。保留该次合成对象及失败输出，不覆盖旧证据。初版动画等待虽让新对象通过 9/9、15/15，但固定 diff 评审用无限循环和暂停帧反例证明该等待可能不返回；最终改为 3 秒有界检查，只观察弹窗自身动画并确认盒宽回到计算宽度。静态 Chrome 的有限、无限和暂停反例与部署只读复现均通过，未放宽 ±1px 宽度容差或删减场景。脚本提交 `40f17a08577c741eba3230e2a10860d06caba501` 后，使用全新对象重新完成上述 9/9 与 15/15。

`make frontend-test` 为 43 个文件、222 项通过；验收脚本语法检查及对应治理测试 8 项通过；`make architecture-guard` 为 38 项及后端边界门禁通过；`make project-verify` 为 68 项通过，`make project-status` 与 `make resume-context` 仍指向 M6／WP-0017。固定代码 diff 的只读评审未发现剩余阻断；无界等待风险由反例发现并在最终脚本修复。上述源码检查不代替实际部署验收。

## 原型一致性结论与下一前沿

新候选对齐了重置说明的折叠结构、移动端“操作”标签位置与三尺寸弹窗宽度，并修复 200% 文字下生产输入框的真实裁切。安全说明采用真实生产身份语义，标题与内容仍不同于固定原型的“演示密码说明”；弹窗高度也仍有约 1–3px 差距。固定原型侧栏还含 M8 的“平台运行状态”和“备份与恢复”，本切片没有真实目标页面，不能添加假入口；固定原型在 390px 把“更多”按钮伸入分页区域，中心命中分页，照搬其绝对几何会破坏按钮与分页的可操作性。这些差异仍按现行严格原型门禁记为**未通过**，不因功能 9/9、登录 15/15 和数据库 18/18 而豁免。

因此 `platform-tenant-admins:0`、`:1` 仍为 `implemented`，管理员独立设置切片、WP-0017 整包及 M6 均未完成；不推进配额、功能开关、登录策略、平台账户、普通会员或 M8。只有新的设计基线经人工接受，或用户明确改变本轮验收范围与口径后，才重新评估这些固定原型冲突。
