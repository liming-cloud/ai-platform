## 只读数据库事实

对上表精确标识在单个 `REPEATABLE READ READ ONLY` PostgreSQL 事务中核对，`transaction_read_only=on`。甲、乙真实 `tenant_lifecycle.status=ACTIVE` 各 1，ACTIVE 生命周期发件箱事件共 2；两份初始管理员 `ENABLED` 资格及角色绑定各 1。共享身份在甲租户有 `ENABLED` 资格及绑定各 1，在乙租户为 0；跨租户重复管理员主体为 0，限制单租户归属的部分唯一索引有效且仅 1 个。共享主体为 `ACTIVE`，密码重置后的非秘密安全修订时间及版本均前进；平台主体及其活动平台角色各 1。

18 项计数与状态均符合预期。只读 SQL 和原始输出分别保存在 `/private/tmp/wp0017-admin-db-final7-skno1eiq/` 的 0600 文件，目录为 0700；SQL 设置两个 5 秒事务内超时并以 `ROLLBACK` 结束。非秘密 SQL 文件 SHA-256 为 `3f6d654bb4c9824d792d33e119f7435016664d7e1b7bbd9c7adafb4aa07ddfef`，原始输出为 `5d0e5c67e731a4dc6f6fcafa5744d226cb4cdb349d7414e92b510b8ba783b8c8`。这些路径用于本机复核，不属于仓库提交物。

旧 `organization_access.tenant` 锚点对两个新租户均为 `DISABLED` 且创建后未更新，这是 ADR-0080 要求的兼容写入，不代表租户实际停用。开户实现将真实状态写入 `tenant_lifecycle`；认证在切换后检查生命周期 `ACTIVE` 和成员资格 `ENABLED`。本轮没有读取密码、摘要、Cookie、Token 或其他秘密列，没有修改数据库。

## 固定原型对照与未关闭差异

最终 Compose 的 390px 页面横向溢出为 0；摘要补齐固定原型移动端子项的 1px 分隔线，正常字号的摘要高度从 92.3906px 对齐到原型 93.3906px。状态选择器移动端为 44px 高，1024/1440 桌面正常字号宽 110px，与原型一致；200% 文字时宽度随内容增长并保持视口内。状态胶囊保持内容宽度。状态及密码两类移动弹窗均从 x=19px 开始、宽 352px，与固定原型一致。1024px 摘要为两列，1440px 为四列；暖色主题、标题字体、侧栏标识与“可信 RAG”、信息顺序和短按钮宽度按固定原型核对。确认框具备影响、恢复、审计三行，重置框具备受控凭据及全范围会话撤销说明。资格文案采用 ADR-0083 已接受的修订，不把原型模拟全局账户停用照搬到生产。

新部署的空白重置表单与固定原型均允许点击提交；两者均聚焦第一项必填密码输入、触发原生必填状态，并显示同一句“请完整填写新密码并确认撤销全部会话。”。最终镜像对首密码输入显示 1px 棕色全边框与 2px 同色焦点外环，移除了 Fluent 底边伪元素；390px 只读截图与计算样式均证实局部焦点修正。三尺寸按相同 200% 文字规则检查时，原型和生产的页面 `scrollWidth` 均等于视口；生产 390px 重置弹窗放大后宽 352px、确认按钮可在 844px 高的视口内到达。键盘可开关“更多”、打开重置弹窗并聚焦密码输入；reduced-motion 下没有运行动画。只读视觉指标与截图仅存 `/private/tmp/wp0017-final4-visual.hEUFHL/`，没有进入仓库。

仍有**不能自行豁免**的视觉差异。固定原型顶栏有六项，包括尚未交付的“平台运行状态”“备份与恢复”；生产导航仅展示前四项。本片不能以假入口冒充后续功能。固定原型 390px 的“更多”控件越过单条管理员表行底部 44px，进入分页区域，命中测试实际落在分页摘要上；生产页面让操作留在本行且可点击，位置不同。原型固定夹具只有一条记录，因此“第二条记录被遮挡”只是由几何关系推出，未作为已观测事实。桌面分页自身均为 57px 且紧贴表格末行；原型只有演示数据单行，生产有两条真实管理员，1024/1440 行高不能当作同内容像素对照。390px 重置弹窗生产高约 535px、原型约 566px，主要由于原型的演示密码说明不能复制到真实生产身份流程。对设计与安全事实的冲突需取得明确决定，当前不得写为原型完全一致。

浏览器正式断言覆盖三尺寸、200% 文字、焦点与键盘、reduced-motion；截图仅保存在 `/private/tmp`，仓库中没有截图。视觉检查支持上述已对齐部分，也明确保留上述未关闭差异；不能由功能 9/9 推导视觉通过。

## 失败过程与结论边界

早期独立合成对象上的几次验收曾触发两项验收器误报：异步目录加载期间过早检查搜索焦点，以及关闭的 `<details>` 子按钮虽然不可绘制却被纳入 200% 字号检查。先复现再分别修正等待条件和可见性判定；关闭菜单仍明确打开后接受实际字号、裁切及触控检查。随后 `6be97b393ba9658da5ad7a5090fbb4039815e68a` 镜像的正式验收在 1024px/200% 文字处发现真实溢出：固定 110px 外框内的筛选器被文字撑至 174px，页面宽到 1056px。改为内容自适应后，同一只读探针由 `scrollWidth=1056` 转为 `1024`，正常字号仍为 110px。

此前 `03255811a69d1637f5f40a8474421a7e811de081` 镜像的首次正式验收在前八组通过后，被增强的最后一组挡住：共享字号工具把关闭 `<details>` 的可见 `<summary>` 也排除，故无法证明“更多”参与 200% 检查。失败输出和本次合成对象保存在独立 0600 文件，未覆盖或删除。修正仅让可见 `<summary>` 参与字号检查；只读浏览器复现 390/1024/1440 的 `summary`、单元格与可见表头均被放大且无页面横向溢出。其后 `e39f538bab45260bf4d523b1b65ade7ecf0ac794` 补齐空表单与服务端拒绝时的弹窗反馈，并完成一轮 9/15/18 复验。

焦点外环修正后的 `d0b5b063295fd15ac258e8edb5d33f38313f4adb` 第一次管理员验收在第六组以“取消仍改变管理员资格”停止。该次合成对象独立保存在 0600 文件中；只读数据库核对资格仍为 `ENABLED`、版本 0 且更新时间未变化，独立 Chrome 连续三次取消后精确 HTTP 查询均为 200/1 条/`ENABLED`/版本 0，且未发送停用请求。原断言把 HTTP 错误、空结果、错行与资格实际改变合为同一提示，原失败瞬间的具体响应未记录，故不能倒推确切触发条件。验收脚本随后增加零停用请求、HTTP 200、精确资格归属与状态的分层断言；新的独立对象完整通过管理员 9/9、登录 15/15、只读数据库 18/18。没有降低断言或容差，没有删除验收步骤或旧对象。

`platform-tenant-admins:0`、`:1` 已实现并通过当前部署的功能、登录与数据库验证，已完成上述局部视觉修正与只读对照，但导航、原型“更多”遮挡和演示说明边界尚需产品决定。矩阵保持 `implemented`，本独立切片不收口。概览五页设置导航 `platform-tenant-detail:0`、配额、功能开关、安全策略、平台账户和其他后续工作继续保持各自未完成状态。WP-0017 整包与 M6 继续进行中；在管理员页原型一致性关闭前，不进入配额实现。
