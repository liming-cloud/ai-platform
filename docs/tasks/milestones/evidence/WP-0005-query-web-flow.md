# WP-0005：最终用户可信问答站点闭环证据

## 结论

最终用户查询站点已经形成可部署的纵向闭环：用户通过同源入口登录，
只能读取当前租户最新的已发布助手版本，提交一次问题后从持久化事件流
获得带引用回答或明确拒答。令牌只存在于页面内存，身份替换、退出和迟到
响应均不能把旧租户状态带入新会话。

- `656eafab3`，修复拒答验收污染默认助手和验收幂等键漂移。

## 已证明行为

- `GET /api/v1/query-assistants` 只返回当前租户每个助手的最新已发布版本。
- 查询助手投影只暴露助手编号、名称、版本编号、版本号和发布时间；
  不暴露提示词、模型部署、索引、知识空间和框架类型。
- 目录同时要求 `assistant:query` 与 `knowledge:read` 权限。
- PostgreSQL 查询以发布时间和助手版本编号组成稳定不透明游标，
  并通过真实数据库测试覆盖最新版本、分页和跨租户隔离。
- 查询站点的认证请求进入控制面，其余查询接口进入查询运行时；
  服务端事件流关闭代理缓冲并支持 `Last-Event-ID`。
- 浏览器令牌不进入本地存储、会话存储、地址或页面内容，刷新后必须重新登录。
- 会话修订号与请求拥有者共同阻止旧登录成功响应覆盖新租户令牌，
  也阻止旧会话的迟到 401 清除新租户令牌。
- 相同助手版本与问题的安全重试复用幂等键；版本或问题变化时产生新键。
- 页面只有登录、助手选择、提问、回答、引用、拒答和恢复所需入口，
  未增加无闭环的历史记录或说明导航。
- 登录失败、目录失败、会话过期、无权限、空目录、查询中、回答、拒答和
  查询失败均有独立状态和恢复入口。
- 回答和引用只作为文本渲染，不解析模型返回的超文本或 Markdown。
- 拒答验收结束后恢复正常阈值的已发布助手版本，演示站点不会停留在
  只能拒答的测试状态。
