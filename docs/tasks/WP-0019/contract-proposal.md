## 建议接受的决定

### D1：连接发布与平台供应授权分别持有事实

保留现有平台连接／部署所有权，增加明确的连接发布修订。VERIFIED 是一次有期限且绑定输入的验证，不能替代原型的“发布连接”；连接发布也不等于模型可用。平台部署只有能力验证通过才能发布，显式租户授权独立检查；停用／撤权使新使用失败关闭，不删除历史或自动修改租户对象。

这比将所有状态塞入一个枚举改写历史事实更容易保留验证、发布和健康的区别；不增加通用工作流或权限框架。原型没有的独立管理按钮不伪造，现有停用和撤权合同仍需 API 回归。

### D2：租户发现消费平台供应，不取得平台连接控制权

原型租户供应商页的“发现／重新探测”定义为刷新当前租户已授权供应的安全投影，不是使用平台密钥对厂商外呼。结果仅含名称、模型能力、驻留、来源修订和安全可用性；保存配置和调用时仍检查实时授权。独立租户供应投影资源不能复用旧租户自有连接的 ID 空间或命令。

移除旧租户连接创建／轮换 UI 的当前页面承接，保留并盘点已有 API 消费者后实施明确迁移；不在 S3 悄悄删除旧合同，也不保留页面隐式转回旧连接来源的兼容分支。“使用此模型”仅导航预选对象，不能提前写配置。

### D3：稳定配置 ID、独立修订及短时凭据

配置拥有启用和待验证修订；编辑与密钥轮换创建新修订，验证成功后显式启用才切换。初始使用平台托管认证；租户提交自己的新密钥时，仅对该配置的新修订覆盖认证，仍冻结同一平台批准的运行地址、模型和驻留，不取得平台密钥或地址编辑权。引用隔离、失败和取消均不影响旧启用修订。

这比原位替换密钥后再回滚更符合原型“旧版本继续服务”，也避免影响其他租户。移除来源校验的可空依赖绕过；缺少必需来源仓储时不能装配可写服务。DTO 和存储迁移须保持当前公开 ID 可追溯；旧数据无法证明来源时不可默认为有效。

### D4：能力验证与路由发布不等于运行回退授权

新增明确的 RERANK 模型能力和最小独立 Port，扩展只依赖公开端口／契约；不伪造通用 OpenAI 重排标准。厂商预设和管理员分类只定义验证意图，真实能力必须由对应协议调用证明。

路由策略发布为不可变配置快照，供后续助手版本显式冻结；不会原位修改已有助手。首版运行继续遵守 ADR-0040：Chat 仅在未输出正文且标准化瞬态失败时有限回退，Embedding 不回退。建议 RERANK 首版也失败关闭，不在本包增加自动回退执行器。原型同能力／同驻留选择布局保持，不能从演示状态机推导 Embedding／Rerank 自动回退授权；不支持的组合必须给安全拒绝原因，不能显示可用或静默按 Chat 执行。此处属于必须明确接受的生产能力约束，不是视觉例外。

模拟使用版本化样本、可追溯计价／负载与实际耗时，不能复制演示 30/30、预算乘比例或固定延迟。月预算是本策略模拟和发布上限；不据此宣称已实现平台全量计费／跨运行进程的月度硬扣费。确需增加全局扣费或扩展回退能力时另行决定，不能用模糊“预算校验”承诺未实现的运行机制。

### D5：最小候选与评测影响承接在所属上下文落地

配置启用保存不含秘密的版本变更事实，由知识上下文登记受影响知识库的重建候选、助手上下文登记重新评测影响。事件读取走模型公开 facade，消费者按配置修订／目标去重并重试；模型不反向依赖知识或助手。不自动构建、激活索引、发布助手或替换冻结路由。

比较方案：提前完整实现 WP-0021／WP-0023 会扩大本包；只写 outbox 并显示“候选已创建”会虚报原型行为。建议只实现被配置启用直接要求的候选／影响持久化与恢复验证，后续包复用这些真实记录继续生命周期。所需最小持久化结构与 facade 必须随专属 ADR 接受；消费者不完整时 S4 不通过，不把范围偷偷移交或把 WP-0019 标记完成。
