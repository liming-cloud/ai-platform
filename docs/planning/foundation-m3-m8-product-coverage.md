# 可信 RAG 基座 M3 至 M8 产品覆盖校准

历史设计说明：本文件记录 2026-07-28 的覆盖判断，不再代表当前 M2/M3 前沿或不可更改的 UI 蓝图。当前里程碑/前沿以 project/STATE.yaml 为准；M6 实施顺序、66 个生产入口、三项暂缓和实际会员验收以 ADR-0079、project/ROADMAP.md 及 project/m6-implementation-map.json 为准。以下历史“当前”与设备凭据范围不覆盖新决定。

## 目的与边界

本计划以 `docs/product/foundation-product-design.md` 和
`docs/design/foundation-frontend-design.md` 为不变的产品蓝图。它根据
2026-07-28 的产品经理浏览器验收，补足后续里程碑的产品覆盖和退出证据；
不改变当前 M2 前沿，也不创建、激活或实施 M3 工作包。

## 当前已验证的产品事实

- 企业控制台已能完成登录、个人 Chat 模型配置创建、凭据写入、草稿启用、刷新后状态读取，以及查询用量和脱敏审计查看。
- 问答工作台已能完成登录、选择已发布助手、提交问题，并展示带核验来源的回答。
- 模型厂家、端点、能力和目录由平台控制；浏览器只显示凭据已配置，创建或轮换后的 API Key 不可回显。
- 数据入口仍是“首份文本发布”引导任务，不是产品蓝图中的数据源、数据集、质量和索引生命周期工作台。

## 调整后的里程碑产品结果

### M3：受治理数据

实现数据源、数据集、Schema、敏感级别、质量规则、连接探测、同步报告、重试、退役、版本化索引和重建的完整任务流。数据来源以受治理身份、不可变同步产物和类型化连接器建模；索引创建只能选择 M2 已授权且已启用的 Embedding 配置，并显示冻结的模型、维度和版本。详细生命周期见 ADR-0028。

### M4：助手与可信查询

实现助手草稿、固定知识和模型依赖、测试问题、可信问答、拒答、引用、流式恢复、反馈和受权查询诊断。该阶段只交付可测试的助手路径，不把评测通过或发布审批伪装为页面按钮。

### M5：模型扩展

在 M2 受控目录边界内扩展多厂商、多类型、工具、MCP、多模态和音频适配器；增加路由、回退、驻留、健康、延迟和成本策略，禁止用户新增厂家或任意端点。

### M6：企业治理与发布制度

交付平台管理员的租户创建、停用、恢复、驻留与安全基线、平台目录授权和全局预算，以及租户组织和访问策略、设备凭据、评测数据集、评测运行、比较、成本预算、发布审批、审计导出和用量治理。企业控制台在此收敛到蓝图的概览、数据、助手、评测、治理、运维六个角色化区域，并严格区分平台管理范围和租户管理范围；当前顶级“模型”任务迁入治理中的模型运行组。

### M7：渠道与同意

交付设备问答外壳、渠道与连接器 SDK、画像同意与撤回、隐私控制和设备安全模型。设备界面只保留开始、提问、回答与继续四步，不能暴露控制台治理概念；SDK/API 不建立开发者门户，除非后续独立产品决策确认自助开发者任务。

### M8：生产就绪

交付运维工作台、生产发布与回滚证据、容量、灾备、漏洞与支持标准。M1 的演示演练只能作为输入，不得替代 M8 生产签署。

## 产品经理复核门槛

- 每个里程碑先以对应角色的浏览器任务证明关键闭环，再执行该阶段的自动化、集成和运行门禁。
- 页面完成不等同于产品完成；必须同时提供角色、任务、状态、权限、失败恢复和后端事实证据。
- M2 人工评审通过前，本计划仅作为后续范围基线，不能据此启动 M3。
- 三个前端应用、平台管理/租户管理双范围和 SDK/API 渠道边界由 ADR-0027 固定；M3 仅实现数据角色化闭环，不提前实现平台管理范围。
