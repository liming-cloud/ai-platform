# WP-0003 MinIO 客户端使用依据

## 研究边界

本记录只回答知识原始文本如何通过正式 Java 客户端写入私有对象存储，
以及该客户端如何被隔离在仓库扩展层。它不评价未来的云对象存储厂商，
也不把演示环境的自动建桶策略推广到生产环境。

研究材料来自 Maven 本地仓库中随正式构件下载的官方元数据和源代码：

- `io.minio:minio:8.6.0` 的 POM。
- `io.minio:minio:8.6.0` 的源代码包。
- 客户端公开类型的字节码签名。

本轮没有依赖互联网搜索结论。

## 固定版本与许可证

根 POM 固定以下正式版本：

| 构件 | 版本 | 用途 |
| --- | --- | --- |
| MinIO Java 客户端 | 8.6.0 | 对象写入、元数据读取、删除和桶检查 |
| OkHttp JVM | 5.1.0 | 客户端运行时网络实现 |
| SpotBugs 注解 | 4.9.3 | 满足客户端公开签名的编译期注解依赖 |

MinIO 客户端 POM 声明 Apache 许可证 2.0。

## 直接确认的客户端行为

从正式客户端的公开接口和源代码确认：

- `PutObjectArgs` 支持输入流、已知对象长度、内容类型和用户元数据。
- `StatObjectArgs` 与 `StatObjectResponse` 可读取对象长度、内容类型和用户元数据。
- 用户元数据键在客户端处理时会统一为小写，因此摘要键固定为 `sha256`。
- `BucketExistsArgs`、`MakeBucketArgs` 和 `RemoveObjectArgs` 分别覆盖桶检查、
  演示环境建桶和受治理删除。
- 客户端提供连接、写入和读取超时设置；系统为三者设置有限默认值，
  避免网络调用无限等待。
- 输入流写入时传入平台已计算的准确字节数，不在适配器中再次把完整内容读入内存。

## Maven 依赖结论

在启用严格编译告警的工程中，仅声明 `io.minio:minio` 会出现两类问题：

- 客户端发布元数据没有为当前 Maven 构建解析出可用的 JVM 版 OkHttp 类。
- 客户端公开签名引用的 SpotBugs 注解缺失。

因此扩展模块显式声明 `okhttp-jvm` 和 `spotbugs-annotations`。
这两项只属于 MinIO 扩展，不进入知识数据核心上下文。

## 工程使用决策

- `knowledge-data` 只定义 `TextContentObjectStoragePort` 和受治理内容引用。
- `object-storage-minio` 单独实现该端口，并独占 MinIO 客户端依赖。
- `control-plane` 作为组合根选择并装配具体扩展。
- 对象键由服务端按租户、知识空间、数据源、内容版本和摘要生成。
- 桶保持私有，匿名读取必须被拒绝。
- 数据库只记录对象键、摘要、长度、媒体类型和发布版本，不保存原文。
- 演示组合部署允许在启动时创建缺失桶；生产配置默认要求桶预先存在。
- 客户端异常只通过固定平台异常向上游传播，避免把端点、凭据或内部错误泄漏给接口调用方。

## 验证要求

扩展模块使用与组合部署相同且固定摘要的 MinIO 镜像执行真实容器合同测试，
覆盖内容寻址写入、幂等覆盖、元数据、匿名访问拒绝、删除、生产建桶限制和摘要缺失。
完整演示验收还必须从接口发布文本，再独立核对 PostgreSQL 事实与对象内容摘要。
