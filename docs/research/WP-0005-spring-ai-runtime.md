## 仓库事实

通过代码图谱探索
`QueryRuntimeConfiguration`、`ProviderConnectionProbe`、
`OpenAiCompatibleConnectionProbe`、`EmbeddingModelPort` 和
`DefaultCandidateSearchService` 后确认：

- 查询运行进程当前只装配可信会话、确定性嵌入和授权候选检索，
  尚无对话模型、助手版本、查询任务和引用生成。
- 模型运行时已有按 `ProviderKind` 选择连接探测器的小型扩展接口，
  但尚无供应商连接和模型部署聚合、持久化及公开接口。
- OpenAI Compatible 探测器已具备出站端点校验、密钥引用解析、
  密钥值及时关闭和最小对话探测能力。
- 当前 OpenAI Compatible 探测器只声明对话和流式对话能力，
  尚未覆盖嵌入模型，也不存在 Ollama 扩展。
- 候选检索已经强制使用服务端可信租户上下文和知识读取权限，
  但检索结果还没有进入回答生成和引用再校验。

## 官方资料直接观察

### ChatClient 与模型对象

- `ChatClient` 同时支持同步和流式调用，并将对话模型、默认提示、
  顾问和运行时参数组合成统一调用入口。
- 对话模型本身无会话状态；需要记忆时，历史必须由平台显式附加。
- OpenAI 与 Ollama 的对话实现同时实现同步和流式模型接口，
  可通过底层依赖手工构造，不要求把单一厂商配置写死在全局启动配置中。
- OpenAI Compatible 允许自定义地址和运行时选项，但额外参数会直接进入请求，
  因此不能把任意键值从页面透传给厂商。
- Ollama 可通过原生适配器构造，也提供 OpenAI 兼容接口；两者支持范围不同，
  平台必须按实际探测能力选择，不能根据厂商名称推断。

### 顾问链

- 顾问可在调用前检查或修改请求，也可在调用后检查响应；同步和流式使用不同接口。
- 顾问加入顺序会改变执行语义，前一顾问的结果会传给后一顾问。
- `RetrievalAugmentationAdvisor` 提供模块化检索增强生成，
  并支持查询变换、检索和文档后处理。
- 原生检索顾问的过滤表达式和文档语义面向通用向量库，
  不能替代本平台已经建立的租户、知识空间、活动索引版本和证据授权规则。
- 工具调用顾问默认可能自动注册。M1 不开放工具调用，应显式关闭，
  防止模型意外触发未纳入权限设计的外部动作。

### 观测和内容保护

- Spring AI 对 `ChatClient`、顾问、对话模型、嵌入模型和向量存储提供指标与追踪。
- 提示词和回答可能包含大量敏感信息，默认不导出；
  官方开关的默认值也是不记录提示词和回答正文。
- 顾问名称、顺序、是否流式和耗时适合作为低敏运行指标；
  租户、密钥、原始问题、检索正文和回答正文不能作为普通指标标签。

### 检索和拒答

- Spring AI 的模块化检索增强生成支持空上下文拒答，也允许对候选文档进行后处理。
- 这只约束交给模型的上下文，不能证明模型回答中的某个事实确实来自某个证据。
- 因此引用必须由平台使用稳定证据标识进行后校验；
  模型生成的任意网址、文档名或分块标识均不能直接成为可信引用。

## 工程推导

以下是依据一手资料和本项目既有安全边界作出的工程决策输入：

1. 模型对象不能作为全局单例绑定一个厂商。运行时按
   `租户 + 供应商连接修订 + 模型部署修订 + 模型类型`
   构造并缓存，缓存有容量和失效边界，键和值均不得包含明文密钥。
2. 供应商连接与模型部署配置属于控制面事实；Spring AI 对象属于可丢弃运行时对象。
   配置发布后淘汰旧对象，新请求只解析已发布修订。
3. 领域层和公共接口使用平台自己的对话、嵌入、流式事件和用量类型；
   `ChatClient`、模型选项、顾问与响应类型只存在于适配器和装配层。
4. 权限、配额、活动索引解析、证据再鉴权、查询事实持久化和计量不能隐藏在
   Spring AI 顾问内。这些阶段由应用服务显式编排，便于事务、重试和安全审计。
5. 提示构造、安全约束和模型生成可以使用固定 Spring AI 顾问链；
   顺序由代码常量和架构测试约束，页面不得增删或排序。
6. 助手发布生成不可变 `AssistantVersion`，固定对话部署修订、知识空间、
   活动索引版本、系统指令摘要、生成限制、引用和拒答策略。
   后续配置变化只能创建新版本。
7. 查询任务在接受时冻结助手版本和索引版本，后续重试不能自动切换模型或索引。
8. 上下文使用平台生成的稳定证据编号。生成结果只允许引用本次候选编号，
   平台再次检查证据属于可信租户、冻结索引和本次查询。
9. 无证据、越权证据、未知引用、缺失必需引用或模型输出无法解析时拒答；
   不以删掉错误引用后继续展示答案的方式掩盖失败。
10. 服务端事件由已持久化查询事实投影产生。每个查询任务内序号单调递增，
    完成和计量事实只写一次，断线重连从最后已接收序号之后继续。
11. 演示环境默认使用确定性对话和嵌入适配器，以保证离线验收可重复；
    它只能证明合同、权限和引用闭环，不能作为真实模型准确率证据。
12. 真实 OpenAI Compatible 与 Ollama 冒烟必须显式启用，
    并复用相同的平台合同、密钥、出站访问和脱敏测试。

## M1 固定生成顺序

M1 查询执行顺序固定为：

`可信上下文 -> 配额 -> 策略 -> 助手版本解析 -> 活动索引校验 -> 候选检索
-> 证据再鉴权 -> 安全提示构造 -> 模型生成 -> 引用校验 -> 查询事实与计量`

其中 Spring AI 只负责“安全提示构造 -> 模型生成”之间的对话调用和观测，
不拥有租户授权、索引生命周期、引用真实性和计量幂等事实。

## 仍未覆盖

- 真实模型的回答质量、吞吐、首令牌延迟、限流和费用。
- 多模型路由、备用切换、数据驻留和成本预算。
- 对话记忆、工具调用、MCP、多模态和结构化查询。
- 大规模流式事件保留期与跨区域恢复。

这些问题不阻止 M1 的确定性可信问答闭环，后续必须通过独立工作包和证据进入。
